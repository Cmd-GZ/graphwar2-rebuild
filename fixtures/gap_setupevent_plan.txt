## 1. 三个口径（**分开定义、分开报，禁止合并**）

| 口径 | 定义 | 复算方法 |
|---|---|---|
| **M：机器码条数** | 某份构建里 `地址互不相同` 的函数个数。Android 侧 = `.symtab` FUNC 按地址去重、模块名取自**该地址的第一个符号名**（= census 口径，`tools/global_triage.py --android-census`）；Linux 侧 = FDE 条数 | census |
| **S：源码函数数** | 把同一源码条目的多副机器码副本**合并**后的条数：`{{closure}}` 并入父函数、泛型单态化多副本算 1、`#[derive]`/宏产物算 0、drop glue 算 0 | §4 规则 |
| **1:1：严格一一对应** | `S` 里**恰好一条**机器码副本、在 Linux 侧**恰好一个** FDE、且那个 FDE 在 527 台账里**恰好一行**的条数 | §4 + 527 台账 |
| **G：Linux 硬归属行** | 527 台账里 `ours_file` == 本模块的行（本表 21 / 0）。⚠️ 这是**归属口径**，不是函数个数：`setup_control` 自己的 Location 锚函数是 **37** 条（`fixtures/module_funcs.tsv`），其中 16 条被 527 的多数投票压到别的模块去了 | `fixtures/function_coverage.tsv` |

> ⚠️ **不许**用 `M − G` 当工作量（那是 census 口径差），也不许用 `M − F1F2`（`gap_proxy` 就是它）。
> 工作量 = §4 判成 `real-missing` 的 **S** 条数。

## 3. 类别定义（**原样继承** T82 `fixtures/f3_triage_plan.txt` §1 / T86 §134.3，不新增类别）

| 类别 | 定义 | 进不进"诚实缺口" |
|---|---|---|
| `real-missing` | **原版有我方没有的源码级函数**：函数体承载原版模块自己的语义，能按源码写出来 | **进** |
| `na:std-mono` | **std/core/alloc 的单态化**：函数体是标准库的，本模块只贡献被内联进去的实参 | 不进 |
| `na:gdext-glue` | **gdext 宏产物**：类注册胶水 / 属性访问器 / `#[func]` 分发壳 / 信号 connect 闭包 / `__inner_init` / vcall 适配器 | 不进 |
| `na:other` | **其它不该手写的编译器生成物**：drop glue / panic 展开 / `#[derive]` 产物 / trait 对象 shim / 泛型单态化实例 | 不进 |
| `unknown` | **判不了**（必须写清缺什么证据） | **进**（保守） |

### 3.1 本轮必须用到的四个 `subclass`（只写在 `subclass` 列，不改类别语义）

* `na:other / derive-product` —— `#[derive(Serialize/Deserialize/Clone/…)]` 生成物：
  `<… as serde::ser::Serialize>::serialize`、`<… as serde::de::Deserialize>::deserialize`、
  `__FieldVisitor::visit_str`、`__Visitor as Visitor>::expecting`、`<T as Expected>::fmt`、
  `<T as core::clone::Clone>::clone`。**源码那一行是 `#[derive(...)]` 属性，不是 `fn`**。
* `na:other / drop-glue` —— `core::ptr::drop_in_place<…>`。
* `na:other / closure-in-fn` —— `…::{{closure}}`：源码级**不是独立 `fn`**，是父函数体内的一段闭包体。
  ⇒ 源码函数数 **+0**；但**必须**在 TSV 的 `note` 列写清"父函数是否已实现、闭包体是否已复现"，
  因为"闭包体没实现"是**行为缺口**（只是不进 527 的分母）。
* `na:gdext-glue / vcall-adapter` —— `__init::__inner_init::{closure}::{ptrcall_fn,varcall_fn}`、
  `__virtual_call::virtual_fn`、`__default_virtual_call::virtual_fn`、`__register_methods`、
  `__register_constants`、`class_id`。

## 4. 判决规则（命中即停；逐条写进 TSV 的 `rule` 列）

**顺序（优先级）**：`gdext-glue` → `derive/drop` → `closure-in-fn` → `real-missing` → `unknown`。

* **R-G1（名字即判）`na:gdext-glue`**：demangled 名含 `godot_core::` / `godot_cell::` /
  `godot_ffi::` 的 trait impl 段，或等于 `_::__init::__inner_init`（含其 `{{closure}}`），
  或 `<… as …UserClass/GodotClass/ImplementsGodot{Aoi,Virtual}>::…`。
  *例外*：`<X as IControl>::init` / `::ready` / `::process` **不是**宏产物（gdext 的宏只生成薄包装，
  用户写的 `fn init/ready/process` 是源码级函数），走 R-R1。判据见 §5 C6。
* **R-G2（名字即判）`na:other / drop-glue`**：名以 `core::ptr::drop_in_place<…>` 开头。
* **R-G3（名字即判）`na:other / derive-product`**：名里出现 `<impl serde::…>` / `serde::de::Visitor` /
  `serde::de::Expected` / `<… as core::clone::Clone>::clone`。
  ⚠️ `VOL_CAP` 不适用于 R-G1/G2/G3（它们是**名字判定**，不是结构推断）；但 TSV 必须记 size。
* **R-C1（`na:other / closure-in-fn`）**：名含 `::{{closure}}` 且父段不是 `_::__init`（那是 R-G1）。
  要求同时满足：能指到父函数名 + 在父函数 FDE 之外有自己的 FDE（真独立边界）。
* **R-R1（`real-missing` 候选）**：名形如 `GraphwarSetupControl::<method>` / `GraphwarEvent::<method>`
  （或 `impl` 段里的业务方法名），即**手写方法**。判定为 `real-missing` 还需 §4.1 两条同时成立。
* **R-U（`unknown`）**：以上都不干净命中，或体没读完（>0x1000 未读完 ⇒ `unknown`，必须写缺什么）。

### 4.1 `real-missing` 的追加要求（比 T82 的 R-REAL 更严一档）

1. **独立边界**：arm64 侧有自己的 `.symtab` FUNC 符号（`st_size > 0`）**且**不是 `::{{closure}}`、
   不是 `_::` 宏段；Linux 侧若有 FDE 则记地址，没有则写"无 Location 锚 / 可能被内联"（**推断**）。
2. **语义可写**：能写出该函数做什么的至少一句可复核描述，并带 ≥1 条**具体指令证据**

## 5. 调用形态闸（T89 `docs/06` §137.5，**本轮强制、逐条记录**）

对**每一条**目标行记 `bl`（arm64 直接调用点数）与 `slot`（**重定位 addend == 本函数地址**的槽数）：

| 形态 | 含义 | 结论约束 |
|---|---|---|
| `bl ≥ 1` 且 `slot = 0` | 被**直接调用** | 泛型单态化的必要形态；但**单靠它不能定案** |
| `bl = 0` 且 `slot ≥ 1` | 地址只出现在**数据槽**里（交给 API 的闭包 / 注册表项 / vtable） | **禁止**据此判 `na:std-mono`（T89 驳回 `0x438880` 的教训） |
| `bl = 0` 且 `slot = 0` | 只经 vtable/间接调用 | 必须另找间接调用链，否则 `unknown` |

**本轮的 arm64 实现法（写死，跑的时候不许改）**：
* `bl`：扫 Android `.text` 的每条 4 字节指令，判 `(word >> 26) == 0b100101`，`target = pc + sign_extend(imm26)*4`，
  计数 `target == addr`。
* `slot`：解 Android `.rela.dyn` 的 `R_AARCH64_RELATIVE`（类型 1027）项，计数 `addend == addr`。
* ⚠️ arm64 侧没有 `rel32` 这个概念，本表用 `bl` 代 `rel32`；Linux 侧若已有 527 行，另记 Linux 的
  `call rel32`/slot（`tools/addr_probe.py callers`）。
