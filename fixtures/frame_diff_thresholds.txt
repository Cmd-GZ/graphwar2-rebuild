# 视觉帧对拍 · **预注册门槛**（`dispatch/94`，`agent/visual-frame-diff`）

> 这份文件**先于任何一次原版↔我方的对拍结果**写定并提交。判据 = 本文 + 三方脚本
> （`tools/frame_capture.py` / `tools/frame_diff.py`），跑完**不许改**门槛来"让它过"。
> 若实测不过，只许在 `fixtures/frame_diff_results.tsv` 与 `docs/06` §53 里如实记录数字与差异区域。

## 0. 这份门槛管什么

同一台机器、同一 Xvfb 尺寸、同一套点击脚本下，**原版真游戏**（`Graphwar.x86_64` +
`Graphwar.pck` + `libgraphwarrust.so`，2.0.60）与**我方客户端**（`client/`，Godot 4.7.2 +
`libgw2_rebuild.so`）在**同一屏、同一交互步骤之后**的两张 1920×1160 截图，

**L1 粗筛 → L2 分区 → L3 逐像素**，三层全过才算"这一屏画出来一样"。

## 1. 固定条件（两路必须一致，否则该屏记"不可比"）

| 项 | 值 |
|---|---|
| Xvfb | 各自私有 display：`Xvfb :NN -screen 0 1920x1160x24 -listen tcp -ac -nolisten unix` |
| 渲染后端 | 两路都强制 **OpenGL3**（本机无 Vulkan ⇒ 引擎自动回落，日志留证） |
| mesa | `__EGL_VENDOR_LIBRARY_FILENAMES=…/50_mesa.json`、`LIBGLX_VENDOR_LIBRARY_NAME=mesa`、`LIBGL_ALWAYS_SOFTWARE=1`（llvmpipe） |
| 窗口 | `--resolution 1920x1160 --position 0,0`（1920 宽屏、无 WM 不最大化） |
| 取帧 | ImageMagick `import -window <游戏窗口 id>`（**只取窗口内容**，不取 root：Xvfb 无合成器，root 上是黑的） |
| 引擎版本 | 原版内嵌 **Godot 4.7.stable.official.5b4e0cb0f**；我方 **Godot 4.7.2.stable.official.ed1daf0bf** ⇒ **大版本同（4.7）、补丁版不同**，这条**如实登记为已知混淆项**，不改（换成原版引擎跑我方工程 = 后补的对照实验，不在本门槛内） |
| 点击脚本 | 两侧**完全同一串**坐标与间隔（见 §2），由 `tools/frame_capture.py` 执行 |

## 2. 三屏与操作步骤（两路同一串）

```
S1 MainMenu      启动后等 4.0 s，不点任何东西
S2 PlayScreen    点 Campaign(534,629) → 等 1.5 s → 点关卡节点 0(241,228) → 等 1.5 s
                 → 点 Start(1074,1009) → 等 3.0 s
S3 PlayScreen+   在 S2 之后：点表达式键盘上的 x(1625,730) → 等 0.6 s
                 → 长按 Fire!(1855,55) 2.0 s → 等 6.0 s（等结算落地）
```

每屏取 **3 帧**，帧间隔 **1.2 s**（同一侧同一屏的三帧互相之间也有差异 —— 见 §3 的噪声地板）。
三帧中**第 1 帧**参与跨侧比较；第 2、3 帧只用来量**同一侧自己的抖动**（噪声地板），
用来判断"跨侧差异是否大于动画相位噪声"。

## 3. 三层判据（逐屏判，数值全部落 TSV）

### L1 尺寸与主色分布（粗筛）

| 判据 | 门槛 |
|---|---|
| L1-a 尺寸 | 两张 PNG 解出来必须**都恰好 1920×1160**；不等 ⇒ 该屏直接判"不可比/不过" |
| L1-b 全局均值 | 三个通道的**平均色** \|Δmean\| 每通道 **≤ 2.0 / 255** |
| L1-c 主色 | 两张图的**第一主色**（像素数最多的 RGB）必须**同一个颜色**，且它的占比相差 **≤ 2.0 个百分点** |

### L2 分区（6×4 = 24 块，每块等分）

| 判据 | 门槛 |
|---|---|
| L2 每块 | 该块**每通道平均色** \|Δ\| **≤ 2.0 / 255**；**24 块全部满足**才算 L2 过 |

块划分：`x` 方向 6 等分（每块 320 px）、`y` 方向 4 等分（每块 290 px），
第 `(row, col)` 块 = `x∈[320·col, 320·(col+1))`、`y∈[290·row, 290·(row+1))`。
**报"差在哪一块"就用这个编号**（`row,col` 从 0 起、左上角为 `0,0`）。

### L3 逐像素（**只在 L1 与 L2 都过时才算数**）

| 判据 | 门槛 |
|---|---|
| L3-a 差异像素比例 | 任一通道 \|Δ\| > 0 的像素占比 **≤ 0.10 %** |
| L3-b 最大通道差 | 全图 `max\|Δchannel\|` **≤ 8 / 255** |

### 判定

```
L1 不过            ⇒ 该屏【不过（L1）】
L1 过、L2 有块超限 ⇒ 该屏【不过（L2）】，报超限的块编号
L1、L2 都过        ⇒ 看 L3：全过 = 【过】；否则【不过（L3）】
```

## 4. 噪声地板（**不是门槛**，只用于解释）

同一侧同一屏的 3 帧里，任意两帧的"差异像素比例"就是**该屏的噪声地板**
（原版在准备态/对局中里士兵的手脚会转、输入框光标会闪 ⇒ 地板不是 0）。
**跨侧差异像素比例 ÷ 噪声地板** 作为"差异是否可归因于相位"的参考量，写进结果表，
但**不参与判定**（判定只看 §3）。
