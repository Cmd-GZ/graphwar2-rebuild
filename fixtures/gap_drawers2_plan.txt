## 4. 判决规则（命中即停；逐条写进 TSV 的 `rule` 列）

**R1 形态继承（先判"是不是源码里的独立 `fn`"）**：
* 名字含 `__register_methods` / `__register_constants` / `__virtual_call::virtual_fn` /
  `__default_virtual_call` / `class_id` / `__init::__inner_init` / `::ptrcall_fn` / `::varcall_fn`
  ⇒ `na:gdext-glue`（**两条**辅证：该地址在全 `.text` 无 `call rel32` 调用点 **或** 位于 `.data.rel.ro` 表项；
  本轮沿用 T82 §4 的 G1/G1b 形态读数，不重跑全量扫描）。
* 名字含 `drop_in_place` / 首段 crate 是 `core` ⇒ `na:other/drop-glue`。
* 名字含 `ready::{{closure}}` ⇒ `na:other/closure-in-fn`（闭包体在父函数体内，父函数已实现 ⇒ 不单独立项）。
  若父函数**未**实现，则该条记 `unknown` 并写明"闭包体随父函数一起缺"。

**R2 双视角必答**：每条 Android 真名都要回答两问 ——
(a) Linux 527 里有没有对应行（`linux_527` 列，`—` = 没有）；(b) 我方 src 里有没有函数体。
(a) 为 `—` 时必须按 **T98 §147.1 R4** 排除三种解释：① 体内无 `panic::Location`（⇒ 进不了 527 分母，
**不是**"原版没有"）；② 归属被多数投票压到别的模块；③ 被内联。
三种解释都排除不了 ⇒ 记 `unknown`，不许判 `implemented` / `real-missing`。

**R3 体积闸（`VOL_CAP = 0x800`）**：`st_size > 0x800` 且未逐条读完 ⇒ 不许判 `na:*`，至少 `unknown`。
（`get_entity_name_label` 2832 = 0xB10 > 0x800 ⇒ 按此条必须读完或降 `unknown`。）

**R4 调用形态闸（T89 §138.5 / T82 §10 E6/E7，原样继承）**：
`na:std-mono` 必须 `call rel32 ≥ 1` **或** R-STD 结构组 A/B/C 命中；
本模块预计用不到 `na:std-mono`，但**判到就按此闸**。

### 4.1 `implemented` 的判据（比 T82 的 P2 更严一档，**T98 §147.6 第 3 条的教训**）

`implemented` 必须满足：**我方 `src/<module>.rs` 里存在同名或同语义函数的函数体**，且
① 该函数体能指到本表某个 vaddr 的**指令**（不是只贴了地址注释）；或
② 它是纯算术/纯结构的一部分，已在 `docs/16`/`docs/06` 有逐条算术复原记录，并在我方有对应 `pub fn`
（例：`draw_offset_triangle` → `entity_drawer::offset_triangle` / `arrow_head`）。
**只贴了地址注释、没有函数体 ⇒ 一律 `real-missing` 或 `unknown`，不许 `implemented`**
（`get_entity_*_sprite` 三条上一版就是被 P2 记成 F1 的；本轮按本条重新裁决）。

### 4.2 `real-missing` 的追加要求（比 T82 的 R-REAL 更严一档）

除 T82 R-REAL 的三组 na 规则全不命中 + 能写出一句可复核语义外，本轮**追加**：
* 必须给出**至少 2 条逐位证据**（指令 + 地址），其中至少 1 条是**判别性**的常量/偏移/字面量
  （例：`cmp qword ptr [rsi+0x60]` 之于 skin 表、`lea ... @0x19f3c0 'set_size'` 之于槽名）；
* 必须写清**返回值形态**（由 sret 写入点 `mov [rbp+…]` / 返回寄存器推断；推不出就写"缺 sret 布局"）。

### 4.3 `S`（源码函数）的算法 —— 回答"真实待写几个"

```
S_real       = |{ 条目 | class == real-missing }|
S_impl_out527 = |{ 条目 | class == implemented 且 linux_527 == — }|   # 已写但不在 527 分母
S_unknown    = |{ 条目 | class == unknown }|
S_total      = S_real + S_impl_out527 + |{ 条目 | class == implemented 且 linux_527 != — }|
待写源码函数 = S_real（本轮要写的） 与 S_real + S_unknown（保守下界/上界一起报）
```
**不许**把 `na:*` 算进"待写"。

## 7. 跑前就承认的已知会漏（写在这里，别事后找补）

* **L1** Android 是**兄弟构建**（arm64）：`A` 口径的函数数受平台层差异影响（全仓 Android 12,609 vs
  Linux 13,263，差 654）；`A` 与 `M` 的**差**不是缺口，只是**代理**。
* **L2** `ready::{{closure}}` 判 `na:other` 是**保守方向的反面**：闭包体在源码层确实存在。
  本轮的处理：只有父函数**已实现**且闭包体内容已被父函数体覆盖时才判 `na:other`；否则 `unknown`。
