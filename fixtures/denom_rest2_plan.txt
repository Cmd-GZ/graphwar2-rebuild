  3. 每个**实参常数**都能指到 `.rodata` 槽地址（或立即数编码），并给出该槽的**值**；

- **不许动**：`fixtures/denom_outside.tsv`、`fixtures/function_coverage.tsv`、`client/**`、门槛/护栏、

## 1. 优先级与逐条判据

### P1 `PlayScreenControl::append_debug_text`（arm64 `0x3deec8` / 436 B；x86 候选 `0x3d93c0`）

**只欠读常数**（操作序列 T109 已读出），所以排第一。

判据（逐条都要在代码注释里指到指令）：
| # | 判据 | 取证方法 |
|---|---|---|
| 1.1 | 序列 = `push_color` → `Control::get_size` → `push_font_size` → `push_outline_size` → `push_outline_color` → `append_text(text)` → `append_text("\n")` → `pop`×3 | arm64 `bl` 目标名（symtab 未 strip）；x86 GOT 槽序（0x9baff8/0x9bb000/0x9bb008/0x9bb010/0x9bb018/0x9bb020）对照 |
| 1.2 | `push_color` 实参 = `.rodata` 0x198ed0 的 **4×f32 = (1,1,1,1)**；x86 同值槽 `0x19ed00` | 读槽 16 字节 + 看 `0x7b4df0 ldr q0,[x19]` 证明 Color 是**按指针**传（x1 = 槽地址） |
| 1.3 | 字号 = `(get_size().x / 25.0) as i32`；25.0 = arm64 `fmov s0,#25.0`，x86 `divss [0x1b9b8c]` | 追 `fmov s8,s0`（x 分量）+ `fdiv` + `fcvtzs`；x86 `cvttss2si` + 饱和 `cmov` 说明是 Rust `as i32` 饱和转换 |
| 1.4 | `push_outline_size(4)`：立即数 `mov w1,#4` | arm64 0x3def64 / x86 `mov esi,4` |
| 1.5 | `push_outline_color` 实参 = `.rodata` 0x197110 的 **4×f32 = (0,0,0,1)**；x86 `0x19cf70` | 读槽 |
| 1.6 | 尾部 `"\n"` = `.rodata` **单字节 0x0a**（arm64 0x19bdfe / x86 0x1bf7e6） | 读字节 |
| 1.7 | `pop` **3 次**（与 4 次 push **不对称**）：两构建都得 3 | 数 `bl`（arm64）/ 数 `call r15`（x86 pop 指针被提到寄存器） |

**风险**：若 x86 候选地址 `0x3d93c0` 被判为不同函数 ⇒ 结构对照不成立，只能降成"arm64 单构建观测"。
反证条件：x86 侧的 `push_color` 槽实参**不是** (1,1,1,1) 或序列不同。

### P2 `PlayScreenControl::append_function_entry`（arm64 `0x3df07c` / 1424 B；x86 候选 `0x3d9590`）

判据：
| # | 判据 | 取证方法 |
|---|---|---|
| 2.1 | 前 5 步与 P1 同（push_color 的实参**来自调用方**，不是常量） | 调用点 arm64 `0x3e27dc` / `0x3e2a70`：`x4 = &Color` 由 `ucvtf`+`fdiv v0.4s` 从字节色算出（**颜色值不是常数，如实登记**） |
| 2.2 | 第一段文本 = **arg1 + ": "**；": " 是 `mov w9,#0x203a; strh` 两字节 | arm64 0x3df1c0-0x3df1c4；x86 0x3d96d2 `mov word [rax+rsi],0x203a` |
| 2.3 | 第二段 = `w3 != 0 ? "dy/dx = " : "f(x) = "`；两串 = `.rodata` 0x179a08(8 B) / 0x19bed0(7 B) | arm64 0x3df208-0x3df228 `csel`+`cinc`；x86 0x3d972d-0x3d973d `cmovne`+`lea rdx,[rax+7]` |
| 2.4 | 第三段 = **arg2** 经 7 次 `str::replace`：`+`,`-`,`*`,`/`,`^`,`(`,`)` 各替换成 `U+200B`+自身 | 7 个 (from,to) 槽对：arm64 0x19bf7f/80, 87/88, 8f/90, 97/98, 9f/a0, a7/a8, af/b0；x86 0x1bf96f/70 … 0x1bf99f/a0；`U+200B` = `e2 80 8b` |
| 2.5 | 尾部同样是 `append_text("\n")`，但 `pop` **4 次**（4 push/4 pop 对称） | arm64 0x3df4c0/4d8/4f0/508；x86 pop 指针提到 `r15` 后 `call r15`×4 |
| 2.6 | arg1 = `&String`（首段用它 + 追加 ": "），arg2 = `String`（被 clone 后替换） | arm64 `ldr q0,[x20]`/`ldr x1,[x20+0x10]`（arg1 三字段）vs `ldr q0,[x21]`→`String::clone`→replace 链 |

**判据被证伪时的处理**：若 `pop` 数与 push 数在某一构建里对不上（例：arm64=4 / x86=1 是我第一版误读，
因为 x86 把 pop 指针提到 `r15`），**以两构建都能解释的读法为准并在注释里写清陷阱**。

### P3 `RootNode::user_args`（arm64 `0x3ab2bc` / 672 B；x86 候选 `0x3b5390`）

T109 把这条判给"clap derive 5752 B 读不通"——**本轮先证伪这条前提**：
`symtab` 里 `_<graphwar_root_node::Args as clap_builder::derive::Args>::augment_args` 是**独立符号**
（`0x3b0bd8` / 5752 B），所以 `user_args` 本身**不含** derive 展开。判据：

| # | 判据 | 取证方法 |
|---|---|---|
| 3.1 | `user_args` = `std::env::args()` → `Vec<String>::from_iter` | arm64 0x3ab2e4 `bl std::env::args` + 0x3ab2f0 `Vec<String>::from_iter` |
| 3.2 | 扫 Vec：只认 `len == 2` 且头两字节 == `"--"`（`mov w10,#0x2d2d`）的项，取**第一个** | 0x3ab334 `ldr x12,[x11,#0x10]; cmp x12,#2` + 0x3ab344 `ldrh w11,[x11]; cmp w11,w10` |
| 3.3 | 结果首元素是合成串 **"graphwar"**（8 字节，`movk` 链 `0x7261_7768_7061_7267`） | 0x3ab3a0-0x3ab3c0 四条 `movk`/`str x8,[x0]` |
| 3.4 | 其余元素 = `--` **之后**的全部参数（`String::clone` 逐条） | 0x3ab490 `add x23, x8, #0x18`（跳过 `--` 本身）+ 0x3ab4ac `String::clone` |
| 3.5 | 没有 `--` ⇒ 结果只有 `["graphwar"]` | 0x3ab328 `cmp x8,x26; b.eq 0x3ab380`（0x3ab380 = 只造 "graphwar" 的臂） |

**副产品（必交）**：从 `augment_args`（`0x3b0bd8`）+ `FromArgMatches::from_arg_matches_mut`（`0x3b2250`）
把 5 个 CLI 参数全表导出到 `fixtures/user_args_table.tsv`：id / 长名 / value_name / 类型 / help 原文 +
每个串的 `.rodata` 槽地址与长度。**类型**判据：`_<u16 as ValueParserFactory>::value_parser` 出现 3 次
⇒ 3 个端口是 u16；另 2 个走 `Arg::value_parser::hf35e5b93a8`（String 的 factory）⇒ 2 个地址是 String；
`from_arg_matches_mut` 里 `try_remove_one` 的两份单态分别被 14/20 与 14/11/11 长度使用，与之一致。

**不做的事**：不引入 clap 依赖、不把 5 个 builder 调用链翻译成 clap 调用。落码只落
**`user_args` 的取参语义**（`std::env::args` + `--` 过滤 + 合成 argv[0]），这是纯 `std` 可复现的。
`augment_args` 的 builder 链**只登记不落**（缺 clap 依赖；且它属 `clap_builder`，不是游戏业务逻辑）。

**风险**：`--` 取"第一个"还是"最后一个"若读错，语义恰好相反（取之后 vs 取之前）。判据 3.2 要求
逐条指令走一遍循环出口；反证条件：若循环在命中后继续扫到末尾，说明取的是**最后**一个。

### P5 `RootNode::print_help_and_exit_if_requested`（arm64 `0x3ab19c` / 288 B）

## 2. 档位纪律

- 双构建（arm64 未 strip + x86 stripped）**逐指令同构** + 常数槽同值 ⇒ 仍只是**观测**：
  没有运行时对拍（不能标逐位）。文档里逐条写"观测（arm64 指令 + x86 同值槽）"。
- 颜色/字号的"值"是**从 `.rodata` 读出来的位模式**，属观测；`as i32` 的语义（饱和 vs 截断）
  在 arm64 是 `fcvtzs`、x86 是 `cvttss2si`+`cmov` 夹取，两侧一致 ⇒ 观测。
- `args` 的 `required`/默认值：只有静态串证据 ⇒ 标**推断**，并把缺什么写清。
