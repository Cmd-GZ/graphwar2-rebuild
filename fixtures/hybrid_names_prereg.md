## 1. 要预测什么

把两条独立证据按**域**组合，输出「一个 x86 函数该用哪个名字、来自哪条轴」：

| 轴 | 来源 | 它强的域（已发表的事实） | 它弱的域 |
|---|---|---|---|
| **结构指纹**（同 ISA，Linux↔Windows） | REF 配置 `W_SAME + scal=0.25`（`docs/02` §43.4 预注册选中），`CF.rank()` 的 top-1 搭档的 Windows 符号名 | 族外 **407/454 = 89.6%**（§35.12） | 关卡闭包族 **14/27 = 51.9%**（§35.12） |
| **顺序轴**（arm64 `.symtab` 顺序 + 体量 ⇒ x86） | `fixtures/seq_align_conv93.tsv` 的 `arm64_name` + `tier` | 族内 **37/44 = 84%**、tier A **28/28 = 100%**（§35.12b） | 族外 **31/282 = 11%**（§35.12b） |

**目标只有一个**：族内（指纹已失效的那一族）能不能提上去，且**族外不掉**。

## 3. 规则（**预注册**，跑数之前写死）

```
R1  族（D2） ∧ 顺序轴 tier == A          ⇒ 采用顺序轴的名字（mode=order）
R2  其余                                  ⇒ 采用指纹的名字（mode=fp）
R3  两者都给出名字且不相等                ⇒ **只报不裁**（名字/模式一格不动，逐条写冲突表）
R4  采用源的规范名解析不出来              ⇒ mode=none（**不回退**到另一条轴、**不看** top-2 的搭档）
R5  指纹方向冻结在 REF（scal=0.25）        ⇒ 不重新选权重、不扫网格
R6  规范名 = module::Type::method 三元组严格相等；分母 = 326 行全体（无名字 = 未命中）；
    另报"两轴都有名字"的可比子集
```

**规范名口径**（与 `tools/name_bridge.py` 的 `demangle + parse_name` 完全相同）两条修补，只为让"同一个名字"
在三种写法下判等，不改任何规则：

1. `ZN…` 开头的 arm64 符号补回前导 `_` 再交 `c++filt`（93 号的对齐表存的是去掉 `_Z` 的形态；实测
   1,873 / 9,607 条被赋名的行是这种形态，不补则整批解析失败）；
2. 方法名末尾 `::_{{closure}}` 去掉（真值表就是**外层方法**口径：326 行里 0 行带 closure）。

## 4. 结论（只有两种写法，**由 §3 的数直接决定，不看别的**）

* **提上去了**：混合族内 > 纯指纹族内 **且** 混合族外 ≥ 纯指纹族外 ⇒ 写「族内可从 51.9% 提到 X%」。
* **不可提**：否则 ⇒ 写「不可提，因为…」（并给出是哪一条不成立）。

## 5. 已知的口径风险（先写下来，免得事后当发现）

1. **D1 的域是"事后定义"的**（用真名的方法名）。所以「族内 84%」这句话的**域**不是可部署判据；
   可部署的 D2 与它不完全重合。**两套数都报**。
2. **指纹那一列的"名字"是转来的**（预测搭档的 Windows 符号）。§35.12 的 51.9% 是**地址口径**
   （top-1 搭档 == 真搭档），本表是**名字口径**；两者在"搭档对"时等价，但 ICF/同名不同函数会让
   名字口径略高 ⇒ 表里两列都留（`hybrid_names_eval.tsv` 的口径列写明 `strict_canon`）。
3. **R1 的 `tier == A` 是预注册的**（A/B/C 是 93 号用合成自检标定的档位），不是在本轮族内数据上挑的。
4. 13,263 行里的 `mode=fp` 是**候选名**，不是结论名（§35.0 口径块：「结构同源候选、逐条待核」）。
