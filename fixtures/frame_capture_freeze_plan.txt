# ## 2. 冻结后**不算进 L3**的固定区域（`tools/frame_diff.py --exclude-rect`，只影响 L3 计数）
#
# 理由：光标是**墙钟 1.0 s 周期**的闪烁元素，相位逐运行随机 —— 任何"按 tick 停帧"都钉不住它
# （它不是 tick 驱动的）。所以把它从 L3 的**计数区域**里排除，同时把"被排除掉的差异像素"
# 单列成 `l3_masked_out_px`，**原始读数**单列成 `l3_diff_px_raw`（不许悄悄丢）。
# L1/L2 一行不动（270 px 对 24 块均值的影响 < 0.001/255）。
#

# ## 4. 诚实登记的边界（**推断/未知**，不许当结论用）
#
# 1. 我方**对局屏**（`match_ready`/`match_play`）的动画时钟是**墙钟**（`play_screen.gd` 的
#    `_curve_tick += delta × 60`），不是原版的定步 tick（`GraphwarTickHandler::get_fractional_tick`）。
#    这是**源码层缺口**（`docs/16` §43.6(d) 第 2 条），不是采集问题 ⇒ `match_ready` 上我方
#    **没有任何运行时 tick 可读**，只能用墙钟停帧并标 `settle`/推断。`match_play` 能读到
#    `set_fractional_tick` 的实参（曲线揭示量 ≈ 63/s），但那也是墙钟积分出来的量。
# 2. 因此 `match_*` 两屏的跨侧残差里有一块是**模型层的相位差**（两侧揭示/待机动画的驱动源不同），
#    按 tick 停帧只能消掉**采集**这一层的模糊，消不掉那一块 —— 预注册带就是按这个前提给的。
# 3. `campaign` / `level_popup` 两屏**不进本表**：它们没有 tick（纯静态屏），本轮只做残差归因
#    （`docs/06` §120.5），停帧口径仍按 `fixtures/static_screens_targets.txt` 的 2.0 s。
