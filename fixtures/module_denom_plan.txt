# A. 分母定义（先定死）
# ============================================================================
#
# A1. 什么叫"一个模块存在"—— 三级判据，逐级更弱：
#   J1  (strict，定义路径)：该模块至少有 1 个符号，其 demangle 后的**定义路径以
#       `graphwarrust::<m>::` 开头**（Type ∈ {FUNC, OBJECT}，Ndx ≠ UND；LOCAL 也算）。
#       ⇒ 证明"这个模块里编译出过函数/静态量"。
#   J1' (loose，任意路径出现)：demangle 后的符号文本里**任意位置**出现
#       `graphwarrust::<m>::`（含 `<... as Trait>` 的 impl 头、泛型实参位置）。
#       ⇒ 证明"这个模块名在这一版源码里被解析过"（Rust 名字解析要求模块存在）。
#   J2  (反证，不是模块)：见 §C 的负对照。核心一条：**取路径的第 2 段**，
#       类型名/函数名/闭包/静态项名都落在第 3 段及以后，天然不算模块。
#
# A2. **分母 N 用 J1'**，理由（与全仓既有口径一致）：
#   docs/02 §18.3 的"权威模块清单"就是这么数的 —— 它把**0 个自有函数**的
#   `graphwar_game_info` / `time_probe` 也算进 78，判据正是"只在 impl / 泛型实参里露面"。
#   若改用 J1，目标版会少 1 个（`time_probe`，见下），与 §18.3 的口径打架。
#   ⇒ **N 的报告口径 = J1'**；**J1 的读数同时报**（两个数一起给，差集点名），
#     因为 J1 才是"能拿去数函数"的那一档，J1' 只证明模块存在。
#
# A3. 主证据用**哪一版**：
#   * 主：`.reference/steam/android-2.0.60/libgraphwarrust.so`
#     （**与逆向目标同版本**、arm64、`.symtab` 完整未剥离、`file` 直接报 "not stripped"）。
#   * 旁证：`.reference/steam/2024-07-30/libgraphwarrust.so`（x86-64、未剥离）——
#     ⚠️ **本机没有这份文件**（只有 2026-08-28 的 stripped x86-64 与 android-2.0.60）。
#     所以 2024 侧只能用**已入库的** `docs/02` §18.3 那张 78 行清单当输入，不能当场重跑。
#   * 目标版与 2024 版都可能因"整模块内联/被消解"而**漏**（time_probe 在 Android 只剩
#     drop glue），也可能因"两年间新增"而**多**（graphwar_crash_reporter 2024 完全没有，
#     docs/02 §18.7-②）。⇒ **N 取两者并集**，并分开报三个读数：
#       N_2.0.60(J1') / N_2.0.60(J1) / N_union(J1')
#     **总账用 N_2.0.60(J1')**（目标版才是要还原的东西）；并集只用来证明"没有漏"。
#
# A4. 模块的作用域（scope）：
#   * 名字带 `graphwar_` 前缀 ⇒ `scope=graphwar`；不带 ⇒ `scope=other`。
#   * ⚠️ **`graphwar_texture_loader` 带前缀 ⇒ scope 必须是 graphwar**。现矩阵把它记成
#     `other`（旧口径只按"有没有同名 graphwar_*.rs"推 scope，这条例外被写进了注释）。
#     本轮按 A4 规则改正 —— **这是分类错误，不是新增模块**。
#
# A5. 函数分母**不动**：
#   * `orig_funcs` 依旧是 panic::Location 可归属函数数（可度量下限，现值 527）。
#     新增模块**不并入** 527 —— 混两种归属方法会静默改掉招牌数字的含义。
#   * Android `.symtab` 的 FUNC 条数另开一列 `sym_funcs`（每模块一个手工值，来源 §D），
#     **只作模块规模参考列**：不进 orig_funcs、不进 527、不进任何总账分子。
#   * 若两者都报，必须带轴名：`527 = Location 可归属`；`sym_funcs 合计 = Android 符号表 FUNC`。
#     两者**不可混报**（就像 fire / batch / batch_conv 三轴不许混）。
#
# A6. 预期读数（写完就贴，跑完逐条对；对不上先查自己的扫法）：
#   * N_2.0.60(J1') = 82 = 66 scope=graphwar + 16 scope=other
#   * N_2.0.60(J1)  = 81（差 1 = `time_probe`，它在 Android 只剩 `core::ptr::drop_in_place<…>`）
#   * N_union(J1')  = 82（2024 的 78 个 ⊂ 2.0.60 的 82 个；2.0.60 侧多
#     ban_list / crash_reporter / id_maker / version 四个 —— 即"两年间新增的模块"）
#   * 现矩阵 = 78 = 63 个 `graphwar_*` 前缀（62 scope=graphwar + 1 个被记成 other 的
#     texture_loader）+ 15 个非前缀 ⇒ **缺 4 个模块**：
#       graphwar_ban_list / graphwar_id_maker / graphwar_version（前缀，scope=graphwar）
#       time_probe（非前缀，scope=other）
#

# C. 负对照（**不该**被算成模块的名字；判法必须把它们拒掉）
# ============================================================================
#   NC1 `graphwarrust`（crate 名，不是模块）
#   NC2 类型名：`GraphwarTextureLoader` / `GraphwarBanList` / `GraphwarIdMaker` / `TimeProbe`
#       都是路径第 3 段（第 2 段才是模块）⇒ 必须不出现在模块集合里
#   NC3 静态项名：`graphwar_id_maker::GraphwarIdMaker::get_unique_id::CURRENT_ID` 里的
#       `CURRENT_ID`（第 4 段）⇒ 不许算模块
#   NC4 外部 crate：`core` / `alloc` / `std` / `libc` / `gdext`（只在 `<...>` 里当泛型实参出现）
#   NC5 闭包：`graphwar_x::foo::{{closure}}` ⇒ 只按第 2 段截断
#   NC6 解名健全性：分别"只解 legacy(`_ZN`)"与"legacy+v0(`_R`)混合"两种解法求模块集合，
#       **两者必须一致**（Android 有 901 条 v0 符号）。若不一致，以混合为准并写明差集。
#       ⚠️ 本条**不**预设"v0 必不可少"：探索性取数显示两者都是 82 ⇒ 如实写"v0 对模块
#       识别没有影响"，别把没起作用的东西写成必要条件。
#

# D. 判据实现（可复跑；不新增 tools/ 脚本）
# ============================================================================
#   readelf -sW .reference/steam/android-2.0.60/libgraphwarrust.so
#     → 只留 Type ∈ {FUNC,OBJECT} 且 Ndx ≠ UND 的行（LOCAL/GLOBAL 都要）
#     → 取最后一列（名字）→ 一次性 `c++filt -s rust` 解名（**legacy 与 v0 都要解**）
#     → 正则 `graphwarrust(?:\[[0-9a-f]+\])?::([A-Za-z0-9_]+)(?:::|\b)`，
#       第 2 段猜模块；J1 只对"以 graphwarrust:: 开头"的名字取第 2 段
#     → 反查 `fixtures/module_denom_audit.tsv` 的逐模块结果
#   已知偏差：`c++filt` 的展开形态随 binutils 版本略有差别（`{{closure}}`、约束语法），
#   不影响第 2 段取名；crate 哈希在 v0 里写成 `graphwarrust[<hex>]`，正则已覆盖。
