## 1. 五类定义（原样继承 T82 §129.1 / T86 §134.3，**不新增类别**；本模块需要的细分只允许写进「子类」列）

| 类别 | 定义（判成它的唯一理由） | 进不进"诚实缺口" |
|---|---|---|
| `real-missing` | **原版有我方没有的业务函数**：函数体承载原版模块自己的语义，且能写出**该函数做什么**的一句话 | **进** |
| `na:std-mono` | **std/core/alloc 的单态化**：函数体是标准库的（`Vec::retain` / `LocalKey::with` / `Rc::new_cyclic_in` …），本 crate 只贡献被内联进去的实参 | 不进 |
| `na:gdext-glue` | **gdext/Godot 宏产物**：类注册胶水 / 属性访问器 / `#[func]` 分发壳 | 不进 |
| `na:other` | **其它不该手写的编译器生成物**：drop glue、panic 展开、`#[derive]` 产物、trait 对象 shim、**泛型单态化实例** | 不进 |
| `unknown` | **判不了**（必须写清缺什么证据） | **进**（保守） |

### 1.1 本模块必须用到的两个子类（写在 `subclass` 列，不改上面的类别语义）

* `na:other / own-generic-mono` —— **本 crate 自己的泛型方法的第 i 个实例化副本**。
  判定语义：源码里**只有一行 `fn`**（一个泛型定义），机器码里 N 份。所以它既不是 `real-missing`
  （源码级我们**有**这个函数，且有实现），也不是"std 的代码"（`na:std-mono` 要求函数体是标准库的）。
  T86 §134.3 的 `na:other` 定义里本来就列了「**泛型单态化实例**」⇒ 用它，不另立类别。
  **必须在 TSV 里同时记 `src_status = implemented-generic` 与 `mono_group_size`**，否则读者会把它
  当成"没写"，或者反过来把 N 份副本当 N 条业务函数（这正是 §7 要防的口径罪）。
* `na:other / drop-glue` —— 编译器生成的 `core::ptr::drop_in_place<…>`（T82 明文举例）。

## 2. 三条**互相独立**的轴（数据来源不同；L/F 沿用 T87 `fixtures/naming_android_plan.txt` §2 的定义）

| 轴 | 内容 | 独立性 |
|---|---|---|
| **L 位置轴** | `panic::Location` 键集 = `(src/<file>.rs, line, col)`（`.data.rel.ro` 的 24 字节结构 + `.rela.dyn` 还原指针）。跨构建、跨 ISA 不变 | 与名字无关；**这是 527 的归属机制** |
| **F 结构轴** | 函数体里与 ISA 无关的常量/身份：①**`.rodata` 16 字节常量内容**（`TypeId::of::<T>()` 的内联值）②**`.data.rel.ro` 4 字 `dyn Any` vtable 的首字**（= `drop_in_place<RefCell<M>>` 的地址，Android 侧该地址**有符号名** ⇒ 直接给出 `M`）③`.rodata` 串集合 ④小立即数集合（含块内步长）；另记 FDE 尺寸与 arm64 size 的比 | **不含任何符号名当特征**；Android 侧的名字只在"给 M 定名"时用（=答案，不是特征） |
| **S 形态轴（T89 §138.5 的调用形态闸）** | `call rel32` 条数（**直接调用**）与"本函数地址出现在数据槽里"的条数（**slot**，值等于本函数入口的重定位表项） | 与 L/F 都无关（看的是调用者/被调用关系，不是函数体常量） |

**F 轴的可复算提取法（先写死，跑的时候不许改）**：
* 16 字节常量 = 反汇编里 `movups xmm, [rip+d]` / `lea reg,[rip+d]`（x86）、`ldr q,[x]` + 字面量池
  （arm64）目标落在 `.rodata` 且**至少 8 字节是编译器算出来的非零随机样值**（TypeId 的特征：高 64 位
  非 0、且同模块内互不相同）。全 `.so` 逐 8 字节建 `{内容 → 地址}` 索引后反查，避免"读错地址"。
* vtable 首字 = `.data.rel.ro` 里 4 个连续 8 字节，其第 0 字由 `R_*_RELATIVE` 重定位指向
  `core::ptr::drop_in_place<…>`（Android 侧可直接读 `.symtab` 名）。
* **FDE 尺寸比** = `min(linux_fde, arm64_size) / max(...)`。只作旁证（跨 ISA 天然不等，
  x86 实测 add≈0.71×arm64、get≈0.82×），**不许单靠它定案**；判据见 §4 R5。

## 4. 判决规则（预注册；命中即停，逐条写进 TSV 的 `rule` 列）

**R-L（L 轴硬归属）**：Linux 侧该地址引用 `src/graphwar_module_container.rs` 的 Location ⇒ 该函数**属于本模块**，
与 527 台账的归属一致。C 组 20 条必须有（正对照）。

**R-REAL ⇒ `real-missing`**：满足任一：
  * `F` 轴显示该 arm64 函数的 vtable 首字所指 `drop_in_place<RefCell<M>>` 给出的 `M` **不在**已注册的 25 型里；
  * 或该函数**没有** `dyn Any`/`TypeId` 形态（不是本模块三个泛型方法的实例）；
  * 或 Linux 侧**没有**对应机器码（等距块断裂、或块内某序号无 FDE 起点）。
  且能写出一句"它做什么"。

**R-GM ⇒ `na:other / own-generic-mono`**（必须**同时**满足，缺一条就降 `unknown`）：
  1. **组内一致性**：本组所有成员的 F 轴"骨架"相同（同一条指令序列的模板），只有身份常量变；
  2. **身份可变**：组内每条的 `M` 互不相同（A 组 25 个不同 `M`），且**并集恰好等于**我方 `MODULES` 的型集合；
  3. **L 轴对齐**：Linux 侧同组地址的形态与 arm64 同组**逐条对应**（A 组 25 / B 组 23 / C 组 20 的块内序号
     一一对上），且 C 组的 L 键集必须落在 `:30:28` 这一个键上（与 527 一致）；
  4. **形态轴**（T89 闸）：`call rel32 ≥ 1` **且** `slot = 0`（泛型单态化是**被直接调用**的，地址不被取走）。
     * 若某条是 `rel32 = 0 且 slot ≥ 1` ⇒ 它可能是"交给 API 的闭包/回调"，**不许**判 `na`，落 `unknown`
       （T89 驳回 `0x438880` 的教训：被内联进 std 的游戏闭包会伪装成单态化）。
  5. **源码级唯一性**：`M` 的不同取值只改 vtable/TypeId，**不改本方法的方法名**——即 demangle 名去 hash 后
     组内只有 1 个方法名。

**R-DROP ⇒ `na:other / drop-glue`**：函数体只做 `dec qword [reg]` / `__rust_dealloc` / `free`，
  无业务常量/串/分支（T82 的 R-OTHER 原文），且 arm64 名就是 `core::ptr::drop_in_place<…>`。

**R-UNKNOWN ⇒ `unknown`**：任一闸不干净命中、或命中互相冲突。必须写「缺什么」。

**纪律**（继承 T82 §3）：`na:*` 每条至少 **2 个独立证据**（不同轴）；单轴 ⇒ `unknown`。
机器/脚本给的只是**候选**；TSV 的 `category` 列是我的人工裁决结果，与脚本候选不同时必须写理由。

## 5. 正 / 负对照（**先做；不全会退回判据，不许先看 49 条的结论**）

| 组 | 做法 | 通过条件 |
|---|---|---|
| **C1 正对照（L）** | C 组 20 条：Linux 20 个地址的 L 键集 ∩ {`graphwar_module_container.rs:*`} | 每个地址**恰好** 1 个键且都是 `:30:28`，20/20 |
| **C2 正对照（F）** | 对 C 组 / A 组 / B 组各取 1 条，人工读 `dis` 输出，确认骨架（§3 的 `dyn Any` vtable + TypeId）读法成立；再全组机判 | 3 组骨架都能被同一套提取器读出来，读不出 ⇒ 先修提取器 |
| **C3 身份并集** | A 组 25 条的 `M` 并集 vs `MODULES` 25 型；B 组 23 / C 组 20 的并集 vs `MODULES` 中 `has_get` / `has_wk` 的子集 | **完全相等**（不是"大体相等"） |
| **C4 负对照（防"总说同意"）** | 把 A 组第 i 条的 `M` 换成第 i+1 条的 `M` 后，Linux 侧按同一提取器应匹配到**另一条** Linux 地址；即映射必须**一一**，不许"任取一个 M 都对得上" | 打乱后匹配率骤降（≤ 同尺寸条数分之一） |
| **C5 证伪闸** | 若 A/B/C 任一组出现：块内序号与 Linux 块不一一对应 / 块内有洞 / 某条 `M` 不在 25 型里 / 某条 L 键与本组不同 | 该行**不许判 na**，落 `real-missing` 或 `unknown` |
