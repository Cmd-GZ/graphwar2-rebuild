## 1. 为什么要改（流水线冒烟时发现的事实，**观测**）

登记的 §2 走的是**战役第 0 关**：主菜单 `Campaign` → 关卡节点 0 → `Start`。
冒烟时同一条点击脚本跑了**两次**，两次的士兵/靶子位置不同：

| 次 | 士兵落点（画面） | 靶子落点（画面） | 修正常数 |
|---|---|---|---|
| 第 1 次 | 棋盘左下（≈`(-5.2, -9.9)` 世界坐标） | 右上 | `10.365` |
| 第 2 次 | 棋盘正中（≈`(0, 0)`） | 右侧 | `- 0.061` |

⇒ **战役关卡的士兵/靶子位置在两次运行之间不同**（同一台机、同一尺寸、同一条点击流）。
`GW2_MATCH_SEED` 是**我方服务端**（`src/graphwar_game_server.rs::run`）的旋钮，
**对原版不起作用**；原版这一层没有外部可钉的种子。
⇒ 按 `fixtures/frame_diff_thresholds.txt` §1 最后一行与 `dispatch/94` §2 红线②，
"局面不同"的屏必须**如实判"不可比"**，不能拿来当渲染差异的结论。

## 2. 增补后的做法：**用冻结快照里的回放**当局面

回放文件把整局的每一拍都写死了（`{"event":…,"tick":N}`），两路读的是**同一个文件**
⇒ **局面逐事件相同**，且两侧都自带"回放"入口（原版主菜单 `Replays`；我方 `ReplayLobby`）。

- 局面 1：`1793897298`（`Level 0`，1 士兵 `cmdgz` + 1 靶子，`ClearObstacles`，104 事件 / 2276 tick）
- 局面 2（备用）：`1783255495`（`Level 16`）
- 两路都把这两份从冻结快照拷进各自的 `user://replays`（原版 `~/.local/share/godot/app_userdata/Graphwar/replays`，
  我方 `$XDG_DATA_HOME/godot/app_userdata/Graphwar II — Client Rebuild/replays`），**不改文件内容**。

## 3. 增补后的四屏与步骤（两路**语义同一串**；坐标不同处已注明，因为两路列表行本身长得不一样）

```
S1 menu          启动后等 4.0 s，不点任何东西                      （与原登记一致）
S2 replay_lobby  点主菜单 Replays(1343,749) → 等 2.0 s
S3 replay_play   点列表第 1 行(局面 1)的播放键 → 等 2.0 s
                 原版播放键 (1805,132)；我方播放键 (1619,124)
S4 replay_end    不再点击，继续等 45.0 s（2276 tick ÷ 60 = 37.9 s ⇒ 两侧都播到文件末尾）
```

- 每屏仍取 **3 帧**、帧间隔 **1.2 s**（同 §2）；
- **S1/S2 与 tick 无关**（静止屏）；**S4 两侧都停在"文件末尾"** ⇒ 是**同一 tick（2276）**；
- **S3 的 tick 对不齐**（原版进入回放屏后停在疑似暂停态；我方 `GwReplayDriver` 一载入就按 60 tick/s 走），
  ⇒ S3 的数字**照 §3 门槛判**，但结论里必须写明"差异里含相位/播放位置"，
  它是"我方回放屏与原版回放屏长什么样"的对拍，**不是**"同一 tick 的画面"对拍。
  S3 的相位差本身也是结论（原版暂停 / 我方自动播放），登记进 `docs/06` §53。

## 4. 门槛（**不变**，原文照抄）

```
L1  尺寸 1920x1160 ∧ 每通道全局均值 |Δ| ≤ 2.0/255 ∧ 第一主色同色 ∧ 占比差 ≤ 2.0 pp
L2  6x4=24 块，每块每通道均值 |Δ| ≤ 2.0/255，24 块全过
L3  只在 L1/L2 都过时算：差异像素比例 ≤ 0.10% ∧ max|Δchannel| ≤ 8/255
判定：L1 不过 ⇒ 不过(L1)；L1 过 L2 有块超限 ⇒ 不过(L2)+报块号；都过 ⇒ 看 L3
```
