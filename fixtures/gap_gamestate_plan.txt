§2 两条"多对多"事实（T87/T89 的教训，写成规则）
================================================================================================
### 2.1 一条源码函数 ⇒ 多副机器码副本（`M > S` 的来源）
* **泛型闭包的逐类型实例化**：同一 `fn` 里的闭包按事件类型单态化，每份一份代码、一份符号。
  判据：符号名（剥哈希后）**完全相同**，地址不同，`size` 相同，且同属一个泛型父函数。
  ⇒ 合并成 **1 个源码条目**。
* **linkonce/ICF 克隆**：符号名带 `.llvm.<n>` 后缀（链接器合并的等价体）⇒ **不新增源码条目**。
* **serde `#[derive]` 生成物**：`<impl Serialize/Deserialize for T>::…`、`__FieldVisitor::…`
  ⇒ 计入 `M`，但归类 `na:other`（源码层那一行是 `#[derive(...)]`，不是我们手写的 `fn`）。

### 2.2 一个地址 ⇒ 多个源码名（内联别名）
* 大函数把小函数**内联**掉：小函数的代码不独立存在 ⇒ Linux 侧没有独立地址（只有内联别名）。
* 反向也成立：Linux 某个地址上可能既是大函数的本体，又挂着被内联者的 `panic::Location`。
  ⇒ 判"缺"时**只认 outer 身份**（T89 §138.1 规则：三份参照构建里 size 最大的名字），
  内联别名不算一个独立缺口（否则同一份源码会被数两遍）。

### 2.3 跨模块归属（只放行一条，其余登记不动）
Linux `527` 的分母按 **ours_file（Location 多数投票）** 切，与本模块的 Android crate 路径**不是同一个切法**。
本模块有 **1 条**落在别的模块名下：
`0x46f690` = `GraphwarGameStateManager::start_game`（Android `0x4a5b38`, 3996 B），
在 `boundary_audit.tsv` 里 ours_file 是 `src/graphwar_turn_manager.rs`（11 条 Location 里 10 条指 gamestate，
但多数投票落在 turn_manager），且**已是 F1**（`src/game.rs:1443`）。
⇒ 判「`start_game` 缺不缺」时**必须**先查这一条，否则会把一个**已实现**的函数算成缺口。
除它以外**不跨模块搬行**，跨模块的相似性只作为 TSV 的备注列。

§3 三轴对齐法（L / F / 尺寸），正对照 = 已实现的 17 条
================================================================================================
对 Android 的每个源码条目 A 与 Linux 的每条归属行 L，算三轴：

* **L 轴（位置键）**：`panic::Location` 键集 = `{(file,line)}`。
  Android 侧取法：`adrp/add` 或字面量池里 `{ptr,len,line,col}` 结构；
  Linux 侧取 `tools/addr_probe.py locs`。判据 = 键集 **Jaccard ≥ 0.5**，或两侧键集**互含**。
  正对照：T87 §136 已用**三份**构建的键集给 348 条定名，自洽率 284/284 = 1.0000。
* **F 轴（结构，不含名字）**：① `.rodata` 串集合 ② 8 字节常量集合 ③ 引擎/GOT 导入槽集合
  ④ ≤0xFFFF 的小立即数集合。判据 = 至少两样有非空交集（**弱于 L 轴，只作旁证**）。
* **尺寸轴**：`min(size_android, size_linux)/max(...)` ≥ **0.6** 视为同量级（同一份源码的两份构建）。
  只作**排除**用（差异过大就说明不是同一个函数），**不单独定案**。

**正对照（必须先跑，全过才继续）**：
* C1：已实现的 **17** 条（`fixtures/function_coverage.tsv` 里本模块 F1 16 + F2 1）在 Android 侧
  都**必须**找到同名源码条目；找不到就说明对齐法坏了（不是"它们不在 Android 里"）。
* C2：Android 侧源码条目里**不该**有任何一条被判成"Linux 没有"，而 Linux 上却有同名 F1/F2 实现
  （反例若出现 = 名字集合漏项）。
* C3：`size` 轴在 C1 的 17 对上的 `min/max` 中位数 ≥ 0.6；低于 0.4 的逐条打印（只登记，不改判）。

§4 缺口判据：五类（**继承 T82 §129.1 + T86 §134.3，不改**）+ T89 的调用形态闸
================================================================================================
类别定义、五层证据优先级、`na` 三小类的判据**原文继承** `fixtures/f3_triage_plan.txt` §1/§2/§3
与 `fixtures/global_triage_plan.txt` §2/§3（本文件不重写、不改动）。落到本模块时补两条操作化：

### 4.1 体积上限（继承 T82 §129.3 / T86 的 `VOL_CAP`）
结构证据（`G1/G1b/G2/A/B/C`）**只对 `max(size, size_fde) ≤ 0x721` 的函数生效**。
本模块 16 条 F3 的尺寸是 `0x68`–`0x59b`，**全部在限内** ⇒ 结构规则对它们**全部可判**，
不存在"因为太大所以不判"的行。⇒ 若某行只靠结构规则被判成 `na:*`，**必须**再给 §4.3 的调用形态证据。

### 4.2 T89 的"调用形态"闸（**硬闸**，与结构规则**同时**满足才可判 `na:*`）
```
泛型单态化（std/core/alloc 的实例）      : call rel32 ≥ 1  且  地址被取（slot）= 0
交给 API 的闭包（gdext/std 回调、spawn） : call rel32 = 0  且  slot ≥ 1
```
理由（T89 §138.5 的实测）：`0x438880` 只靠负向推断被判成 `std::monomorphization`，但它的
`call rel32=0 / slot=1` 是"交给 API 的闭包"形态，反汇编头三条就是 `connect_timeout(addr, 30 s)`
⇒ 它是**游戏** `connect` 的线程闭包体。**这一条闸的用途正是拦住"把游戏闭包判成 std"。**

### 4.3 本模块的 `real-missing` 追加要求（比 T82 更严一档）
T82 的 R-REAL 只要求"能给出该函数做什么的一句可复核描述"。本模块再要求**二选一**：
* ① **自己有一条 `.eh_frame` FDE**（真独立边界），**且** 体内有 ≥1 条本模块业务被调者
  （本模块的其它方法 / `get_module` 的 8 个单态 / `0x3d3530 add_event` / `0x3bf230`）—— 
  ⇒ 判 `real-missing` 并**落码**（§5）；**或**
* ② 无独立 FDE（被内联进父函数）⇒ 判 `real-missing(inlined)`，**只登记不落码**
  （落码等于凭空造一个原版不存在的边界；这条与 T48「setup_level_2/3 内联」同一纪律）。

§5 落码判据（什么时候算 F3 → F1，什么时候**不许**算）
================================================================================================
1. 函数体第 1 行写 `//!` 级的 vaddr 出处；**真名**取自 `fixtures/boundary_audit.tsv` 的 `name_src`
   为 `v2唯一锚` 的行；`hyb:*` 行**只作候选**，不落码（§4.3 的 3 条 `hyb` 行先单独裁决）。
2. 关键指令（常量 / 分支判据 / tag 立即数 / 载荷偏移）逐条写进注释，**注明地址**。
3. 单测的**期望值必须来自反汇编**（立即数、tag、字段偏移、臂数），**不许**来自我方输出。
   例：`set_lock` 写 `[+0x11e]` + `emit tag 0x45` ⇒ 断言"写的是偏移 0x11e 的布尔 + 发 tag 69"这件事
   本身要在代码里可指认（我方结构的字段名与偏移的映射写在注释里）。
4. **不许**为了"看起来落完了"把语义猜出来填充：函数体里凡是没有指令支撑的分支，
   函数文档必须写 `缺：…`（与 T45 §102.3 同一纪律）。
5. 每条落码**单独 commit**，commit message 写 `vaddr | 真名 | F3→F1`。
