**本轮新增的三条**（只在新 flow 上用，既有四支 `campaign`/`replay`/`static`/`match` 一行不改）：

### 2.1 对局服务器（`--flow matchpop`）
`tools/match_serve.py` + `fixtures/frame_match_events.txt`（**只读、不改**），与 `--flow match` 同一份剧本；
本轮**不触发 phase2**（不 touch 触发文件）⇒ 一直停在 S7 准备态，弹窗期间底图不会突然开火。

### 2.2 UDP 房间广播（`--flow lobby` / `--flow setup` / `--flow connect`）
LAN 大厅的"房间行"是**服务端数据**，离线时原版可能一行都没有，行数还会随"原版自播房间"
出现的时机抖动（本轮探路实测：不加广播时 5 次里 3 次有 1 行、2 次 0 行）。
⇒ 三个 flow 都由 `tools/match_serve.py` 起一条**固定的**房间广播（同一份 fixture 的 `[meta] room=`，
`udp_targets=127.0.0.1`、周期 0.5 s），**两侧吃到同一条房间记录**，于是"有几行"不再随机。
这不改任何被测代码，只是把"服务端数据"钉死（`docs/06` §48/§51/§60 都是这个办法）。

### 2.3 静默 TCP 监听（`--flow connect`）
`127.0.0.1:46799` 只 `accept()`、**不发任何字节**：让"连接中"停在屏幕上而不是 1 秒内变断线。
它是**环境**不是被测对象，两侧同一份。

## 3. 判据（预注册，原文照抄 `fixtures/frame_diff_thresholds.txt` §3）

13 屏**每一屏**都要同时满足：

```
L1  两张 PNG 都恰好 1920x1160
    每通道全局均值 |Δmean| ≤ 2.0/255
    第一主色（像素数最多的 RGB）同色，且占比差 ≤ 2.0 个百分点
L2  6x4 = 24 块（x 每块 320 px、y 每块 290 px），每块每通道均值 |Δ| ≤ 2.0/255；24 块全过
L3  只在 L1/L2 都过时算：差异像素比例 ≤ 0.10 % ∧ 全图 max|Δchannel| ≤ 8/255
判定：L1 不过 ⇒ 不过(L1)；L1 过、L2 有块超限 ⇒ 不过(L2)+报块号；都过 ⇒ 看 L3
```

**这些数字不许改、不许放宽、不许按屏"特批"**；跑完也不许回头调。达不到就按 §4 如实报。

## 4. 达不到时怎么报（预先讲好，避免事后找理由）

1. 逐块列出 L2 超限块号（`row,col`，左上为 `0,0`）与该块 `dmean_max`；
2. 对人眼可辨的差异区域给**差异 bbox**，并指到"原版帧里的哪个元素 / 哪个坐标"；
3. 每屏额外给一档**归因**：缺元素 / 版式（位置·尺寸·比例） / 字色·图标 / 服务端数据（不可归零）——
   这是下一轮派活的输入；
4. 证据分档（`AGENTS.md`）：真帧 ⇒ **观测**；只靠推导 ⇒ **推断**（写明缺什么）；
   没量到的 ⇒ **未知**。**不许把推断写成陈述句**。

### 4.1 "多数 < 0.5 %"这条旧账怎么判
`docs/00-status.md` §4 里写着"逐屏残差多数 < 0.5 %"。本轮**不改** `docs/00`，只回答两件事：

* 本轮 13 屏里**有多少屏**的差异像素比例 < 0.5 %（按本轮实测）；
* 其中**有多少屏**同时满足 L3 的 0.10 % 门槛（两者不是一回事）。
