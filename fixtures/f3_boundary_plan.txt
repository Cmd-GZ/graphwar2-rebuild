§1 "落了"的判据（写死；跑完不许放宽）
================================================================================================
一条算**落了**，必须**四条同时**成立：

1. **落点 = 原版模块文件**：函数体写在 `src/<该行的 原版模块>.rs`，**不许**写进 `src/_scaffold/`
   （§0 的"文件名就是证据"）；也不许为了它就新开一个旁表文件。
2. **名字 = 真名**：用 `fixtures/boundary_audit.tsv` 第 3 列 `name_src` 为 `v2*`（三向符号匹配）
   或 `naming_android`（Android 符号表）的名字，**逐字符相同**。`name_src = hyb:*`（结构指纹预测）
   的行，**不许**拿预测名当结论 —— 要么另外证出名字，要么只按 vaddr 指认并在代码里写明"名字未定"。
3. **函数体第 1 行写 vaddr**，关键指令给**地址注释**（`0x……` + 指令 + 解读），且注释里的地址
   必须是 §0 口径的 ELF vaddr。
4. **≥1 条单测**，期望值**只能来自反汇编**（立即数 / 跳转表 / 分支形状 / tag word / 字段偏移），
   **不许**来自我方输出（AGENTS.md §0 第 5 条：自写断言只能证明自洽）。
   次选真值来源（按优先级）：`.rodata` 常量槽 / 已入库 `fixtures/` 真值 / 冻结语料。

判"落了"之后必须**跑 `python3 tools/function_coverage.py` 复算**（生成物归 t110/生成器管，
本分支只**跑**不改），确认该行 `F档` 由 `F3` 变 `F1`（或 `F2`，见 §3）。

**没落**也必须写清楚：缺哪一样证据（不是"没时间"）。允许的三种结论：
`未落-工作量超本轮`（附 FDE 字节数/指令数/Location 数/被调者数）/
`未落-缺证据`（指名缺哪一条：名字？父函数？被调者语义？跨构建匹配手段？）/
`不适用`（源码层本就不是独立 fn）。

§2 取证方法（每条都按这个顺序做，可复跑）
================================================================================================
```
PY=/home/CG/Myprojects/graphwar2-rebuild/.reference/venv/bin/python
$PY tools/addr_probe.py fde     <vaddr>   # ① 真实范围（.eh_frame FDE，**不读** Ghidra 表）
$PY tools/addr_probe.py dis     <vaddr>   # ② 逐指令（工具会就地注解 .rodata 串 / GOT 槽 / Location）
$PY tools/addr_probe.py locs    <vaddr>   # ③ panic::Location（→ 源码行号，用来钉"哪段源码"）
$PY tools/addr_probe.py callers <vaddr>   # ④ 调用点：call rel32 + 函数指针三形态
$PY tools/addr_probe.py jt      <地址>    # ⑤ 跳表展开（有 lea 到 int32 相对表时）
```
判定要点（本项目踩过的坑，照用）：
* `fde` 说 **NOT an FDE function start** ⇒ 该地址是**内联**在更大函数里的 "Location 锚点"，
  源码里**仍有**独立 `fn`（Location 的 file:line:col 就是证据）⇒ 仍然要落码，但代码注释里
  必须写明"内联，无独立机器码边界"。
* **GOT 槽间接调用**（`call *0x……(%rip)`）必须解：`addr_probe dis` 会打 `slot → addend`，
  这样才能得到真正的被调者。只看 `call rel32` 会漏掉一大半（本项目已踩）。
* `locs` 只给聚合值；本轮另用一次性脚本（`.agent-work`，**不入库**）把
  `指令地址 → file:line:col` 逐条打印，用来把"哪条指令对应哪个源行"钉住。

§5 度量口径（三个数分开报，**不许混**）
================================================================================================
按 lead 任务书：
* **机器码**口径：原版 `.text` 里的函数条数（Ghidra 13 263 / Android census）。
* **源码函数**口径：把"一份源码函数多副机器码副本"合并后的条数。
* **严格 1:1** 口径：`M1_1to1`（`--stats` 的 R6 敏感度）。

本轮动的只有**函数级三口径**（A / B / D_A）与 F3 计数：
* 口径 A（含 na，分母 527）= F1/527，当前 **336/527 = 63.8%**
* 口径 B（剔 na，分母 438）= F1/438，当前 **336/438 = 76.7%**（← 招牌数）
* 口径 D_A（分母外加 X=132，分母 659）= **336/659 = 51.0%**
* F3 剩 **119**
落 N 条且都进 F1 ⇒ 预期 A = (336+N)/527、B = (336+N)/438、F3 = 119−N。
**实际读数以跑 `--stats` 为准**；若与预期不符，如实写差在哪（例如某条只到 F2）。
