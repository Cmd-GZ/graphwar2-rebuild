## 2. 判据（继承，不改阈值）

### 2.1 五类定义（T82 `fixtures/f3_triage_plan.txt` §1 逐字）

| 类别 | 定义 | 进不进"诚实缺口" |
|---|---|---|

### 2.2 两个 `denom:no-loc` 子类（写在 `subclass` 列，不改上面五类的语义）

* `implemented / denom:no-loc` ——（T97 §2.2 定义，原样继承）**我方源码里已有同名实现**，但原版该函数在
  Linux 侧**没有 `panic::Location`** ⇒ 永远进不了 527 分母。既不是 real-missing（我方有），
  也不是 `na:*`（它是业务代码，该由我们写）。**必须**同时记 `ours_src = 文件:行`。
* `real-missing / denom:no-loc` —— **本轮新增**（因为本轮第一次遇到）：原版有我方**没有**的业务函数，
  且 Linux 侧**没有 `Location`** ⇒ 它**可以也应当**被写出来，但**不会**改变 527 口径的任何数字
  （分母不收它、分子也不收它）。⚠️ 这条必**同时**给出：源码层合并规则（几条机器码 = 几个源码 fn）
  与「为什么不进分母」的机器证据（`tools/addr_probe.py locs <linux_va>` = 0 条）。

  ⇒ **"落码了但三个数不动"不是失败，是本轮要写清的事实**（§6 P3）。

### 2.3 机判特征（T82 §2，原样继承）

`SZ`（FDE/st_size 尺寸）· `LOC`（`panic::Location` 引用）· `SELF`（自递归次数）· `STRIDE` ·
`CMP` · `BULK` · `CMOV` · `ATOMIC` · `BORROW` · `CALLERS`（`call rel32` 数）· `SLOTS` ·
`CALLER_LOC` · `CALLEE`。

### 2.4 体积上限（T85 M4 / T86 `VOL_CAP`，**硬闸**）

`na:*` 要求 **FDE 尺寸（Linux）/ `st_size`（Android）≤ 0x800**。**> 0x800 一律不许判 `na:*`**。
本轮 A1 里 17 条 `get_node_by_name_rec` 的 Android `st_size` = 1906–2056（其中 2056 / 2070 > 0x800）、
A2 里 `draw` = 9810 / `ready` = 4360 ⇒ 体积闸对它们自动生效（**不可能被判 `na:*`**）。
这也是体积闸的**正对照**：若某条 >0x800 的行被印成 `na:*`，判法坏了。

### 2.5 **调用形态闸（T89 `docs/06` §137.5，本轮强制且逐条记录）**

对**每一条** A1/A2 行按 **Android 侧**记录 `rel32`（`bl` 直呼 `.text` 内目标的**调用点条数**）与
`slot`（`R_AARCH64_RELATIVE` 重定位表项里 addend == 本函数地址的条数）：

| 形态 | 含义 | 结论约束 |
|---|---|---|
| `rel32 ≥ 1` **且** `slot = 0` | 被**直接调用** | 泛型单态化的**必要形态**；业务函数也常见 —— **单靠它不能定案** |
| `rel32 = 0` **且** `slot ≥ 1` | 地址只出现在**数据槽**里（交给 API 的闭包 / 注册表项） | **禁止**据此判 `na:std-mono`（T89 驳回 `0x438880` 的教训） |
| `rel32 = 0` **且** `slot = 0` | 只经 vtable/间接调用 | **必须另找间接调用链**（`adr`/`adrp+add`/字面量池），否则判 `unknown` 并写明缺哪条链 |

⚠️ 这一列是**排除用的**，不是定案用的：`na:gdext-glue` 的定案依据必须是 §2.6 的两条独立证据。

### 2.6 两条独立证据（T82 §3 纪律；`na:*` 每条至少 2 个）

1. **机器特征**（§2.3/§2.4/§2.5 任一）+ **人工复核过的那条指令/表项**（写进 TSV 的「依据」列）；
2. **源码级证据**：该函数在源码层**没有独立 `fn`** —— 即 Android demangle 名里的可识别宏形态
   （`__register_methods` / `__register_constants` / `ptrcall_fn` / `varcall_fn` / `virtual_fn` /
   `__default_virtual_call` / `class_id` / `_::__init::__inner_init` / `drop_in_place<…>`）**或**反之：
   名字是**业务函数名**（`GraphwarNodes::<method>` / `PlayerShowcase::<method>`）。
   ⚠️ 名字是**观测**，但它只说明**原版这一条是什么**，**不**说明"我们该不该手写" —— 后者要第 1 条佐证。

### 2.7 判决顺序（T82 E4 优先级，**不许跳过前面**）

`na:gdext-glue` → `na:std-mono` → `na:other` → `implemented / denom:no-loc` → `unknown`(G4) →
`real-missing / denom:no-loc` → `real-missing`
