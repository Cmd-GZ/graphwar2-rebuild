## 0. 四档（与规格 §2① 一致，逐字照搬定义）

F1 有实现 + 有物证   我方存在一个函数，能指到该原版函数（名字/表/结构/指令一条以上），
                     且其档位有可复核出处。
F2 有实现 + 无物证   有对应代码，但指不到原版函数（= 推断级；写清缺什么）。
F3 只有文件/骨架     文件在、档位也写了，但**没有函数体**（T30 那 9 条就是这一类）。
F4 完全没有         连文件/条目都没有。

## 1. 判定的三层步骤（机判，逐函数）

记 R = 该原版函数在 fixtures/boundary_audit.tsv 里的那一行：
  module  = basename(R.loc_main_file)      # 原版文件，例 graphwar_event_handler.rs
  ours    = R.ours_file                     # 我方该模块的文件（coverage-matrix 给的）
  grade   = coverage-matrix.tsv 里 module 的 status（逐位 / 观测 / 推断）

### 第 0 层：文件在不在
S0  ours 为空或 src/ 下不存在该文件                 ⇒ **F4**（连文件都没有）
S1  ours 存在，但它**没有实现函数**                 ⇒ **F3**
    「实现函数」= `fn NAME` 定义，且**不属于** `#[cfg(test)]` 块
    （理由：coverage-matrix 的 ours_funcs 把测试 fn 也算进去了，会虚高；本审计一律剔除）

### 第 1 层：找「指认」（pin）——证明"我方有这个原版函数"的指针
按**优先级**取第一个命中的 pin，全部要能写进 TSV 的判据列：

P1 NAME（强）  原版函数名来自符号表真名（name_src 以 `v2` 开头，= fixtures/name_to_addr_v2.tsv
               三向匹配的 Unique/DeducedByElimination 落地名），取其**函数段**：
                 - 名字结尾 `::{{closure}}` ⇒ 去掉该后缀，用**父函数名**（闭包体住在父 fn 里）
                 - 否则取最后一个 `::` 段（`graphwar_level_manager.rs::GraphwarLevelManager::setup_level_1`
                   ⇒ `setup_level_1`）
               在 ours 文件的 fn 索引里找同名实现函数；找不到再全 src/ 找（并记下跨文件）。
               命中 ⇒ pin=name。
P2 ADDR（强）  原版地址 `0xNNNNNN` 出现在我方**注释**里（去掉下划线的十六进制全等匹配），
               且该注释能**贴到一个 fn** 上：
                 - 注释行落在某个 fn 的 `{...}` 行区间内，或
                 - 注释行在某个 fn 起始行上方 ≤30 行内、中间只有注释/属性/空行（doc 注释）
               命中 ⇒ pin=addr（记下贴到的 fn）。
               ⚠️ 只认 ELF vaddr；若只出现 `addr + 0x100000` 的 Ghidra 口径写法，**不算命中**，
                  单独记 `ghidra_only` 供核对（那是本仓库反复踩过的坑）。
P3 HYB（弱）   原版函数名只有结构指纹**预测名**（name_src = `hyb:*`），预测的函数段在我方
               实现函数里同名命中 ⇒ pin=hyb。
               **候选名不能当结论**（AGENTS.md §0.3），所以 P3 **只能支撑 F2，不能支撑 F1**。

### 第 2 层：定档
  pin=name 或 pin=addr，且 grade ∈ {逐位, 观测}           ⇒ **F1**
  pin=name 或 pin=addr，但 grade = 推断                    ⇒ **F2**（档位本身没证据，只能算推断级）
  pin=hyb（无论 grade）                                     ⇒ **F2**（指认只是预测）
  无 pin：
     - S1 已判 F3 的，仍 F3
     - module 的实现函数数 == 0                              ⇒ F3（子类 skel）
     - 名字是 `::{{closure}}`、其父函数在我方**不存在**      ⇒ F3（子类 parent-missing：闭包体无处安放）
     - name_src 是 v2 真名但**找不到同名实现**               ⇒ F3（子类 named-miss：名字是硬的，实现是缺的）
     - name_src 是 hyb 预测名但没命中                         ⇒ F3（子类 hyb-miss：弱证据，保守归缺）
     - 名字是 `—`（无名）                                     ⇒ F3（子类 noname）
  ⚠️ 有 pin 的情形下 F2 与 F1 的分界 = **指认强度**；无 pin 的情形下一律不进 F1/F2，
     宁可在 F3 里标子类，也不把"我们的代码可能实现了它"写成"已实现"。

## 2. 三个分子（分母恒为 527）
  M1 = |F1|                    ——「严格函数级复原」
  M2 = |F1| + |F2|             ——「有对应代码」上限（含推断级）
  M3 = |F1| + |F2| + |F3|      ——**不得使用**：F3/F4 就是"没函数体/没有"，
                                  这个口径等于把"没做"数成"做了"，正是 T30 揭穿的算法。
  ⇒ 招牌数字应当用 **M1**（并把 M2 作为上限备注）；"527/527" 必须撤回。

  - orig_funcs ≥ 5 的 35 个模块（452 个函数）—— 全部复核；

## 5. 两条硬纪律（判法自身）
1. **不许**"有 mod() 条目 / coverage-matrix 有这一行"就算实现（T30 的坑）。实现 = 有 fn 定义（非测试）。
2. 名字优先用符号表**真名**（name_src=v2*）；预测名（hyb）只能到 F2。无名（—）不猜。
3. 本审计的产物只有三个：`fixtures/function_coverage.tsv`、`tools/function_coverage.py`、
   `docs/06` §85。**不改任何 src/**（只读）。**

## 6. 已知会漏（写在这里，跑前就承认）
- L1 F3 里 `noname` / `hyb-miss` 子类可能被**高估**：我方可能把若干原版函数的逻辑**内联**进了
  另一个函数（或合并成一张数据表），源码层没有一一对应的 fn，但行为在。按 §0 的标准这仍
  不算"函数边界复原"，但读者要知道 F3 ≠ "行为一定没做"。
- L2 pin=name 只证明"我方有个同名函数"，**不证明**它实现的是原版那套逻辑（同名不同义可能）。
- L3 注释里的地址引用（P2）可能来自纪律好的登记，也可能被我方当成"待办"写着 ⇒ 只证明"指认"存在。
- L4 闭包/单态化函数的"原版函数"本身可能在 Rust 源码里没有独立 fn（编译器产物）⇒ 用父函数判；
  父函数在、闭包体在父函数里 ⇒ 记 F1，但读者要知道它不是源码层的一行 `fn`。
