## 1. 六类定义（五类继承 T82 §129.1 的语义，第六类是「不用判」的已实现）

| 类别 | 定义 | 进不进"诚实缺口" |
|---|---|---|
| `implemented` | 527 台账里 **F1/F2** 的行（已有实现；F1 有物证、F2 无物证） | 否（已实现，缺口看 T38/T82） |
| `real-missing` | **原版有我方没有的业务函数** | **进** |
| `na:std-mono` | **标准库代码**：①`/rustc/<hex>/library/{core,alloc,std,…}/…` 的 Location（硬）；②T82 的排序单态化结构特征 | 否 |
| `na:gdext-glue` | **gdext/Godot 侧产物**：`godot*`/`gdext*` crate 的 Location；类注册 `/` 属性访问器 / `#[func]` 分发壳的结构特征；只引 Godot 引擎词汇 | 否 |
| `na:other` | **其它非本 crate 源码**：三方 crate（`~/.cargo/registry/src/…/<crate>-<ver>/`）、泛型单态化实例、编译器产物、Ghidra 重复切分块 | 否 |
| `unknown` | **判不了**（证据不足，必须在 `evid` 列写明缺什么） | **进**（保守） |

**为什么"不该由我们手写"这类要单列**：`na:*` 的原版 Rust 源码里**没有那一行 `fn`**——它的边界来自
①标准库泛型实例化 ②宏展开 ③编译器生成 ④三方 crate。我们**写不出**对应源码，
强行写一份等于"凭空造一份没有物证的实现"（违反 `AGENTS.md` §0.3/§2）。
反过来，若把 std 地址写进我方注释，会让 P2 地址指认**虚高**（T71 实测假抬 5 条 F1，`docs/06` §123.5）。

## 2. 三层证据（优先级从高到低，**命中即停**）

**L1 = Location 硬归属**（机械可复算，证据档 = `观测`；每个 file 路径都能指到 `.data.rel.ro` 槽）：

| # | 命中条件 | 判 |
|---|---|---|
| L1a | 引用 `src/<x>.rs` 的 Location，且该地址在 **527 台账**里 `bucket ∈ {F1,F2}` | `implemented`（子类 = F1/F2） |
| L1b | 同上但 `bucket = F3` | 直接用 **T82 §129 的逐条裁决**（`fixtures/f3_triage.tsv` 的类别列） |
| L1c | 引用 `src/<x>.rs` 的 Location，**但不在 527**，且该 Location 与 527 里某条**共享** | `na:other / dup:ghidra-split`（同一源码函数被 Ghidra 切出的另一块，**不重复计缺口**） |
| L1d | 引用 `src/<x>.rs` 的 Location，不在 527 且不共享 | `real-missing / crate-loc-unmapped`（保守进缺口） |
| L1e | 引用 `…/.cargo/registry/src/…/<crate>-<ver>/…` 的 Location | crate 名匹配 `^(godot\|gdext)` ⇒ `na:gdext-glue`；否则 `na:other` |

**L2 = 结构证据**（继承 T82 §129.1 §2 的 13 项特征里的 6 条；**只对 `max(size,size_fde) ≤ 0x721` 的函数生效**）：

* `VOL_CAP = 0x721`（来自 T82 §129.3 的实测：`na` 全部 ≤0x721 字节；≥0x800 的大函数上这些特征是
  假阳性，反例 `0x3c2bc0` 2624 指令的业务函数同时命中 `STRIDE/CMP/BULK`）。上限**取 max(size,size_fde)**。
* `G1` = `lock cmpxchg` 写可写全局（`.data/.bss/.got/.data.rel.ro`）**且** 全 `.text` 零 `call rel32` 调用点 ⇒ `na:gdext-glue`
* `G1b` = 零调用点 **且** 本函数地址出现在 `.rela.dyn` 数据表（`SLOT≥1`）**且** `imul …,0x78`（gdext 方法/属性记录步长）⇒ `na:gdext-glue`
* `G2` = `[reg+0x10]` 0→−1 借用标记 **且** 调用点 ≤1 **且** `SLOT≥1` ⇒ `na:gdext-glue`
* `A` = 直接自递归 ≥2 **且** 元素步长 `imul …,imm (0x20..0x10000)` 命中 ⇒ `na:std-mono`
* `B` = `ucomisd ≥2` 且 `jp ≥2` **且** (`movups/movaps/movdqu ≥2` 或 `cmov ≥4`) ⇒ `na:std-mono`
* `C` = `ucomisd ≥2` 且 `jp ≥2` **且** 本批内存在**同 size** 的另一条 ⇒ `na:std-mono`（成对单态化）

## 4. 抽样人工复核（成本控制：13,263 条不可能条条人看）

* 抽样率（**先写死**）：`real-missing` **10%**、`na:std-mono` / `na:gdext-glue` / `na:other` / `unknown` 各 **5%**。
* 抽样方式：`random.Random(20261127)` 对每类的候选按地址排序后 `sample`，**随机种子写死在命令里**。
* 复核方式：逐条读 `.eh_frame`/反汇编 + 引用串 + Location（`--dump <addr>` 的输出），
  判 `agree` / `disagree` / `unclear`，`disagree` 必须写清**为什么**。
* 报告：每类的**抽样错误率 + 95% 置信区间（Wilson）**，并给"纠偏后的点估计"（类计数 × 该类的 agree 率）。
* **反向也要抽**：`na:*` 与 `unknown` 都抽，这样能抓到"**被误判成 na 的真业务函数**"（这类最危险：
  它会让工作量被系统性低估）。

## 5. 已知判据边界（**会漏什么，先写明**）

1. **L1 只能覆盖"引用 Location 的函数"**。没有 panic 点的函数（纯计算、被内联的叶子）没有任何 Location，
   只能落到 L2/L3/unknown。⇒ `unknown` 里**必然混着**真游戏函数，这是本轮**估不出精确值**的部分。
2. **L2 的体积上限是取舍**：`≤0x721` 之外的大函数即使命中结构特征也不判 na（宁缺勿滥）；
   反过来，超大函数若真是 std/gdext，会落到 `unknown`（保守进缺口）。
3. **L3 的"游戏侧串"正则会命中一部分 std 代码**：`core::fmt` 的格式化路径会引用调用方传进来的格式串。
   抽样复核要专门盯这一类。
4. **`na:other` 是个收容所**（三方 crate + 泛型实例 + 编译器产物 + Ghidra 切分重复块），
   它的 `sub` 列必须可区分，否则"na:other 有多少"没有解释力。
5. **funcstart 分区不是真实函数边界**（Ghidra 会把一个函数切成几块）：1,382 条 funcstart 不是 FDE 起点。
   这些条目的 `size` 是块大小，不是函数大小 ⇒ **不许**把"条数"直接当"原版有多少个函数"。
6. **本表不改任何既有计分工具**（`tools/function_coverage.py` / `tools/f3_triage.py` 一行不动），
   也不写回 `fixtures/function_coverage.tsv` / `fixtures/f3_triage.tsv`（那是别人的台账）。
