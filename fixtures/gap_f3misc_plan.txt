## 2. 判据（**继承，不改阈值**）

### 2.1 五类定义（T82 `fixtures/f3_triage_plan.txt` §1 逐字）

| 类别 | 定义 | 进不进"诚实缺口" |
|---|---|---|
| `real-missing` | **原版有我方没有的业务函数**：函数体承载原版模块自己的语义，能按源码写出来 | **进** |
| `na:std-mono` | **std/core/alloc 的单态化**：函数体是标准库的，本模块只贡献被内联进去的比较器/步长 | 不进 |
| `na:gdext-glue` | **gdext 宏产物**：类注册胶水 / 属性访问器 / `#[func]` 分发壳 / 信号 connect 闭包。源码层无独立 `fn` | 不进 |
| `na:other` | 其它不该手写的编译器生成物：drop glue / panic 展开 / `#[derive]` / trait 对象 shim | 不进 |
| `unknown` | **判不了**：证据不足以判成上面任一类（**必须写明缺什么证据**） | **进**（保守） |

### 2.2 机判特征（T82 §2，原样继承）

`SZ`（FDE 尺寸/指令条数）· `LOC`（`panic::Location` 引用）· `SELF`（自递归次数）· `STRIDE`（元素步长乘法）·
`CMP`（`ucomisd`+`jp`）· `BULK`（`movups/movaps/movdqu` ≥2）· `CMOV` · `ATOMIC`（`lock cmpxchg` 写可写段）·
`BORROW`（`[reg+0x10]` 0→-1 借用标记）· `CALLERS`（`call rel32` 数）· `SLOTS`（值 == 本函数地址的重定位槽）·
`CALLER_LOC` · `CALLEE`。

### 2.3 判决规则（T82 §3 + §9 勘误 E1–E4，**含优先级**）

* `R-STD ⇒ na:std-mono`：A 组（`SELF≥2` 且 `STRIDE`）/ B 组（`CMP` 且 (`BULK≥2` 或 `CMOV≥4`)）/
  C 组（`CMP` 且**同批另一条 F3 行 FDE 尺寸逐字节相同**）。**A/B/C 全不中 ⇒ 不许判 std**。
* `R-GDEXT ⇒ na:gdext-glue`：G1（`ATOMIC` 且 `CALLERS==0`）/ G1b（`CALLERS==0` 且 `SLOT≥1` 且 `imul …,0x78`）/
  G2（`BORROW` 且 `CALLERS≤1` 且 `SLOT≥1`）/ G3（`CALLERS==1` 且调用者 `CALLER_LOC==0` 且体 ≥0x180）。
* `G4 ⇒ unknown`（**不是** na）：同一个 `panic::Location` 被 ≥2 条无名 F3 行共享（源码闭包的多份实例）。
* `R-OTHER ⇒ na:other`：只做 drop glue / panic 展开 / `#[derive]` 生成物 / 空壳，**且**无业务常量/串/分支。
* `R-REAL ⇒ real-missing`：上面三组都不命中，**且**能写出该函数做什么的至少一句可复核描述
  （来自：被调者 + 常量 + `.rodata` 串 + Location 行号 + 调用者模块）。
* `R-UNKNOWN ⇒ unknown`：规则都不干净命中/相互冲突，或函数体太大本轮没读完（T82：>0x1000 未读完 ⇒ unknown）。
  **必须写「缺什么」**。
* 优先级（E4）：`na:gdext-glue` → `na:std-mono` → `na:other` → `unknown`(G4) → `real-missing`。
* 纪律（T82 §3）：`na:*` 每条**至少 2 个独立证据**（1 个机器特征 + 1 条人工复核的指令/表项），
  单条证据 ⇒ `unknown`；`real-missing` 必须能写出语义，写不出但也不像 na ⇒ `unknown`（不许猜）。

### 2.4 体积上限（T85 M4 / T86 `VOL_CAP`，**硬闸**）

`na:*` 要求 **FDE 尺寸 ≤ 0x800**（T85 实测：全部 na ≤ 0x721；反例 `0x3c2bc0`=0x308d 是业务函数）。
**>0x800 一律不许判 `na:*`**（可判 `real-missing` 或 `unknown`）。本轮最高的一条是 `0x3db3e0`=0x108e ⇒ 天然不可能 na。

### 2.5 **调用形态闸（T89 `docs/06` §137.5 新增，本轮强制且逐条记录）**

对**每一条**目标行记录 `rel32`（`call rel32` 调用点数）与 `slot`（值 == 本函数地址的重定位槽数），判据：

| 形态 | 含义 | 结论约束 |
|---|---|---|
| `rel32 ≥ 1` **且** `slot = 0` | 被**直接调用** | 泛型单态化的**必要形态**；也是业务函数的常见形态 —— **单靠它不能定案** |
| `rel32 = 0` **且** `slot ≥ 1` | 地址只出现在**数据槽**里（交给 API 的闭包 / 注册表项） | **禁止**据此判 `na:std-mono`（T89 驳回 `0x438880` 的教训：被内联进 std wrapper 的游戏闭包也是这个形态） |
| `rel32 = 0` **且** `slot = 0` | 只经 vtable/间接调用（如订阅回调） | 必须另找间接调用链（vtable 项 / `call_mut`），否则判 `unknown` 并写明缺哪条链 |

⚠️ 本轮 `0x4bef20`/`0x4bf090` 实测 `rel32=0 / slot=0`（音频订阅回调）⇒ 它们的"谁调我"必须靠
`new` 里 4 个 `dyn FnMut` vtable 的 `call_mut` 项解出来（`fixtures` 里已有：`0x85b0f8`/`0x85b170` 等），
**不许**因为"没有 `call rel32`"就判它们不存在。

### 2.6 Android 侧正向指名（T87/T89 判据①，`na:std-mono` 的另一半）

`na:std-mono` 必须给**正向**指名：本址 `panic::Location` 键集在 Android 2.0.60 `.symtab`
（`.reference/steam/android-2.0.60/libgraphwarrust.so`，未 strip）里命中的函数是**标准库/alloc 的泛型本体**
（如 `Vec::from_iter` / `Rc::new_cyclic_in` / `LocalKey::with`），而不是游戏 crate 的闭包。
命中物是**游戏闭包** ⇒ 不是 na（T89 驳回项）。

## 4. 落码口径（什么算"这条 F3 真落下来了"）

对本轮判 `real-missing` 的每一条：

1. **落点必须是我方同名原版模块文件**（`src/graphwar_replay_player.rs` / `graphwar_backend.rs` /
   `graphwar_audio_control.rs` / `graphwar_play_screen_control.rs`），**不许**落 `src/_scaffold/**`
   （`AGENTS.md` §4 + `function_coverage.py` 的 R1：scaffold 里的同名函数不计复原）。
2. **函数名 = v2 真名的方法段**（`fixtures/name_to_addr_v2.tsv` 的 `method` 列），大小写与下划线一致。
   名字来源不是 v2（如 hyb / android-only）的，**不许**当结论用 —— 那种行只登记、不落码（本轮 #7/#8 若属此列）。
3. **注释必须带**：`vaddr`（ELF 口径）+ FDE 尺寸 + 证据档（`逐位`/`观测`/`推断`）+ **关键指令**
   （立即数 / 字段偏移 / `.rodata` 串 / 表项地址）。**只写"对应 0xNNNN"不算**。
4. **单测**：能单测的加单测，**期望值只能来自反汇编读出的立即数/分支/表项**，不许来自我方实现的输出
   （`AGENTS.md` §0.5）。无法隔离（要 Godot 节点/线程/分配器）的，写明"能做什么、缺什么"，
   档位降到 `观测`/`推断`，**不许编语义**。
5. **接线**：若它被别处调用/调用别处，把调用点接上（保持既有 API 不变，必要时加 `pub`）；
   **既有测试断言若与本轮证据冲突**，改断言并写明地址与理由（不许删测试）。
6. **每处 real-missing 单独一个 commit**（便于逐条复核）。

### 4.1 判 F1 的机制（**不得为凑数改判据**）

复用 `tools/function_coverage.py` 的既有三层判法，一字不改：
* `P1`（真名）：`name_src ∈ {v2*, naming_android}` 的函数段（`::{{closure}}` 取**父函数**，R2）在我方
  **同名实现函数**里命中；
* `P2`（地址）：原文地址出现在**能贴到某个 fn** 的注释里（文件顶部台账注释块**不算** —— T85 N1 的假抬教训）；
* 定档：`pin ∈ {name, addr}` 且 `grade ∈ {逐位, 观测}` ⇒ **F1**。
⇒ 落码时"文件名 + 函数名 + 紧贴 fn 的 vaddr 注释"三件事同时做，是**判据要求**，不是包装。

### 4.2 **诚实拆解三口径**（本轮报告必须分开给）

| 口径 | 定义 | 复算 |
|---|---|---|
| **机器码** | `function_coverage.py --stats` 的 F1 条数变化（分母 527） | `--stats` 前后对比 |
| **源码级** | 本轮**新增的不同源码函数**个数（`::{{closure}}`/单态化多份副本只算 1 个） | 逐条数 TSV 的 `落码` 列去重 |
| **严格 1:1** | `--stats` 的 `M1_1to1`（R6：一个我方函数只对一个原版函数）变化 | `--stats` 的 `敏感度 R6` 行 |

⚠️ 三个数**通常不等**（T87：+30 机器码 = +4 源码级；T89：+3 机器码 = +0 源码级）。
本轮的 `::{{closure}}` 行（#7/#8）和"一条源码函数被切多份"的行，必须按这个口径扣掉。

## 9. 已知风险（**跑前承认**）

* **L1** 机器特征是**形态**证据不是语义证据：一个真业务函数若恰好是"自递归 + 步长"会被误判 std。
  缓解：R-STD 要 ≥2 特征同时命中 + 每一条 na 都人工复核一条具体指令。
* **L2** "原版源码里没有这一行 fn"本身是**推断**（我们手上没有原版源码），档位写「推断」，不许写"确定"。
* **L3** `unknown` 计入缺口 ⇒ 本轮缺口读数**偏大**（保守方向，不虚报完成度）。
* **L4** R2（`::{{closure}}` 按父函数判）会让"机器码 +2"虚高成"源码级 +2"，必须按 §4.2 拆开报。
* **L5** 本轮 4 个模块都是 `观测` 档（`coverage-matrix`），不是 `逐位` ⇒ 落了码也只是"观测级 F1"，
  **不等于**逐位验证；报告里每条都要写清这一点。
* **L6** 落码"能编译、测试绿"**不是**复原证据（`AGENTS.md` §0.2）：判据是"注释能指到指令"。
