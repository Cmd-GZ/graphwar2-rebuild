# 75 · `agent/new-evidence`：换**证据类型**，不是换特征编码（71 号已把"加特征"关掉）

**优先级 P0。71 号的结论是这次任务的依据。**

## 0. 为什么必须换"类型"

```
71 号把 24 个特征的边际逐个量完：
  gram  −16.63 点（命脉）｜scal −2.49 点｜size 0.0｜consts 0.0（纯冗余）
  24 个里 **7 个拿掉后 top-1 反而涨**  ⇒ "加特征"平均**负收益**
  二阶编码 cgram_a 单用 54.89%（留一最强），**但叠到 REF 只多 1 个样本**
  3,000 组配置实测：只比 24 组多 3 个样本
72 号把样本从 348 扩到 975，但 **622/629 是依赖 crate**；游戏代码仍 n≈169、±6.4
⇒ **结论：现有数据源的信息已经被榨干**。要提准确率只能引入**新的数据类型**。
```

## 1. 三条候选（按"能不能拿到"排序，**先各做可行性验证再动手**）

| # | 数据源 | 它为什么可能有用 | 怎么拿 |
|---|---|---|---|
| 1 | **`crash_reporter` / panic 栈字符串** | 栈里常含 `模块::函数` 文本 ⇒ 能给部分无 Location 函数**间接命名**（不是结构相似，是字符串里就有名字） | 包内搜 `crash_reporter`、panic 消息、`RUST_BACKTRACE` 相关字符串；看有没有可解析的栈模板 |
| 2 | **campaign 关卡表**（21 关参数，`docs/118` §7） | 关卡构造调用了 `calculate_paths` / `setup_level_*` 一批函数 ⇒ 能锚定**关卡构造侧**的一批地址（那批现在名字最乱） | 已有 `tools/campaign_params.py` + `fixtures/levelgen_*`；把它变成"地址 → 已知用途"的锚 |
| 3 | **真机帧**（有原版实跑画面） | 屏幕上的数值/文本可反向锚定绘制与状态机 | 现有 `docs/img` + 用户可录；成本最高 |

**要求**：三条各写"可行性结论 + 预计能锚定多少个函数**，再选 1–2 条做下去。

## 2. 判据（**必须两边都报，否则又是泄漏**）

对每个新数据源，都要回答：

```
① 正对照（348/975 里已定名的）能用它锚到吗？命中率多少
② 目标集合（12,736）里有多少条能用它锚？（覆盖数）
③ **两边覆盖率之比**：一边有、另一边没有 ⇒ 这个源只能当"判别特征"，不能当"证据"
④ 若用来做匹配：留出半 top-1 与 95% CI（并报 76.4% 的基线做对照）
```

⚠️ 41 号那条纪律仍然有效：**"正对照有、目标集合没有"的特征不许用**。

## 3. 硬约束
