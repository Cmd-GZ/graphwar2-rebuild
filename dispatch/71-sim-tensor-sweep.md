## 0. 为什么这个才能真正用上 GPU（63 号自己给的诊断）

```
61 号那套是 **top-K 检索器**：只吐排名，不吐"每个特征的相似度"
而"多组权重"要的是：**同一批相似度的加权和**（相似度与权重无关 ⇒ 只该算一次）

63 号的做法：每换一组权重就重算一遍分值 ⇒ 接口形状决定了 GPU 帮不上
正确设计：**物化一次相似度张量（逐特征）+ N 组加权和** —— 63 号明确写"我没做、也未实测"
```

## 1. 要做什么

1. **物化相似度张量**：对四份构建的交叉（先做 Linux × Windows 6.9 亿对），
   把 **16–18 个特征各自的分数** 存成矩阵（float16/float32，按块落盘或常驻显存，
   显存 ≤4 GB 就切块）；
2. **318 组（或更多）权重 = 一次批处理**：把所有配置当第 0 维，
   `score[c] = Σ_f w[c,f] · S[f]` —— 纯 GEMM/广播；
3. **给出三条实测**：
   ```
   ① 旧做法（每组重算一遍）墙钟  vs  新做法（一次物化 + 批加权）墙钟
   ② GPU 与 CPU 的 top-1/top-5 **必须逐条一致**（348 正对照全对）
   ③ 显存峰值、块大小、以及"若把配置数从 318 提到 3,000 会怎样"（外推要标明）
   ```
4. **口径必须写清**（63 号的教训）：报"工具内部计算时间"与"进程墙钟"**两个数**，
   并注明 `import torch` 的固定开销。
