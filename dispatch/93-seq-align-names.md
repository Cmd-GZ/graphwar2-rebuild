# 93 · `agent/seq-align-names`：**全序列对齐**给 12,736 个无锚函数定名（本项目最大的一次"质变"机会）

**优先级 P0，重活。目标不是"再涨 1 个点"，而是把"名字"这条线从 348/527 推到另一个数量级。**

## 0. 为什么这条路和以前不一样

```
现状：527/527 可归属；但 13,263 个函数里 **12,736 个一个 Location 都不引用**
     结构指纹只能给"同源候选"（76.4%，n=165），且**关卡闭包族系统性失效（51.9%）**
     目前已经关掉：加特征 / 调权重 / 补图 / 扩样本 / 换证据类型（五条全关）

**没试过的是"顺序"这条轴**：
  · Android arm64 有**完整 .symtab**：18,793 个 FUNC 符号（其中 1,300 个含 `graphwar`）
  · x86 Linux 有 13,263 个函数
  · `tools/sym_match.py` 已经证明"**函数顺序 + 体量比**"能用：1,300 个里 **762 个给出唯一候选（63%）**
  · 但它只做了**有名字的那 1,300 个**，并且是逐条启发式，**没有做全局单调对齐**
```

**质变的点**：把两条**有序函数序列**做**全局单调对齐**（order + size 双信号），
用 18,793 个 arm64 符号去覆盖 13,263 个 x86 函数 —— 覆盖的不再是"能给名字的 1,300 个"，
而是**大部分函数**。而"近孪生族"（结构指纹死掉的地方）**顺序+体积**恰好是**独立信号**。

## 1. 要做什么

1. **建两条序列**：
   ```
   A  x86：13,263 个函数（`analysis/funcstarts_ghidra_va.pkl`；**别用 funcstarts.pkl，它是错的**），
      每个函数带"体量"（下一条函数起点 − 本函数起点）
   B  arm64：18,793 个 FUNC 符号（`.symtab`），每个带 st_size
   ```
2. **全局单调对齐**（这是本轮的核心算法）：
   ```
   · 目标函数：最大化 Σ 匹配质量，约束是**保持相对顺序**（单调）
   · 匹配质量用"体量比 + 局部特征"（体量比先验：跨架构同一函数的体量比分布**已经量过**，
     例：calculate_function 0.61）
   · 规模 18,793 × 13,263 ≈ 2.5e8 格 ⇒ 用**带状 DP**（band 宽度可调）或**锚点分段 + 段内 DP**
     （已知 348 个真名就是最好的锚点！把它们当**分段边界**）
   · 允许"跳过"（一侧有、另一侧没有：内联 / ICF / 只在一侧存在的单态化）
   ```
3. **验收（必须两边都报）**：
   ```
   · 用 348 个三源真名做**留出验证**：对齐器给的名字与真名一致的比例（这就是它的准确率）
   · **覆盖率**：12,736 里有多少个拿到了"唯一对齐"（并给置信档）
   · **近孪生族专项**：关卡闭包族那 27 行（结构指纹 51.9% 的地方）对齐器给对几个
     —— 这一项比总准确率更能说明它是不是真质变
   ```
4. **产出**：`fixtures/seq_align.tsv`（x86 地址 / arm64 地址 / 体量比 / 置信 / 名字来源），
   以及一份"哪些函数仍然没名字"的清单。

## 2. 硬红线（这条会决定结果可不可信）

```
① 348 个真名**只能当留出验证**，绝对不能拿去调参与选择
   ⇒ 先把算法与参数**写死并提交**，再跑留出验证（预注册！参照 71 号那次的做法）
② 允许失败：若对齐器在留出上低于 76.4% 的结构指纹基线，如实报"这条轴不如结构指纹"
③ 不许把"顺序相同"当成"名字正确"——必须有独立验证
```
