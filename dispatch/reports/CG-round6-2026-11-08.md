## 3. 29：任务书的前提被证伪，真因在别处

**任务书说**："我方一路走到 `-24.99`、回放停在 `-20.7553`" ⇒ Ode 停止判据错。

**实测**：

1. 原版 Ode **只有五个出口**（`|x|>25` / `|y|>15` / 候选 NaN / 二分 100 次不收敛 / 点数 `(200/step)` 用尽），
   且**全部在收敛之后才判**；x86 `0x3c25bd..0x3c2918` / arm64 `0x3b5374` 逐条对上
   ⇒ **与我方实现逐条同构，无可修**。
2. 普查 1290 发：**Ode 550 发里「走到边界」= 0 发 / 0 批**；停点逐位相同 Ode 490/550、Normal 619/740；
   Ode 12 发水平直线弹道 12/12 逐位相同。
3. 任务书那个 `-24.9928` 是 `replay_endx_probe`（**绕掩膜**）的输出；同一批的**管线停点是
   `-20.75531942288392`，与回放逐位相同**。

**真因**：那批的 `function == ""` ⇒ `shot_points` 见空 token 树直接 `return Vec::new()` ⇒ 整条弹道消失。

它把 1 行反事实测出来了（`if toks.is_empty() && mode != Mode::Ode`），但那行在
`src/graphwar_shot_calculator.rs`、不在它的允许清单 ⇒ **由协调者落地**（`7d5d42f`）。
Normal 局早退**逐字保留**（实测 355/331 一条不动），三轴因此 +4。
档位：**推断**——"空 = 导数 0（水平直线）"是从这 4 批的改善反推的，不是从二进制读出来的。

## 4. 30：任务书的分母算错了（176 → 179）

`176 = 527 − 351`，但 351 是 **v1+v2+Windows 三份夹具的地址并集**，其中 **6 个地址不在 527 内**
（`0x3bd640` clap / `0x519450`/`0x519530` std time / `0x4eb830`/`0x4ec160` 无 Location /
`0x748000` 引用 25 个 miniz_oxide Location）。统一口径后 **348 可定名 ⇒ 179 无名**。

| 项 | 结果 |
|---|---|
| 模块分布 | 27 个（weak_caller 39 / module_container 20 / game_client 20 / …） |
| 分桶 | A 个体 20 / B 单态化族 94 / C 二选一 24 / D 真身无名 39 / 低分 2 |
| 档位 | **推断 138 / 未知 41** |
| 正对照（地址级） | 调参半 **98.8%**、留出半 **100%**、top-3 100%、"真身无名"闸门误报 **0** |
| 名字级 | 89.2% / 88.0%——差额**全部**是两套 `parse_name` 口径差（留出半 20 个失败里 20 个地址其实对上） |
| 消融 | 只有直方图与尺寸有用；f64/f32/字符串/整数常量/被调者**零增益** |

三个负结论：`__register_methods` vs `__register_constants` 结构不可分（367 B/95 指令全同、仅 51 字节不同）；
B 族缺的是**类型参数**；我方独立分出 weak_caller 23 `call` + 16 `call_0`，与 §34 用 Location 行号分出的 16+24 **互证**。

**删掉** `client/src/play/plane_view.gd`(527) / `fire_fx.gd`(261) ⇒ `git ls-files client/src | grep -E "plane_view|fire_fx"` **为空**。

`selftest` 双口径：**有 assets 694 → 709**；无 assets 675/2/10 → **690/2/10**（那 2 条 FAIL 与基线逐字相同）。

## 6. 32：三个缺口解出两个、纠正两处任务书错误

| 缺口 | 结论 | 纠错 |
|---|---|---|
| tick 源 | `fractional = tick + ((now−base)−accum)/0.016666666`，除数 = `f64(16_666_666)/1e9` | 任务书以为 1/60；**不是** |
| `update_transform` 三实参 | `x=w/2`、`y=h/2`、`scale=w/50`（f32 标量）+ `flip` 位组合 | 任务书说在 `ready`；**实际在 `GraphwarPlane::draw` `0x4b6147`**（我用 objdump 独立验：唯一调用点，正对照 `0x4b69ec`）。第三实参是 **f32 标量不是 Vector2** ⇒ §42.5 那条"自相矛盾"作废 |
| 两张表 | `get_team_overview` 返回 **u32 的 4 个布尔位，不是表** | §42.3 那句错；真正的两表在 `init_team_colors`（x86 `0x465070`），12 色与 arm64 一字不差 |

还查明**棋盘内部是工程底色的真因**：`AxisDrawer::draw` 的 filled 白矩形没被画（那个类不在它白名单）
⇒ 加了默认关的 `board_fill`，因为既有断言按"每次 `_draw` 1 条 `draw_rect`"计数。
