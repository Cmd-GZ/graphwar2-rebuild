## 3. 83：盲区的根因不是"少一种形态"，是**底层库返回值反直觉**

`tools/addr_probe.py` 里那句判据**一直是恒假的**：

```python
if y.regs_write and reg in y.regs_write:   # ← 永远为假
```

因为 **capstone 5.0.7 对 `add rax, 0xf` 的 `regs_write` 只返回 `[EFLAGS]`**（隐式写），显式 dst 不在里面。
我复验：`detail=True` → `add rax, 0xf` → `regs_write = ['rflags']` ✓。

**修复后的复扫**：站点总数 **3379 不变**（**无丢点，只换桶**），**129 处换桶 / 33 个 tag**；
tag 0 **2235 → 2106**、tag 1 501→551、tag 6 4→14、tag 15 45→46。

**历史结论逐条点名（9 条，最坏情况没有发生）**：

| 判决 | 条数 | 内容 |
|---|---|---|
| 改数但结论仍成立 | 2 | tag 0（2235→2106）、tag 15（45→46） |
| **完全仍成立**（地址一字不差） | 5 | tag 33 = 3 处、tag 44 = 4 处（2 生产+2 消费）、"40+ 变体"、TargetInfo tag 23 = 28 处 |
| 已作废（非本轮推翻） | 1 | `docs/00` §0.4 第 4 条（早结案没回填），已就地补注 |
| 未复核 | 1 | `docs/10` §15.5 是 **arm64 口径**，工具 x86-only |

**正对照 4/4 全绿**，其中 **tag 15 形态④ `0x474b8d` 是修前必红**的新增对照；
另有独立互验：`0x3d38f0` 认出 **17** 个 tag word，与 `docs/07` §7.2 的 17 行**完全一致**。

⚠️ 我纠了它一处措辞：它写"windows 两份不存在" —— **不准确**，Windows DLL 在 `.reference/windows/`（前几轮任务书也写过错的
`.reference/steam/windows-*/`）。**但结论不受影响**：`addr_probe.py` 自己文档写着"一律 ELF 虚地址"，**它本来就是 ELF-only 工具**。

## 5. 85：**决定不接**，而且把负结论做成了可执行的工程

**三条判据（都很硬）**：

1. **可见时序的缺口在消费者，不在驱动**：原版曲线揭示走 `get_fractional_tick`(`0x519530`) 喂点循环，我方仍是 `_advance_curve(delta)`。
   **接驱动不改画面**（实测），却让 `frames()/ticks()` 从 0 变每秒 +65/+60 ⇒ **下一轮会以为曲线是 tick 驱动的**。
2. **`V` 与 `base` 是一对相位**：只接 `V` ⇒ `H = min(π/6 + (V−base)/60, 1.0733775)` **立刻饱和**（实测 1.0472 → **2.1468** rad），准备圈永远全开。
3. **门没有可验证对应物**：原版 `0x515dd1` 判 `[backend+0x1e0]`；我方只有 `_running`，而 80 号五轮全是战役本地局 ⇒ **给两种无真值状态发明行为**。

**负结论的正对照 = 变异测试**：临时插 `drive_frame` ⇒ `PROCESS_LOOP 64/2 failed`、`PLAY_FLOW 198/1 failed`；
改 `set_ring` 实参 ⇒ `PLAY_FLOW 197/2 failed`（含 T1 tripwire）；还原后 `git diff` 为空、全绿。
⇒ **断言真的会红**，不是写了就算。

**那 5 个读数的实测**（真 `EntityDrawer._draw` 的 `last_arc`）：

| 读数 | 接线前 → 后 |
|---|---|
| `EntityDrawer::V` | 内核钟读数 0.485 → 60.0，但**弧逐位不变**（1.047197580 rad）⇒ **改的是读数，不是画面**（67 号那句"静默改 V"要拆成两半） |
| `KernelBus` frames/ticks/probes | 0/0/0 → **+65 / +60 / +125** 每秒 |
| `tick_event` | 零 → 每 tick 一条，**但只在有订阅者时**（实测无订阅者：泵照跑、队列抽干、**投递 0 条**） |
| `_advance_curve` | 不变 ⇒ 两只钟并存 |

**触发条件（可执行，Tripwire 会红）**：T1 = `V` 与 `base` **同时**改由内核钟供给（或位置表出现生产写入者）；
T2 = 门有对应物（联机/回放局各量一次）；T3 = 生产路径出现 `tick_event` 订阅者。
**落地顺序**：T1 → 同一改动里加门 → **再**删 `_advance_curve` 累加（**先删后接会一帧两倍速**）。

顺手量出下一轮的数：7 个处理器体内共 **10** 处 `add_event`。

**门⑤命中分支打到了，手法值得记**：**自建协议服务器**（LAN 发现灌 9 字段 `GameInfo` → 客户端点 Join → **TCP 帧序我们控**）：

| 局面 | 帧序 | 结果 |
|---|---|---|
| **hit** | `BotAdded{232}` → 第一发 `PlayerInfo{232}` | **`gate5_found`（`0x51a0e0`）**，5 条请求**零次发出**（frida + 线上帧，**两条独立**） |
| **nobot** | 不发 BotAdded | `gate5_miss` + 5 条照发（**正对照**，两条独立） |
| **selffirst** | 先 self 再 Bot | 门④ 先拦 ⇒ 现场复现 §46.5 的结构性原因 |
| **rebuild** | 第二条 `NewConnection{231}` | 门④ len 清 0 ⇒ **再次命中**（"连接重建"那条路成立） |

**它把边界写得极清楚**：

> 顺序是**我们造的** ⇒ 证明「分支可达 + 命中就不发」，**不**证明原版服务器会产出这种顺序。
> **剩的唯一缺口** = 真房源抓一次加 Bot 时 `BotAdded` vs `PlayerInfo` 的**先后与连接归属**。

## 7. 87：有界否定，但给了一条**会影响下一轮**的负结论

**两处序列化都没有算式**（都直接打印 `event+0x10` 那 8 字节）⇒ 1 ulp 在**结构体里**，不在序列化处。
**两个候选分叉点全被否**：`y0` 是纯拷贝无算术；那张表全库只有 **2 个写入者、都是字节拷贝**；
`calculate_shot_results` 只有 2 个调用点 ⇒ **两次采样是两次调用，不是一次调用里的两遍**。
缺口缩成一句：**两条路拿的是不是同一张表 / 同一刻的同一张表** —— 只需 **3 行 frida**，人打一发就能比。

**与语料那 13 批不同源**（那批是 x 侧、NaN vs 数；本条是 y 侧、量级低 12 个数量级）。

⚠️ **它那条负结论我标了"待复扫"**：它按三种形态扫 `FunctionPoints` 构造点得到 **0**，
而 **83 修好的第四形态恰好可能覆盖这种情况** ⇒ **83 合并后必须复扫**，本轮不能当定论。
