## 3. 76：护栏从"不可靠"变成"可信"，而且方法论可复用

**上游这轮才发现的**：`selftest` 同命令反复跑会 704/4、697/1。⇒ **每一轮"没退"的判断都建立在不可靠信号上。**

它先**复现不出**（HEAD 连跑 10/10 绿），然后做了关键一步：

> **把骰子换成旋钮** —— `GW2_SELFTEST_MATCH_SEED=89` ⇒ 稳定 `696/1/2`，连跑 3 次逐字相同。

**真因**：`serve_match` 默认 `seed_from_os()`，而 `_test_net_real_server` **没钉** `GW2_MATCH_SEED`。
扫 400 个种子：**14 个（3.5%）一个障碍都不生成**，而 `_server_started()` 要求 `AddObstacle > 0` ⇒ 抽到必红。
正对照：真随机跑 60 次有 2 次（3.3%）0 障碍，比例吻合。

**我独立验过**：默认种子 × 3 次全 `714/0/1`；`SEED=89` × 2 次全 `696/1/2` —— **那个"偶发失败"现在是可随时开关的确定性现象**。
**断言一条没删**（`_expect(` 701 → 701、`_skip(` 22 → 22）。

它还照实记了一个**负结果**：同批 60 次里命中链路 60/60 都有回包 ⇒ **上游那次 `704/4` 不是"打空"，机制未知**。

### ⚠️ 工具盲区（我用 objdump 复核，属实）

`tools/addr_probe.py tags` 文档里只认三种 materialize 形态，而实际有第四种：

```
0x474b8d  movabs $0x8000000000000000,%rax     ← 值是 0x8000…000 本身，不是 i64::MAX
0x474b97  add    $0xf,%rax                    ← +15 ⇒ tag 15（SoldierInfo）
0x474ba5  call   *0x9bac80                    ← 发布
```

工具的 `TAG_SENTINEL = 0x7fffffffffffffff`，`_tag_of_reg` **只从 i64::MAX 起算** ⇒ 这些点全被记进 **tag 0（2235 处）**。
⇒ **凡是用 `addr_probe.py tags` 下过"某 tag 只有 N 处"结论的，都要复查。**
（对照：60 号"`pos_y` 只有 2 条写入指令"是我用 `movdqu` 直接 grep 的，**不受影响**。）

## 6. 79：G7 结案（四条独立证据链）

第五道门那张 **120 B entry 的表 = CPM 的 Bot 表**；`M+0x30` 不是表，是**模块容器弱句柄**；
门 = `0x519fb5 call 0x46c5a0`（`get_module_wk::<CPM>`）→ 按 **`player_id`** 哈希查（stride `0x78`、state@entry+8）
→ **命中就不发** 59/50/52/54/66。四条链：指令形状 / 返回值形状 / CPM 自三个函数同套偏移 / **运行时返回值 3/3 == CPM 盒基**。

**`Computer.state` 只有 3 和 1**（`0`/`2` 无写入点，有界否定 + 正对照）；运行时 3 次迁移全是 **3→1→3**。

⚠️ **它照实报：门⑤的命中分支没打到**（3 局都走未命中），并给了**结构性原因**（门④ 只放"本连接第一个 `player_info`"，
而那个永远是本机玩家）+ **正对照**（每次完整打出 `gate5_enter → get_module_wk(match_cpm=true) → gate5_miss → 5×send`）。
顺带**更正三条旧结论**（Bot 表键是 `player_id` 不是 `connection_id`；state 在 `BotData+0x00`；`handle_tick` 体内没有 `0x5ec160`）。

## 7. 80 + 81：先量真值，再把真值变成结构约束

**80 量到的（观测）**：

```
tick 率恒 60.00/s（5 次运行、12,856 个 tick）
pumps ≡ ticks 逐帧严格相等 ⇒ 0-tick 帧泵 0 次（默认帧率下占 10.9%）
顺序恒 TP；长帧追赶无上限（SIGSTOP 1500 ms ⇒ 单帧 91 圈）；tick 间隔 16,667.2 µs、70 s 零漂移
delta 确实没读：指令层 0x518400..0x518527 无一条 xmm（我 objdump 复验 = 0 处）
                + 行为层 --fixed-fps 10 下 delta 恒 100,000 µs 而 tick 仍 60.01/s
原版有"对局中"门：0x515dd1 判 [backend+0x1e0]，菜单 28 窗口实测 0/s
```

**81 把它变成代码**：

```rust
drive_ticks_inner = for _ in 0..n { tick(); pump(); }   // pumps ≡ ticks 是结构性的
```

⇒ "每帧调一次"这个错**在新代码里不可能发生**（旧 `.gd` 是 `tick += dt × 60` 每帧一次，而且长帧夹到 60）。
§44 五条真值逐条有断言。

**但 81 最诚实的一句**：

> 原版回放界面的**时序未知**（`graphwar_replay_control::process` `0x4c6f40` 的播放时钟没解）
> ⇒ **本轮驱动是"我方自定"，只有"节奏"是观测来的。**
