## 3. 34：真机 37 发，否掉「数组被换掉」

**抓取**：两个真游戏进程（Linux 2.0.60，`.so` sha256 `9a538115…`），frida 17.26.1，
断点 `execute_results` 的 `movdqu` **RVA `0x472865`**（`pos = pts[n-1]`），共 **37 发**。

| 问题 | 答案 | 档位 |
|---|---|---|
| ① `rdx`/`rcx` 是什么 | `rdx` = 点数组基址、`rcx` = **n×16**；37/37 满足 `rcx%16==0` 且 `n == rcx/16 == r13` | 观测 |
| ② 是不是同一块 | **是**：`rdx` 37/37 = `execute_results` 入口扫到的队列项指针，`len` 与整条摘要一致（函数内**没有就地改写**）；且该指针 37/37 = **`gw+3c30c7`** 的返回，**不是** `gw+3e2d3b` 那块 | 观测 |
| ③ 两块内容 | **37/37 逐位相同**（`diffPoints = 0`）。正对照齐全：装机自检三档（相同 / 翻 1 bit / 翻 2 bit）+ 运行期真数据里跨发不同文本的两条数组被稳定报出 **1976 个不同点** | 逐位 |
| ④ 同发两次调用 | **37/37 逐位相同，0 发不同**（长度档 1261 / 4473 / 5172 / 5441 / 7066） | 逐位 |

⇒ 对那 407 批：**「数组被换掉」（报文读了另一条数组 / 队列项被改写）在本构建、Normal 局、单机条件下被否**；
`越界停` 本轮未动；**倾向「回放自身不自洽」**。

**顺带抓到一个可复算的 1 ulp 机制**（档：**推断**）：同一条可见曲线有两种 `(文本, 常数)` 折叠 ——
两组各 5441 点、第 0 点与 x 全同，y 有 **1976/5441** 个点差**恰好 +1 ulp（全是 +1，无 −1）**，
两组分别被 `fl(fl(sin(x)+3)+1.916)` 与 `fl(fl(sin(x)+4)+0.916)` **逐位复现 5440/5441**
（唯一 miss = i=0 炮口点）。缺的是 407 批实际 `(文本, 常数, pos_x)` 的复算，且**没有 DiffEq/Ode 局样本**
（Y 桶 114 发 DiffEq 一发未覆盖）。

**它自己的一条更正**：第一版配对只按 `ret+len`，把"上一发的数组"当成本发的另一次调用 ⇒
把 20 发的"相同"误判成 3 发"不同"；给每次调用加全局 `seq` 后修正为 37/37。

**本机新坑（对后续跑真机的人有用）**：frida `spawn` 会把这份游戏挂在 `wait4`、永不建窗口
（5 次抓取全废）⇒ 必须用 `Popen` + `attach`。
