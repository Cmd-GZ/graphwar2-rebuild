# 89 · 实况步长是 **0.01**，不是 0.5（此前所有对比都用了错参数）

## 1. 怎么发现的

追查 `docs/86` §9.1 的"采样器提前中止"时，发现该缺陷**只在 step=0.01 下出现**。
于是反问：实况到底用哪个步长？同一批 21 发，用三个步长各跑一遍比停点：

| step | 中位 \\|Δx\\| | \\|<0.05\\| | 最大 |
|---|---|---|---|
| 0.5 | 0.130 | 6/21 | 0.5 |
| 0.1 | 0.036 | 15/21 | 0.1 |
| **0.01** | **0.000** | **20/21** | 2.2 |

**step=0.01 时中位差为 0.000**（20/21 在 0.05 内），唯一离群值是 2.2——
正是 §9.1 那个提前中止的样本。

⇒ **实况步长 = 0.01**，与 `AGENTS.md` 记的 `0x3f847ae147ae147b` 一致。

## 2. 这意味着什么

| 影响 | 说明 |
|---|---|
| 此前 `docs/83`/`84` 的"21 发差 <0.5、击杀数一致" | **参数用错**（0.5），结论虽未被推翻，但**证据强度要重算** |
| 采样器早停缺陷 | **真实存在且影响线上**（step=0.01 下约 1/21 ≈ 5%，与子 agent 报的 4/93 相当） |
| "0.5 是实况"的说法 | **错误**，本文件更正 |

## 3. 为什么 0.5 也能"看起来对"

停点是连续曲线的第一个碰撞点，采样步长只影响**离散化误差**：
0.5 步长下停点误差约 ±0.25，正好对应实测中位 0.13。
所以错步长不会让结果离谱，只会让它**不够精确**——这也是它能骗过我之前几轮的原因。

## 7. ⚠️ 未解矛盾：`live_hits` 的 4 个测试只在 0.5 下通过

把 `tests/live_hits.rs` 里的 0.5 一并改成 `SERVER_STEP` 后，**4 个测试立刻失败**：

```

```

这些测试的内容是：**用真实抓取的命中点，验证我们重算的弹道第一个撞到的实体与游戏一致**。

| 证据 | 指向 |
|---|---|
| replay 停点对比（21 发）：0.01 中位 0.000，0.5 中位 0.130 | **0.01** |
| `AGENTS.md` Hard facts：`0.01 on the server` | **0.01** |
| `live_hits` 4 个抓取回放测试 | **0.5** |

⇒ **两者冲突，原因未明**。可能的方向：

1. `live_hits` 的抓取来自**我们自己的 harness**，而 harness 走的不是服务器的 0.01 分支；
2. 那 4 个测试的期望值当初是**照着 0.5 调出来的**（即测试被拟合过），本身不可靠；
3. 停止判定（掩膜走查）在某一步长下另有分支。

**当前处置**：`tests/live_hits.rs` 暂时保持 0.5（已回退），源码全绿；
矛盾写在这里，**在查清前不得声称"步长问题已解决"**。

## 8. 缺陷严重程度：实况步长下 **23% 的射击曲线被截断**

子 agent 在 4 个 SimultaneousTurns replay（82 发）上用 **0.01** 重算：

| step | 半空终止 | 击杀集合（观测 152） | 多报 / 漏报 |
|---|---|---|---|
| 0.5（旧、错） | 3/93 | 并集 151 | 0 / **1** |
| **0.01（实况）** | **19/82 = 23%** | 并集 **129** | 0 / **23** |

⇒ 用对步长时**我们的物理对不上击杀集合**（漏 23 个），比本文档原先写的 "≈5%" 严重得多。

**精确复现**（`examples/rep.rs`，已核对与子 agent 数字一致）：

```rust
let toks = parse("(abs(cos((-1.43*x)))*8.65)");   // 外层括号必须保留
let (x0, y0) = (-1.3401100016801577, 7.565109751327434);
let c = correction(&toks, x0, y0, false);          // = 4.635142442441488
calculate(&shifted_tokens(&toks,c), x0, y0, 0.50, false, Mode::Normal); // 70 点，末点 (3.236, 5.368)
calculate(&shifted_tokens(&toks,c), x0, y0, 0.01, false, Mode::Normal); // 2078 点，末点 (1.096, 4.661)
```

**陷阱**：`f` 是偶函数，只有"穿过 x=0"的那一支会早停；`c` 差 0.006 就会走到另一支。

⇒ **这是当前最优先的物理缺陷**，优先级高于 AI 收尾与界面重建。
