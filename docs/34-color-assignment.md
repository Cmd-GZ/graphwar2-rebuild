# 34 · 玩家颜色分配（观测，规则未定）

## 1. 观测数据

多次对局里 `ColorInfo{entity_id, color{r,g,b}}` 的取值（累计 5 局 8 个样本的汇总，
加上更早几局的记录）：

| 颜色 | 观测次数 | 备注 |
|---|---|---|
| `(234, 0, 219)` | 3（同一玩家 229 连续三局） | 品红系 |
| `(0, 116, 26)` | 2 | 绿色 |
| `(107, 0, 234)` | 2 | 紫罗兰 |
| `(17, 0, 108)` | 2 | 深蓝 |
| `(238, 114, 0)` | 1 | 橙色 |
| 更早记录：`(186,42,32)`、`(125,104,0)`、`(149,5,62)`、`(21,83,221)`、`(122,160,0)` | 各 1 | — |

**共 10 个不同取值**，且**有重复**——所以不是"每局完全随机的 RGB"。

## 2. 观察到的特征

- 多数颜色**恰好有一个通道为 0**（`(0,116,26)`、`(107,0,234)`、`(17,0,108)`、`(234,0,219)`），
  少数没有（`(238,114,0)` 也没有）；
- 明度差异大（`(17,0,108)` 很暗，`(238,114,0)` 很亮），不像固定的"色轮 N 等分"；
- 同一个玩家 id 在不同局拿到不同颜色（229 先后拿到 `(186,42,32)`、`(125,104,0)`、
  `(234,0,219)`），所以**不按玩家 id 绑定**；
- 但 `(234,0,219)` 连续三局给了同一个玩家——若纯随机，概率很低。

## 3. 结论（诚实版）

**规则未确定。** 现有样本能排除"完全随机 RGB"与"按玩家 id 固定"两种简单假设，
但也凑不出稳定的调色板索引关系；可能是"从一组候选里随机挑"，候选集尚未取全。

因此 `server` 里**没有实现颜色分配**，只用固定值占位。这一条在进度表里
属于"联机实现"的未完成部分。

2. 若能确定候选集，再判断选择是随机还是按某种序号（例如加入顺序）。
