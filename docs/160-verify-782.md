工具不直接支持按值域拆特征，但**不需要改工具**：`score_same()` 读的就是 `fe["scal"]` 这个集合，
所以只要在内存里把每个函数的 `scal` 换成它的子集，再走**同一个** `Pair.ev` / 同一个 scorer，
就是严格的单一变量对照（`Pool`、`rank`、窗口、真值、分半一个字都没动）。实测（留出半 n=165，权重 0.5）：

| `scal` 的取值定义 | top-1 | Δ vs 基线 120 | 说明 |
|---|---|---|---|
| 全部 IMM（原样） | **129 = 78.18%** | **+9** | headline |
| `2..0xFF`（原 `consts` 漏掉的下界段） | **126 = 76.36%** | **+6** | 原文归功的那一段 |
| `>= 0x100` | 127 = 76.97% | +7 | "新加 IMM 全量"的另一半 |
| `0x100..2^32-1`（本来就在 `consts` 里） | **120 = 72.73%** | **0** | 加进去一格不动 |
| `> 2^32`（原 `consts` 够不到的上界段） | **127 = 76.97%** | **+7** | 原文只顺带提了一句 |

三件事：

1. **不能按波段分摊**（Jaccard 非线性，6 + 7 ≠ 9）：两个子集各自都能拿到 2/3~7/9 的增益，
   说明它们**在真配对上是冗余的两条入口**（同一批样本两边都有重合），不是两份独立贡献。
   能说的最强口径是：**`consts` 的两条边界各补一条都能拿到大部分增益，32 位中段本来就是 `consts` 的地盘、补了等于 0。**
2. **原文的根因句只写了下界**（`<0x100`），漏了上界（`>2^32`）。而数据显示这两条**同样重要**，
   且下面这一条让归因更难看 ↓
3. **两支都干净，但**"`consts` 的两条边界"这个说法必须写全：`<0x100` 与 `>2^32` 是**对称的两条边界**，
   原文只写下界，读者会以为"只有小常数有货"。另外 `2..0xFF` 在权重 2 时是 **119 < 120 基线**（比不加还差）、
   权重 0.5/1 时是 126 —— 这一支的增益对权重**敏感且非单调**，写"根因"时至少要带上这个前提；
   `>2^32` 那一支在 0.5 和 1 都是 127（见 §160.3.4 的注意：`>2^32` 结构性不含行号）。

**⇒ 根因句应改成**：「原 `consts` 有**两条**边界（`0x100` 与 `2^32`），`scal` 把两条都补上了；
实测任一条单独都能拿到 +6/+7 个样本中的大部分，而**本来就在 `consts` 里的 32 位中段单独为 0**；
两支都不含 `Location` 通道（逐样本 0/9 与 0/6）。」
