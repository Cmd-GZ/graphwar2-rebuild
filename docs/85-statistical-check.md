# 85 · 生成器 vs 真实机器人函数的统计对照（结论：一元可验，二元不可验）

## 1. 数据

375 局 replay，按 `soldier_id → player_id → 名字` 分离出机器人函数，
按 `FunctionModeInfo` 分 Normal/DiffEq，共 **155 条开火函数、453 个算子 token**。

## 3. 为什么二元算子的偏差**不是矛盾**

语料是**进化后的最优解**，不是生成器的随机抽样。
`+`/`/`/`*` 在解题时有用，被选择压力保留；`^`/`sqrt` 少用而被淘汰。
**选择压力必然让观测分布偏离生成器权重**，所以：

| 用途 | 可行性 |
|---|---|
| 用一元算子频率验证权重表 | ✅ 可行（`abs`/`sin`/`cos` 三项吻合到 0.7 个百分点内） |
| 用二元算子频率验证权重表 | ❌ **不可行**（被进化偏置） |
| 用长度分布验证生成器 | ❌ 不可行（同上，见 `docs/79`/`80`） |

⇒ 权重表的唯一可靠证据仍然是 `archive/ai/71` 的**二进制直读 + 40 万次运行时抽样**。
replay 语料只能作为"不矛盾"的旁证。

## 4. 同族微调（这条能对上）

replay 里能看到 `(0.33*(-6.80+x))` 与 `(0.33*(-6.95+x))` 这类
**结构相同、常数微差**的族 —— 与 `archive/ai/73` 的 `const *= (1+N(0,1))` 一致。
