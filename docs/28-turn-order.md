# 28 · 回合出场顺序（四局抓包验证）

## 1. 已验证：队伍之间严格交替

四局独立对局抓到的 `TurnInfo.soldier_id` 序列（`230/231` 属 Team1，`233/234` 属 Team2）：

| 局 | 序列 |
|---|---|
| A | `230(T1) 234(T2) 231(T1) 233(T2) …` |
| B | `234(T2) 231(T1) 233(T2) 230(T1) …` |
| C | `233(T2) 231(T1) 234(T2) 230(T1) …` |
| D | `234(T2) 231(T1) 233(T2) 230(T1) 234(T1?) …` |

**四局全部满足：相邻两次出手来自不同队伍。** 这条写成了实现
（`src/turn.rs::alternating_order`）与测试。

## 2. 被数据否定的假设（重要）

我一开始按"每队内部按士兵 id 升序循环"实现，**测试立刻失败**：

```
期望（抓包）: 230, 234, 231, 233, 230, …
我的实现:     230, 233, 231, 234, 230, …     ← T2 队内顺序反了
```

四局对比后，队内顺序也不一致（局 A 的 T1 是 `230→231` 正序，T2 是 `234→233` 逆序；
局 B 两队都像逆序）。**所以"按 id 排序"是错的，队内顺序规则目前未知。**

同时抓包是双向重复的，把两个方向按 fd 拼接可能影响顺序判定，
这也是我不下结论的原因之一。

## 3. 仍未确定

- **起始队伍**：局 A 从 Team1 起，B/C 从 Team2 起；
- **队内顺序**：见上；
- **阵亡后如何从循环里移除**：没有"同局内既有死亡又有后续回合"的样本；
- **并发回合**（`SimultaneousTurns`）：只观测到顺次模式。

## 4. 实现

`src/turn.rs`：

```rust
pub fn alternating_order(teams: &[Vec<i64>], start_team: usize, rounds: usize) -> Vec<i64>
```

调用方给出每队的出场顺序（因为该规则未确定，不自作主张排序），
函数只负责"队伍交替 + 队内循环"这一条**已验证**的部分。
