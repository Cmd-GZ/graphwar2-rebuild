## 5. 关键检查：A 轴用的到底是哪种文本？

三种取法，同一批语料、同一个求值器：

| 取法 | 定义 | 全 740 发 `Normal` | 407 里 A 轴批数 |
|---|---|---|---|
| **V1 公式**（§25.1 的代码框） | `eval(parse(corrected_function), ±pos_x)` | 判据本体 | **262**（= 声称值） |
| **V2 表头字面**（§25.1 的表） | `fl( eval(parse(function), ±pos_x) + c )`，`c` = `corrected_function` 里"原文之后"的那一段**逐字节**切出来 | **9 发切不出来**（见下） | **260 + 2 无法判定** |
| **V3 我方常数** | `fl( eval(parse(function), ±pos_x) + correction_used(…) )` | 常数串 **30 发**与回放不同（**全是 NaN 参与的情形**，回放记 `+ NaN`；普通常数一处没差） | **262（逐批完全相同）** |

**V2 为什么切不出来**：回放会把**没闭合的 `(` 补上**再拼常数。例：

```text
function          = -3.3/(1+exp(-999(x)))+…-e^(999(x
corrected_function= -3.3/(1+exp(-999(x)))+…-e^(999(x)) + 3.241
                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 补了 2 个 ')'
```

所以"原文之后逐字节切出来的那一段"是 `)) + 3.241`，不是浮点数。9 发都是这一族
（`5/155sin(4exp(4*6cos(`、`cos((x*x)`、`sin(abs(cos(7`…）。
⇒ §25.1 的**表头**与实际数据不自洽，**代码框**（`parse(corrected_function)`）才对。

**结论会不会不同**：会，但只撬动 **2 批**（都是"唯一不自洽的那一发正好是残缺括号文本"）：

* `1787655342#0` → 用 V2 变"无法判定"，但它在 **B** 里（`pos_x`/`end_x` 差 1 ulp），仍被覆盖；
* `1782927763#1` → 用 V2 变"无法判定"，而它 **`pos_x == end_x` 逐位成立 ⇒ 不在 B**
  ⇒ 按 V2 口径，**A∪B = 406、漏 1 批**。

⇒ "407 / 0 漏网"这个结论**依赖 V1/V3 这个正确口径**。这不是把结论推翻，而是说明
**§25.1 的表头必须改**（已在 §25 就地加注）。

**V3 的意义**：把回放记的常数换成**我们自己**算的 3 位小数常数（`correction_used`），
**逐批判定与 V1 完全相同**（262 不变），尽管有 30 发常数串不同。
⇒ "常数是谁算的"不是这 407 批的机制；**文本/常数这一侧没有隐藏的自由度**。
