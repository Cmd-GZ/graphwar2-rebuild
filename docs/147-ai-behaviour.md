## 2. 难度值 → 参数（本轮新解，顺带解掉"50 之谜"）

### 2.1 难度值从哪来

关卡数据里每关一个立即数，写进 `bot_added_event`（tag 10）载荷 `+0x10`
（`0x4a0882`–`0x4a0898`、`0x4a6d62`–`0x4a6d7c` 两处，`docs/118` §12.4）：
`3 / 25 / 50 / 100 / 250`。

### 2.2 收到之后怎么用（逐条）

`bot_added_event` 的分支在 `0x3e3d75`（分派表 `0x1beda8` 的 index 8）：

```asm
3e3d75  mov  ebp,[rbx+0xc]      ; 载荷 b（player/team id）
3e3d78  mov  r14d,[rbx+0x10]    ; ★ 难度值
3e3d7f  call 0x46c5a0           ; 取模块
3e3d95  mov  ecx,0xa             ; s = 10
3e3d9a  mov  r9d,0x5             ; limit = 5
3e3da0  cmp  r14d,0x4
3e3da4  jb   0x3e45a8            ; d < 4    ⇒ (s=10, limit=5)
3e3daa  mov  ecx,0x14            ; s = 20
3e3daf  cmp  r14d,0xb
3e3db3  jb   0x3e45a8            ; d < 11   ⇒ (s=20, limit=5)
3e3db9  cmp  r14d,0x1a
3e3dbd  jae  0x3e456d            ; d >= 26  ⇒ 下一段
3e3dc3  mov  ecx,0x1e            ; s = 30
3e3dc8  mov  r9d,0xa             ; limit = 10
3e456d  cmp  r14d,0x65
3e4571  jae  0x3e458d            ; d >= 101
3e4573  mov  ecx,0x28            ; s = 40
3e4578  mov  r9d,0xf             ; limit = 15
3e458d  cmp  r14d,0xfb
3e4594  mov  eax,0x19            ; 25
3e4599  mov  r9d,0xc8            ; 200
3e459f  cmovb r9d,eax            ; d < 251 ⇒ limit = 25，否则 200
3e45a3  mov  ecx,0x32            ; s = 50
3e45a8  ...
3e45c2  mov  esi,ebp             ; 第 2 参 = key
3e45c4  mov  edx,r14d            ; ★ 第 3 参 = 难度值本身
3e45c7  mov  r8d,0x5             ; 每槽个体数恒为 5
3e45cd  call 0x478fc0            ; (self, key, 难度, s, 5, limit)
```

`0x478fc0` 把四个数写成一个 16 字节的值插进表（`0x478fd1`–`0x479035` 取参，
`0x4790a0 call 0x440890` 插表）：

```text
值里的四个 u32（顺序即实参顺序）= edx, ecx, r8d, r9d
   = 难度值（后面被当**代数**用）, s = 种群/5, 5 = 每槽个体数, 复杂度上限
```

驱动侧的证据链闭合得很干净：`0x479b0b movdqu xmm0,[r14-0x10]` 从那张表旁边搬出 16 字节 →
`0x479ce5 movdqu [payload+0x70],xmm0` → `0x438780` 从 `cfg+0x70/+0x74/+0x78` 取出
代数 / s / 每槽个体数 → `0x51b459` / `0x51b451` / `0x51b77f` 使用。

|---|---|---|---|---|---|---|
| `0..=3` | **d** | 10 | 50 | 5 | 5 | `d × 53`（d=3 ⇒ 159） |

### 2.4 为什么 `docs/AI.md` 的六档表"看起来对、其实是采样"

六档表（代数 / 种群 / 上限 = 3/50/5、10/100/5、25/150/10、100/200/15、250/250/25、1000/250/200）
是**在 6 个特定难度值上测出来的**（3/10/25/100/250/1000），每一档都落在一个区间里，
所以它**恰好**等于上表在这 6 个点上的取值：
`difficulty_params(3) == params(1)`、`(10)==params(2)` … `(1000)==params(6)`
（`tests/ai_explain.rs::six_tier_table_is_a_sample_of_the_banded_mapping` 钉住这条）。

⇒ 关卡可以用**任意**难度值，只要落在同一区间，种群与上限就相同，**只有代数不同**。
关 12 的 `50` 就是这样一个值：`(50, 200, 15)`，六档表里没有对应行。
`docs/118` §12.4 记的"7/8 能对上代数、50 对不上任何一列"因此有了完整解释：
"对得上"的那 7 个值本来就是六档表用的那 6 个数（100 出现 3 次），不是巧合。

### 2.5 两条独立的运行时交叉验证（都不是本文自己的测量）

这张区间表不是从六档表"反推"出来的，它还能反推出**两组别人测过的运行时数字**：

1. **复杂度上限**。`docs/archive/ai/74` §4 运行时读 `ctx+0x58`，六档得到
   `5 / 5 / 10 / 15 / 25 / 200`。本文区间在对应的 6 个难度值（3/10/25/100/250/1000）上
   给出 `5 / 5 / 10 / 15 / 25 / 200` —— 逐档相同。
2. **评分次数**。`docs/93` §3 的实测次数 `159 / 1030 / 3825 / 20300 / 63250 / 253000`
   正好等于本文的 `d × (种群+3)`：
   `3×53`、`10×103`、`25×153`、`100×203`、`250×253`、`1000×253`。
   （`docs/AI.md` §5.2 的"每代 种群+3 次评分"就是从这条来的。）

⇒ 区间边界（`4 / 11 / 26 / 101 / 251`）虽然只有静态证据，但它给出的**每档数值**与两批
运行时实测**逐项吻合**，所以"分档位置搞错了"的可能性很低。反过来，
若哪天有人测到某档的上限不是这几个数，第一个该怀疑的就是这四条边。

## 3. 适应度到底在优化什么（逐项 + 逐条指令）

### 3.1 公式

```text
score = 净击杀 × 2_000_000
      − 距离项 d
      − V² / 100
      − (V > limit ? 50_000_000 : 0)
      − (净击杀 > 0 且 sret+0x14 ≠ 0 ? sret+0x14 × step × 100 : 0)
```

其中 `V` = token 数，`d` 的初值是 **1e6**（所以"什么都没打到"就是 `−1e6`）。
常数：`0x19fc00` = 2e6、`0x19fb30` = 1e6、`0x19f6d8` = 100、`0x19f478` = −5e7、
`0x19f6d0` = 0.5（既是粗评步长也是一致性容差）、`0x19f110` = 0.01。

逐条指令（`0x51b079`–`0x51b11d`）：

```asm
51b079  movsd xmm0,[0x19f6d8]     ; 100.0
51b085  test  eax,eax / jle 51b0a5; 净击杀 <= 0 ⇒ 跳过"掩膜项"
51b08f  mulsd xmm3,xmm0            ; step × 100
51b09d  mulsd xmm1,xmm3            ; sret+0x14 × step × 100
51b0a1  subsd xmm2,xmm1            ; 减掉
51b0ad  cvtsi2sd xmm1,eax          ; 净击杀
51b0b1  mulsd xmm1,[0x19fc00]      ; × 2e6
51b0b9  addsd xmm1,xmm2
51b0c0  imul  rcx,rdx              ; V²（整数）
51b0d9  subsd xmm1,[rsp+0x8]       ; − 距离项
51b0eb  divsd xmm3,xmm0            ; V²/100
51b0ef  subsd xmm1,xmm3
51b0f3  mov   ecx,[ctx+0x58]       ; limit
51b0fb  cmp   rdx,rcx / jbe        ; V <= limit 跳过
51b100  addsd xmm1,[0x19f478]      ; + (−5e7)
51b10d  movsd [sret+0x00],xmm1     ; score
51b111  mov   [sret+0x10],eax      ; 净击杀
51b114  mov   [sret+0x14],esi      ; 那个累加器
51b11d  movsd [sret+0x08],xmm0     ; 距离项
```

### 3.2 逐项

| 项 | 值 | 后果 | 等级 |
|---|---|---|---|
| 打**死一个敌人** | `+2e6` | 一发的最高收益 | 观测 |
| 打**死一个自己人** | `−2e6` | **与击杀等权**：一命换一命净收益 0 | 观测（`0x51ae4c`） |
| 什么都没打到 | `−1e6`（距离项的初值） | 所有"打空"的候选同分 | 观测 |
| 表达式复杂度 | `−V²/100` | 1 token 罚 0.01、10 token 罚 1、100 token 罚 100 —— **数量级远小于 2e6**，但足以在"全都打空"时决定胜负 | 观测 |
| 超复杂度上限 | `−5e7` | **只是扣分不是过滤**：全种群都超限时最优者照样会被发射 | 观测 |
| 距离项 | 初值 1e6，只在 **tag 3 事件**里取 min | 常规对局里恒 1e6（`docs/archive/ai/74` 的运行时分布）⇒ 这一项**实际是死的** | 观测（静态）/ 转引实测 |
| 那个累加器 | tag 4 事件把 `value>>32` 累加进 `[rsp+0x34]` | 非 0 时：① 额外扣 `累加值 × step × 100`；② **净击杀被压到 1**（`0x51b063`–`0x51b075` 的 `cmovle/cmove`） | 观测（指令）/ **未知**（tag 4 何时出现） |

### 3.3 三处更正

1. **友军不是"死代码"。** `docs/AI.md` §4 写"友军惩罚项在反汇编里恒为 0"，
   本轮的指令级证据相反：`0x51ae21`–`0x51ae5a` 是一段完整的"同队 ⇒ 减、不同队 ⇒ 加"，
   每命中一个实体都要查一次队伍表。`docs/97` §3.1 的记法（`0x51ae4c dec` / `0x51ae5d inc`）
   才是对的。**运行时为什么看起来恒 0**：常规对局 AI 几乎打不到自己人，不是代码不扣分。
2. **`sret+0x14` 不是"未定"**，它是 tag 4 的累加器，且它会**反过来压制净击杀**
   （`0x51b06b cmovle` / `0x51b075 cmove`）。`docs/archive/ai/74` 把它记成"掩膜扫描累加器、
   常规对局恒 0"——数值观察对了，作用漏了一半。
3. **多一项 `− 累加器 × step × 100`**：`docs/AI.md` §4 与 `archive/ai/74` §1.1 的公式里
   都没有它（因为它恒 0）。补全后公式见 §3.1。

## 4. "估计命中"是不是真模拟？—— **是，而且用的是真开火那条路**

### 4.1 调用链（三条独立事实拼起来）

```text
0x51a750（评分核心）
  0x51a98e  movq xmm0,[rsp+0x78]     ; 第一阶段步长（0.5 / 0.01）
  0x51a994  movq [ctx+0x18],xmm0     ; ★ 把步长写进 config 的第 0 个字段
  0x51a9a1  call [0x9bacb0]          ; ★ 结算函数
                ↓ .rela.dyn: R_X86_64_RELATIVE @0x9bacb0 → 3c2bc0
0x3c2bc0（graphwar_shot_calculator，12 KB）
  0x3c2cd6  rax = config; rdx=[rax+0x28]; rbx=[rax+0x10]; r13=[rax+0x30]
  0x3c2d0b  movsd xmm0,[rax]         ; config+0x00 = 步长
  0x3c2d18  movzx eax,[rax+0x39]     ; config+0x39 = function_mode
  0x3c390d  cmp BYTE [rsp+0xa0],0x1  ; = config+0x38
  0x3c3957  call 0x3f11e0            ; ★ 障碍 → 掩膜（0xFF=空）
  0x3c30c1  call [0x9bac98]          ; ★ 采样器
                ↓ .rela.dyn: 0x9bac98 → 3c2530（弦长采样器，step 来自 config+0x00）
```

**`0x3c2bc0` 全库只有两个调用点**：

| 调用点 | 用途 |
|---|---|
| `0x471825` | **真开火**：config 在栈上现搭（`0x4717f7 movabs 0x3f847ae147ae147b` = 0.01 写入 config+0x00；`0x4717ef` config+0x38 = 1；`0x471806` config+0x39 = function_mode；`0x47180e` config+0x3a = 1） |
| `0x51a9a1` | **AI 评分**：config 就是 AI 的 `ctx+0x18`，只把第 0 个字段换成当前阶段步长 |

⇒ **AI 的"想象"不是近似模型，就是真开火的结算函数本体。**
它比真开火少的东西只有两样：步长（粗评 0.5）与后续的伤害/死亡/爆炸（那些在 `life_manager`，不在这个函数里）。

### 4.2 结算函数吐出来的是什么：32 字节事件 + 5 个 tag

`0x3c2bc0` 把结果写成一个 `Vec<Event>`（元素 32 字节：`+0x00` tag、`+0x08` 值、
`+0x10`/`+0x14` 两个 u32；写回点在 `0x3c51a6`–`0x3c51b7`）。
评分核心再逐条解释（`0x51ab6c` 起，`lea r14,[rax+0x20]` = 每次前进 32 字节），
tag 分派用跳转表 **`0x1c63a0`**——表里**只有 5 项**：

| tag | 处理地址 | 做什么 | 等级 |
|---|---|---|---|
| 0 | `0x51aef0` | 什么都不做（继续下一条） | 观测 |
| 1 | `0x51aef0` | 同上 | 观测 |
| 2 | `0x51abb3` | **命中一个士兵**：拿 `+0x8` 当 key 查队伍表（默认 2）→ 同队 `dec`、异队 `inc` | 观测 |
| 3 | `0x51acd1` | **命中一个靶**：`+0x14` 当 key 查队伍表，`+0x8` 当距离 f64；非同队就 `d = min(d, dist)` | 观测 |
| 4 | `0x51acc1` | `esi += value >> 32`（累加器，见 §3.2） | 观测（指令）/ **未知**（触发条件） |

队伍表是 `ctx+0x08` 指向的 `HashMap<u32, u8>`（hashbrown 探测在
`0x51aa32`–`0x51aa92`、`0x51ac49`–`0x51adbf`），查不到返回 **2**。
这也解释了 `docs/AI.md` §5.2 的"每评一次还多做 3 次哈希查找"：
射手一次 + tag2 一次 + tag3 一次。

## 5. 它瞄准谁？—— **谁也不瞄准**

三条互证：

1. **评分只数净击杀**，没有"距离目标多近"这一项在常规对局里生效（§3.2 的距离项恒 1e6）。
   所以"最近的敌人 / 血量最低的敌人 / 随机一个敌人"这三种瞄准规则在代码里**都没有对应物**：
   函数体里没有任何"选一个目标"的步骤，只有"这一发打死了几个、其中几个是自己人"。
2. **实体表不区分目标**：`0x3c2bc0` 一开始就通过 `0x4628d0` 取出**全部候选 id**（`0x3c2c25`
   的调用、`0x3c2db5` 的 `mov r12d,[rbp+0]` 逐个遍历），对每个都做一次位置查询。
3. **运行时侧**：`docs/archive/ai/74` §1 的命中分布 `{0: 36939, 1: 9226, 2: 10760}`
   ——2 杀的比例不低，与"每一发都在最大化击杀总数"一致，与"死盯一个目标"不一致。

⇒ 对攻略的直接含义：**它不会"换目标"，只会"换曲线"**。让两个士兵站在同一条可能的曲线上
比让他们分散更好（对它而言）。

## 6. 候选从哪来 / 每代跑多少次

| 环节 | 做法 | 地址 | 等级 |
|---|---|---|---|
| 第 0 代 | 没有独立初始化函数；每槽 `随机函数 → 补齐 → 变异一次`，作为**父代**，再产 `per_slot−1 = 4` 个工厂子代 ⇒ 第 0 代仍是 `5s` 个个体 | `0x51b90f`/`0x51b923`/`0x51b95c`；`docs/110` §1.3 | 观测 |
| 随机长度 | `trunc(N(0,1)×5 + 10)`，均值 ≈ 9.5 | `docs/AI.md` §3 | 观测 |
| 每 token 抽样 | `rand % 85`，**每次一个 u32** | `0x4ef193`；`docs/AI.md` §8.7 | 观测 |
| 补齐 | `rand%50`：<25 常数、25..41 `x`、42..49 模式变量 | `0x4ee2c0 cmp r12d,0x2a` | 观测 |
| 变异 | 常数 `c *= 1+N(0,1)` 或重采样；变量/运算符包成 `(op const v)` | `0x4ee720` | 观测 |
| 交叉 | **单父代**取一棵完整子树（`0x4ee3a0` 只有 `(out,&mode,&parent)`） | `docs/AI.md` §5.1 | 观测 |
| 父代太短 | `len < 20` ⇒ 直接随机重生 | `0x4ee470` | 观测 |
| 精英 | 每代排序后**只留前 20%**（`s = 种群/5`），下一代全克隆 | `0x51cb6f`/`0x51c208` | 观测 |
| 每代评价数 | `种群 + 3`（克隆也重评，无缓存） | `0x51bc8b`/`0x51c0c1` + 3 处 0.01 | 观测（转引实测 `代数×(种群+3)`） |

**跨回合记忆**：种群存在按士兵的哈希表里，每回合**取走**再算（`0x479c6d` 取走后置空）。
⇒ 上一回合的存活者会成为下一回合的初始种群 —— 这是"取"的一侧（**观测**）；
"上一回合是谁写回去的"本轮只确认了 `0x3f27d0` 收到整个存活者数组（**推断**：它就是写回者）。

⇒ 攻略含义：**同一个士兵连续开火会越打越准**（种群是热启动的），而它**第一次**开火最随机。

## 7. 25 秒到点怎么收尾

`docs/93` 已逐条读死，本轮复核了指令（`0x51b7cf cmp $0x19`、`0x51b7d5 test %edx,%edx`、
`0x51cc60 jmp 0x51cbaf` 与 `0x51cb6d jmp 0x51cbaf` 汇合）：

1. 检查在**每代顶部**，所以最多超时**一代**（≈ 种群+3 次评分）；
2. 超时后**直接返回当前种群**，不设标志、不降级重跑；
3. 调用方（与 replay 文件）**无法得知**这一发是"算完了"还是"被截断了"；
4. 六档共用 25 s，不随难度变；难度 1000 代在快机器上能跑满、慢机器上会被截断（`docs/100`）。

⇒ 攻略含义：**高难度关的 bot 强弱不完全由难度决定，也取决于它的机器**。同一关同一位置，
快机器上的 bot 可能真的跑完 250 代，慢机器上可能只跑了 100 代 —— 这不是玩家能控的。
