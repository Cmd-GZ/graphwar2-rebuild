# 51 · 障碍生成的两条线索（一条确定，一条未成）

## 1. 确定：从"生成"到"发送"的调用链

hook libc `send`，在报文里出现 `AddObstacle` 的那一刻取调用栈，得到稳定链路：

```
GW+0x8f46c3   ← 发送封装（send 的返回点）
GW+0x45d404   ← 构造/发送报文
GW+0x3d8d2b   ← 广播
GW+0x45a60c   ← 处理"添加障碍"
GW+0x3f1d85   ← 调用者（疑似生成循环）
GW+0x3d21f5
GW+0x3d3730
GW+0x451be5
GW+0x438876
GW+0x43b6cb
GW+0x90ab4f   ← 线程入口
```

三帧样本的链路完全一致，说明这是唯一的产生路径。

**这条链是目前最可靠的抓手**：随机数一定在 `0x3f1d85` 及其更上层被消费。

## 2. 未成：内存里扫 ChaCha 状态

思路：ChaCha 的状态前 16 字节就是 σ 常量 `"expand 32-byte k"`，
所以在生成障碍那一刻扫可写内存，就能捞出活的 PRNG 状态（含密钥与计数器）。

实现：`tools/scan_chacha_state.js`，在 `send` 见到 `AddObstacle` 时对
61 个 `rw-` 区间做 `Memory.scan`。

结果：**命中 7 处**，但**结构不像 ChaCha 状态**：

```
61707865 3320646e 79622d32 6b206574    ← σ 常量（对）
e80012f0 00007f1f 00000028 80000000    ← 这里应是 8 个 u32 的密钥
7a639fd7 40225a07 53debeaf c0238b27    ← 这两组像 double（≈9.17 / ≈-9.77）
dacc17d2 40163433 ab913468 aeaa7698    ← 末 8 字节在 5 条记录里完全相同
```

判据：ChaCha 状态的字节 16~47 必须是**随机密钥**。这里出现的是
`0x00007f1fe80012f0`（像堆指针）、`0x28`（40）、`0x80000000`——
**不是随机数**。所以这些是常量被拷进了某个缓冲区，不是活的 PRNG 状态。

⇒ 该扫描**未能定位 RNG**。记录在此，避免以后重复踩。

## 3. 下一步（按可行性排序）

1. **从 `0x3f1d85` 往上追**：反汇编该函数，找它从哪个参数/字段取浮点数；
   若这些值来自某个结构体字段，再找谁写这个结构体；
2. **hook `0x45a60c` 的参数**：直接看传入的 `(x, y, r)` 是寄存器传的还是从内存读的，
   顺着来源往上找；
3. **对 `0x3f1d85` 做短程 Stalker**（只跟这一小段），记录它调用的所有函数，
   在调用序列里找那个"每次返回不同值"的函数。

这三条都不需要 syscall hook，也不会破坏 frida 自身通信。
