## 1. 你敲的不是普通数学表达式

玩家输入被解析成**前缀（Polish）顺序**的 token 列表（不是语法树）`[逐位]`。
一个 token 占 **16 字节**：`{ tag: u64, value: f64 }`，`value` 只对 `CONST` 有意义。

| id | 记号 | id | 记号 | id | 记号 | id | 记号 |
|---|---|---|---|---|---|---|---|
| 0 | `x` | 5 | `neg`（一元负） | 10 | `log`（**log10**） | 15 | `cos` |
| 1 | `y` | 6 | `*` | 11 | `ln` | 16 | `tan` |
| 2 | `y'` | 7 | `/` | 12 | `exp` | 17 | `const` |
| 3 | `+` | 8 | `^` | 13 | `abs` | 18 | `(` |
| 4 | `-` | 9 | `sqrt` | 14 | `sin` | 19 | `)` |

变体名在 `.rodata` 里**连续排列**，这是判定编号的直接证据 `[逐位]`。

**示例**：`sin(x) + 2` → `[ADD, SIN, VAR_X, CONST(2.0)]`。

## 2. 预处理（三步，顺序固定）

1. 整串**转小写**（`SIN(x)` 合法）`[逐位]`
2. `"pi"` → `"n"`，`"π"` → `"n"` ⇒ **`n` 是 π 的别名** `[逐位]`
3. 用一条固定正则切词（注意 **`y'` 排在 `y` 之前**，`sqrt|log|...|ln` 也按长优先）：

```
[0-9]*\.?[0-9]+ | \( | \) | x | y' | y | \+ | - | \* | / | \^
                | sqrt | log | abs | sin | cos | tan | ln | n | exp | e
```
`[逐位]`

## 3. 优先级与结合性（三处与"数学常识"不同，必须记牢）

```
函数应用  >  ^  >  一元负号  >  * /  >  + -
```

| 现象 | 真实行为 | 档位 |
|---|---|---|
| `^` 的结合性 | **左结合**：`2^3^2 = (2^3)^2 = 64`（**不是** 512） | `[逐位]` |
| 一元负号与 `^` | 负号比 `^` **松** ⇒ `-x^2` = `(-x)^2` | `[逐位]` |
| `log` | 是 **log10**；自然对数是 `ln` | `[逐位]` |

## 4. 七个会让人算错的怪癖

| # | 怪癖 | 具体行为 | 档位 |
|---|---|---|---|
| 1 | **隐式乘法** | 任意相邻的"可结束"与"可开始"单元之间自动插入 `*`：`2x`→`2*x`、`2sin(x)`→`2*sin(x)`、`(x+1)(x-1)`→`(x+1)*(x-1)`、`xy`→`x*y` | `[逐位]` |
| 2 | **函数可以不带括号** | `sinx`、`sqrt x` 合法；函数名只作用于**紧跟其后的一个 primary** | `[逐位]` |
| 3 | **`sin^2(x)` 的灾难** | 解析成 `sin(空) ^ 2 * x`（因为 `sin` 后面紧跟的是 `^` 不是 primary）⇒ **不是** `sin(x)^2` | `[逐位]` |
| 4 | **缺失操作数填 `CONST 0`** | 二元运算符缺一侧就填 0，**不报错**。这是"随手乱敲也能出图"的原因，也是上面那条怪癖的下游 | `[逐位]` |
| 5 | **常量折叠** | 解析后有一趟折叠（`0x4eb830`）：纯常量子树压成一个 `CONST`。`2*3+1` 直接变成 `CONST(7.0)` | `[逐位]` |
| 6 | **`y` 在普通模式下恒 0** | 普通模式求值 `eval(tokens, x, 0, 0)` ⇒ 写 `y` **不判非法**，等价于 0 | `[逐位]` |
| 7 | **`y'` 永远是 0** | 第三变量在**全部 7 个求值调用点**都传 `0`。写 `y'` 得到的不是斜率，是零 | `[逐位]` |

**常量值** `[逐位]`：`e` = `2.718281828459045`（`2.71828182845904523536` 的 f64）、
`n`/`pi`/`π` = `3.141592653589793`。

## 5. 定义域：`log` / `ln` / `sqrt` 与 NaN

| 输入 | `log`（log10） | `ln` | 档位 |
|---|---|---|---|
| `0.0` | **NaN** | **NaN** | `[逐位]`（直接对 `0x4eb9d0` 喂值实测） |
| `-0.0` | **NaN** | **NaN** | `[逐位]` |
| `1e-320`（次正规） | `-320.000004834948` | `-736.8272408909739` | `[逐位]` |
| `-1.0` | NaN | NaN | `[逐位]` |
| `1.0` | `0.0` | `0.0` | `[逐位]` |
| `10.0` | `1.0` | `2.302585092994046` | `[逐位]` |

判据是 **`v <= 0` → NaN**，**不是**"负数才 NaN、0 给 `-inf`" `[逐位]`。

> **这条有实际后果，也是攻略里最能坑人的一点**：
> `NaN` 会让点序列**立刻终止**（弹道只剩起点 = 哑弹），而 `-inf` 会让二分继续。
> 所以 `x = 0` 处出现 `log(x)` ⇒ 子弹**当场停在原地** `[逐位]`（`docs/03` §11）。

## 6. 采样：为什么弹道是"等弦长"的

游戏要画一条**看起来匀速**的曲线，于是要求相邻两点的**弦长恒为 `step`**：

```
L(i) = hypot( x_{i+1} − x_i ,  y_{i+1} − y_i )  =  step
```

直接把 `x` 加 `step` 是错的（斜率大时弦长会变大），所以对每个新点都在 `x` 区间上做**二分** `[逐位]`。

### 6.1 算法本体

```
pts = [(x0, y0)]                      # 首点就是士兵位置
x = flip ? -x0 : x0 ;  y = y0
n = (200.0 / step) as i32 ; if n < 1 { n = 1 }    # 点数预算，饱和转换

repeat at most n times:
    lo = x ;  hi = x + step
    repeat at most 100 times:
        mid = (lo + hi) / 2
        L   = hypot(mid - x, F(mid) - y)
        if not (|L - step| < 0.001):        # 严格 <；等号与 NaN 都算"不满足"
            if L > step or is_NaN(L): hi = mid
            else:                     lo = mid
            continue

        # 容差已满足 —— 普通模式还要做一次"半步复检"
        if 普通模式:
            mid2 = (x + mid) / 2
            L2   = hypot(mid2 - x, F(mid2) - y)
            hi   = mid2                     # ★ 比较之前就无条件写（0x3c2a0a）
            if not (L > L2):                # 复检不通过
                lo = x                      # ★ 退回基点（0x3c2a47）
                continue                    # ★ 两行必须同时有

        # 接受
        px = flip ? -mid : mid
        if is_NaN(px) or is_NaN(F(mid)): return pts
        if |mid| > 25 or |F(mid)| > 15:  return pts
        pts.append((px, F(mid))) ; x = mid ; y = F(mid) ; break

    若二分 100 次未收敛：整条曲线到此结束（不裁剪、不留坏点）
```
`[逐位]`（逐条汇编见 `docs/91`；`hi = mid2` 这一行补齐后 **24/24 用例整条点序列逐位相等**）

> **ODE 模式没有这段半步复检**（`0x3c2840` 在容差满足时直接接受）`[逐位]`。

### 6.2 常量（全部来自 `.rodata` 观测，`[逐位]`）

| 量 | 值 | 出处 |
|---|---|---|
| 弦长容差 | `0.001` | `0x19fc78` |
| 点数预算基数 | `200.0` | `0x19f8c0` |
| 二分次数上限 | `100` | 立即数 |
| 棋盘 X 半宽 | `25.0` | `0x19fbc8` |
| 棋盘 Y 半高 | `15.0` | `0x19fd40` |
| **服务端步长** | **`0.01`**（十进制 `0.01` 的 f64 位型 `0x3f847ae147ae147b`） | 立即数 |
| RK4 的 `1/6` | `6.0` 作除数 | `0x19f098` |

### 6.3 点预算与"射程"（把三个数字乘起来）

```
点数上限 = (200.0 / 0.01) as i32 = 20000 点
每点之间弦长 = 0.01 ⇒ 理论弧长上限 = 20000 × 0.01 = 200 游戏单位
```

`[逐位]`（公式与常量） / `[推断]`（"200 单位弧长"是由这两个常量直接乘出来的等价说法，
文档里没有单独一条常量叫"200 弧长"）。

棋盘本身只有 **50 × 30 游戏单位**，所以：

- 一条**平直**的弹道横穿全场约消耗 **50** 弧长，
- 剩下的 **150** 单位弧长都会被"来回摆动"吃掉 —— 这就是"`sin(100x)` 跑不远"的定量解释 `[推断]`。

### 6.4 四种终止原因（攻略里必须分清）

| 终止原因 | 判据 | 档位 |
|---|---|---|
| 求值出 **NaN** | `F(mid)` 或 `mid` 是 NaN（`log`/`ln` 的 `v<=0`、`sqrt` 负数、除零…） | `[逐位]` |
| **越界** | `\|x\| > 25` 或 `\|y\| > 15`，在**入列前**检查 ⇒ 曲线干净停住 | `[逐位]` |
| **二分 100 次不收敛** | 弦长条件始终不满足 ⇒ "斜率太高 / 太陡" ⇒ 子弹消失 | `[逐位]` |
| **弧长预算耗尽** | 跑满 `200/step` 个点 | `[逐位]` |

> `[观测]` 佐证：这四种终止与 GW1 攻略里写的四种**完全对应**（`docs/106` §5）。
> 其中"斜率太高"**不是额外规则**，它就是"二分不收敛"那条。

## 7. 修正常数 `c`：曲线必定穿过射手

```
c = y0 − f(x0')        x0' = flip ? −x0 : x0
实际射击使用 f(x) + c  →  f(x0') + c = y0
```
`[逐位]`（`0x3c5c50` 构造 `"f(x) + c"`；93 发的修正常数串与回放记录的 `corrected_function`
**93/93 逐字符相同**，`docs/86` §7）

| 事实 | 结论 | 档位 |
|---|---|---|
| 实现方式 | 把函数**文本**改写成 `"f(x) + c"` 然后**重新解析**一遍（不是数值上加偏移） | `[逐位]` |
| 后果 | 产生两个 token 列表（原串、修正串），精度受**浮点字面量格式化**影响，不是简单浮点加法 | `[推断]`（`docs/05` §3） |
| 界面显示 | 右下角那行 `" + 0.591"` / `" - 1.000"` 就是这个 `c`，**保留 3 位小数** | `[观测]` |
| **ODE（微分方程）模式** | **不做修正**（`apply_correction && mode == Normal`）；`offset` 恒 `NaN`，界面那行字是**空**的 | `[逐位]`（`docs/138` 单测与 `shot_points(…, Mode::Ode, false)` 逐点相等） |

> **为什么 ODE 不需要 `c`**：微分方程的**初值**就是射手位置，曲线天然从射手出发 `[推断]`（结构上唯一自洽解）。

## 8. 坐标与方向（写数值技巧前先对齐坐标系）

```
px = x * 1000 / 50 + 500  =  20x + 500
py = y * 1000 / 50 + 300  =  20y + 300
r_px = size * 20
```
`[观测]`（`0x4be3e0` 画框、`0x4f11e0` 光栅化、`0x4f15b0` 点测试**三处同构**，没有一处出现 `-y`）

| 量 | 值 |
|---|---|
| 画布 | **1000 × 600 px** |
| 比例 | **20 px / 游戏单位** |
| x 范围 | `[-25, 25]` → `[0, 1000]` |
| y 范围 | `[-15, 15]` → `[0, 600]` |

- 扩展内部 **`y` 增大 ⇒ `py` 增大，无翻转** `[观测]`；
- "屏幕上 y 是上是下"取决于 Godot 场景节点（`scale.y = -1` 之类），**不在 `.so` 里，未验证** `[未知]`。
  写攻略时**只用棋盘坐标**，不要写"上/下"。

### `flip`：方向由队伍决定，不是由几何猜

| 队伍 | 半场 | 开火方向 | `flip` |
|---|---|---|---|
| Team1（我方） | `x ≤ 0` | 向右 `+x` | `false` |
| Team2（敌方） | `x ≥ 0` | 向左 `−x` | `true` |

`[观测]`（`docs/105`：120 局 773 个 `PosInfo`，Team1 394 个全 `x<0`、Team2 379 个全 `x>0`，0 例外；
开火方向 Team1 108 发全向右、Team2 97 发全向左）

**一个容易漏的细节**：`flip=true` 时点存的是 `px = -mid`，函数**自变量是 `mid = -x_board`**
⇒ **Team2 的 `f(x)` 里的 `x` 是棋盘 x 的相反数** `[逐位]`（`docs/04` §2、`px = flip ? -mid : mid`）。
我方（Team1）`flip=false`，`f(x)` 的自变量**就是棋盘 x**，写攻略时按我方口径写即可。

**弹道是单调的**：内部 `x` 只从 `x` 增到 `x + step`，`px` 只可能单调前进
⇒ **弹道不能在一次飞行中掉头** `[逐位]`。
（注意：这不是"只能向右"——Team2 那一侧的弹道就是向左的，见 [`148`](../148-guide-manual.md) §3 #3。）

## 9. 障碍：为什么会被墙挡、被挡了之后发生什么

### 9.1 掩膜是位图，不是几何

```
障碍 (x, y, size) --rasterize--> 掩膜 1000×600，0xFF = 空
点序列 --逐点 is_occupied--> 首个占据点的序号 = 停止点
```
`[逐位]`（光栅化 `0x4f11e0` 与真二进制**逐字节**一致；点测试 `0x4f15b0` **300 个随机点**一致）

坐标换算在**像素空间**：`px = 20x + 500`、`py = 20y + 300`，半径 `r_px = (int)(size * 20)`；
圆按**逐行硬填**（`row = py + dy`，`dy ∈ [-r, r]`）`[逐位]`。

### 9.2 命中障碍之后

| 事实 | 结论 | 档位 |
|---|---|---|
| 发生了什么 | 在命中点用 `fill=0xFF`、半径 **`0.5`** **挖一个洞**（不是移除障碍） | `[观测]`（frida 活体 hook：一局 28 次光栅化里 8 次 `fill=0xFF`） |
| 洞会恢复吗 | **不会**。掩膜整局只建一次，`ClearObstacles` 397 份回放里**中途出现 0 次** | `[观测]` |
| 协议侧 | `QueueDestroyObstacle{pos, radius:0.5, tick}` → `DestroyObstacle`，延迟 **165 tick**；`radius` **恒为 0.5** 就是洞的半径 | `[观测]` |
| 对后续子弹的影响 | 后续子弹会穿过这个洞 ⇒ **多发射击的误差会累积**（第 2 发命中点从"差 23.3"变成"差 0.34"） | `[观测]` |

### 9.3 关卡里的障碍数量**不是常数**

散布式（`0x3f1e50`，逐位复现 13/13）`[逐位]`：

```
n = trunc( normal() * 7.0 + 15.0 )      # N(15, 7²) 后向零截断
if n <= min_count: n = min_count        # ← 每关一个的"下界"
每颗:  r = max(normal()*1.6 + 2.6, 0.8)
       x = (2r + 25) * (2u - 1)
       y = (2r + 15) * (2v - 1)
```

中心单障碍（`0x49f1c0`/`0x49f370`/`0x4a5e80`）`[逐位]`：

```
r = u * 5.0 + 3.0     位置恒为 (0, 0)     恰好 1 颗
```

**`min_count` 是下界而不是定值** `[逐位]` + `[观测]`：关 11/18/20（1 基关号）的实际障碍数出现过**恰好 10**，
关 5/21 出现过**恰好 15**；其余样本都比下界大。逐关的 `min_count` 见
[`03-关卡与战役.md`](03-关卡与战役.md) §3。

**障碍布局每局都不一样** `[观测]`（同一关出现过 10…29 个；种子来自 `/dev/urandom`）
⇒ **不存在"每关固定坐标"，攻略里不要写"这个墙在图上的某处"，
只能写"这类关有 N~M 颗半径 0.8~X 的圆，随机撒在棋盘内"**。

## 10. 这张表回答"我的子弹为什么没打到"

| 现象 | 机制原因 | 档位 |
|---|---|---|
| 子弹刚出膛就没了 | 函数在起点附近求值出 **NaN**（`log(x)`、`sqrt(-x)`、除零）⇒ 立即终止 | `[逐位]` |
| 子弹在半空停住，没撞墙 | 二分 100 次不收敛（函数太陡 / 不连续）；或越界 `\|y\|>15` | `[逐位]` |
| 子弹中途消失但没有爆炸 | 越界或 NaN —— 这是"停住"不是"命中"，**不产生洞** | `[逐位]` |
| 明明画着穿过敌人却没死 | 命中用**连续折线距离**判（不是采样点）；但**如果敌人正好是自己那一发的射手，按 id 被排除** | `[逐位]` + `[观测]` |
| 一发打掉多个 | 正常。子弹穿过实体不停，一个士兵一回合只死一次 | `[观测]` |
| 第二发轨迹和第一发不一样 | 障碍被挖了洞，掩膜变了 | `[观测]` |
| `sin^2(x)` 结果很怪 | 它被解析成 `sin(空)^2 * x` = `0^2 * x` = `0` | `[逐位]`（注意：`sin(空)` = `sin(0)` = 0，整式的值恒 0） |
