## 1. 你敲的不是普通数学表达式

玩家输入被解析成**前缀（Polish）顺序**的 token 列表（不是语法树）`[逐位]`。
一个 token 占 **16 字节**：`{ tag: u64, value: f64 }`，`value` 只对 `CONST` 有意义。

| id | 记号 | id | 记号 | id | 记号 | id | 记号 |
|---|---|---|---|---|---|---|---|
| 0 | `x` | 5 | `neg`（一元负） | 10 | `log`（**log10**） | 15 | `cos` |
| 1 | `y` | 6 | `*` | 11 | `ln` | 16 | `tan` |
| 2 | `y'` | 7 | `/` | 12 | `exp` | 17 | `const` |
| 3 | `+` | 8 | `^` | 13 | `abs` | 18 | `(` |
| 4 | `-` | 9 | `sqrt` | 14 | `sin` | 19 | `)` |

变体名在 `.rodata` 里**连续排列**，这是判定编号的直接证据 `[逐位]`。

**示例**：`sin(x) + 2` → `[ADD, SIN, VAR_X, CONST(2.0)]`。

## 2. 预处理（三步，顺序固定）

1. 整串**转小写**（`SIN(x)` 合法）`[逐位]`
2. `"pi"` → `"n"`，`"π"` → `"n"` ⇒ **`n` 是 π 的别名** `[逐位]`
3. 用一条固定正则切词（注意 **`y'` 排在 `y` 之前**，`sqrt|log|...|ln` 也按长优先）：

```
[0-9]*\.?[0-9]+ | \( | \) | x | y' | y | \+ | - | \* | / | \^
                | sqrt | log | abs | sin | cos | tan | ln | n | exp | e
```
`[逐位]`

## 3. 优先级与结合性（三处与"数学常识"不同，必须记牢）

```
函数应用  >  ^  >  一元负号  >  * /  >  + -
```

| 现象 | 真实行为 | 档位 |
|---|---|---|
| `^` 的结合性 | **左结合**：`2^3^2 = (2^3)^2 = 64`（**不是** 512） | `[逐位]` |
| 一元负号与 `^` | 负号比 `^` **松** ⇒ `-x^2` = `(-x)^2` | `[逐位]` |
| `log` | 是 **log10**；自然对数是 `ln` | `[逐位]` |

## 4. 七个会让人算错的怪癖

| # | 怪癖 | 具体行为 | 档位 |
|---|---|---|---|
| 1 | **隐式乘法** | 任意相邻的"可结束"与"可开始"单元之间自动插入 `*`：`2x`→`2*x`、`2sin(x)`→`2*sin(x)`、`(x+1)(x-1)`→`(x+1)*(x-1)`、`xy`→`x*y` | `[逐位]` |
| 2 | **函数可以不带括号** | `sinx`、`sqrt x` 合法；函数名只作用于**紧跟其后的一个 primary** | `[逐位]` |
| 3 | **`sin^2(x)` 的灾难** | 解析成 `sin(空) ^ 2 * x`（因为 `sin` 后面紧跟的是 `^` 不是 primary）⇒ **不是** `sin(x)^2` | `[逐位]` |
| 4 | **缺失操作数填 `CONST 0`** | 二元运算符缺一侧就填 0，**不报错**。这是"随手乱敲也能出图"的原因，也是上面那条怪癖的下游 | `[逐位]` |
| 5 | **常量折叠** | 解析后有一趟折叠（`0x4eb830`）：纯常量子树压成一个 `CONST`。`2*3+1` 直接变成 `CONST(7.0)` | `[逐位]` |
| 6 | **`y` 在普通模式下恒 0** | 普通模式求值 `eval(tokens, x, 0, 0)` ⇒ 写 `y` **不判非法**，等价于 0 | `[逐位]` |
| 6b | **Steam 里 `^` 可能打不出来** | Steam Linux Runtime 强制 `LC_ALL=C`，破坏 X11 dead-key 组合 ⇒ 不经启动脚本时按不出 `^`。作者用 `start_graphwar.sh`（`unset LC_ALL` + `LC_CTYPE=C.UTF-8`）修掉 | `[观测]`（发行版自带脚本原文） |
| 7 | **`y'` 永远是 0** | 第三变量在**全部 7 个求值调用点**都传 `0`。写 `y'` 得到的不是斜率，是零 | `[逐位]` |

**常量值** `[逐位]`：`e` = `2.718281828459045`（`2.71828182845904523536` 的 f64）、
`n`/`pi`/`π` = `3.141592653589793`。

## 5. 定义域、NaN 与"这一发直接报废"

> ⚠️ **本节 2026-11 更正过一处**：原写「`log`/`ln` 的判据是 `v <= 0` → NaN」——
> **那是反的**（旧版 `docs/03` §11，来自 oracle 的假象：把 libm 之外的实现当成了二进制）。
> 实测：**`±0` 给 `-inf`、负数才给 NaN**，中间没有定义域检查，就是系统 libm `[逐位]`。

### 5.1 三个边界值

| 输入 | `log`（log10） | `ln` | 档位 |
|---|---|---|---|
| `0.0` / `-0.0` | **`-inf`**（`fff0000000000000`） | **`-inf`** | `[逐位]`（`docs/03` §11） |
| `-1.0` / `-2.0` | **NaN** | **NaN** | `[逐位]` |
| `1e-320`（次正规） | `-320.000004834948` | `-736.8272408909739` | `[逐位]` |
| `1.0` / `10.0` | `0.0` / `1.0` | `0.0` / `2.302585092994046` | `[逐位]` |

`sqrt(负数)` 与 `0/0` 也给 **NaN**（`pow(-2.5,0.5)` 同样，`docs/03` §14.7）；
**非零 ÷ 0** 给 **±inf**（IEEE 默认行为，两条都 `[逐位]`）。

### 5.2 一发的结果：NaN 与 ±inf 都让这一发"只剩起点"

| 机制 | 证据档 + 出处 |
|---|---|
| 求值出 **NaN** ⇒ 这个点不入列、曲线在此收线；**第一格就 NaN 时弹道只有一个点（哑弹）** | `[逐位]`（`docs/04` §5：`F(mid)`/`mid` 为 NaN 即停，检查在"入列前"；`docs/06` §29.6 另有一处实测：在这种输入上二分跑满 100 次也直接收线 —— **两条路的结果相同**，只是停因的名字不同） |
| 求值出 **±inf** ⇒ 弦长算成 `inf` ⇒ 二分永远不收敛 ⇒ 跑满 100 次后同样收线 | `[逐位]`（`docs/03` §11 + `docs/04` §5） |
| 两者都**不是"打偏"**：整发只有起点，等于白扔一个回合 | `[推断]`（由上面两条直接推出；缺"一局里空放了几发"的原版录像计数） |

**对打法的含义**：在有限回合的关里，一发 NaN **不是"差一点"，是把整回合扔掉** ——
`Level 7` 只有 1 个回合（见 [`01-对局规则.md`](01-对局规则.md) §7），一发哑弹就是直接判负。

### 5.3 哪些写法会踩雷：按"你在内部坐标的哪儿"分，不是按"敌方半场"

写式子时看到的 `x` **不是棋盘 x**，而是"内部横坐标"：Team1 直接用 `x0`（`x0 < 0`）、
Team2 用 `−x0`（`x0 > 0`）⇒ **两支队伍的射手自己的内部横坐标都 < 0**，
而弹道在内部坐标里单调增加 ⇒ 只要没半路停住就会穿过**棋盘中线**（内部 `x = 0`）`[逐位]`（`flip` 定义，§8）
`[观测]`（773 个站位：Team1 394 个全 `x<0`、Team2 379 个全 `x>0`，0 例外）。

| 写法 | 什么时候出事 | 结果 | 档位 |
|---|---|---|---|
| `sqrt(x)`、`log(x)`、`x^0.5` | **第一格**（射手自己的内部 x < 0） | 整发只剩起点 | `[推断]`（由上面两条合成；缺一条"写了就哑"的实测录像） |
| `1/x`、`log(abs(x))` | 接近**棋盘中线**（内部 x → 0）时 | 停在**中线附近**（`y` 冲向 `∓inf` ⇒ 先撞 `\|y\|>15` 越界；或弦长成 `inf` ⇒ 二分空转 100 次。具体走哪条取决于式子，但都在中线一带） | `[推断]`（同上） |
| `sqrt(abs(x))`、`log(abs(x)+1)` | 不会（恒有定义 / 恒正） | 安全写法 | `[逐位]` |

⚠️ **别把危险区理解成"敌方半场"**：两支队伍的内部坐标都在**中线**过零，
所以 `1/x` 这类是**在棋盘中间断**，跟你在哪一侧无关。

### 5.4 真实对局里见过这种发吗 —— 见过，而且游戏会把 `NaN` 印在界面上

| 事实 | 结论 | 档位 + 出处 |
|---|---|---|
| 修正常数真的会是 `NaN` / `±inf` | 403 份回放 **1291 条** `corrected_function` 里，**741 条**带数字后缀，其中 **30 条**不是有限数（`+ NaN` / `- inf` 共 29 条，补 `)` 后 `+ NaN` 1 条） | `[观测]`（`docs/06` §26.6 的 D/E 形状） |
| 常数是 `NaN` 的那一发，弹道什么样 | **"没走"**：回放里这些发的 `end_x` 就等于开火者自己的 x（**11 批**，全部来自同一份"自指 NaN 探针"回放） | `[观测]`（`docs/06` §41.3） |
| 那些发是怎么造出来的 | 玩家写 `sin(u)/u`（`u = x + A`），把 `A` 的末几位按 **1 ulp** 逐个扫，让 `u` 在自己站位上恰好为 0 ⇒ `f = 0/0 = NaN` ⇒ `c = NaN` ⇒ **整条弹道退化成 1 个点**。共 **14 批** | `[观测]`（`docs/06` §42.1–§42.2） |
| 有多"刀刃" | 同一份探针、同一个站位：`u = −1.78e−15` 时 `sin(u)/u = 1.0`、常数印成 `+ 1.197`；`u = 0` 时印成 `+ NaN`。**两者只差 1 ulp**，而这 14 批里两种都出现过（方向还反过一次） | `[观测]`（`docs/06` §42.2 的逐位表、§42.1 逐批表） |

**对打法的含义**：① 想让一发"废掉"很容易，但想**精确**控制它是不是 NaN 几乎不可能
（1 ulp 就翻面）⇒ 别把 NaN 当可控战术。② 反过来更要紧：**别在自己脚下放奇点**，
它不会让你"打偏一点"，而是让整发归零。

## 6. 采样：为什么弹道是"等弦长"的

游戏要画一条**看起来匀速**的曲线，于是要求相邻两点的**弦长恒为 `step`**：

```
L(i) = hypot( x_{i+1} − x_i ,  y_{i+1} − y_i )  =  step
```

直接把 `x` 加 `step` 是错的（斜率大时弦长会变大），所以对每个新点都在 `x` 区间上做**二分** `[逐位]`。

### 6.1 算法本体

```
pts = [(x0, y0)]                      # 首点就是士兵位置
x = flip ? -x0 : x0 ;  y = y0
n = (200.0 / step) as i32 ; if n < 1 { n = 1 }    # 点数预算，饱和转换

repeat at most n times:
    lo = x ;  hi = x + step
    repeat at most 100 times:
        mid = (lo + hi) / 2
        L   = hypot(mid - x, F(mid) - y)
        if not (|L - step| < 0.001):        # 严格 <；等号与 NaN 都算"不满足"
            if L > step or is_NaN(L): hi = mid
            else:                     lo = mid
            continue

        # 容差已满足 —— 普通模式还要做一次"半步复检"
        if 普通模式:
            mid2 = (x + mid) / 2
            L2   = hypot(mid2 - x, F(mid2) - y)
            hi   = mid2                     # ★ 比较之前就无条件写（0x3c2a0a）
            if not (L > L2):                # 复检不通过
                lo = x                      # ★ 退回基点（0x3c2a47）
                continue                    # ★ 两行必须同时有

        # 接受
        px = flip ? -mid : mid
        if is_NaN(px) or is_NaN(F(mid)): return pts
        if |mid| > 25 or |F(mid)| > 15:  return pts
        pts.append((px, F(mid))) ; x = mid ; y = F(mid) ; break

    若二分 100 次未收敛：整条曲线到此结束（不裁剪、不留坏点）
```
`[逐位]`（逐条汇编见 `docs/91`；`hi = mid2` 这一行补齐后 **24/24 用例整条点序列逐位相等**）

> **ODE 模式没有这段半步复检**（`0x3c2840` 在容差满足时直接接受）`[逐位]`。

### 6.2 常量（全部来自 `.rodata` 观测，`[逐位]`）

| 量 | 值 | 出处 |
|---|---|---|
| 弦长容差 | `0.001` | `0x19fc78` |
| 点数预算基数 | `200.0` | `0x19f8c0` |
| 二分次数上限 | `100` | 立即数 |
| 棋盘 X 半宽 | `25.0` | `0x19fbc8` |
| 棋盘 Y 半高 | `15.0` | `0x19fd40` |
| **服务端步长** | **`0.01`**（十进制 `0.01` 的 f64 位型 `0x3f847ae147ae147b`） | 立即数 |
| RK4 的 `1/6` | `6.0` 作除数 | `0x19f098` |

### 6.3 点预算与"射程"（把三个数字乘起来）

```
点数上限 = (200.0 / 0.01) as i32 = 20000 点
每点之间弦长 = 0.01 ⇒ 理论弧长上限 = 20000 × 0.01 = 200 游戏单位
```

`[逐位]`（公式与常量） / `[推断]`（"200 单位弧长"是由这两个常量直接乘出来的等价说法，
文档里没有单独一条常量叫"200 弧长"）。

棋盘本身只有 **50 × 30 游戏单位**，所以：

- 一条**平直**的弹道横穿全场约消耗 **50** 弧长，
- 剩下的 **150** 单位弧长都会被"来回摆动"吃掉 —— 这就是"`sin(100x)` 跑不远"的定量解释 `[推断]`。

#### 采样密度：横向 50 个单位 = 5000 个点（可以直接打表的数）

步长 `0.01` 是**弦长**，所以"棋盘上有多少个采样点"可以直接除出来 `[逐位]`（两个常量，
`docs/04` §3 是这对常量的权威出处）：

| 量 | 计算 | 值 |
|---|---|---|
| 横向全场（`x` 从 `-25` 到 `+25`，**平直**弹道，弧长 ≈ `50`） | `50 / 0.01` | **5000** 个采样点 |
| 同一个靶子 / 士兵的**直径**（半径 `0.5`，见 [`01`](01-对局规则.md) §5） | `1.0 / 0.01` | **100** 个采样点 |
| 点数上限能覆盖几个"平直横向全场" | `20000 / 5000` | **4** 个 |
| 若弹道摆起来（弧长变长，横向却只有 `50`） | 点数 = **弧长** / `0.01` | 摆动越多、点数越费（就是上面"射程"那一节） |

**怎么用这些数**：

- 步长 `0.01` 只有靶子半径 `0.5` 的 **1/50** ⇒ 一条曲线**在采样意义上不会"从两个点之间漏过去"**。
- 边界是**入列前**判的（§6.4）：一条擦着 `y = 15` 或 `x = 25` 走的曲线**不会被裁剪**，
  它只是在越界的那一步停住 ⇒ **贴着边线走 / 打角落里的靶子**，限制你的是"你选的函数形状"，
  不是"采样太粗" `[推断]`。
- 命中本身也不是"数采样点"：判定用的是弹道到目标的**连续折线最近距离 < 半径**
  （[`01`](01-对局规则.md) §5）`[观测]`。
- 对照一下 bot：它**粗评**时把步长换成 `0.5`（[`04`](04-AI与难度.md) §3）⇒ 横向全场只剩 **100** 个点、
  一个靶子直径只剩 **2** 个点 —— 这就是"粗评会漏掉细目标"的来源
  （[`bot-行为说明.md`](bot-行为说明.md) §3.2）`[观测]`。

### 6.4 四种终止原因（攻略里必须分清）

| 终止原因 | 判据 | 档位 |
|---|---|---|
| 求值出 **NaN** | `F(mid)` 或 `mid` 是 NaN（`log`/`ln` 的 `v<=0`、`sqrt` 负数、除零…） | `[逐位]` |
| **越界** | `\|x\| > 25` 或 `\|y\| > 15`，在**入列前**检查 ⇒ 曲线干净停住 | `[逐位]` |
| **二分 100 次不收敛** | 弦长条件始终不满足 ⇒ "斜率太高 / 太陡" ⇒ 子弹消失 | `[逐位]` |
| **弧长预算耗尽** | 跑满 `200/step` 个点 | `[逐位]` |

> `[观测]` 佐证：这四种终止与 GW1 攻略里写的四种**完全对应**（`docs/106` §5）。
> 其中"斜率太高"**不是额外规则**，它就是"二分不收敛"那条。

## 7. 修正常数 `c`：曲线必定穿过射手

```
c = y0 − f(x0')        x0' = flip ? −x0 : x0
实际射击使用 f(x) + c  →  f(x0') + c = y0
```
`[逐位]`（`0x3c5c50` 构造 `"f(x) + c"`；93 发的修正常数串与回放记录的 `corrected_function`
**93/93 逐字符相同**，`docs/86` §7）

| 事实 | 结论 | 档位 |
|---|---|---|
| 实现方式 | 把函数**文本**改写成 `"f(x) + c"` 然后**重新解析**一遍（不是数值上加偏移） | `[逐位]` |
| **参与计算的常数** | **就是界面上印出来的那串 3 位小数**。把采样串里的常数换成全精度：Y 桶逐位命中 **26 → 1**、X 桶 **52 → 0**；换成截断：647 → 469 | `[逐位]`（`docs/06` §36.0 ⑤、§36.3；**原写"[推断]：精度受格式化影响"，实测这就是二进制的行为**） |
| 打印规则 | **四舍五入（半值取偶）**，不是向零截断：两边给不同串的判别样本里，回放 **186/186** 是四舍五入（截断只 107/186）；647 个命中批的 367 发是 **367/367** 对 182/367 | `[逐位]`（`docs/06` §36.2） |
| 舍入误差量级 | 印出来的 `c` 与全精度 `c` 最多差 **4.99e-4** —— 正好是 3 位小数网格的半格（`5e-4`） | `[逐位]`（`docs/06` §36.2） |
| 界面显示 | 右下角那行 `" + 0.591"` / `" - 1.000"` 就是这个 `c`，**保留 3 位小数** | `[观测]` |
| **ODE（微分方程）模式** | **不做修正**（`apply_correction && mode == Normal`）；`offset` 恒 `NaN`，界面那行字是**空**的 | `[逐位]`（`docs/138` 单测与 `shot_points(…, Mode::Ode, false)` 逐点相等） |

> **为什么 ODE 不需要 `c`**：微分方程的**初值**就是射手位置，曲线天然从射手出发 `[推断]`（结构上唯一自洽解）。

### 7.1 三位小数就是实际参数：多写的小数位没有效果

**结论：手写/复刻式子时按"四舍五入到 3 位"处理 `c` 就对了 —— 第 4 位起不参与计算。**

| 机制 | 证据档 + 出处 |
|---|---|
| 游戏把 `c` 印成 3 位小数、再把这**串文本**重新解析后拿去采样 ⇒ 真正参与采样的是"3 位小数值"，不是 `c` 的全精度值 | `[逐位]`（`docs/06` §36.1 的第 4–6 环；我方打印串与回放串**逐字节相同 188/188**，§36.3） |
| 舍入方式 = **四舍五入·半值取偶**（不是截断，也不是"随便截掉"） | `[逐位]`（`docs/06` §36.2） |
| 网格是 `1e-3`、半格 `5e-4` ⇒ 对 `c` 的调整**只有跨过 `0.0005` 边界时**才让印出来的数变一格（所以 `1e-4` 量级的微调**多数时候被吃掉**，边界附近会翻格）；调整量 **>`1e-3`** 才**一定**变 | `[推断]`（由前两行直接推出；`docs/06` §36.2 的回归锁：`y0 = 3.4458198403310867` 印成 `3.446`，截断会给 `3.445`） |

**对打法的含义**：

1. 自己列方程算 `c` 时，**只要 3 位**；写第 4 位不会让你"更准"，也不会让游戏更准。
2. 想靠"微调常数到第 4 位"来修弹道基本是**无效动作**：`1e-4` 量级的改动多数会被舍入吃掉；要让印出来的数**一定**变，得动 `>` `1e-3`。
3. 反过来说，**同一个式子、同一个站位，`c` 是唯一确定的 3 位小数** ⇒ 复现别人的弹道时，
   常数对到 3 位就已经对到"游戏能表示的全部信息"。

## 8. 坐标与方向（写数值技巧前先对齐坐标系）

```
px = x * 1000 / 50 + 500  =  20x + 500
py = y * 1000 / 50 + 300  =  20y + 300
r_px = size * 20
```
`[观测]`（`0x4be3e0` 画框、`0x4f11e0` 光栅化、`0x4f15b0` 点测试**三处同构**，没有一处出现 `-y`）

| 量 | 值 |
|---|---|
| 画布 | **1000 × 600 px** |
| 比例 | **20 px / 游戏单位** |
| x 范围 | `[-25, 25]` → `[0, 1000]` |
| y 范围 | `[-15, 15]` → `[0, 600]` |

- 扩展内部 **`y` 增大 ⇒ `py` 增大，无翻转** `[观测]`；
- "屏幕上 y 是上是下"取决于 Godot 场景节点（`scale.y = -1` 之类），**不在 `.so` 里，未验证** `[未知]`。
  写攻略时**只用棋盘坐标**，不要写"上/下"。

### `flip`：方向由队伍决定，不是由几何猜

| 队伍 | 半场 | 开火方向 | `flip` |
|---|---|---|---|
| Team1（我方） | `x ≤ 0` | 向右 `+x` | `false` |
| Team2（敌方） | `x ≥ 0` | 向左 `−x` | `true` |

`[观测]`（`docs/105`：120 局 773 个 `PosInfo`，Team1 394 个全 `x<0`、Team2 379 个全 `x>0`，0 例外；
开火方向 Team1 108 发全向右、Team2 97 发全向左）

**一个容易漏的细节**：`flip=true` 时点存的是 `px = -mid`，函数**自变量是 `mid = -x_board`**
⇒ **Team2 的 `f(x)` 里的 `x` 是棋盘 x 的相反数** `[逐位]`（`docs/04` §2、`px = flip ? -mid : mid`）。
我方（Team1）`flip=false`，`f(x)` 的自变量**就是棋盘 x**，写攻略时按我方口径写即可。

**弹道是单调的**：内部 `x` 只从 `x` 增到 `x + step`，`px` 只可能单调前进
⇒ **弹道不能在一次飞行中掉头** `[逐位]`。
（注意：这不是"只能向右"——Team2 那一侧的弹道就是向左的，见 [`21`](../21-guide-manual.md) §3 #3（旧号 `148`）。）

## 9. 障碍：为什么会被墙挡、被挡了之后发生什么

### 9.1 掩膜是位图，不是几何

```
障碍 (x, y, size) --rasterize--> 掩膜 1000×600，0xFF = 空
点序列 --逐点 is_occupied--> 首个占据点的序号 = 停止点
```
`[逐位]`（光栅化 `0x4f11e0` 与真二进制**逐字节**一致；点测试 `0x4f15b0` **300 个随机点**一致）

坐标换算在**像素空间**：`px = 20x + 500`、`py = 20y + 300`，半径 `r_px = (int)(size * 20)`；
圆按**逐行硬填**（`row = py + dy`，`dy ∈ [-r, r]`）`[逐位]`。

### 9.2 命中障碍之后

| 事实 | 结论 | 档位 |
|---|---|---|
| 发生了什么 | 在命中点用 `fill=0xFF`、半径 **`0.5`** **挖一个洞**（不是移除障碍） | `[观测]`（frida 活体 hook：一局 28 次光栅化里 8 次 `fill=0xFF`） |
| 洞会恢复吗 | **不会**。掩膜整局只建一次，`ClearObstacles` 397 份回放里**中途出现 0 次** | `[观测]` |
| 协议侧 | `QueueDestroyObstacle{pos, radius:0.5, tick}` → `DestroyObstacle`，延迟 **165 tick**；`radius` **恒为 0.5** 就是洞的半径 | `[观测]` |
| 对后续子弹的影响 | 后续子弹会穿过这个洞 ⇒ **多发射击的误差会累积**（第 2 发命中点从"差 23.3"变成"差 0.34"） | `[观测]` |

### 9.3 关卡里的障碍数量**不是常数**

散布式（`0x3f1e50`，逐位复现 13/13）`[逐位]`：

```
n = trunc( normal() * 7.0 + 15.0 )      # N(15, 7²) 后向零截断
if n <= min_count: n = min_count        # ← 每关一个的"下界"
每颗:  r = max(normal()*1.6 + 2.6, 0.8)
       x = (2r + 25) * (2u - 1)
       y = (2r + 15) * (2v - 1)
```

中心单障碍（`0x49f1c0`/`0x49f370`/`0x4a5e80`）`[逐位]`：

```
r = u * 5.0 + 3.0     位置恒为 (0, 0)     恰好 1 颗
```

**`min_count` 是下界而不是定值** `[逐位]` + `[观测]`：关 11/18/20（1 基关号）的实际障碍数出现过**恰好 10**，
关 5/21 出现过**恰好 15**；其余样本都比下界大。逐关的 `min_count` 见
[`03-关卡与战役.md`](03-关卡与战役.md) §3。

**障碍布局每局都不一样** `[观测]`（同一关出现过 10…29 个；种子来自 `/dev/urandom`）
⇒ **不存在"每关固定坐标"，攻略里不要写"这个墙在图上的某处"，
只能写"这类关有 N~M 颗半径 0.8~X 的圆，随机撒在棋盘内"**。

## 10. 这张表回答"我的子弹为什么没打到"

| 现象 | 机制原因 | 档位 |
|---|---|---|
| 子弹刚出膛就没了 | 函数在**射手自己那一格**求值就无解：`sqrt(负数)`、`0/0`、`log(负数)` ⇒ NaN ⇒ 只剩起点（§5.3：射手的内部 x 恒为负，所以 `sqrt(x)`/`log(x)` 属于这一类） | `[逐位]` + `[推断]`（组合推导，见 §5.3） |
| 子弹停在**棋盘中线附近** | 内部 x → 0 时 `1/x`、`log(abs(x))` 这类发散 ⇒ `±inf` ⇒ 撞 `\|y\|>15` 越界，或弦长成 `inf` 让二分空转 100 次 | `[推断]`（`docs/03` §11 + `docs/04` §5） |
| 子弹在半空停住，没撞墙 | 二分 100 次不收敛（函数太陡 / 不连续）；或越界 `\|y\|>15` | `[逐位]` |
| 子弹中途消失但没有爆炸 | 越界或 NaN —— 这是"停住"不是"命中"，**不产生洞** | `[逐位]` |
| 明明画着穿过敌人却没死 | 命中用**连续折线距离**判（不是采样点）；但**如果敌人正好是自己那一发的射手，按 id 被排除** | `[逐位]` + `[观测]` |
| 一发打掉多个 | 正常。子弹穿过实体不停，一个士兵一回合只死一次 | `[观测]` |
| 第二发轨迹和第一发不一样 | 障碍被挖了洞，掩膜变了 | `[观测]` |
| `sin^2(x)` 结果很怪 | 它被解析成 `sin(空)^2 * x` = `0^2 * x` = `0` | `[逐位]`（注意：`sin(空)` = `sin(0)` = 0，整式的值恒 0） |
