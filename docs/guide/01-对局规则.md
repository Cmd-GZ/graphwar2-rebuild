# 01 · 对局规则：回合、开火、命中、死亡、胜负

> **这本手册写给攻略作者，不是写给逆向工程师。**

## 1. 一局是什么

| 规则 | 结论 | 档位 |
|---|---|---|
| 队伍数 | **恰好两队**：队索引 `0`（下文称 Team1 = 我方）、索引 `1`（Team2 = 敌方） | `[观测]`（`docs/105`：773 个位置样本里只出现两队；协议只出现 `Team1`/`Team2`） |
| 站位 | **Team1 永远 `x < 0`，Team2 永远 `x > 0`**；773 个 `PosInfo` 样本 **0 例外**（Team1 394 个全为负、Team2 379 个全为正） | `[观测]` |
| 开火方向 | 由队伍决定，不由几何猜：Team1 `flip=false`（朝 +x）、Team2 `flip=true`（朝 −x） | `[观测]`（Team1 108 发全向右、Team2 97 发全向左；Team2 那 3 发"向右"是弯曲弹道的 `end_x` 假象） |
| 靶子的队伍 | 战役靶子建在 **Team2** 里（`0x46f310` 里发 `TeamInfo{Team2}`） | `[逐位]` |
| **分队规则**（谁进哪队） | 系统按「**人少的那队**」放：`Σ team < Σ (team^1)` ⇒ 进人少的一侧；**平手进 Team1**。房间上限 **10 人** | `[观测]`（`0x3c1b40` 逐条条件码；`docs/10` §13.2） |
| **回合超时**（不是按钮） | 由 `handle_tick` 里的**时钟谓词**判定（`0x470989`），到点自动结束回合；界面上那个按钮只是同一条路径的手动入口。**时长是房间设置**（6 档：30 s / 1 / 2 / 3 / 5 分钟 / ∞），战役关恒为"无截止" —— 见 §2.6 | `[观测]`（`docs/14` §11、§3.3.2；`docs/16-client.md` §16.4） |
| 胜负判定的实体集合 | 原版只看**队伍里还有没有活着的实体**；靶子就是 Team2 的普通实体 | `[观测]`（`docs/123` §4.5：45/45 份出现 `EndingGame` 的回放都是某队实体全灭） |

**给攻略作者的一句话**：靶子不是"另一种东西"，它是**站在敌方半场的敌方单位**。
所以"打靶关"和"对战关"在原版里用的是**同一条**胜利条件（Team2 全灭），
只是 Team2 里装的东西不同（靶子 / Bot 的士兵）。`[观测]`

## 2. 回合骨架

### 2.1 状态机（6 状态 / 7 事件 / 13 次迁移逐个相同）

```
Setup → WaitingForFunctions → CalculatingResults → SynchronizingResults
      → ExecutingResults → WaitingForFunctions → … → EndingGame → Setup
```

- 6 个状态、7 个事件、真实对局里 **13 次迁移逐个相同** `[逐位]`（`docs/41`）
- 一回合里**恰好一条** `FunctionPoints` / `FireRequest` ⇒ **每回合每人只能打一发** `[观测]`（`docs/106` §3）
- 每个状态持续多久（时间驱动）**未知**：`EndOfTurnInfo.end_of_turn_tick` 实测 `10886 / 11184 / 11457`，
  与 60 Hz tick 时钟（同一时刻只有 `65 / 126 / 426`）**对不上** `[未知]`（`docs/41` §3）

### 2.2 两种回合模式（这是"关卡参数里的 `turn`"那一位）

| 模式 | 含义 | 关卡里出现在 |
|---|---|---|
| `SequentialTurns`（`turn=0`） | 一人一发，轮流 | 19 关 |
| `SimultaneousTurns`（`turn=1`） | 每回合所有玩家**同时**提交函数，一起结算 | 只有 **`Level 11`** 与 **`Level 14`** 两关 `[逐位]` |

`turn` 数字来自 `level_info()` 每关分支的模式 dword（`+0x39` 字节），并与 385 份回放的
`TurnModeInfo` 事件 **21/21 对上** `[逐位]`（`docs/118` §4.3、§12.5）。

### 2.3 同时回合制：三段流程（这是本手册里最容易写错的一节）

同步回合的一批**不是**"每人一个完整窗口"，而是**一个事务**，分三段 `[观测]`（`docs/141` §1，
130 个真实多发批全中）：

```
收集阶段：FunctionInfo(owner,"",null) × 全部士兵   ← 函数槽复位
          TurnCountInfo + TurnInfo × P + EndOfTurnInfo{0,time_mode} × 1
          + GameStateInfo(WaitingForFunctions)
结算阶段：GameStateInfo(CalculatingResults)
          FunctionInfo × N   ← 按类型分组、同一顺序
          FunctionPoints × N ← 按类型分组、同一顺序
          GameStateInfo(SynchronizingResults)
广播阶段：[EffectInfo(死亡/灰烬)] × D  ← 一个连续块，按飞行时间升序
          (FunctionActive(owner, active_tick) + EffectInfo(爆炸)) × N  ← 每发一对
          GameStateInfo(ExecutingResults)
延迟段：  LifeInfo{alive:false} × D（真正的死亡时刻）、DestroyObstacle（约 165 tick 后）
```

| 规则 | 结论 | 档位 |
|---|---|---|
| 弹道怎么算 | **士兵表**用"批开始那一刻"的（谁死不影响别人）；**掩膜不是** —— 同批更早爆炸的洞已经在里面，会改变后面几发的路径（见 §2.4） | `[观测]`（死亡 **152/152**、多报 0 漏报 0，`docs/86` §14；掩膜：`docs/06` §34.4–§34.5。**原写"每发都对着批开始那一刻的掩膜算"，实测掩膜是演化的**） |
| 谁被谁打死 | **按弹丸飞行时间串行**：一个士兵一回合只死一次，归属**最先飞到他身上的那颗** | `[观测]`（可判别时刻样本 **38:0**，即"最早到达"38 例对"固定顺序"0 例，`docs/86` §14） |
| 同时起飞吗 | 同一回合所有发的 `FunctionActive.active_tick` **完全相同**（13/13 回合） | `[观测]` |
| 弹丸速度 | ≈ **0.29 游戏单位 / tick**（= 5.8 px/tick = 348 px/s），82 发里 75 发能一对一配爆炸，p10~p90 = `0.255~0.300` | `[推断]`（用爆炸 tick 反推，缺逐 tick 位置观测） |
| "谁先到"怎么算 | 因为 `active_tick` 相同 ⇒ **"先到" ⇔ "弧长更短"**，速度不参与排序 | `[观测]`（由上一行推出，`docs/141` §2.2） |
| 两发**同时**到达同一士兵（并列） | **未知**。61 个多命中样本里同一士兵两发到达时刻最小间隔是 **4.0 tick**，没有真并列 | `[未知]`（我们的实现用 `(弧长, 发序号, 士兵 id)` 兜底，是**重建版自有规则**） |
| 批内"谁排前面" | = 本回合 `TurnInfo` 的公告顺序（去掉 `soldier_id==0` 与公告了但没交的） | `[观测]`（130/130；其它候选：士兵 id 升序 44/130、降序 55/130、请求到达序 0/130） |

> ⚠️ **给攻略作者的实用结论**：同时回合里，"我这发把对面打死"**不会**阻止对面那发把我打死
> —— 判定是并行几何，两人可以互杀。已有实测样本：`1782642754` tick `48967`，
> 两名射手**互杀、四人全死** `[观测]`（`docs/122` §5）。

### 2.4 同批挖洞：同时回合**不是**"完全并行"

**结论：同一批里先爆炸的那几发已经在地面上挖了洞 —— 你这一发会看见它们，路径会被改变。**

| 机制 | 证据档 + 出处 |
|---|---|
| 真值里，同批**更早爆炸**（`start_tick` 更小）的那几发挖的洞，在后面几发解算时**已经在掩膜里** | `[观测]`（单变量实验：只把同批两发（`249`/`258`）的洞加进掩膜，被挡那一发的停点就**逐位等于**回放，`docs/06` §34.4） |
| 但**每一发都看不到自己挖的洞**（自己的洞不挡自己） | `[观测]`（`docs/06` §34.5 的实验设定与掩膜阶梯：`prefix` 不够、`arrival` 够；§34.4 还量到停点落在别人洞的边缘 `0.5034 ≈ 0.5`） |
| "顺序 = 爆炸时刻"本身 | `[推断]` —— 语料里"所有同批洞"与"更早爆炸的洞"**打平**（88/89 对 88/89），缺一发"穿过更晚爆炸那发的洞"的样本（`docs/06` §34.5） |
| 量级 | 89 发里因此差停点的 **2 发**（0.3758 / 0.0422；差 = 同一条弹道上 166 / 54 个采样点） | `[观测]`（`docs/06` §34.3） |

**对打法的含义**：同时回合里"各打各的"只对**人**成立，对**地形**不成立 ——
队友（或敌人）先爆的那一发如果打了墙，你这一发的走廊就变了。
所以"同一回合两个人打同一堵墙"不是重复劳动，是**后爆的那发会穿过先爆的洞**。

### 2.5 一回合到底几发：最多见过 **8 发**，但 **88% 的回合只有 1 发**

**结论：同时回合的一批是"这一回合所有交过函数的人一起结算"，规模可以到 8 发；不过日常大厅里绝大多数回合只有 1 发。**

| 机制 | 证据档 + 出处 |
|---|---|
| 一批的发数分布（全语料 **1080 个结算批**）：1 发 **950（88.0%）**、2 发 **98**、3 发 **18**、4 发 3、5 发 2、6 发 1、7 发 2、**8 发 6** | `[观测]`（`docs/06` §35.2） |
| **≥6 发的批只有 9 个（0.8%）**，这 9 个**全部**失败；但 9 批只来自 4 份回放，那 4 份的 ≤3 发批也全失败 ⇒ "发多"与"这局本来就崩"**分不开**（无局内对照） | `[观测]` + `[推断]`（`docs/06` §35.3） |
| 8 发同一 tick 的批逐条可查（4 个批的 `tick` 分别是 22734 / 3722 / 10085 / 16554） | `[观测]`（`docs/06` §34.1） |
| **模式可以在局内改**：有一份回放先 `SequentialTurns`、后 `SimultaneousTurns` ⇒ 别拿"开局那条广播"判定整局模式，要看批内 tick 是否相同 | `[观测]`（`docs/06` §34.1 注） |

**对打法的含义**：① 同时回合里"这一回合会死几个人"是按批算的，8 发同批时**一回合内可能连续互杀**（`[推断]`）；
② 但 88% 的回合是单发，**别按大混战的节奏准备**——真正同时开火的房间很少见（≥2 发只占 12%）。

### 2.6 回合倒计时：房间设置里的 6 档（战役**没有**）

**结论：联机每回合有倒计时，房主可选 30 秒 ~ 5 分钟或无限；战役关一律无限 —— 所以"慢慢算"只在战役里成立。**

| 机制 | 证据档 + 出处 |
|---|---|
| 六档 = `Timer30s` / `Timer1m` / `Timer2m` / `Timer3m` / `Timer5m` / `TimerInf`，时长 30 s / 1 / 2 / 3 / 5 分钟 / 无截止 | `[观测]`（六档全部实测：`end_of_turn_tick − 当时 tick` 分别落在 1800/3600/7200/10800/18000 的正偏差上，`docs/14` §3.3.2） |
| 数值 = "回合开始 tick + 时长"，单位是 **60 Hz tick**（不是墙钟秒） | `[观测]`（`docs/14` §3.2：10800 = 180 s × 60 正好是 `Timer3m`） |
| 图标与名字一一对应（`turn_30s.svg` … `turn_inf.svg`，同样的顺序） | `[逐位]`（`docs/16-client.md` §16.3.1 图标表 / §16.3.2 的 12 项名字表，两处同序） |
| **新建房间默认 1 分钟**；战役 **21/21 关 = `TimerInf`** | `[观测]`（按键算术交叉验证）/ `[逐位]`（`docs/16-client.md` §16.5） |
| 界面显示 = **时长 − 1 秒**（`02:59` / `01:59` 真帧）；30 s 与 5 分钟档是延伸推断、无限档未知 | `[观测]` + `[推断]`（`docs/16-client.md` §16.4） |
| 无限档在线上把截止 tick 发成 `0` | `[观测]`（`docs/14` §3.3.2 实测 `−66` ⇒ 线上 `0`） |

**对打法的含义**：① 联机里"磨"会被时钟硬切，每个回合的思考时间是**房主设的**；
② 战役关没有倒计时限制，可以按 §2.5 的节奏慢慢算 —— 但**回合数**限制仍然存在（见 §7）。

## 3. 射手：这回合轮到谁

多士兵玩家（每玩家 4~5 个士兵）下，射手是**回合系统轮转**出来的，**AI 不参与选择** `[观测]`。

```
每玩家一张 Vec<soldier_id> + 一个游标 index
index = (index + 1) % len          ← 先自增，旧值不用
若该士兵 life_state & 1 为真 → 发 TurnInfo{player, soldier_id}
否则继续往后转（最多 len 次）
一个活的都没有 → 发 TurnInfo{soldier_id: 0}，本回合该玩家不发 FunctionFire
```

| 细节 | 结论 | 档位 |
|---|---|---|
| 存储 | 每玩家一张 `Vec<soldier_id>` + 游标（`HashMap` entry 步长 `0x28`，`0x4628d0`） | `[观测]`（反汇编） |
| 顺序 | = 该玩家士兵 `Vec` 的**存储顺序**（实测 = `SoldierInfo` 的创建顺序）；**不是** id 排序、不是坐标、不是随机 | `[观测]`（三局逐发吻合：HAL `7445→7448→7444`；玩家 1053 `1054→1055→1085→1083`；玩家 621 只剩两人时严格交替 7 次） |
| 死人 | 跳过，继续往后转 | `[观测]`（`0x463da0` 调 `0x454950` 取状态，**先自增再取**） |
| 存活判定 | 状态字节 `& 1` 为真才算活；**查不到返回 `2`** ⇒ `2`（未上场）与 `0`（死）同被视为"不能开火" | `[观测]` |
| 函数存在谁身上 | **按士兵**：`FunctionInfo`/`FunctionActive` 的 `owner_id` 就是 `soldier_id`；开局每个士兵各广播一条**空**函数 | `[观测]` |
| AI 与射手的关系 | AI 只为"这一回合的那一个士兵"跑一次进化，写进**那个士兵自己的**函数槽 | `[观测]` + `[推断]`（"每回合重跑"是推断） |

**单士兵关（1 个士兵的关）不轮转**，永远是同一个士兵 `[观测]`（`docs/123` §5.1 #5）。

## 4. 一次射击：从函数文本到"谁死了"

```
① 取开火士兵坐标            HashMap<soldier_id,(x,y)>::get   @0x3c2f20       [逐位]
② 取步长                   服务端常量 = 0.01 (0x3f847ae147ae147b)             [逐位]
③ 计算修正常数 c 并改写函数串  c = y0 − f(±x0)，构造 "f(x) + c"  @0x3c5c50    [逐位]
④ 采样 calculate_path(...)   间接调用，函数指针 @0x9bac98                     [逐位]
⑤ 广播 FunctionPoints {start_x, start_y, end_x, points}                     [逐位]
```

**第 3 步是这套游戏最反直觉、也最该写进攻略的一条**：
**曲线必定穿过开火的士兵本人**，因为 `f(x0') + c = y0` 是构造出来的。
界面上右下角那行 `" + 0.591"` / `" - 1.000"` 就是这个 `c`（保留 3 位小数）`[观测]`。
细节见 [`02-函数与弹道.md`](02-函数与弹道.md) §7。

## 5. 命中判定

| 规则 | 结论 | 档位 |
|---|---|---|
| 谁决定弹道停在哪儿 | **只有障碍**。掩膜 = 障碍光栅化后的位图（`1000×600`，`0xFF` = 空） | `[逐位]`（光栅化 `0x4f11e0` 与点测试 `0x4f15b0` 均与真二进制逐字节/300 随机点一致） |
| 士兵挡弹道吗 | **不挡**。实测：死者 `x ≈ -10.45`，同一发弹道继续飞到 `x ≈ -24.99` 才停 | `[观测]`（`docs/30` §2） |
| 怎么算"打到" | 弹道点到士兵的**最近距离 < 半径** ⇒ 记一次命中；判定用 `hypot`（`0x887090`，16 字节无分支） | `[逐位]`（`0x3c41a9`–`0x3c41d6`） |
| 是"采样点上判"还是"连续判" | **连续**（或按 tick 插值，等效）：只在 0.5 步长的采样点上判会漏掉擦边（149/152 vs 151/152） | `[观测]`（`docs/86` §5.3） |
| 致死半径从哪来 | **士兵/目标记录自带的数据字段**（条目 `+0x18`），**不是编译期常量**；回放里 5300 条 `PosInfo.radius` 恒 `0.5` | `[观测]`（读字段）+ `[推断]`（"这个字段就是 radius"，缺写入口的反汇编） |
| 靶子的半径 | **`0.5`**（与士兵同值）。语料 **302/302** 条靶子的 `PosInfo.radius` 都是 `0.5` | `[观测]`（`docs/150` §6.1 #3；**原写"[推断] 从未被观测到"，实测有 302 条**） |
| 靶子挡弹道吗 | **不挡**。掩膜里只放障碍 | `[逐位]`（`src/_scaffold/api.rs` 把 `obstacles` 光栅化，`soldiers` 只按半径判死） |
| 障碍被击中后 | 在命中点用 `fill=0xFF`、半径 `0.5` **挖一个洞**，不是移除；洞**整局不恢复** | `[观测]`（frida 活体 hook：28 次光栅化里 8 次 `fill=0xFF`） |
| 挖洞后弹道 | 后续弹道会穿过这个洞 ⇒ **多发射击的误差会累积** | `[观测]`（第 2 发命中点从"差 23.3"变成"差 0.34"） |
| `DestroyObstacle` 何时到 | `QueueDestroyObstacle` → `DestroyObstacle`，延迟 **165 tick** | `[观测]`（`docs/44`） |

**射手不自伤（这条极重要，容易被写成错的规则）**

| 规则 | 结论 | 档位 |
|---|---|---|
| 机制 | **按实体 id 跳过**：遍历士兵表时 `cmp 射手id` / `je 下一个`（`0x3c4452`、`0x3c3e81` 两处） | `[观测]`（指令级，机器码在 `docs/122` §2.3） |
| **不是**"跳过开头若干点" | 扫描起点是**二分查找**按士兵 x 坐标算出来的，没有"跳前 k 点"的常量 | `[观测]`（`docs/122` §3.1） |
| **不是**"在射手位置挖洞" | 整个开火结算函数里只有**一处** `rasterize`，坐标是**该发的停止点**，不是射手位置 | `[观测]`（`docs/122` §3.2） |
| 免疫范围 | **只对自己那一发免疫**，不是整回合免疫。A 的弹道穿过 B 的起点 ⇒ B 会被 A 判死 | `[观测]`（`1782642754/48967` 两名射手互杀） |
| 免疫被运行时走到过吗 | **没有 Frida 实测**；依据是反汇编 + 1289 发"弹道起点与射手坐标逐位相同、无一发自杀" | `[未知]`（`docs/122` §7 #1） |
| 别人的弹道穿过射手 ⇒ 射手会死吗 | **会**。177 例"死亡特效落在射手自己身上"里 **165 例**由**别人**的一发解释（≤ 0.5 距离） | `[观测]` |

> **常见误解纠正**：
> ① "射手有整回合无敌" → 错，只对自己那一发 `[观测]`。
> ② "子弹会跳过射手位置附近" → 错，是按 id 排除 `[观测]`。
> ③ "站在射手旁边的人会被顺带豁免" → 反汇编预测**不会**，但**回放里 0 个样本**
>    （非射手到起点最小距离 **3.0006** > 0.5），所以这条只有反汇编依据 `[推断]`。

## 8. 胜负

### 8.1 原版（二进制 + 回放）

- **胜利条件 = 某队实体全灭**。45/45 份出现 `EndingGame` 的回放里，胜方都是"某队全灭"，
  败方存活实体数为 0 `[观测]`（`docs/123` §4.5、`docs/45` §2）。
- **靶子就生在 Team2** ⇒ 在打靶关里，"靶子全清"与"Team2 全灭"是**同一件事** `[逐位]` + `[观测]`。
- **目标没全灭时游戏不会结束**（否则 45 份里也该有"目标还活着就 EndingGame"的样本）`[观测]`。

### 8.2 按关卡类型分开（我们的实现口径，攻略写作请用这张表）

| 关卡类型 | 判据 | 胜利 | 失败 |
|---|---|---|---|
| **打靶关**（`targets > 0`、`bot == 0`）：13 关 = `Level 0/1/2/3/4/6/7/8/10/12/13/16/17` | 全部靶子被摧毁 | **靶子全清** | 回合上限用尽仍未清完（仅 `turn_limit > 0` 的关） |
| **对战关**（`bot > 0`、`targets == 0`）：8 关 = `Level 5/9/11/14/15/18/19/20` | 对方队伍全灭 | **对方全灭** | 我方全灭 |
| 两者都有 | 21 关里**不存在**这种关卡 | — | — |

档位：打靶关判据 `[观测]`+`[逐位]`（上面的等价性）；对战关判据 `[观测]`（45/45）；
**"回合上限用尽 ⇒ 判负"已从 `[推断]` 升级为 `[逐位]`**（`docs/150` §5），
`[未知]` 的只剩"它在屏幕上怎么表现"。

### 8.3 判定顺序（我们实现的 `reason` 码）

```
① 对战：我方全灭                        → 结束，human_won = false，reason = "own_wiped"
② 打靶：靶子全部被摧毁                  → 结束，human_won = true， reason = "targets_cleared"
③ 对战：对方全灭                        → 结束，human_won = true， reason = "enemy_wiped"
   ③' 同一刻两边都空                   → 结束，human_won = false，reason = "mutual_wipe"   ← 未观测
④ 打靶：turn_limit > 0 且已用回合 ≥ 上限 → 结束，human_won = false，reason = "turn_limit"
⑤ 其余                                 → 继续，reason = "playing"
   连"双方都不在场"也判不了             → 继续，reason = "no_verdict"
```

"失败优先"是**我们的选择**；21 关数据里没有"既有靶子又有 Bot"的关，所以这条分支**不可达** `[推断]`。
`mutual_wipe`（同时回合双方同时清场）**未观测** `[未知]`。

### 8.4 空放 / 走火

- **不判胜**，只消耗一个回合 `[推断]`（我们的实现 + 端到端实测；`Level 7` 上限 1 ⇒ 空放一发就是失败）。
- 打靶关失败时"胜方"取 Team2（靶子的队伍），语义上对，但**没有原版真帧** `[推断]`。
