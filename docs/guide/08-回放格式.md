# 08 · 回放：文件格式、怎么复现一局、怎么用语料

> **为什么攻略作者要读这一章**：回放是这款游戏**唯一**能被第三方复算的物证 ——
> 它记的是服务端广播的**完整事件流**（谁在哪一 tick 提交了什么函数、谁死了、地形长什么样）。
> 想统计"某个关卡的玩家都在哪一发射偏"、想验证"我这套打法是不是只在特定回合制下成立"，
> 都从这一章开始。
>
> **边界**：报文本身的形状（字段名、顺序、枚举取值）在 [`07-联机协议.md`](07-联机协议.md)，
> 回放和它**同构**，本章不重抄；回放里的 tick 语义在 [`06 §5`](06-时钟与回合推进.md)，也不重复。
> 本章**不做新的逆向**：结论来自 `src/` 静态读 + 已有文档 + 一次**冻结语料复算**（复算命令在 §6，可自行复跑）。

## 2. 容器与行格式

```text
user://replays/<unix 秒>             ← 文件名 = unix 秒，无扩展名
1f 8b 08 00 …                        ← gzip（RFC 1952）
<DEFLATE 正文>                       ← 解压后是 UTF-8 的 JSONL

{"event":{"AddObstacle":{"pos_x":2.9390,"pos_y":-2.8351,"radius":3.4329}},"tick":21592}
{"event":{"FunctionInfo":{"owner_id":635,"function":"(-0.35*(-11.40+x))","corrected_function":null}},"tick":21593}
{"event":{"FunctionFire":{"soldier_id":637}},"tick":21611}
```

| 事实 | 档 | 出处 |
|---|---|---|
| 写侧用 `flate2` 的 **`GzEncoder`**，一行一条记录；一行是**手写**拼出来的 JSON（不是 `serde_json::to_writer`） | `[逐位]` | `src/graphwar_game_recorder.rs:85,88`（`save_game` 的固定序列 + `flate2-1.0.30` 的 `panic::Location`） |
| 内层 `{"<事件名>":{…}}` 与**网络协议同一套名字/字段/顺序** ⇒ 解析可以复用同一个解析器 | `[逐位]`+`[观测]` | `src/graphwar_replay_player.rs:13`（`parse_message` 复用）；[`07 §3`](07-联机协议.md) |
| 一局的量级：**中位数 209 条**事件，最少 2 条、最多 **1471** 条（403 份快照统计） | `[观测]` | 本章 §6 复算 |
| 还有 **2 份空回放**（gzip 有效、正文 0 字节，各 20 字节） | `[观测]` | 本章 §6 复算；[`docs/archive/133 §2.2`](../archive/133-replay-player.md) 同现象 |
| **解析不了的行**：原版**跳过、不中断**（`Result` 被 drop 后回循环头）；我们的读层同口径 | `[逐位]` | [`docs/09 §12.3`](../09-network.md) 事实 #9；`src/graphwar_replay_reader.rs:39` |

> **一个容易踩的坑（`[观测]`）**：`FunctionInfo` 在玩家**打字过程中**就会不断广播，
> 所以"这一发实际用的函数"是**该次 `FunctionFire` 之前最后一条非空 `FunctionInfo`**，
> 绝不是"整局最后一条"。`tools/parse_replay.py --functions` 就是按这个口径取的。

## 4. 读侧：原版怎么读（读与播是两层）

**这条对写工具的人最重要：原版把"读文件"和"按时间播"拆在两个模块里**
（`[逐位]`，判据是"被调者清单"——见 [`docs/09 §12.3`](../09-network.md)）：

| 层 | 模块 | 干什么 | 碰文件 | 碰时钟 |
|---|---|---|---|---|
| 文件层 | `graphwar_replay_reader` | 列目录 → 读字节 → `flate2::gz::bufread::GzDecoder` **整份解成一个 String** → `StrSearcher` 拆行 → `serde_json` → `Vec<EventInfo>` | **是** | **不碰** |
| 播放层 | `graphwar_replay_player` | 拿 `Vec<EventInfo>` 按 `tick += floor(dt×60×speed)` 推进、还原局面 | 不碰 | **是** |

| 细节 | 档 | 出处 |
|---|---|---|
| 解压是**一次性整份**解成 `String`（不是流式） | `[逐位]` | arm64 `0x3da48c` + `0x3da4e4`（[`docs/09 §12.3`](../09-network.md)） |
| 拆行用 `str` 的 `StrSearcher`（即 `lines()`），**不是** `serde_json` 的流式反序列化器 | `[逐位]` | arm64 `0x3da628` |
| 每行反序列化成 `graphwar_game_recorder::EventInfo` ⇒ **写侧和读侧共用同一个结构体** | `[逐位]` | arm64 `0x3da714` |
| 我们的客户端不用内核的手写解压，而用 Godot 的 `PackedByteArray.decompress()`（`FileAccess.open_compressed()` **读不了裸 gzip**，它认的是 Godot 自己的 `GDPC` 容器） | `[观测]` | [`docs/archive/133 §2.5`](../archive/133-replay-player.md) |

## 5. 怎么用语料复现一局（给攻略作者的流程）

### 5.1 只用 Python 读（纯标准库，不需要编 Rust）

```bash
# 汇总一份回放：事件总数、tick 范围、每种事件多少条
python3 tools/parse_replay.py <replay 文件或目录>
# 只抽出"每回合真正开火用的函数"
python3 tools/parse_replay.py <目录> --functions
# 把整个语料的函数汇总成 JSON（做统计用）
python3 tools/parse_replay.py <目录> --corpus funcs.json
```

`[观测]`：`tools/parse_replay.py` 只依赖 `gzip/json/argparse`，事件名与字段名见 [`07 §3/§4`](07-联机协议.md)。

### 5.2 还原"某一发出手前的完整局面"（零依赖）

```bash
python3 tools/replay_state.py <replay> [--index N] > state.txt
```

输出是纯文本：`MODE` / `SHOOTER <id> <x> <y> <team>` / `FLIP` / `FUNC <函数文本>` /
`O <x> <y> <radius>`（障碍逐行）/ `S <id> <x> <y> <r> <team>`（士兵）/ `END`。
`[观测]`：口径与 Rust 侧局面还原**逐条一致**（`tools/replay_state.py` 的文档字符串 + `src/graphwar_replay_player.rs`）。

### 5.3 口径："哪些事件会改局面"

只有下面这些事件改局面，其余**只进事件流**（不猜副作用）——`[观测]`，
[`docs/archive/133 §3`](../archive/133-replay-player.md)（原文 400 份实测；现快照 **401 份**，2026-11-27 更正，与 `tools/replay_state.py` 逐条一致）：

| 事件 | 改什么 |
|---|---|
| `ClearObstacles` / `AddObstacle{pos_x,pos_y,radius}` | 障碍表（追加，半径是棋盘单位） |
| `DestroyObstacle{pos_x,pos_y,radius?}` | 记一个"洞"（**不移除**障碍数组；`radius` 缺省 0.5） |
| `PosInfo{entity_id,pos_x,pos_y,radius?}` | 实体位置（`radius` 缺省 0.5） |
| `TeamInfo{entity_id,team}` | `"Team1"` / `"Team2"`（**字符串，不是数字**） |
| `LifeInfo{entity_id,alive}` | 生死（**缺省视为活着**，这是 `[推断]`） |
| `FunctionInfo{owner_id,function,corrected_function}` | 函数槽（`function` 为空**不覆盖**上一条；`corrected_function` 为 `null` 单独记） |
| `FunctionPoints{owner_id,start_x,start_y,end_x}` | 记一次开火 + 那一刻的函数文本（**没有点序列**） |
| `FunctionActive{owner_id,active_tick}` | 激活 tick |
| `EffectInfo{…}` / `EntityEffectInfo{…}` | 特效记录 |
| `EntityRemoved{entity_id}` | 移除（**不删**位置/队伍表） |
| `GameStateInfo` / `TurnCountInfo` / `TurnInfo` / 四个 `*ModeInfo` / `GameNameInfo` | 状态机与房间参数 |
| `TargetInfo` / `SoldierInfo` / `PlayerInfo` / `NameInfo` / `ColorInfo` / 三个 `*GraphicsInfo` | 实体关系与外观（**两张全局表**：`NameInfo.entity_id→name`、`SoldierInfo.soldier_id→player_id`） |

## 6. 冻结语料：现状读数与纪律

**语料位置**：`.reference/replays/gw2-replays-snapshot/replays`（本机；gitignore 的外部参考件）。
**指纹**：`fixtures/guardrails.json` 的 `corpus` 记了 **403 份**文件的逐份 sha256 + 文件名集哈希
（`count: 403` / `replays: 401`）。同一文件里的 `axes` 就是 §5.4 那三组读数。

**本章复算（`[观测]`，纯标准库、只读快照、不写快照）**：

```bash
R=.reference/replays/gw2-replays-snapshot/replays
python3 - "$R" <<'PY'
import gzip,json,os,sys,collections,statistics
d=sys.argv[1]; kinds=collections.Counter(); per=[]; empty=[]; regress={}
for f in sorted(os.listdir(d)):
    raw=open(os.path.join(d,f),'rb').read()
    if raw[:2]!=b'\x1f\x8b': continue                     # MANIFEST.tsv / SHA256SUMS
    txt=gzip.decompress(raw); lines=[l for l in txt.split(b'\n') if l.strip()]
    if not lines: empty.append(f); continue
    per.append(len(lines)); prev=None
    for l in lines:
        o=json.loads(l)
        for k in o.get('event',{}): kinds[k]+=1
        t=o.get('tick')
        if prev is not None and t is not None and t<prev: regress[f]=regress.get(f,0)+1
        if t is not None: prev=t
print('回放份数(非空)',len(per),'空回放',len(empty),empty)
print('事件总数',sum(kinds.values()),'事件种类',len(kinds))
print('每份事件数 中位/最少/最多',statistics.median(per),min(per),max(per))
print('tick 回退的文件数',len(regress),regress)
PY
```

| 读数 | 值 | 备注 |
|---|---|---|
| 文件数 / 其中回放 | **403** / **401**（另 2 个是 `MANIFEST.tsv`、`SHA256SUMS`） | 与 `guardrails.json` 的 `count`/`replays` 一致 |
| 空回放（正文 0 字节） | **2**（`1782674520`、`1782761998`，各 20 字节） | `[观测]` |
| 事件总数 | **103 183** | `[观测]` |
| 每份回放事件数 | 中位 **209** / 最少 **2** / 最多 **1471** | `[观测]` |
