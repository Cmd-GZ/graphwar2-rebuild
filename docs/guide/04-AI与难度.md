## 0. 一句话

电脑玩家**不是**一个手写的瞄准算法，而是一个**遗传编程搜索器**：
每一回合，它根据"这一回合的射手是谁"，为**那个士兵**跑一次函数进化，
在 **25 秒墙钟预算内**把一条随机函数逐步搜索成"打得死人"的函数，然后把它当成本回合的开火函数 `[逐位]` + `[观测]`。

## 2. 战役里实际用的难度值（**有一个对不上的数，不圆**）

`bot_added_event`（tag 10）载荷第 3 个 u32 就是难度值，布局逐位解出：

```text
+0x00  u64  tag = 0x800000000000000a        (10 = bot_added_event)
+0x08  u32  a   （运行时算出的 player/team id）
+0x0c  u32  b   （运行时算出的 player/team id）
+0x10  u32  c   = 难度值（3/25/50/100/250）
```
`[逐位]`

| 关（`level_n`） | 静态难度值 | 运行时皮肤 | 与本文 §1 六档表能对上的是 |
|---|---|---|---|
| `level_5` | **3** | `bot_0` | 代数 3 = 档 1 |
| `level_9` | **25** | `bot_2` | 代数 25 = 档 3 |
| `level_11` | **50** | `bot_3` | **对不上**：六档表里代数/种群/`limit` 三列都没有 50 |
| `level_14` | **100** | `bot_3` | 代数 100 = 档 4 |
| `level_15` | **250** | `bot_4` | 代数 250 = 档 5 |
| `level_18` | **100** | `bot_3` | 代数 100 = 档 4 |
| `level_19` | **100** | `bot_3` | 代数 100 = 档 4 |
| `level_20` | **250** | `bot_4` | 代数 250 = 档 5 |

`[逐位]`（难度值是立即数）+ `[观测]`（皮肤由运行时给出）

**结论与反例**：**7/8 能对上"代数"列**，`level_11` 的 `50` **对不上任何一列** `[推断]`（缺 `new_bot` 消费者里那张表的用法）。
另两条相关事实：

- `bot_N` 皮肤与难度值**不同向**（`bot_3` 同时出现在 50 和 100）`[观测]`
- Bot **名字是随机的**：`level_15`/`level_20` 的 40/26 份回放里名字覆盖了 **9–10 个不同值**
  （`Alpha Zordon`/`Deep Blue`/`Skynet`/`Multivac`/`Deep Thought`/`HAL`/`Cleverbot`/`ChatGPT`/`Wolfram`/`Agent Smith`
  都出现过）`[观测]`

> **给攻略作者**：写"这关的 bot 有多强"时，**用难度值**（3/25/50/100/250），
> **不要用名字、不要用 `bot_N` 皮肤** —— 这两个都是随机的。也只能写"代数指标"这个口径，
> 因为 `50` 这个值本身还没有解释 `[未知]`。

## 3. 进化流程（每一代做什么）

```
s = 种群 / 5                        （50→10、100→20、150→30、200→40、250→50，即 20%）

对每个槽 i in 0..s:
    父代 = 上一代排序后的第 i 名
    产出 1 个精确克隆 + (5 − 1) = 4 个工厂子代      ← 字面量 5 = 每槽个体数
    ★ 这 4 个子代共用同一个父代

代末：5s 个个体全部重新粗评（step = 0.5） → 降序排序 → 截断只留前 s 个
      → 前 3 名各做一次精评（step = 0.01）→ 不一致则整条换成「随机函数 + 变异」并保留旧分数
```
`[逐位]`（`0x51b440` 变体 A；`docs/95`、`docs/AI.md` §5）

| 细节 | 结论 | 档位 |
|---|---|---|
| **"精英 5"存在吗** | **不存在固定 5 个**。精英 = 每代**前 20%**（`s = 种群/5`），下一代把这 `s` 个**全部克隆** | `[逐位]` |
| 那字面量 `5` 是什么 | `param_7 = 5` = **每个槽产几个个体**（1 克隆 + 4 工厂子代） | `[逐位]` |
| 有"两个父代"吗 | **没有**。工厂 `0x4ee3a0` 只有 3 个参数 `(out, &mode, &parent)` ⇒ 交叉是**从单个父代里取一棵完整子树** | `[逐位]`（签名级） |
| 每代评几次 | **`种群 + 3`** 次（粗评全部 + 前 3 精评），**无缓存**；克隆只复制 token 数组、不复制分数 | `[逐位]` + `[观测]`（运行时：每代恰好 `种群+3` 次评分，250 代全同） |
| 精评 step | **0.01**，每代**恰好 3 次**且固定是该代**最后 3 次** | `[观测]` |
| 粗评 step | **0.5**，只有 `0.5` 与 `0.01` 两种 step，**没有第三个值** | `[观测]` |
| "精评不一致"的判据 | `(hits_fine ≠ hits_coarse) ∨ (\|dist_fine − dist_coarse\| > 0.5)`。**比的是 `hits` 与 `dist` 两个字段，不是总分**；长度不参与；阈值 `0.5` 复用粗评步长那个 rodata 常量 | `[逐位]`（`docs/97`） |
| NaN 算一致吗 | **算**（`ucomisd` + `jbe`） | `[逐位]` |
| 精评写回分数吗 | **不写**。换新时只覆写 24 字节个体数据，**旧分数留着** ⇒ 最后交出去的最优个体可能挂着不属于它的分数（这是真行为） | `[逐位]` |
| 正好 3 名 | 硬编码（三段展开，没有循环常量） | `[逐位]` |
| 第 0 代从哪来 | **没有独立初始化函数**。空缓存时 `s` 个槽全部走随机分支：`0x4ef020`(随机函数) → `0x4ee0e0`(装配补齐) → `0x4ee720`(变异)。即"随机生成 + 补齐 + **再变异一次**"，且它是该槽 1 克隆 + 4 工厂子代的**共同父代** | `[逐位]`（`docs/110`） |

## 4. 适应度（它到底在优化什么）

```
score = hits * 2e6 − 1e6 − V*V/100 − (V > limit ? 5e7 : 0)
```
`[逐位]`（逐条反汇编，评分核心 vaddr `0x51a750`）

| 符号 | 含义 | 备注 |
|---|---|---|
| `hits` | 弹道命中的士兵数 | **不分敌我**。"友军惩罚"那一项在反汇编里**恒为 0**，是死代码 ⇒ **有友军误伤** |
| `V` | 函数的 token 个数 | |
| `limit` | 见 §1 表 | 超限只扣分，不过滤 |

**读法**：`hits*2e6 − 1e6` 意味着"**打中 1 个就 +1e6，一个不中就是 −1e6**"。
所以这套适应度**只看打没打中**，完全不管"打得漂不漂亮、函数复不复杂"——
复杂度只通过 `V*V/100` 这一项做很轻的惩罚（`V=10` 只扣 1，`V=100` 扣 100，
相对于 1e6 的量级可以忽略） `[推断]`（由公式量级直接读出）。

## 5. 它生成什么样的函数

### 5.1 token 权重表（总和 **85**）

| 项 | 权重 | 项 | 权重 | 项 | 权重 |
|---|---|---|---|---|---|
| 常数 | 11 | `/` | 7 | `abs` | 7 |
| 变量 | **10（见下）** | `^` | 2 | `sin` | 7 |
| `+` | 10 | `exp` | 6 | `cos` | 5 |
| `-` | 5 | `sqrt` | 1 | `tan` | 1 |
| `*` | 11 | `log` | 1 | `ln` | 1 |

`[逐位]` + `[观测]`（40 万次运行时抽样）

**变量槽随模式变化** `[逐位]`：

- `NormalFunction`（`y=f(x)`）：10 个权重**全给 `x`**；
- `DiffEqFunction`（`y'=f(x,y)`）：拆成 **`x` 6 个 + `y` 4 个**；
- **`y'`（tag 2）两种模式都不产生**。

实测占比 `[观测]`：Normal 下 `x` 11.92%、`y` 0%；DiffEq 下 `x` 6.83%、`y` 4.86%。
replay 交叉验证：Normal 局 100 发里含 `y` 的 **0%**；DiffEq 局 57 发 **42.1%**（预测 37%）。

### 5.2 随机函数的长度

```
n = (normal() * 5.0 + 10.0) as i32     // trunc 向零截断
```
`[逐位]` + `[观测]`（40 万次抽样）

- 均值约 **9.5**（截断不是四舍五入）；
- **两种函数模式共用同一条公式**；
- 长度为 0/1/负数时也会产生（退化表达式）。

### 5.3 装配 / 补齐规则（`FUN_005ee0e0`）

1. **截断**：用"还缺几个操作数"的计数器走一遍，走到 0 就截断；
2. **补齐**：还缺时按固定比例追加叶子 `[逐位]`：

| `rand % 50` | 概率 | 追加 |
|---|---|---|
| `< 25` | **50%** | 常数 `normal() * 10.2` |
| `25..41` | **34%** | `x` |
| `42..49` | **16%** | `tag = mode & 1`（Normal 下仍是 `x`，DiffEq 下是 `y`） |

### 5.4 变异

- 常数：`c *= (1 + normal())`，或重新采样；
- `y` / `x` / 运算符：包成 `(op const v)`。
`[逐位]`

### 5.5 RNG 粒度

每次 token 抽样**只消耗一个 u32**（`0x4ef193` 从 ChaCha 输出块里按 4 字节步长取字），
权重表是 `rand % 85` `[逐位]`。
**种子来自 OS 熵（`/dev/urandom`）** ⇒ 即使粒度对齐也**无法与真游戏对种** `[观测]`。

## 6. 时间预算：墙钟 25 秒

```
每一代开始前检查一次 clock_gettime(CLOCK_MONOTONIC) 的 elapsed
终止条件 = 「代数到顶」∨「elapsed > 25 s」取先到
两者共用同一个出口 ⇒ 调用方（乃至 replay 文件）无法得知是否被截断
```
`[逐位]`（`0x51b7cf cmp $0x19,%rax` + `0x51b7d5 test %edx,%edx`；秒表 `0x8f5bf0` 包 `clock_gettime`）

| 事实 | 结论 | 档位 |
|---|---|---|
| 常量 | **立即数 25 秒**，六档共用、**不是配置** | `[逐位]` |
| 变体 B 同构 | `0x51d398 cmp $0x19` | `[逐位]` |
| 回合时限参与吗 | **不参与**。AI 调用链三级包装上没有任何取时间；`Timer30s/1m/…` 是 tick，只决定回合何时结束 | `[逐位]` |
| 难度 6（1000 代 × 250）跑得完吗 | **取决于机器与负载**。同一次运行里出现过：`25.007 s` 截断在第 461 代（116380 次评分）、`13.4 s` 跑满 1000 代（253000 次评分）、`20.2 s` 跑满、`25.0 s` 截断在第 214 代 | `[观测]` |
| 难度 ≤ 5 | 稳定跑满（`63250 = 250 × 253` 次评分） | `[观测]` |

> **对攻略的意义**：这一条属于"**本质上不由输入决定**"（B 类）——同一关同一次运行都可能给出不同结果。
> 所以"这关的 bot 会打出什么"**不可能**写成确定答案 `[推断]`。

## 8. AI 的已知"行为特征"（写攻略时真正用得上的部分）

### 8.1 它提交什么样的函数（真实抓包）

在 harness 里驱动一局、抓协议侧的 `FunctionUpdateRequest` `[观测]`：

```
{"FunctionUpdateRequest":{"player_id":232,"function":"sin(x)"}}
{"FunctionUpdateRequest":{"player_id":232,"function":"0.00"}}
{"FunctionUpdateRequest":{"player_id":232,"function":"(-1.06*x)"}}
{"FunctionUpdateRequest":{"player_id":232,"function":"(-23.81*x)"}}
```

⇒ **多数是过原点的线性函数 `k*x`**，系数带两位小数 `[观测]`。
这与机制一致：过原点意味着 `f(0)=0`，加上修正常数 `c = y0 − f(x0)` 后，
**直线会穿过射手自身位置**，只需再选一个斜率就能扫过目标 `[推断]`。

另一局（高难度 `level:25`）提交过 `tan(sin((-0.12*x)))`、`abs((-3.49+x))`
——明显是搜索出来的 `[观测]`。

### 8.2 它会算"瞄准"吗

**未验证**：斜率/偏移是否由目标位置算出（这会决定 `computer_player_manager` 的瞄准规则）`[未知]`。
这不是"没查"，而是**没有可用的真值**（玩家函数注入没打通，拿不到"同一局面下 AI 选了哪个"的对照）。

### 8.3 它不选射手

射手由回合系统轮转决定，**AI 只是被喂"这回合的射手是谁"** `[观测]`（见 [`01`](01-对局规则.md) §3）。
AI 每回合只为**当前那个士兵**跑一次进化，写进**那个士兵自己的**函数槽。

### 8.4 它对友军的态度

适应度里 `hits` **不分敌我**、友军惩罚项是死代码 ⇒ **它没有理由避开自己人** `[逐位]`。
实际影响：如果你的士兵站在它弹道经过的地方，它照样打 `[推断]`（由机制推出，无实测）。
