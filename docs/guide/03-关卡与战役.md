**散布式的实际数量**（生成公式见 [`02`](02-函数与弹道.md) §9.3）`[逐位]`：

```
n = trunc( normal() * 7.0 + 15.0 )     # 均值 15、标准差 7
if n <= min_count: n = min_count
```
⇒ **`min_count` 是下界，不是定值**。运行时硬证据 `[观测]`（关号按上面那张表的**左列**，1 基）：

> `level_7`「≥ 6 颗」；`level_5`/`level_9`/`level_11`/`level_14`「≥ 5 颗」。

## 5. 解锁与存档

### 5.1 `user://campaign.save` 格式（**逐位要求，写错就归零**）

| 项 | 值 | 档位 |
|---|---|---|
| 路径常量 | `.rodata 0x1bfe28`，长度 `0x14` = 20 字节 = `"user://campaign.save"` | `[逐位]` |
| 编码 | **纯文本**，`FileAccess` + `store_string`（**不是** `store_var` / `ConfigFile` / JSON / 二进制） | `[逐位]` |
| 字段 | **只有一个**：形如 `level_<n>` 的字符串 | `[观测]` |
| 读法 | 整文件读成 `String` → `split('_')` 取**最后一段** → `parse::<u32>()` | `[逐位]`（`0x417ef0`，标准库 `split` + `FromStr` 内联） |
| 写路径 | **只增不减**：新值 **>** 旧值才写，否则直接返回不动文件 | `[逐位]`（`0x4183b0`：`cmp ebp, edx` / `jbe` 直接返回） |
| 行尾 | **必须没有任何字节**（没有 `\n`、没有空格） | `[逐位]` + `[观测]` |
| 语义 | **最后通关的那一关**（0 基下标） | `[观测]`（用户实测：打完第 1 关写的是 `level_0`，不是 `level_1`） |
| 0 基还是 1 基 | **0 基**（字符串本身就是 `level_0`…`level_20`） | `[逐位]` |

> ⚠️ **用户实测的坑（值得写进攻略的"存档修改"一节）**：
> `echo 'level_20' > campaign.save` 会写进去 **9 字节**（多一个 `\n`），
> 结果是 **已通关进度显示 0**。原因：`str::parse::<u32>()` **不会跳过空白**，
> `"20\n"` 解析失败 ⇒ 取默认 0。正确的文件必须是 **8 字节**、`level_20`、**无行尾** `[观测]`（`docs/118` 附录 A）。

**解锁规则**：文件里就一个 `level_<n>`，代表"到第 n 关为止都解锁"，没有每关通关次数 / 星级 / 最高分 `[观测]`。
"`level_n` = 可以点开第 n 关"这一条是 `[推断]`：已证"文件只存这一个数 + 写入单调 + 写完后用 `n+1` 去调按钮刷新"，
**未证** `0x418820` 到底把按钮改成什么样（`disabled=false`？换图？）`[推断]`。

## 6. 目标"打不全就全部复原"（这一节决定单发关怎么打）

**规则**（有真机样本）：一关里 **≥2 个靶子**时，

```
一发只打掉其中一部分（打掉 ≥1 个，但没全清） ⇒ 回合末**整组靶子复活**
                                              （死掉的那个 + 本来就没死的那个，都重播 alive:true）
                                              但这一发**照样消耗一个回合**
一发全清                                      ⇒ **不复原**，直接进结算（游戏结束）
一个都没打掉                                   ⇒ 没有靶子需要翻回（报文会不会也整组重播一遍：`[未知]`，见 §6.3）
```

```text
报文层面你会看到：打掉的那个 → alive:false →（停一下，实测 67 / 74 / 101 tick）
                → 整组靶子重播 alive:true（含没死的那个）→ 2 tick 后进入下一回合
```
（`alive:false` / `alive:true` 在**画面上**怎么表现没有原版真帧，见 §6.3 `[未知]`）

证据：**两把针对性真机录制**，其中第二把**同一份 replay 里同时含正例与反例**
（`docs/06` §34b；冻结语料为什么做不到，见本节 6.2 末）。

### 6.1 形状部分（复原长什么样）

| 结论 | 依据 | 档位 |
|---|---|---|
| 复原**不是**重建实体：不新分配 id、不发 `TargetInfo`、不发 `EntityRemoved` | 造目标的 `0x46f310` **只有 13 个调用点，全在关卡开场**；109 份含目标的回放里目标**从未**被 `EntityRemoved` | `[逐位]` + `[观测]` |
| 复原表现为 **`LifeInfo{alive:true}`**，而且是**整组广播**——死掉的那个与**本来就没死的那个都收到一次** | 结构上目标只有 `TargetInfo`(23) 与 `LifeInfo`(27) 两种状态事件，分派器 `0x3e2830` 的 70 个分支里**没有一处**构造 `life_info`；运行时：两把真机样本里 `232`/`537` 这两个"没死的靶子"都被重播 `alive:true`，**2/2 发**（`docs/06` §34b.2） | `[逐位]` + `[观测]` |
| 复原**不碰掩膜**（障碍的洞留着） | 掩膜整局只建一次，`ClearObstacles` 397 份回放里中途出现 **0 次** | `[观测]` |
| 目标整局**不移动、不重生、不计时** | `PosInfo` 只在开场与开局快照出现，之后再没有新的位置事件 | `[观测]` |
| 复原**不发任何特效事件**（连火花都没有） | 复原路径只写存活位、不构造任何特效载荷 | `[推断]`（负面证据：`docs/150` §7 #4。真机时间线只筛了 `LifeInfo` 与状态事件，**不能**当成"没有特效"的证明） |

### 6.2 判定点、判据与时序（`[逐位]` + `[观测]`）

```
本发把靶子清空              → 不复原（全部达成，直接结算）
本发一个都没打掉            → 不复原（没有靶子需要翻回）
否则（回合末还有靶子活着）  → 把**全部**靶子翻回 alive（不是只复原这一发打掉的）
```

| 机制 | 证据档 + 出处 |
|---|---|
| 判定时刻 = **回合末**（不是"这次射击结算完"，也不是"下一次开火前"），且**早于**下一回合的开始 | `[逐位]`（`docs/150` §4：先发 `TurnCountInfo`，判定在其后）+ `[观测]`（`docs/06` §34b.2：`alive:true` 之后 **2** tick 才进 `WaitingForFunctions`） |
| 判据 = "**至少一个靶子还活着**" ⇒ 把**全部**靶子翻回 alive | `[逐位]`（`docs/150` §4 的循环）+ `[观测]`（两把里 3 次"部分命中"全部整组复原） |
| 复原 = 只把存活位写回 `true`，**不**新建实体、**不**发 `TargetInfo` | `[逐位]`（同上；与 §6.1 一致） |
| 游戏**已经结束**时不会复原；靶子**全部**已死时什么都不做 | `[逐位]`（同上） |
| 复原还要**过一道关卡位**：`cmpb $0x1,0x11d(%rbx)`，只有该字节为 `1` 的关卡才走这段 | `[逐位]`（`0x475a91`；**哪些关是 `1` 见 §6.5**） |

#### 时序：两把真机 replay、4 发（3 次部分命中 + 1 次全清）的逐 tick 时间线（`docs/06` §34b.2）

| 样本 | 死亡报文 → 整组 `alive:true` | 之后 |
|---|---|---|
| `1794176948`（靶 `232`/`233`，打掉 1 个） | `3889` `233 false` → **`3990`** `232 true` + `233 true`（间隔 **101** tick） | `3992` 进下一回合（+**2** tick） |
| `1794177110` 第 1 发（靶 `537`/`538`） | `1414` `538 false` → **`1481`** 整组 `true`（间隔 **67** tick） | 随后进下一回合（这一发没逐 tick 列出，原文见 `docs/06` §34b.2） |
| `1794177110` 第 2 发 | `2512` `537 false` → **`2586`** 整组 `true`（间隔 **74** tick） | 同上 |
| `1794177110` 第 3 发（**全清**） | `8286` `537 false`、`8413` `538 false` → **后面没有任何 `true`** | `8479` `EndingGame` |

- 三个间隔 **67 / 74 / 101** 互不相同 `[观测]` ⇒ 这个延迟**不是固定常量**，它等于"结算阶段还要走多久"，
  而那个时长本身是 `[未知]`（[`01`](01-对局规则.md) §9 #3）。**tick 也不是 60 Hz 墙钟**（[`README`](README.md) §4），
  所以不要把它换算成秒写进攻略。
- 第 1 个样本把顺序钉死了：复原（`3990`）**先于**下一回合开始（`3992`）⇒ 这一发是一个**正经回合**，
  不会被白送 `[观测]`。
- **为什么以前没有语料**：冻结语料 **397 份回放、0 次部分命中**——多目标关
  （`level_3/6/8/10/13/17`）里"打到了东西"的射击共 **7 次，7 次全部一次打掉全部目标** `[观测]`。
  本节的两把是**针对性补录**（不在冻结快照里），所以"语料里没有"和"游戏里没有"是两件事。

### 6.3 现在还剩哪些未知

| 问题 | 状态 |
|---|---|
| "全部复原"还是"只复原本发打掉的" | ✅ **已解：全部** `[逐位]`（`docs/150` §4）+ `[观测]`（`docs/06` §34b.2） |
| 复原会不会重置回合计数 | `[未知]`。能看到的是"复原之后确实进了下一回合" `[观测]`；那个计数器是 `+1` 还是被复原吞掉，报文里看不出来 |
| 复原有没有视觉效果（火花/闪烁） | `[推断]`：复原路径只写存活位、**不发任何特效事件** ⇒ 至少**没有** `EntityEffectInfo`（`docs/150` §7 #4，负面证据）；原版真帧仍缺 |
| 哪几关打开这道关卡位（`self[+0x11d]`） | `[未知]`，见 §6.5：判据本身 `[逐位]`，但**没有任何指令写这个字节** |

### 6.4 一个**我们做了选择**的地方（攻略需注明）

`docs/123` 建议过用一个逐关布尔量 `all_in_one_shot`（只有描述里写了 "in a single shot" 的
`level_6/8/10/13/17` 五关为真）。**我们的实现没有采用逐关开关，而是对所有打靶关通用**。

- 代价：`level_3`（3 个靶子、10 回合、2 个射手，描述**没写** single shot）从"分次能打完"变成"必须一发全清"。
  而这一条**与原版是否一致仍未证实**：判据里那道关卡位（§6.5）说明原版**确实**是逐关开关，
  所以"通用"这个口径对 `level_3` 大概率是错的 `[推断]` —— 缺的是 `level_3` 的一次"部分命中"样本。
- 好处：用户口述是一条**通用**规则；而且如果允许分次打完，`level_3` 的 10 回合就变成了宽松计时器。

### 6.5 哪些关会复原：`self[+0x11d]` 这道关卡位

复原那一段代码**不是无条件执行**的，前面有一句判断：

```asm
475a91  cmp BYTE PTR [rbx+0x11d],1
475a98  jne 475d7e            ; 不是 1 就整段跳过（不复原）
```
`[逐位]`（`docs/150` §4.2；`docs/16-client.md` 在 arm64 侧读到同一句，`0x4abc80-0x4abc94`）

| 问题 | 现状 |
|---|---|
| 这个字节是**逐关配置**的开关吗 | **是**（一个按关卡配的布尔位置，处在 `GameStateManager` 自己身上）`[推断]`（强：判据读的就是它，`==1` 才复原） |
| 是哪几关打开 | `[未知]`。**全库 `+0x11d` 的访问一共 10 处**，其中 `0x475a91` 是唯一与本结构相关的读，**没有任何一条指令写它** ⇒ 只能是被整块结构拷贝写进去，静态侧追不到（`docs/151` §2.6 把这条负结论做实了） |
| 那为什么说"只有单发关" | **描述原文**：21 关里明写 "in a single shot" 的正好 5 关 —— `level_6` / `level_8` / `level_10` / `level_13` / `level_17` `[逐位]`（§4.1 原文）。而这 5 关**正好就是**多靶子关里除 `level_3` 之外的全部 ⇒ 开关的方向与"一发全清模式"一致 `[推断]` |
| 那两把真机样本是哪几关 | 第二把"一炮清掉两个靶子 ⇒ 立刻 `EndingGame`"说明**这关总共就 2 个靶子**；21 关里正好 2 靶的是 `level_6/10/13/17`，**全是单发关** `[推断]`（强：由 §2 主表 + 胜负规则推出）。也就是说本轮拿到的正例与反例都出现在单发关上，**没有** `level_3` 的样本 |
| 那 `level_3` 呢 | **推断不会复原**：它是唯一"多靶子 + 描述不提 single shot"的关（描述讲的是"每回合换一个士兵"）。**缺的证据**：`level_3` 的一次"打掉 1~2 个靶子然后停手"的样本；以及关卡表里那个字节的写入点 |

**攻略含义**（`[推断]`，理由见上表）：

- 单发关（`level_6/8/10/13/17`）里，**打不全不会让你当场输**——靶子会整组回来，
  你损失的是**一个回合**（这几关的回合上限是 **6 / 6 / 6 / 5 / 6**，见 §2 主表）。
  所以"先随便打一发给下一发挖洞/试形状"在这些关里是**有代价但可行**的。
- `level_3`（10 回合、3 靶、2 射手）如果原版**不**复原，那它就是"分次清靶"的关；
  我们目前的实现要求一发全清，比原版可能更严（§6.4）。

## 8. 写"关卡攻略"时可以直接抄的结论 vs 不能抄的

| 可以直接写（有硬证据） | 不能写（没有证据 / 每局不同） |
|---|---|
| 这关有几个士兵、几个靶子、有没有 Bot、难度值多少、回合上限多少 | "靶子在这个位置" / "障碍摆成这个样子" |
| 这关的网格密度、是不是同时回合、是不是微分方程模式 | "敌人会先往左走"（Bot 行为细节见 [`04`](04-AI与难度.md)） |
| 障碍数量下界与半径分布 | "这关有 17 颗障碍" |
| 左上角 / 存档文件的确切格式 | "通关后解锁下一关的动画"（`[未知]`） |
| "打靶关 = 一发全清，否则复原"，且**复原只发生在单发关**（`level_3` 是否也会复原仍是 `[推断]`，§6.5） | "复原发生在第 N tick"这个**绝对**值（取决于本局，`[未知]`）—— 能写的是相对量：**死亡报文后 67 / 74 / 101 tick 复原，再 2 tick 进下一回合** `[观测]` |
