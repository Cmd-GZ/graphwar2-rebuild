# 05 · 武器与技巧：从机制推出来的战术结论

> ## ⚠️ 本章的证据等级与其它章**不同**
>
> **本章几乎每一条都是 `[推断]`。**
> 它们是从 [`01`](01-对局规则.md) / [`02`](02-函数与弹道.md) / [`03`](03-关卡与战役.md)
> 里那些 `[逐位]` / `[观测]` 的机制**推**出来的，**没有一条经过实战对局验证**。
>
> 换句话说：**"游戏机制是这样"有证据；"所以你应该这样打"没有。**
> 我们没有任何一局"用人写的函数打败某个 bot"的对照实验，也没有胜率数据。
> 谁要把本章内容写进攻略，请自己标成"推论"或做实测升级。
>
> 反过来说，本章**不写**任何机制层面没有依据的东西——
> 比如"这样打能骗过 bot 的瞄准"这类话，机制上**根本没有"瞄准"这一环可以骗**（见 §8）。

## 1. 三条硬机制，所有技巧都从它们来

| # | 机制（有证据） | 档位 | 直接后果（推断） |
|---|---|---|---|
| A | **曲线必定穿过射手本人**：射击用的是 `f(x) + c`，其中 `c = y0 − f(±x0)` | `[逐位]` | 你**无法**写一条"不从自己位置出发"的曲线；所有函数的起点都是固定的 |
| B | **弹道单调前进、不能掉头**：内部 x 只从 `x` 增到 `x + step` | `[逐位]` | 函数必须是**单值** `y=f(x)`，且只能朝一个方向铺开；"回头打"不存在 |
| C | **士兵/靶子不挡弹道**，只有障碍挡；一个士兵一回合只死一次 | `[逐位]` + `[观测]` | **一发可以打穿一列人**，穿过后继续飞；这是多杀的全部基础 |

补充两条同样是机制级的量：

| 量 | 值 | 档位 |
|---|---|---|
| 弧长预算 | `20000 点 × 0.01 = 200` 游戏单位 | `[逐位]`（两个常量）+ `[推断]`（"200 弧长"是等价说法） |
| 棋盘 | `x ∈ [-25, 25]`、`y ∈ [-15, 15]`，越界**入列前**检查 | `[逐位]` |

## 2. 常数函数 = 水平线（最强的一发，也是所有攻略的起点）

```
f(x) = 0   ⇒   c = y0 − 0 = y0   ⇒   实际射击 y = y0
```

⇒ **写 `0`（或 `5-5` 之类）就是一条从射手出发、保持射手高度、向右无限延伸的水平线** `[推断]`（由 A 直接推出）

为什么它是最强的基线：

| 理由 | 依据（机制） |
|---|---|
| 起点就是射手位置，**必然命中射手这一行上的任何东西** | A `[逐位]` |
| 弧长消耗最小（≈ 45 单位就横穿全场，预算 200） | `[逐位]` |
| **不会因为太陡而出界**：`y` 恒为 `y0`，永远碰不到 `\|y\| > 15` | `[逐位]` |
| 穿人不停 ⇒ **敌方一列人全死** | C `[观测]` |

**这条被显式用作测试夹具**：我们的端到端验证就是用 `f(x)="0"` 把靶子打进/打出
（`docs/131` §5.2），说明"水平线穿过 `(x, y0)`"这件事在实现里是精确成立的 `[观测]`。

> ⚠️ 但**原版没有"打到就停"**，所以水平线会**继续飞**：
> 如果射手身后（或前方）有自己人站在同一高度，**也会被打死**——友军误伤是真的 `[观测]`。
> 同时回合里，水平线还可能打到"同一 tick 里另一个射手" `[观测]`。

### 2.1 线性函数的射程（这条能直接算）

`y = kx` 加上修正后变成 `y = k(x − x0) + y0`。它会在

```
Δx = (15 − y0) / |k|        （向上出界）
Δx = (15 + y0) / |k|        （向下出界）
```

之后被 `|y| > 15` 截断 `[推断]`（由 A + 边界规则推出）。

- 要在 `y0 ≈ 0` 的情况下横穿 30 单位，需要 **`|k| ≲ 0.5`**；
- 抓包里出现的 `(-23.81*x)` 这种斜率，在 `Δx ≈ 0.6` 之后就出界了——
  **它只对"贴着射手 x 位置的敌人"有用** `[推断]`。

⇒ **"斜率越大越猛"是错的；斜率大 = 射程短。** 这条与"弧长预算"是同一件事的两面。

## 3. 弧长预算：为什么"摆动的函数"打不远

- 每 0.01 弦长消耗 1 个点，预算 **20000 点** ⇒ **总弧长 ≈ 200 单位** `[逐位]` + `[推断]`
- 棋盘横穿一次只要 **50** 单位，所以**平直**的弹道能飞 4 个来回；但
- 一个 `sin(kx)` 的弧长 ≈ `∫sqrt(1 + k²cos²) dx`，`k` 越大越接近 `k·Δx`
  ⇒ 振幅大 + 频率高的函数**在几单位 x 内就把 200 单位花光** `[推断]`

| 写法 | 弧长（`Δx` 段内） | 结果 |
|---|---|---|
| `0`（水平线） | 恰好 `Δx` | 打满全场 `[推断]` |
| `kx` | 恰好 `Δx·sqrt(1+k²)` | `k` 稍大就"既费弧长又很快出界" `[推断]` |
| 振幅 `A`、在 `Δx` 内摆 `m` 个来回 | 每个来回 ≈ `4A`（上 `2A`、下 `2A`）⇒ 总 ≈ `4·m·A` | **走不远**（"`sin(100x)` 跑不远"就是这个原因）`[推断]` |
| 大振幅锯齿/尖刺 | 每个齿 ≈ `2×振幅` | 齿越多越费 `[推断]` |

⇒ **想让弹道"走得远"，就得让它"少拐弯"。**

## 4. 陡峭与不连续：100 次二分不收敛 = 子弹消失

采样器对每个新点做**最多 100 次**二分来满足"弦长 = 0.01"，容差 `0.001` `[逐位]`。
不收敛 ⇒ **整条曲线到此结束**（不裁剪、不留坏点）`[逐位]`。

⇒ **在函数不连续 / 斜率趋于无穷的地方，弹道会直接断掉** `[推断]`。

| 写法 | 采样器的下场 | 建议 |
|---|---|---|
| 阶跃（`x>0 ? 5 : 0` 类写法，虽然语言里没有三元） | 在不连续点附近弦长永远压不到 0.01 ⇒ 断 | 用**陡但连续**的近似（如大斜率 sigmoid、`atan` 缩放）`[推断]` |
| `sqrt(x)` 在 `x=0` 附近 | 导数无穷 ⇒ 容易不收敛 | 平移让起点离开奇异点 `[推断]` |
| `tan(x)` 在 `π/2` 附近 | 同上，且会突然越界 | 避开极点 `[推断]` |

> **这条不是缺陷，是游戏本来的规则** `[观测]`（`docs/106` §5：四种终止原因在 GW1/GW2 都成立）。
> 我们的实现曾把它误触发 2300 倍（漏写半步复检），修好后 82 发零漏报 `[观测]`。

## 5. NaN / ±inf：不是"打偏"，是这一发直接报废

> ⚠️ **本节 2026-11 更正**：原写「`log`/`ln` 的判据是 `v <= 0` → NaN」——**那是反的**。
> 实测 `±0` 给 `-inf`、负数才给 NaN（机制与逐位证据见 [`02-函数与弹道.md`](02-函数与弹道.md) §5）。

**先记住一条几何**：式子里的 `x` 是**内部横坐标**，两支队伍的射手都站在**负数**上，
弹道在内部坐标里递增、在**棋盘中线**过 0 `[逐位]`（`flip` 定义）+ `[观测]`（773 个站位 0 例外；
推导见 [`02`](02-函数与弹道.md) §5.3）。

| 危险写法 | 什么时候出事 | 后果 | 档位 |
|---|---|---|---|
| `sqrt(x)`、`log(x)`、`x^0.5` | **第一格**（射手自己的内部 x < 0） | 整发只剩起点 = 白扔一个回合 | `[推断]` |
| `1/x`、`log(abs(x))` | 接近**中线**（内部 x → 0）时 | 停在**中线附近**（先撞 `\|y\|>15`，或弦长成 `inf` 让二分空转） | `[推断]` |
| `sqrt(abs(x))`、`log(abs(x)+1)` | 不会（恒有定义 / 恒正） | 安全 | `[逐位]` |

⇒ **凡是在自己脚下无定义的写法都不能用**，这跟"敌方半场"没关系；
要绕开就把自变量抬进定义域（`abs` / `+1`）。

**为什么值得单开一节**：这一发的损失不是"偏几格"，而是**整个回合** ——
`Level 7` 只有 1 个回合，一发哑弹就判负（[`01`](01-对局规则.md) §7）`[逐位]`。
真实对局里确实会这样：**1291 条**修正常数里 **30 条**不是有限数（`[观测]`，`docs/06` §26.6）。

**别指望"故意写 NaN"当战术**：要让 `c` 恰好是 NaN，得让 `f` 在自己站位上**精确**发散 ——
真实样本里相邻 **1 ulp** 就从 `NaN` 翻回 `1.0`（`[观测]`，`docs/06` §42.2），玩家控制不了。

## 6. 多杀：把敌人"对到同一条曲线上"

机制 C（穿过不停、一回合只死一次）意味着：**一条曲线经过 k 个人，就死 k 个人** `[观测]`。
所以多杀的关键是**让目标共线（共曲线）**，而不是"打得准"。

| 场景 | 做法（推断） |
|---|---|
| 敌人排在一条水平线上 | 水平线（`0`）一发全清 |
| 敌人排成一条斜线 | 线性函数 `y = kx`，`k` 由两个目标算出来 |
| 目标分散在不同高度 | 用**低频**曲线（`sin(x/5)`、多项式）串起来；频率越高越费弧长 |
| 打靶关要求"一发全清" | 见 [`03`](03-关卡与战役.md) §6：**部分命中会全部复原**（这条本身是 `[推断]`） |

> ⚠️ **反面**：友军也在这条曲线上 —— 我方士兵在 `x < 0`、敌方在 `x > 0`，
> 而弹道从射手出发**先经过我方半场**。所以**水平线首先扫的是自己人** `[推断]`。
> 多士兵关（我方 2~5 人）里，`0` 这条水平线有相当概率先打死队友 `[推断]`。

## 7. 绕墙：代价是弧长，不是"精度"

- 掩膜只有障碍，命中的是**像素位图** `[逐位]`；
- 命中后只在命中点挖 **`r=0.5`** 的洞，**洞不恢复** `[观测]`；
- 所以要"打穿一堵墙"，需要**同一位置连打几发**? —— **不行**：洞半径只有 0.5，
  而后续弹道必须严格穿过这个 0.5 的圆才不撞墙 `[推断]`。

⇒ **实用打法只有"绕"**：

| 手法 | 代价（推断） |
|---|---|
| 从障碍上方/下方绕 | 曲线必须在障碍处让开至少一个半径 `r`，于是那一段的**斜率上升、弧长增加**；`r` 越大代价越大 |
| 用高频抖动"擦边" | 弧长爆炸，且容易在不收敛处断掉 |
| 贴着棋盘边界走 | `|y|` 逼近 15 时余量很小，一抖就出界 |

**散布关（≥ 10~15 颗、半径多为 0.8~8）的难度来源就是"弧长预算被障碍吃掉了"** `[推断]`。

## 8. 对 bot 的战术（**全部是推断，且"骗瞄准"这条路不存在**）

先破一个常见的攻略套路：**没有"bot 的瞄准"可以骗**。
机制上 bot 每一回合都是**现场跑一次进化搜索**（25 s 墙钟内），
它不读你的位置去算角度——它靠**大量随机函数的适应度**挑一个能打中人的 `[逐位]`（见 [`04`](04-AI与难度.md)）。

| 说法 | 机制上的实际情况 | 档位 |
|---|---|---|
| "走位躲 bot" | 游戏里没有移动指令；士兵位置在开局公布后不再有位置事件 | `[观测]`（120 局 773 条 `PosInfo` ≈ 每局每实体一条，全部来自开场；**没有**单独验证"整局不动"的对照实验） |
| "让 bot 打不中" | 它搜索的是"打中任何人"（`hits` **不分敌我**），**包括它自己的队友** | `[逐位]` |
| "bot 会避开自己人" | **不会**。友军惩罚项是死代码 | `[逐位]` |
| "bot 的函数永远是直线" | 多数是过原点的 `k*x`，但也会出现 `tan(sin(...))` 这种 | `[观测]`（抓包样本） |
| "高难度 bot 一定更强" | 代数/种群/`limit` 更大是事实，但**25 s 墙钟可能截断**，且结果**不可预测** | `[逐位]` + `[观测]` |

**可以推断的三条**（依旧没有实测）：

1. **bot 的直线也穿过它自己**（同一条修正规则 A）⇒ 它的水平线/直线会**先扫它自己的半场** `[推断]`。
   所以"我方士兵站在它那一行上"是危险的；反过来，"它自己人站在它那一行上"它也会打死 `[推断]`。
2. **同时回合关（`level_11`/`level_14`）里双方可以互杀** `[观测]`（已有互杀样本）
   ⇒ 这两关的"先手"没有意义，比的是"谁能一发清场"。
3. **多士兵关（我方 2~5 人）里，射手轮转 ⇒ 每回合的出发点不同** `[观测]`
   ⇒ 预先算好的"一条万能曲线"不存在；必须按当前射手的 `(x0, y0)` 现场调 `c`（游戏自动算 `c`，你只需调形状）`[推断]`。

## 9. 逐关的战术要点（参数见 [`03`](03-关卡与战役.md) §2）

| 关 | 硬约束 | 战术含义（推断） |
|---|---|---|
| `level_0` | 无障碍、1 靶、无上限 | 训练关：`0` 一发即可（靶子在射手那一行） |
| `level_1` | 上限 **5** | 5 次机会，可以试错调形状 |
| `level_2` / `level_3` / `level_12` | **中心单障碍**（原点，`r ∈ [3,8)`） | 障碍正好挡在"从负 x 到正 x"的中线上 ⇒ **必须绕**（直线会撞） |
| `level_3` | **2 个士兵、3 个靶子、上限 10** | 三靶 + 两射手；描述**没写**"一发全清"⇒ 是否要求一发全清 `[未知]` |
| `level_4` | 散布 **≥ 15** | 墙最密的一关 |
| `level_6` / `level_8` / `level_10` / `level_13` / `level_17` | 多靶 + 描述明写 **"in a single shot"** | **必须一发全清**（部分命中会复原）`[推断]` |
| `level_7` | 目标 1、**上限 1** | **只有一次机会**；空放也算用完 `[推断]` |
| `level_5` / `level_9` / `level_11` / `level_14` / `level_15` / `level_18` / `level_19` / `level_20` | 对战关，**无回合上限** | 没有"打不完"这回事，只有"被打光"；比的是谁先清场 `[推断]` |
| `level_11` / `level_14` | **同时回合** | 双方同 tick 出手、可互杀（见 [`01`](01-对局规则.md) §2.3） |
| `level_15` / `level_20` | **无网格**（`a=0`） | 没有任何参照线，纯靠脑内坐标；机制上**不影响判定** `[未知]`（无证据表明网格参与判定） |
| `level_16`…`level_20` | **微分方程模式** | 写的是 `y' = f(x, y)`，**没有修正常数**，初值 = 射手位置；`y` 变量**真的可用**（权重表里 `y` 有 4 份）`[逐位]` |

## 10. 微分方程模式的写法（`level_16`…`level_20`）

| 事实 | 结论 | 档位 |
|---|---|---|
| 输入含义 | `dy/dx = f(x, y)`，一阶，**RK4 积分**，`h = step` | `[逐位]` |
| 初值 | 射手位置（所以**不需要**修正常数，`offset` 恒 `NaN`，界面那行字是空的） | `[逐位]` |
| `y'` 变量 | 仍然恒 0（第三个变量在全部 7 个求值点都传 0） | `[逐位]` |
| `y` 变量 | **可用**（普通模式里恒 0，微分方程模式里是当前高度） | `[逐位]` |
| 同样的 `f(x)` 与普通模式的结果 | **不同**：普通模式是直接图像，ODE 模式是积分曲线 | `[逐位]` |
| ODE 模式有"半步复检"吗 | **没有**（`0x3c2840` 在容差满足时直接接受） | `[逐位]` |

**可以推断的写法**（无实测）：

- `y' = 0` ⇒ 水平线（与普通模式的 `0` 等价）`[推断]`
- `y' = k` ⇒ 斜率 `k` 的直线，但 **`y` 会累积**，所以和普通模式 `kx` 的形状相同、**起点保证在射手上** `[推断]`
- `y' = c*y`（指数增长）⇒ 立刻撞上下边界 `[推断]`
- 想"贴地飞"可以用 `y' = -a*y` 把曲线拉回 `y=0`：这是一种**自动回中**的写法，
  普通模式做不到（普通模式的曲线形状与 `y0` 无关，只是整体平移）`[推断]`

## 11. 哪些流传的说法**没有**证据（别写进攻略）

| 说法 | 实际 |
|---|---|
| "子弹会在敌人身上停下" | **不会**，穿过继续飞 `[观测]` |
| "打中会扣血" | **没有血量系统**，只有活/死 `[观测]` |
| "射手不会打死自己，所以可以放心贴脸" | 只对**自己那一发**免疫；别人的那一发照样打死你 `[观测]` |
| "受伤的士兵更弱" | 不存在"受伤" `[观测]` |
| "网格线会影响弹道/命中" | 无任何证据 `[未知]` |
| "`y'` 可以在普通模式里用" | 恒 0 `[逐位]` |
| "子弹可以向左掉头" | 不能掉头；但**方向本来就可以向左**（敌方那一侧）`[逐位]` |
| "sin^2(x) 是 sin 的平方" | 解析成 `sin(空)^2 * x` = `0` `[逐位]` |
| "线上有聊天指令（`-skip` 之类）" | GW2 **完全没有聊天指令** `[观测]`（`docs/106` §2） |

## 12. 怎么把本章的 `[推断]` 升级成 `[观测]`

本章所有结论都停在同一道门槛前：**没有对照实验**。要升级只需要一种实验：

1. **玩家函数注入**：让 harness 在真游戏里提交**指定**的函数文本（这条路**没打通**，`docs/06` §15.3）；
2. 然后跑同一局面 N 次，比较"预期的弹道/死亡集合"与实际报文。

在打通之前，本章的价值是：**它把"该验什么"写清楚了**——
每一条 `[推断]` 都对应一个可判定的预测（弹道停在哪、谁死、剩多少点），
不是含糊的"这样打比较好"。
