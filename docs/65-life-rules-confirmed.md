# 65 · 生命/伤害规则：三项结论（证据来源：用户游戏内实测）

## 1. 三项问题的结论

> **证据来源说明**：这三条来自**用户在真游戏里的实际操作观察**，
> 不是我方仪器抓到的报文。我方仪器尝试见 §3——受限于"打不中队友"，没拿到样本。
> 两个来源相互印证：我们的实现（`src/settle.rs`）本来就与这三条一致。

| 问题 | 结论 |
|---|---|
| 是否存在血量？ | **没有。碰到即死**（无血条、无掉血过程） |
| 友军是否致死？ | **会**（有友军误伤） |
| 一发多杀的结算顺序？ | **按弹道先后**（子弹有飞行速度，先后命中，不是同时消失） |

用户另补充：士兵不会出现在同一位置；GW2 有相当部分逻辑源自 GW1。

## 2. 与我们的实现对照

| 结论 | `src/settle.rs` / `src/game.rs` 的做法 | 一致？ |
|---|---|---|
| 无血量 | 只有 `killed: Vec<i64>`，命中即加入 | ✅ |
| 友军致死 | `Match::fire` 只排除**射手本人**（同位置的判等），队友照常参与判定 | ✅ |
| 按先后顺序 | `killed` 在遍历弹道点时**按经过顺序**推入 | ✅ |

新增测试 `friendly_fire_kills_teammates_in_path_order`：
射手在 `(-10,0)`、队友在 `(-2,0)`、敌人在 `(5,0)`，开一发水平直线，断言：

```rust
assert_eq!(killed, vec![2, 3]);   // 先队友(2)、后敌人(3)，射手自己不受影响
assert_eq!(m.soldiers.len(), 1);  // 两人都被移除
```

**通过**。这条测试同时固定了"友军致死"和"按先后顺序"两件事。

## 3. 我方仪器化尝试（未拿到样本）

| 尝试 | 结果 |
|---|---|
| 3 局数据挖掘（随机 AI） | 3~4 发/局、2 次死亡、**0 次友军误伤**、0 次一发多杀 |
| 让 harness 的探针持续开火（12 种函数，2.5 分钟） | 12 发、1 次死亡、0 次友军误伤 |
| 改为斜率扫描（`x/5, x/2, x, 2x, -x/5, …`） | 3 发、2 次死亡、0 次友军误伤 |

**为什么拿不到**：2v2 对局打死两人就全灭（`EndingGame`），每次只有 2~4 发；
而机器人的函数是**瞄准敌人**的，永远不会打自己人。要制造友军误伤必须
**精确瞄准队友**，而这需要"屏幕坐标 → 士兵实体"的映射——我们把场景节点 dump 出来了
（`EntityDrawer` 下都是 `@Sprite2D`，有位置），但**没有实体 id/队伍信息**，
所以还无法选定"哪个 sprite 是队友"。

## 4. 对复刻的影响

- `life_manager` 的行为模型**不需要改**：现有实现已经符合这三条；
- 之前标 🔶 的"血量/友军规则未知"现在**已确定**，且与实现一致；
- 仍然未知的只有一处：**同一 tick 内多人死亡时，`LifeQueuedDeath` 的 `tick` 值是否相同**
  （用户说"先后命中"，但那是视觉上的先后，报文里的 `tick` 我们还没观测到多杀样本）。
