## 3. 已知矛盾：素材之间打架的地方（**矛盾台账**）

### 3.1 已知矛盾（**素材之间打架的地方，以及本手册怎么裁的**）

裁定原则：**以更硬的证据为准**（逐位 > 观测 > 推断 > 未知）；
同等硬度时以**样本数多、能指到地址**的一方为准；无法裁定的写成"两条并存 + 缺什么"。

#### 3.1.1 #1 胜负条件：一条判据还是两条判据？（**这是最实质的一处**）

| 说法 | 出处 | 原文档档位 |
|---|---|---|
| **A**：胜利 = **Team2 全灭**（原文明写"**不是**目标数归零"） | `15-target-life.md` §5.1 #1 | 观测（45/45 回放）+ 逐位（`0x46f310` 发 `TeamInfo{Team2}`） |
| **B**：胜负**按关卡类型分开**——打靶关 = 靶子全清、对战关 = 对方全灭 | `10-campaign.md` §2.1、`docs/INDEX.md` 第 133 行 | 观测 + 逐位（并称"两者在原版里等价"） |

**裁定：采用 A 作为"原版行为"，把 B 当作"我们客户端实现的写法"。**
理由：

1. A 的证据是**原版二进制的行为 + 45/45 份原版回放**；B 的证据是**我们自己客户端的规则层**
   （`client/src/game/level_rules.gd`），而 `client/` 是照 `.tscn` 与截图重写的仿制品，
   **流程/时序没有原版证据**（`gw2-rebuild/AGENTS.md` §0 第 4 条）。
2. 两条判据在**原版**里确实等价（靶子属于 Team2，Team2 空了 = 靶子清空了）；
   但在**我们的客户端**里**不等价**——`10-campaign.md` §3 自己写明"我们的客户端**没有给靶子分配队伍**"。
   ⇒ 这正是"等价性被打破"的地方，也是两处表述会打架的根因。

**影响手册的哪些条目**：[`01 §8`](guide/01-对局规则.md)、[`03 §6`](guide/03-关卡与战役.md)、
[`03 §7.1 #1`](guide/03-关卡与战役.md)。手册的写法是：**先给原版那一条（Team2 全灭），
再给"按关卡类型分开"这张表并标明它是我们的实现口径。**

**还缺什么**：原版在"打靶关 + 回合上限"这一组合下的真值（见 #2）。

#### 3.1.7 #7 Bot 难度值 `50`「对不上六档表」→ **已结案：不是对不上，六档表本来就不是映射表**（2026-11-27 改判）

> **原裁定（留档）**："**不圆**。手册写'7/8 能对上，`level_11` 的 `50` 对不上' `[推断]`，
> 并规定攻略里只能用难度值这个口径，不许把 `50` 说成'某档'。"
> 这个裁定立在一个错误前提上：**把"六档表"当成了"难度值 → 参数"的映射表**。

**现结论（逐位，T61 复核）**：真映射是**两层**——
① **难度值直接当"代数"**；② **种群 / `limit` 按难度值落进哪个区间分档**。
分档指令在 `bot_added_event` 分支 `0x3e3d75`：`0x3e3d78 mov r14d,[rbx+0x10]` 取难度值，
`0x3e3da0/0x3e3daf/0x3e3db9/0x3e456d/0x3e458d` 五处 `cmp`/`jb` 把难度值分成
`<4 / 4–10 / 11–25 / 26–100 / 101–250 / ≥251` 六段，`0x3e45c4 mov edx,r14d` 把**难度值本身**
当第 3 个实参传给建表函数 `0x478fc0`。
⇒ **`50` 落在 `26–100` 段 = 代数 50 / 种群 200 / `limit` 15**（`0x3e4573 mov ecx,0x28` ⇒ 种群 `40×5=200`；
`0x3e4578 mov r9d,0xf` ⇒ `limit` 15）。`src` 侧同一消费者：`graphwar_function_evolutionator::difficulty_params(50)`
（`src/graphwar_function_evolutionator.rs:342`，`:356` 把 `difficulty` 填进 `generations`）。
六档表 = 这套区间映射在 **6 个采样点**（3/10/25/100/250/1000）上的取值（`docs/147` §2.4）
⇒ "六档里没有 50"只说明 50 不是采样点。

**仍然成立的两条反证**（原裁定附带，结论不变）：`bot_N` 皮肤与难度值**不同向**
（`bot_3` 同时出现在 50 与 100）；Bot **名字是随机的**（同一关 9–10 个不同名字）⇒ 名字和皮肤都不能当难度用。

**手册侧**：[`guide/04`](guide/04-AI与难度.md) §2 已改成"难度值 = 代数 + 区间分档"，
`guide/bot-行为说明` §5 本来就是对的。

### 8.2 判定线（这是可复算的，不是拍脑袋）

判据全文在 `tools/guide_marker_triage.py` 文件头，**`--self-test` 是 6 条正对照（3 T + 3 O）+ 5 条负对照**，

### 10.2 三条的判据（复核时我实际跑的东西）

1. **`-x^2`**：真解析器 `0x4ed670` 给 `5,8,0,17:C(2)`（`NEG POW VAR_X CONST(2)`）、真求值器 `0x4eb9d0` 在 `x=3` 给 **`-9.0`**（`0xc022000000000000`）；
   **同时直调 `(-x)^2`** 得 `8,5,0,17:C(2)`、`x=3` → **`+9.0`**（`0x4022000000000000`）⇒ 两种写法是**两棵不同的表达式**，旧结论把内外写反了
   （同一行前半句"负号比 `^` 松"本来是对的，所以这行一直**自相矛盾**，`docs/03` §3 在 2026-11-08 就已改成 `-(x^2)`）。
2. **`sin^2(x)`**：真 tag 流 `6,8,14,17:C(2),0` 按前缀序还原 = `MUL(POW(SIN(CONST 2), VAR_X), ␀)` ⇒ 人类写法 `sin(2)^x * ␀`。
   原文错在两处：`sin` 吃的是 `^` **后面的** primary `2`（不是"空"）；`x` 落在 `^` 的右操作数（不是 `*` 的右操作数）。
   另补边界：`x=NaN` → `NaN`（`0·NaN`），`x=0/1/3/−2/1e300` → 全 `0.0`；`sin(x)^2` 在 `x=3` 是 `0.0223…` ⇒ 确认不是 `sin(x)^2`。
3. **「常量折叠」**：见 10.3 —— 这条是本轮最值得留下的一条。

**我方侧对照**（不是档位依据，只是确认手册描述的是我们也在跑的东西）：`parse` 的 tag 流 + `CONST` 位型 **12/12 与真侧相同**、
`eval` 的 f64 位型 **9/9 与 7/7 相同**（`examples/bitexact_harness` 对同一组输入）。

### 10.3 第 ③ 条：手册**错在地址与位置，没错在现象** —— 折叠真存在，只是不在解析器里

- **解析期没有折叠**（真解析器 tag 流）：`1+2*3-4/5^6` → 11 个 token、`+ − * / ^` 一个没少；`2*3+1` → `3,6,C(2),C(3),C(1)`；
  `1+2+3` / `2*3` / `2+3` / `sqrt(4)+sqrt(9)` / `2^3^2` 同样不折。⇒ 手册那句"解析后有一趟折叠"**错**。
- **`0x4eb830` 不是折叠器**：它是 `MathFunction::remove_offset`（FDE `0x4eb830..0x4eb920`，2 个双向唯一 `panic::Location` 锚 = `src/math_function.rs:52:43`/`:53:43`；
  Windows 侧同一函数）。直调读数：`[ADD,VAR_X,C(3)]`→`[VAR_X]`、`[SUB,ADD,VAR_X,C(3),C(1)]`→`[VAR_X]`、`[ADD,SIN,VAR_X,C(3)]`→`[SIN,VAR_X]`、
  `[MUL,VAR_X,C(3)]` 不动 ⇒ **剥掉最外层的 `± CONST` 偏移**，全程**没有把算出的 f64 写成 CONST 的写点**。
  `call rel32` = 0；唯一引用是重定位槽 `0x9bc250` 的使用点 `0x51d312`（在 `calculate_functions_old` 里，且能被 `0x51d2fc cmp byte [rax+0x5c],0` 跳过）。
- **折叠确实存在**：**`0x4ebbe0`**（FDE `0x4ebbe0..0x4ec154`，`panic::Location` = `src/math_function.rs:184:24`；名字预测 `MathFunction::simplify_recursive`，**[推断]**）。
  直调读数：`[MUL,C(2),C(3)]`→**`[CONST(6.0)]`**、`[ADD,C(1),MUL,C(2),C(3)]`→**`[CONST(7.0)]`**（正是手册那句 `2*3+1`）、
  `[SIN,C(2)]`→`[CONST(0.9092974268256817)]`、`[POW,C(2),C(10)]`→`[CONST(1024.0)]`；含变量的原样保留。
  指令级：两个子结果都必须是 `CONST`（`0x4ebdbf`/`0x4ebdca` 两处 `cmp dword […],0x11`）→ `0x4ebde3 call 0x4eb920`（per-tag 常量算子分派）→
  `0x4ebe11 mov qword [rax+rcx],0x11` 写回 `CONST`。
- **它只在 AI 进化路径里跑**：`0x4ebbe0` 的 `call rel32` 共 7 处 = 3 处自递归 + **4 处外部**：`0x51b993`/`0x51bdd7`（在 `calculate_functions` `0x51b440`）、
  `0x51d3c5`/`0x51e564`（在 `calculate_functions_old` `0x51d080`）⇒ 解析器不调它。
- ⇒ **对攻略读者的结论**：玩家写的 `2*3+1` **不会**被折成 `7`；对局里 `f(x)` 文本、求值、弹道都不受影响。折叠只发生在 AI 评估候选函数串时。

### 10.4 我方 `src/` 侧：**没有多实现折叠**（不是"做多了"的复原错误），而是**少实现两个原版函数**
