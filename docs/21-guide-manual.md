# 21 · 攻略向行为手册（`docs/guide/`）的元文档与矛盾台账

> **本篇解决什么问题**：`docs/guide/` 那本手册里**每一条是从哪来的、有多硬、
> 哪些地方我们其实不知道、素材之间哪里打架**；另外登记 GW1 指南的条目在 GW2 是否仍成立。
>
> ⚠️ **边界（先读，否则会高估整本手册）**：写这本手册的过程**没有重新逆向任何东西**：
> 所有数字与结论都是**转引**仓库里已有的文档，并保留它们在原文档里的证据档位。因此
> **如果某条源结论本身是错的，手册会跟着错**。手册的价值在于"按游戏怎么运作重组 +
> 逐条标档 + 把矛盾摆出来"，**不在于新增证据**。

## 3. 已知矛盾：素材之间打架的地方（**矛盾台账**）

### 3.1 已知矛盾（**素材之间打架的地方，以及本手册怎么裁的**）

裁定原则：**以更硬的证据为准**（逐位 > 观测 > 推断 > 未知）；
同等硬度时以**样本数多、能指到地址**的一方为准；无法裁定的写成"两条并存 + 缺什么"。

#### 3.1.1 #1 胜负条件：一条判据还是两条判据？（**这是最实质的一处**）

| 说法 | 出处 | 原文档档位 |
|---|---|---|
| **A**：胜利 = **Team2 全灭**（原文明写"**不是**目标数归零"） | `15-target-life.md` §5.1 #1 | 观测（45/45 回放）+ 逐位（`0x46f310` 发 `TeamInfo{Team2}`） |
| **B**：胜负**按关卡类型分开**——打靶关 = 靶子全清、对战关 = 对方全灭 | `10-campaign.md` §2.1、`docs/INDEX.md` 第 133 行 | 观测 + 逐位（并称"两者在原版里等价"） |

**裁定：采用 A 作为"原版行为"，把 B 当作"我们客户端实现的写法"。**
理由：

1. A 的证据是**原版二进制的行为 + 45/45 份原版回放**；B 的证据是**我们自己客户端的规则层**
   （`client/src/game/level_rules.gd`），而 `client/` 是照 `.tscn` 与截图重写的仿制品，
   **流程/时序没有原版证据**（`gw2-rebuild/AGENTS.md` §0 第 4 条）。
2. 两条判据在**原版**里确实等价（靶子属于 Team2，Team2 空了 = 靶子清空了）；
   但在**我们的客户端**里**不等价**——`10-campaign.md` §3 自己写明"我们的客户端**没有给靶子分配队伍**"。
   ⇒ 这正是"等价性被打破"的地方，也是两处表述会打架的根因。

**影响手册的哪些条目**：[`01 §8`](guide/01-对局规则.md)、[`03 §6`](guide/03-关卡与战役.md)、
[`03 §7.1 #1`](guide/03-关卡与战役.md)。手册的写法是：**先给原版那一条（Team2 全灭），
再给"按关卡类型分开"这张表并标明它是我们的实现口径。**

**还缺什么**：原版在"打靶关 + 回合上限"这一组合下的真值（见 #2）。

#### 3.1.3 #3 弹道能不能向左？

| 说法 | 出处 | 原文档档位 |
|---|---|---|
| **A**："子弹只沿 `+x` 前进，**不能向左**" | `21-guide-manual.md` §1（对账 GW1 指南时写的） | 该文标 ✅ |
| **B**：Team2 `flip=true`，**向左（−x）开火**；实测 97 发向左 | `10-campaign.md` §1 | 观测（497 发的方向分布） |

**裁定：采用 B；A 的措辞是错的（它想说的是"不能掉头"）。**
理由：`04-path-sampling.md` 的采样器里有 `px = flip ? -mid : mid` 与 `x = flip ? -x0 : x0` 两个分支，
这是**逐位**的结构；`10-campaign.md` 有 97 发向左的样本。A 把"单侧（我方视角）"写成了"全体"。

**手册的写法**：`"弹道单调前进、不能掉头"（[逐位]）` + `"方向由队伍决定，Team2 朝 −x"（[观测]）`。
见 [`02 §8`](guide/02-函数与弹道.md)。

#### 3.1.7 #7 Bot 难度值 `50` 对不上六档表（**未解决，保持未知**）

- `level_11` 的难度值是 **50**（立即数，逐位）；`docs/AI.md` 六档表里代数/种群/`limit` **三列都没有 50**。
- 其余 7 个对手关的难度值（3/25/100/250）**都能对上"代数"列**。

**裁定：不圆。** 手册写"7/8 能对上，`level_11` 的 `50` 对不上" `[推断]`，
并规定**攻略里只能用难度值这个口径**，不许把 `50` 说成"某档"。
另附两条反证：`bot_N` 皮肤与难度值**不同向**（`bot_3` 同时出现在 50 与 100）；
Bot **名字是随机的**（同一关 9–10 个不同名字）⇒ 名字和皮肤都不能当难度用。

#### 3.1.8 #8 `campaign.save` 存的是"最高进度"还是"最后通关关"？

| 说法 | 出处 |
|---|---|
| "字段 = 已保存的**最高进度**" | `10-campaign.md` §3.1 的表格 |
| "存的是**最后通关的那一关**（0 基）：打完第 1 关写 `level_0`，不是 `level_1`" | `10-campaign.md` 附录 A（用户实测）+ `README` 工作包表 |
| "`level_n` = **到第 n 关为止都解锁**（推断）" | `10-campaign.md` §5.1 / §5.3 |

**裁定：三种说法兼容，但必须按下面的顺序读**：
① 文件里**只有一个** `level_<n>`（逐位）；② `n` = **最后通关的关卡下标**（观测：打完第 1 关写 `level_0`）；
③ 因此"到第 n 关为止都解锁"是**由此推出的**（推断，缺 `0x418820` 到底改哪个 UI 属性的证据）。
⇒ 手册写"最后通关的那一关（0 基）"，并明确"解锁的 UI 表现是推断"。
**"最高进度"这个措辞容易读成"最高解锁"**，是歧义源。
