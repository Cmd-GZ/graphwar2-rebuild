# 67 · AI 的参数表：代数 × (种群 + 3)

## 1. 反编译 AI 核心（`FUN_0061b440`，虚地址 `0x51b440`）

签名与结构（Ghidra）：

```c
void FUN_0061b440(..., int param_4, int param_5, uint param_6, int param_7, ...)
...
  iStack_70 = param_7 - 1;
  do {                                   // 外层：代数
      ... for (uVar13 = 0; uVar13 != uStack_e8; uVar13++) {   // 内层：种群
              FUN_0061a750(0x3fe0000000000000, ...);          // 评分，步长 0.5
          }
      // 每代结束：对**前 3 名**再用步长 0.01 复评
      FUN_0061a750(0x3f847ae147ae147b, ...);   // 第 1 名
      FUN_0061a750(0x3f847ae147ae147b, ...);   // 第 2 名
      FUN_0061a750(0x3f847ae147ae147b, ...);   // 第 3 名
  } while (iStack_6c != local_a0);        // local_a0 = param_5
```

- `param_5` = 外层循环次数 = **代数**
- `param_6` = 内层循环次数 = **种群**
- 步长常数：`0x3fe0000000000000` = `0.5`、`0x3f847ae147ae147b` = **`0.01`**
- 所以每代评估次数 = 种群 + 3（前三名精评一次）

⇒ **每回合评估次数 = 代数 × (种群 + 3)**

## 2. 实测验证（六个难度）

用 `tools/hook_ai_counts.js` 统计 `score`（`0x51a750`）的调用次数，
每回合的增量在低难度下**完全一致**（说明是固定预算，不是时间驱动）：

| 难度 | 每回合评估 | 分解 | 代数 | 种群 |
|---|---|---|---|---|
| 1 | **159** | 3 × 53 | 3 | 50 |
| 2 | **1030** | 10 × 103 | 10 | 100 |
| 3 | **3825** | 25 × 153 | 25 | 150 |
| 4 | **20300** | 100 × 203 | 100 | 200 |
| 5 | **63250** | 250 × 253 | 250 | 250 |
| 6 | 217580（单样本） | 860 × 253 | ? | ? |

前五个难度**全部精确整除**，与"代数 × (种群+3)"的模型一致，
且种群按 50 递增（50/100/150/200/250）、代数按 3/10/25/100/250 递增。

### 难度 6：**不是时间截断，是提前结束**（修正）

先看关键对照：难度 1 与难度 3 在**无限时**下复测，评估次数与默认时**完全一致**
（159 / 3825）⇒ 低难度是**固定预算**，与时间无关。

难度 6 的实测值：

| 条件 | 评估数 | ÷253 | 说明 |
|---|---|---|---|
| `Timer1m` | 217580 | 860 | 整数代 |
| 无限时（200s 窗口） | 234278 | 926 | 整数代 |
| 无限时（更长） | 两次入口间 545 代，总 1472 代 | — | 整数代 |

用户明确说明：**这一局把回合时间设成了无限**。所以"被回合时限截断"这个解释**不成立**。

剩下的解释是 **提前结束**：每次评估数都是 `253` 的**整数倍**（整代数），
只是代数不同 ⇒ AI 在满足某个条件时提前跳出循环。
最可能的条件是"**已经找到能打死人的解**"——这同时解释了为什么
低难度（找不到击杀解）总是跑满固定代数，而高难度忽快忽慢。

**待验证**：若能在高难度下记录"AI 提前结束的那些回合是否都打死了人"，
即可证实或否证这个假设（GW1 的循环里**没有**提前退出，所以这是 GW2 的新增行为）。

## 3. 与 GW1 的关系

| 项 | GW1（源码 `../graphwar`） | GW2（本轮） |
|---|---|---|
| 等级 → 代数 | `numGenerations = level` | 代数 3/10/25/100/250 由难度决定 |
| 种群 | 固定 50 | **随难度变**：50/100/150/200/250 |
| 精英/变异/交叉 | 5 / 25 / 20（和为 50） | **未测**（可按同法统计父代来源） |
| 适应度 | `±2e6 命中 + (1e6 − minDist²)` | `命中×2e6 − minDist²/100 − (步数超限?5e7:0)` |
| 评分步长 | 固定 | 粗评 `0.5` + 前 3 名精评 `0.01` |

⇒ **同源，但 GW2 把参数做成了随难度递增的表**，并加了精评与步数惩罚。

## 4. 复现

```bash
# 需要 harness 能起真游戏
GW2_BOT_OPT=3 timeout 220 node tools/hook_ai_counts.js
# 输出里 "每回合 score 增量" 应为 3825
```

`GW2_BOT_OPT` 取 1..6，对应弹窗里的六个难度（`docs` 里附有节点路径映射）。
