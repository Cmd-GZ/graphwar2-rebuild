## 2. 两个曾经搞错的解释（留作教训）

**① "难度 6 被回合时限截断"——错。**
用户确认那局把回合时间设成**无限**；而且用户录屏显示三次 AI 求值分别耗时
25.1 秒 / 21.4 秒 / 25.1 秒，**基本一致**，正是固定预算的表现。

**② "提前结束（找到击杀就停）"——错。**
用户提供的截图里，AI 那一发**没有把敌人打完**，求值照样正常结束。
所以不存在"达成条件提前退出"。

**真正原因**：我自己 hook 了 `0x51a750`（每次评分都拦一次），
在难度 6 上要拦 25 万次，**instrumentation 把游戏拖慢到跑不完**，
于是测到的 217580 / 234278 都是被我截断的。
⇒ 教训：用 hook 计数做性能相关结论前，必须先确认 hook 自身开销不改变被测行为。

## 3. 与 GW1 的关系

| 项 | GW1（源码 `../graphwar`） | GW2（本轮） |
|---|---|---|
| 等级 → 代数 | `numGenerations = level` | 代数 3/10/25/100/250 由难度决定 |
| 种群 | 固定 50 | **随难度变**：50/100/150/200/250 |
| 精英/变异/交叉 | 5 / 25 / 20（和为 50） | **未测**（可按同法统计父代来源） |
| 适应度 | `±2e6 命中 + (1e6 − minDist²)` | `命中×2e6 − minDist²/100 − (步数超限?5e7:0)` |
| 评分步长 | 固定 | 粗评 `0.5` + 前 3 名精评 `0.01` |

⇒ **同源，但 GW2 把参数做成了随难度递增的表**，并加了精评与步数惩罚。

## 4. 复现

```bash
# 需要 harness 能起真游戏
GW2_BOT_OPT=3 timeout 220 node tools/hook_ai_counts.js
# 输出里 "每回合 score 增量" 应为 3825
```

`GW2_BOT_OPT` 取 1..6，对应弹窗里的六个难度（`docs` 里附有节点路径映射）。
