# 95 · "精英 5"在 GW2 里存在吗？（静态结论：不存在固定 5 个）

状态：结论性。回答 `docs/AI.md` §8 的第一条未解项。全部为**静态**证据
（REA/Ghidra 12.1.4 反编译 + GNU objdump 2.47），本轮**没有**做新的运行时实验
（运行时数据一律转引 `archive/ai/67`、`archive/ai/74`、`archive/ai/75`，并在表里分开标注）。

地址约定同全仓：**Ghidra 地址 = ELF vaddr + 0x100000**。本文两个都给，形如
`vaddr 0x51b829 / Ghidra 0x61b829`。objdump 输出是 vaddr。

## 0. 结论（一段话）

**GW2 没有"每代固定保留 5 个精英"这回事。** 精英是**按比例**留的：

```
每代：评 5s 个个体  →  按分数降序排序  →  截断只留前 s 个  →  下一代把这 s 个全部克隆
      （s = 种群/5）        （s = 种群/5 = 20%）
```

`s` 是参数（10/20/30/40/50），**不是常量**；代码里唯一的字面量"5"是另一个参数
`param_7 = 5`，语义是**"每个槽位产几个个体"**（1 个克隆 + 4 个工厂子代）。
`archive/ai/67` 里那个"栈首 = 精英数 = 5"就是它，标签错了。

于是三种候选里：**(a) 部分成立**——没有"精英 5"这个量；
**(b) 不成立**——没有 `const 5` 当精英数；
**(c) 部分成立**——"5"确实以**比例分母**的形式存在：精英率 = `1/param_7` = **20%**，
且 种群 = `s × 5`。GW1 的"5 个精英"在 GW2 里被换成了"保留 1/5"。

## 2. 每代流程（逐段地址）

### 2.1 槽循环：`s` 次，每次"1 个克隆，否则随机重生"

```asm
51b78f: mov  0xd0(%rsp),%r15        ; r15 = s
51b829: cmp  %r14,%r12              ; r14 = 槽号, r12 = 上一代存活数(= s)
51b82c: jbe  51b900                 ; 槽号 >= 存活数 → 走"随机函数"分支
51b832: lea  (%r14,%r14,2),%rax
51b836: shl  $0x4,%rax              ; rax = 槽号 × 48（个体 48 字节）
51b83a: mov  0xb8(%rsp),%rsi        ; 上一代个体数组基址
51b845: mov  0x10(%rsi,%rax,1),%r14 ; token 数
51b874: mov  0x8(%rsi,%rax,1),%rsi  ; token 指针
51b8c5: call *0x9ba638              ; memcpy  ← 深拷贝 = 克隆
51b8fa: jmp  51b961                 ; 落到"评分 + 追加"
...
51b900: 随机分支
51b90f: call 0x4ef020               ; makeRandomFunction
51b923: call 0x4ee0e0               ; 构造/收拾
51b95c: call 0x4ee720               ; 变异
...
51bda1: inc  %r14
51bda4: cmp  %r15,%r14
51bda7: jne  51b829                 ; 槽循环（每代 s 次）
```

克隆**按槽号递增**取 `prev[0], prev[1], …`（`archive/ai/75` 运行时看到的就是这个 `[0,1,2,…]`
序列），而 `prev` 是上一代**排好序并截断后的前 s 名**（§2.5/§2.6）⇒ **克隆的就是前 20%**。

### 2.2 每个个体都要打分（粗评 0.5）

```asm
51bc8b: movq 0x19f6d0(%rip),%xmm0   ; = 0.5  （粗评步长）
51bc93: call 0x51a750               ; 评分核心（Ghidra 0x61a750）
...
51c0c1: movq 0x19f6d0(%rip),%xmm0   ; = 0.5
51c0c9: call 0x51a750               ; 工厂子代那一份（同一循环体被复制成两块）
```

⇒ 每代 `5s` 次粗评 + 3 次精评 = **种群 + 3**，与 `archive/ai/67` 实测的
"每回合 = 代数 × (种群+3)"逐档吻合。

### 2.3 工厂子代：每个槽再来 `param_7 − 1` 次

```asm
51b77f: mov  0x1c0(%rsp),%eax       ; eax = param_7（第 7 个实参 = 栈上第一个）
51b786: dec  %eax
51b788: mov  %eax,0x148(%rsp)       ; 记住 param_7-1
...
51b961: mov  0x1c0(%rsp),%eax
51b968: test %eax,%eax
51b96a: je   51bd80                 ; param_7 == 0 时该槽不产子代
...
51bd5f: mov  0x148(%rsp),%ebx       ; ebx = param_7-1
51bd66: mov  0x1c0(%rsp),%eax
51bd6d: cmp  $0x1,%eax
51bd70: jne  51bdb2                 ; param_7 != 1 → 进工厂循环
...
51be93: call *0x9bc288              ; GOT → Ghidra 0x5ee3a0 = FUN_005ee3a0（子代工厂）
51c19c: dec  %ebx
51c19e: jne  51bdb2                 ; 重复 param_7-1 次
51c1a4: jmp  51bd80                 ; 下一个槽
```

工厂**本身**再按父代长度分"变异 / 重生 / 交叉+变异"（`AI.md` §5，本轮未重验）。

⇒ **每个槽 = 1 个克隆 + (param_7−1) 个工厂子代 = param_7 个个体。**
`param_7 = 5` 时：每代 `s + 4s = 5s = 种群`，其中克隆 `s` = **20%**、工厂 `4s` = **80%**。
**这就是"0.2×种群克隆 / 0.8×种群工厂"的来源**——两条比例都只是 `1/5` 和 `4/5`。

### 2.4 工厂子代超长时的修补（用到 `limit`）

```asm
51be99: mov  0x50(%rsp),%rax        ; rax = ctx（param_2）
51be9e: mov  0x58(%rax),%eax        ; eax = ctx->limit
51bea6: cmp  %rax,%r14              ; r14 = 子代 token 数
51bea9: jbe  51bf3c                 ; len <= limit → 不修补
```

### 2.5 代末排序（**新增直接证据**）

```asm
51c1e2: cmp  $0x2,%rsi
51c1e6: jae  51cb6f                 ; 元素 >= 2 才排序
51cb6f: cmp  $0x15,%rsi
51cb73: jae  51cb91                 ; >= 21 个 → 归并排序
51cb7f: call 0x41b500               ; 否则 → 插入排序 FUN_0051b500
51cb96: call *0x9bbdc0              ; GOT → Ghidra 0x5605f0 / vaddr 0x4605f0（Rust sort_by）
                                    ;   内核 0x481140，比较器用个体 +0x18 的 f64
```

比较器：插入排序版 `FUN_0051b500`（vaddr `0x41b500`）里是

```asm
; 伪代码（Ghidra）
dVar3 = puVar17[3];                 // 新元素分数 = 结构 +0x18 的 double
if ((double)puVar17[-3] < dVar3) {  // 前一个更小
    do { 整体右移; dVar4 = 再前一个的分数; } while (dVar4 < dVar3);
}
```

即**降序**（大分数在前）；NaN 走 panic（`src/graphwar/function_evolutionary…`）。
归并版内核 `0x4812e0 movsd 0x18(%rdi); 0x4812e5 movsd 0x48(%rdi)`——同一字段、同 0x30 步长，
NaN 也走 panic，方向按同一比较器**推断**为降序。

### 2.6 截断：只留前 `s` 个（= 20%）

```asm
51cb84: mov  0xd0(%rsp),%r15        ; r15 = s
51c1f0: mov  0xa8(%rsp),%rbp        ; 个体数组
51c1f8: mov  0xb0(%rsp),%rax        ; rax = 本代评过的个数 = 5s
51c200: mov  %rax,%rbx
51c203: sub  %r15,%rbx              ; rbx = 5s - s
51c206: jb   51c219                 ; 不足 s 就原样
51c208: mov  %r15,0xb0(%rsp)        ; len = s      ← **截断**
51c210: jne  51c540                 ; 多出来的 4s 个逐个释放
```

### 2.7 收尾：前 3 名用 0.01 精评，不一致就整条换掉

```asm
51c3ab: movsd 0x19f110(%rip),%xmm0  ; = 0.01
51c3b3: call  0x51a750              ; 第 1 名
51c6e6: movsd 0x19f110(%rip),%xmm0  ; 第 2 名（三段展开，不是循环）
51c9a0: movsd 0x19f110(%rip),%xmm0  ; 第 3 名
; 若与粗评不一致（**此处原文有误，已由 `docs/97` §3 更正**：真正比的是 `hits_fine ≠ hits_coarse` 或 `|dist_fine − dist_coarse| > 0.5`；长度不进比较，也不是总分差）：
51c731 / 51c745 / 51c787            ; 随机函数 + 构造 + 变异 → 顶掉该条
```

⇒ 是**前 3 名**精评（`archive/ai/67` 的"前 3 名用步长 0.01 精评"），不是 5 名；
3 是**展开**的三段代码，没有"3"这个循环常量。

## 3. 三种候选逐条排查

### (a) 有没有 `cmp/mov $0x5` 这种立即数？

用 objdump 把四个相关区间扫了一遍（`grep '$0x5'`，只保留真正的立即数，
排除 `shl/shr $0x5` 这类移位）：

| 区间 | `$0x5` 立即数 | 只有 |
|---|---|---|
| 驱动 `vaddr 0x51b440–0x51d000` | **0 处** | `0x51b53c shl $0x5,%r9`（×32，哈希用） |
| 工厂 `0x4ee3a0–0x4ee720` | **0 处** | — |
| 评分核心 `0x41a750–0x41b400` | **0 处** | `0x41ad29/0x41ad2d/0x41ad34 shl $0x5` |
| 第二份同构主体 `0x51d080 段` | **0 处** | `0x51d526 shl`、`0x51dda1 shr` |

⇒ **不存在"每代强制保留最好的 5 个"这种常量 5。** 候选 (b) **否**（观测）。

### (b) 有没有 `0.05`（`0x3fa999999999999a`）？

全文件 3 处：`file 0x19d5d0`、`0x19d5d8`、`0x2504e8`。

- `0x2504e8` 落在一个通用数值池里（`0x2504a8–0x250520`：0.25 / 0.5 / 0.75 / 1.0 /
  0.1 / 0.2 / 0.3 / 0.4 / 0.03 / 0.05 / 0.09 / 0.13 / 0.01 / 0.03 / 0.06 / 0.1），
  Ghidra 对该地址 **0 条 xref**；
- `0x19d5d0` 的 4 条 xref 全在 `vaddr 0x49e…–0x4a6…`（Ghidra `0x59e…–0x5a6…`），
  **与 AI 区（`0x51a750–0x51d000`）不重叠**；
- GA 代码里出现的浮点立即数只有两个：**0.5**（`0x19f6d0`，2 个调用点）和
  **0.01**（`0x19f110`，3 个调用点）——与 `archive/ai/74` §1.1 一致。

⇒ **GA 里没有 0.05。** 候选 (c) 的"5%"表述**不成立**（观测）。

### (c) 那"5"到底是什么？

`param_7 = cfg+0x78`，在这个函数里**唯一的用法**是 `param_7 − 1`
（`0x51b786 dec %eax` → `0x51c19c dec %ebx`），即"每个槽位再来几个工厂子代"。
它同时决定了两个比例：

```
克隆占本代 = 1 / param_7        = 1/5 = 20%
工厂占本代 = (param_7-1)/param_7 = 4/5 = 80%
种群       = s × param_7         = s × 5
```

⇒ 字面量 5 是**分组因子/比例分母**，不是个数。说"精英 5"错在把它当成了计数。

## 4. `archive/ai/67` 的"栈首 = 精英数 = 5"是怎么来的

`archive/ai/67` §1 的 hook 表把 `FUN_0061b440` 的第 7 个实参标成了"精英数"。
静态上这个实参就是 `cfg+0x78`（`0x4387a4 mov 0x78(%rdi),%r10d` →
`FUN_0057a300` 第 7 参 → `FUN_0061b440` `param_7`），而它在函数里只做
`param_7−1` 次的工厂重复 + "每槽 1 克隆 / param_7−1 工厂"的配比。

同一张表里"`rcx`(士兵) = 233/234"对应 `cfg+0x6c`，也只被当缓存 key 传给评分函数，
**它的含义本轮仍未定**（不在本文范围）。

`archive/ai/74` §4 的 `limit`（5/5/10/15/25/200）是 **`ctx+0x58`**，在 `0x51be9e` 被读，
与 `cfg+0x78` 是**两个不同结构体的两个字段**。难度 1–2 上两者都等于 5，
这就是"精英 5"这个说法的直接来源。

## 5. 顺带纠正 `docs/archive/ai/75` §2.5 的一句实测

`archive/ai/75` 写"堆排序候选 `0x5605f0` 每代调用 **0 次**；插入排序候选 `0x51b500`
attach 失败 ⇒ 没抓到显式排序动作"，并据此把"头部已排序"降级成**推断**。

静态上排序是**确实存在**的（§2.5）：`0x51cb6f` 分派，`0x51cb7f call 0x41b500`
（vaddr；Ghidra `0x51b500`）、`0x51cb96 call *0x9bbdc0` → GOT 解析为
**Ghidra `0x5605f0` = vaddr `0x4605f0`**。种群 250 ⇒ 每代 250 ≥ 21 ⇒ **走后者，每代一次**。

**推断（未复验运行时）**：那两个 hook 用了**vaddr**当 Ghidra 地址
（`0x51b500` / `0x5605f0` 都在错误的地址空间里：vaddr `0x51b500` 不是指令边界、
vaddr `0x5605f0` 是别处的代码），于是"attach 失败 / 0 次"。同一份文档里
工厂地址 `4ee3a0` 用的正是 vaddr，说明当时两种地址空间是混着用的。

⇒ `archive/ai/75` 的"头部按质量排序"可以从**推断**升为**观测（排序存在 + 截断存在）**；
`docs/AI.md` §5 应补上"代末排序 + 截断"这一步。
