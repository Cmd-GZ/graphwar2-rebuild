# 81 · 用 replay 局面验证我们的弹道与适应度

## 1. 做了什么

写了一条完整链路：

```
tools/replay_state.py   → 从 replay 还原"某发出手前"的局面（障碍/士兵/射手/方向）
examples/replay_compare → 建掩膜、算真实函数的 fitness、再跑我们的 AI 对比
```

局面来源：`ClearObstacles` + `AddObstacle`（障碍）、`DestroyObstacle`（挖洞→补 0xFF）、
`PosInfo`（士兵坐标）、`TeamInfo`（队伍）、`LifeInfo`（生死）、
`FunctionInfo`+`FunctionPoints`+`FunctionFire`（谁、用什么函数、从哪打到哪）。

方向 `flip` 由 `FunctionPoints.start_x` 与 `end_x` 的先后决定。

## 2. 最重要的验证：**几何是对的**

拿真实函数重算弹道，看它在 replay 记录的终点 x 处落在哪：

```
局面: Alpha Zordon @ (22.10, 8.78)，函数 (-0.35*(-11.40+x))
replay 记录的终点 x = -9.609
我们轨迹在 x≈-9.61 处是 (-9.57, -2.30)
```

而 replay 的 `DestroyObstacle` 正好在 **(-9.608, -2.315)** —— **误差 0.05**。

⇒ 修正常数、路径采样、方向翻转**全部正确**。

## 3. 一个系统性偏差：障碍边界大了约半个像素

统计 58 个"击停点"（`DestroyObstacle` 且半径 0.5）到最近障碍圆心的距离减去该障碍半径：

| 统计量 | 值 |
|---|---|
| 中位数 | **+0.030** |
| 均值 | +0.052 |
| 36/58 个样本 | ≈ 0.00 |
| 13/58 个样本 | ≈ +0.10 |

即**弹道停在障碍边界"外侧"约 0.03**，而 **1 像素 = 0.05 世界单位**
⇒ 偏差量级正好是**半个像素**。

**推断**（未证实）：游戏的掩膜光栅化判据可能是"像素方块与圆**有重叠**"，
而我们 `rasterize` 用的是"像素**中心**在圆内"，于是我们的障碍每边小了约半像素。

后果：**贴边的弹道**在我们的模型里会穿过去，而在真游戏里会停下。
这解释了为什么我们的 AI 在某些真实局面里"找到"了真游戏打不中的解。

## 4. 对 AI 对比的影响

| 机器人 | 真实函数得分 | 我们模型最优 | 结论 |
|---|---|---|---|
| Deep Thought (L6) | +999999（1 杀） | +3000000（2 杀） | 我们"更好"，但可疑 |
| Multivac (L4) | −1000000（打空） | +1000000 | 同上 |
| Alpha Zordon (L3) | −1000000（打空） | +1000000 | 同上 |
| ChatGPT (L1) | −1000000 | −1000000 | 打平 |

**在掩膜边界问题修好之前，这组对比不能当作"我们的 AI 更强"的证据**——
更可能是我们的墙薄了半像素，让本来会被挡住的解通过了。

## 5. 下一步（明确）

1. 把 `rasterize` 的判据从"像素中心在圆内"改成"像素方块与圆有重叠"（或等效地
   把半径加半像素），然后**重跑 `docs/16` 的 mask 对拍**与本节第 3 步的统计，
   看偏差是否从 +0.03 变成 0；
2. 修好后重跑第 4 步的对比——那才是真正有意义的"像不像"检验。

## 6. ⚠️ 修正：`docs/81` §3 的"半像素"推断**被推翻**

### 6.1 掩膜对拍重新跑：**PASS**

```

点测试：300 个随机点，差异 0

```

我们的 `rasterize` 与真二进制 `0x3f11e0` **逐字节一致**（点测试也对拍通过）。
⇒ §3 那条"我们的障碍小了半个像素"的推断**不成立**，撤回。

`+0.03` 那个均值偏差另有来源（尚未确定）。

### 6.2 批量对比：多数弹道根本没匹配上

从 `1793874543` 取 26 发，比较"我们算的终点 x"与 replay 的 `end_x`：

| 判据 | 命中 |
|---|---|
| \|Δx\| < 0.05 | 1/26 |
| \|Δx\| < 0.5 | 4/26 |
| 中位数 | **10.6** |

⇒ **不是边界像素问题**：大多数情况下我们的弹道比真实的多飞了 6~43 个世界单位。

### 6.3 两个具体的反例

**反例 A（平滑函数，差 1 像素）**

```
Alpha Zordon  (-0.35*(-11.40+x)) @ (22.10, 8.78)
replay 终点 (-9.608, -2.315)；我们曲线在 x≈-9.61 处 = (-9.57, -2.30)
⇒ 曲线吻合到 0.02，但采样点落在相邻像素（218 vs 217），边界处判定翻转
```

**反例 B（真实终点处根本没有障碍）**

```
Deep Thought  tan(...) @ (9.27, -0.42)
replay 终点 (-14.109, -4.342) —— 该点在我们（已对拍通过的）掩膜里是**空的**
最近障碍 (-16.82, 1.83) r=2.72，到终点距离 6.7
而我们的弹道一路飞到 x=-24.98（左边界）
```

⇒ 真实弹道在 **(-14.1, -4.3)** 这个"什么都没有"的地方停了。
**停下的原因未确定**（不是障碍、不是边界、不是 NaN 可见区、不是长度预算——
从 (9.27,-0.42) 到 -25 的弧长才 ~34 单位，远小于 200）。

### 6.4 结论与下一步

| 项 | 状态 |
|---|---|
| 掩膜与真二进制一致 | **逐字节验证 PASS** |
| 修正常数/采样/方向 | **观测**（反例 A 吻合到 0.02） |
| 真实弹道的**停止条件** | **未知**——存在"空地上停下"的实例，现有实现无法解释 |

**下一步（最直接的路）**：不再从"终点"倒推，改为**在活体游戏里逐点对拍轨迹**——
hook 真游戏的路径函数，喂一个已知函数与起点，把它吐出的点序列与我们 `path::calculate`
的输出逐点比较。这样才能定位停止条件的差异。
