## 2. GW1 的算法（源码事实）

`src/Graphwar/ComputerPlayer.java`：

```java
this.numGenerations = level;                 // 等级 == 代数！
this.numFunctions = Constants.NUM_FUNCTIONS_AI;   // 种群大小 = 50
```

`Constants.java`：

```
NUM_FUNCTIONS_AI            = 50   种群
NUM_FUNCTIONS_UNCHANGED_TURN_AI = 5    精英（原样保留）
NUM_FUNCTION_MUTATED_AI     = 25   变异
（其余 20 个）                       交叉
```

每代：保留 5 个精英 → 25 个"复制一个轮盘赌选中的父代再变异" → 20 个"两个父代交叉"，
然后**全部重新评估**。所以每回合的评估次数 = `代数 × 50`。

**这正好解释用户说的"等级越高等得越久"**——等级就是代数，线性放大工作量。

适应度（`evaluateFunction`）：

```java
if (命中敌人)  totalPoints += 2_000_000;
else if (命中队友) totalPoints -= 2_000_000;   // 友军误伤重罚
...
totalPoints += 1_000_000 - minDistSquared;     // 越靠近敌人越好
```

## 3. GW2 二进制里的对应证据

在 `libgraphwarrust.so` 里搜这两个常数：

| 常数 | 出现次数 | 文件偏移 |
|---|---|---|
| `2_000_000.0` | **1** | `0x19fc00` |
| `1_000_000.0` | **3** | `0x19fb30`、`0x257298`、`0x2ad3f8` |

引用它们的三条指令全部落在 **AI 区域内**
（`0x51ab2d`、`0x51afdf`、`0x51b0b1`；AI 入口 `0x51b440`、评分循环 `0x51a750`，见 `docs/29`）。

反编译 `0x519950` 那段（Ghidra 被 jump table 干扰，但评分表达式是清楚的）：

```c
dVar13 = (((double)命中数 * 2000000.0 + ...) - ...) - (minDist² / 100.0);
if (步数 > 阈值) dVar13 += -50000000.0;
```

⇒ **GW2 保留了"每次命中 ±2e6"的核心结构**，但相对 GW1 有改动。

> ⚠️ 本节这段当时的描述**不准确**，已由 `docs/74` 用逐条反汇编修正：
> 实际是 `命中×2e6 − 友军项×100 − 1_000_000 − V²/100 − (V>阈值 ? 5e7 : 0)`，
> **`1e6` 是减不是加**，二次项是**整数 `V` 的平方**而不是"最小距离"。
> 我当时把 GW1 源码里的 `1e6 − minDist²` 记忆直接搬了过来，没有核对 GW2 的符号。

## 4. 从截图看进化出来的函数

用户给的两个机器人函数：

```
(4.66/(x--2.99))
exp(cos((-6.01-exp(x))))
```

特征：**两位小数的常数**、结构是"随机 token 序列 + 交叉/变异"的典型产物
（GW1 的 `makeRandomFunction` 就是 `长度 ≈ 10×|高斯|` 的随机 token 串再修正成合法前缀式）。
GW1 里常数由 `random.nextDouble()` 生成，显示时会截断——与截图一致。

## 5. 结论与状态

| 命题 | 状态 |
|---|---|
| GW2 的 AI 是**进化算法**（种群 + 精英 + 变异 + 交叉 + 重新评估） | **强证据**：`±2e6` 常数与 GW1 完全一致，且落在 AI 区域的评分表达式里 |

| 随机函数生成器（token 集合与权重） | **未知** |
