# 69 · 函数表达式的 token 编码（二进制证据）

## 1. 来源

`FUN_005ebbe0`（Ghidra 址，虚地址 `0x4ebbe0`）：一个**常量折叠 / 化简**过程，
按 token 码分派。反编译出来的 `switch` 直接给出了全部 token 码：

| 码 | 操作 | 折叠示例（反编译里看到的） |
|---|---|---|
| 3 | `+` | `__x = __x + 0.0` |
| 4 | `-` | （不折叠） |
| 5 | 取负 | `__x = XOR(__x, 符号位)` |
| 6 | `*` | `__x = __x * 0.0` → `0` |
| 7 | `/` | `__x = __x / 0.0` |
| 8 | `^` | `__x = 1.0`（即 `x^0 = 1`） |
| 9 | `sqrt` | `__x = SQRT(__x)` |
| 0xa | `log` | `__x = log10(__x)` |
| 0xb | `ln` | `__x = log(__x)` |
| 0xc | `exp` | `__x = exp(__x)` |
| 0xd | `abs` | `__x = ABS(__x)` |
| 0xe | `sin` | `__x = sin(__x)` |
| 0xf | `cos` | `__x = cos(__x)` |
| 0x10 | `tan` | `__x = tan(__x)` |
| 0x11 | 值（`x` 或常数） | `__x = local_40`（值本身） |

⇒ **语言层面**支持：`+ - neg * / ^ sqrt log ln exp abs sin cos tan` + 值。
与上游 REPORT 里的 18 个 tag（`0..17`）对得上（这里从 3 开始是因为前面几个另有含义）。

**注意**：`exp` 在 GW1 的随机算子表里**没有**，但它在 GW2 的语言里是一等 token（码 0xc）。
这与 `docs/68` 的观测一致（GW2 的 AI 会输出 `exp(...)`）。

## 2. 它回答了什么、没回答什么

| 问题 | 答案 |
|---|---|
| 语言支持哪些算子 | ✅ 上表全部 |
| AI 的**随机生成器**会抽哪些算子、权重多少 | ❌ **仍未确定**（这是生成器的事，不是化简过程） |
| 为什么统计里 `sqrt`/`ln`/`^` 是 0 次 | 可能是生成器不抽它们，也可能是极低概率——需要读到生成器的分支表才能定论 |

## 3. 下一步

要找的是"随机生成函数"的那个函数：它会
1. 调用随机数取一个算子编号；
2. 按编号构造 token。

线索：`FUN_005ebbe0` 的调用者里应该有生成/变异路径；
AI 核心 `FUN_0061b440` 的其它被调函数（`FUN_005ee3a0`、`FUN_005ef020`、
`FUN_005ee0e0`、`FUN_005ee720`）还没逐个看。

拿到那个函数后，权重就是它里面 `% N` 或 `next_u64 % N` 的**分支表大小**，
不需要再靠统计估。
