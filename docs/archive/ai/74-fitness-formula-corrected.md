# 74 · 适应度公式的修正版（反汇编核对）

## 1. 结论（**已修正**）

> ⚠️ 本节最初把中间那项写成 `− 友军数 × X × 100`，**是错的**。
> 后来的验证（§1.1）表明 `X` 是**采样步长**、与它相乘的 `esi` 是**掩膜扫描累加器**，
> 常规对局里恒为 0。实际生效的公式是：

```c
score = hits * 2_000_000.0
      - 1_000_000.0
      - (V*V) / 100.0
      - (V > limit ? 50_000_000.0 : 0.0)          // 常规对局中没有"友军惩罚"项
```

其中 `hits` 是**命中数**（2v2 下最多 2），实测分布 `{0: 36939, 1: 9226, 2: 10760}`。
⇒ 全未命中约 **−1e6**、命中一人约 **+1e6**、命中两人约 **+3e6**。

### 1.1 那一项到底是什么（逐条证据）

| 事实 | 证据 | 类别 |
|---|---|---|
| `X = [rsp+0x78]` 来自**第一个 SSE 入参** | `0x51a761: movq %xmm0,0x78(%rsp)`，紧跟函数序言 | 反汇编 |
| `0x78(%rsp)` 全函数只有 3 次访问 | 写 `0x51a761`、读 `0x51a98e`、读 `0x51b089` | 反汇编 |
| 5 个调用点的 `xmm0` = **0.5 / 0.01** | `0x19f6d0 = 0.5`（粗评，2 处）、`0x19f110 = 0.01`（精评，3 处） | 反汇编 + 常数直读 |
| 运行时 `X` 只有 0.5 / 0.01 | hook `0x51b08f`，60/60 样本 | **实测** |
| 与 `X` 相乘的 `esi` 是**掩膜扫描累加器** | `pcmpeqb`+`pmovmskb` 后 `add %eax`；清零 `0x51ab42`、累加 `0x51acc8` | 反汇编 |
| 该累加器**常规对局恒为 0** | 56925 次采样全 0，累加指令 40 秒内执行 0 次 | **实测** |
| `X` 与士兵坐标/距离**无关** | 该栈槽只来自 `xmm0`，无坐标变换参与 | 反汇编 |

**仍是空白**：那个掩膜累加器**在什么情况下才会非零**（累加点从未执行，
静态上也没找到明确跳转来源，该处反汇编错位）。所以"这一项在哪种模式下有意义"未知。

## 2. 证据（`0x51b079`–`0x51b100` 逐条）

```asm
51b079: movsd  [0x19f6d8] -> xmm0      ; 100.0
51b08f: mulsd  xmm0, xmm3              ; xmm3 = [rsp+0x78] * 100.0
51b098: cvtsi2sd esi -> xmm1           ; esi = 友军数
51b09d: mulsd  xmm3, xmm1              ;   × [rsp+0x78] × 100
51b0a1: subsd  xmm1, xmm2              ; xmm2 = -友军项
51b0ad: cvtsi2sd eax -> xmm1           ; eax = 命中数
51b0b1: mulsd  [0x19fc00], xmm1        ;   × 2_000_000.0
51b0b9: addsd  xmm2, xmm1              ; += 友军项（负）
51b0c0: imul   rdx, rcx                ; rcx = V*V  ← 整数平方
51b0d9: subsd  0x8(%rsp), xmm1         ; -= 1_000_000.0  ← **是减不是加**
51b0e7: addsd  xmm2, xmm3
51b0eb: divsd  xmm0, xmm3              ;   / 100.0
51b0ef: subsd  xmm3, xmm1              ; -= V²/100
51b0f3: mov 0x38(%rsp),%rcx ; mov 0x58(%rcx),%ecx   ; limit
51b0fb: cmp %rcx,%rdx ; jbe skip       ; V <= limit 则跳过
51b100: addsd [0x19f478], xmm1         ; += -50_000_000.0
```

常数核对（直接读 `.rodata`）：
`0x19f478 = -50000000.0`、`0x19fb30 = 1000000.0`、`0x19f6d8 = 100.0`、`0x19fc00 = 2000000.0`。

## 3. 修正了什么

| 旧说法（`docs/66`） | 实际 |
|---|---|
| `±2e6 每次命中 + (1e6 − minDist²)` | 命中 `+2e6`、**`−1e6`**、**`−V²/100`**，常规对局无友军项 |
| `− minDist²/100` | 减数不是"最小距离"，而是**整数 `V` 的平方除 100** |

`minDist²` 这个说法是从 GW1 源码（`totalPoints += 1000000 - minDistSquared`）带过来的，
**GW2 改成了减 1e6 再减 V²/100**。我此前没核对符号就写进文档，属于把 GW1 的记忆当成了 GW2 的事实。

## 4. 惩罚阈值随难度变化（实测，每档 400 样本恒定）

| 难度 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| `*(u32*)(ctx+0x58)` | 5 | 5 | 10 | 15 | 25 | 200 |

难度 6 的 200 实际等于不设限（400 次采样中 `V > limit` 出现 0 次）。
比例：难度 1 约 4.25%、难度 2 约 6%、难度 4 约 7% 的评分会吃到这 5e7 惩罚。

⇒ 这是一个**随难度放宽的复杂度惩罚**：难度越高越允许多项式变复杂。

## 5. `V` 的语义：**已确认 = 被评分函数的 token 数** ✅

### 5.1 结论

`V` 就是**当前被评分那个函数的 token 个数**（token 向量长度）。
于是适应度里的 `−V²/100` 是**表达式复杂度的二次惩罚**，
而 `V > limit` 时的 `−5e7` 是**复杂度硬上限**：超过就不许用。

`limit` 随难度放宽（`5 / 5 / 10 / 15 / 25 / 200`），
即"低难度只允许 5 个 token 的短式子，最高难度放宽到 200"——这与"AI 越强式子可以越复杂"的直觉一致。

### 5.2 证据（运行时，40 次采样 100% 命中）

在 `0x51b0f8`（读 `limit` 那条）下探，扫描当前栈帧：

- 布局：**`[rsp+440]` = token 数组指针、`[rsp+448]` = 长度**
- **12/12 样本**都在该位置找到 `len == V` 的向量，且前若干个元素的 tag 全在 `0..19`
- 抽查标签：

| V | tags |
|---|---|
| 7 | `[3,3,3,17,0,17,17]` = `Add,Add,Add,Const,VarX,Const,Const` |
| 9 | `[3,3,3,17,6,17,0,17,17]` |
| 17 | `[3,3,3,17,3,11,6,15,4,7]` |
| 25 | `[3,11,4,6,6,13,3,13,6,15]` |

`V=7` 那条按前缀式核算：需要操作数 `1 →(Add)2 →3 →4 →(Const)3 →(x)2 →(Const)1 →(Const)0`
—— 正好 7 个 token 收尾，**是合法的完整前缀式**。

### 5.3 之前的三个弯路（留作教训）

1. 以为 `[rsp+0x58]` 是评分函数内部算出来的 → 实际是入参存进去的；
2. 把 `0x51a890` / `0x51ae50` 当成两个函数（函数起点表的伪入口）→ 整段其实是同一个函数；
3. 只扫寄存器找向量（扫不到）→ 向量在**栈上** `rsp+440`，寄存器里当然没有。

**教训**：找"某个整数和某个数据结构的对应关系"时，别只盯着寄存器，
栈帧里往往有完整的一份。
