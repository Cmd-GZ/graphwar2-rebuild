# 38 · 动态掩膜假设：**被数据否定**

`docs/37` 留了一个差异：同一关第 1 与第 3 发起点、函数完全相同，
但抓包终点不同（`1.050` vs `1.603`）。当时的解释是"中间有障碍被摧毁，状态变了"。
本轮去验证这个解释。

## 1. 数据

同一关 4 发，其中两发各带一次 `QueueDestroyObstacle`：

| # | 射手 | 函数 | 抓包终点 x | 摧毁点数 |
|---|---|---|---|---|
| 0 | 230 | `0.00` | `1.050` | 1 |
| 1 | 233 | `abs((11.66-x))` | `-24.996` | 0 |
| 2 | 230 | `0.00` | `1.603` | 1 |
| 3 | 234 | `(exp(x)*(3.34-x))` | `-3.583` | 0 |

## 2. 假设与结果

**假设**：#0 击毁了挡路的障碍，所以 #2 能飞得更远。

模拟（每发之后按抓包的摧毁点移除最贴近的障碍，再重算）：

```
#0 抓包终点 1.050   我们 1.445   差 0.394   阻挡=True
     移除障碍 (4.50,-11.14,r=3.45)，边缘偏差 0.029   ← 匹配得很好
#1 抓包终点 -24.996 我们 -24.942 差 0.054   阻挡=False
#2 抓包终点 1.603   我们 24.899  差 23.295  阻挡=False  ← 飞过头了
#3 抓包终点 -3.583  我们 -3.577  差 0.006   阻挡=False
```

**假设不成立**：移除障碍后。#2 应该一路飞到边界（24.899），
但真实游戏里它仍然停在 `1.603`。

而且 #2 自己的摧毁点与现存障碍的边缘**对不上**（最小偏差 2.309），
说明"摧毁点落在被毁障碍边缘上"这个建模对它不成立。

## 3. 结论

- "障碍被摧毁导致后续弹道变远"**不能**解释 1.050 → 1.603 的差异；
- `QueueDestroyObstacle` 的位置语义可能不是"碰撞点落在障碍边缘"
  （#0 匹配 0.029，#2 匹配 2.309，数据不一致）；
- 那 0.394 与 0.159 的差异**仍然没有解释**，只能记为已知偏差（均小于采样步长）。

## 4. 下一步可能的方向

1. 用 frida 在真实进程里 hook 掩膜写入/查询，看 `QueueDestroyObstacle` 之后
   掩膜对应像素是否真的被清空；
2. 检查这两发是否属于**不同回合**（中间可能有士兵移动，导致起点虽然显示相同、
   实际状态不同）。
