# 09 · 报告是否拆分：决策与依据

目标要求：重建达到可交付程度后更新上游 `REPORT.md`，并**自主判断是否拆分报告**，
且把决策依据留在仓库里。这份文档就是依据，结论可能随进度变化。

## 1. 现状

上游 `REPORT.md` 约 730 行，实际承载了三类内容：

| 类型 | 章节 | 稳定性 |
|---|---|---|
| **算法本体**（解析器、采点、修正常数） | §0、§2、§3 | 高：已逐位验证，几乎不会再改 |
| **工具链与方法**（.eh_frame、capstone、unicorn、验证方式） | §1、§6、§7、§9 | 中：已被证伪过一轮（§12 那条），仍在演进 |
| **对比与旁证**（GW1 vs GW2、guide 对账、行为细节） | §5、§8 | 中：依赖 GW1 源码与外部文档 |

复原子仓库 `gw2-rebuild/docs/` 现在是 9 篇：架构、模块地图、函数语言、采点、开火链路、
验证、协议、坐标系、本决策。**内容已与上游报告明显分工**。

## 2. 决策：**暂不拆分上游报告**（保持单一权威文档）

理由：

1. 上游报告的核心价值是"这条曲线为什么是这样"的**完整论证链**，一旦拆开，
   算法与它的验证方法会被分到两个仓库，读者要多跳一次才能判断结论可信度。
2. `AGENTS.md` 明确要求 `REPORT.md` 章节编号稳定，且 `analysis/discontinuity.py`
   与代码注释按编号引用（如 "REPORT §5.7"）。拆分会打断这些引用。
3. 复原子仓库已经承担了"实现与观测"的角色，再拆上游会导致**两份都在讲实现**。

## 3. 触发拆分的条件（满足其一再动）

- 上游报告超过约 1200 行，且新增内容集中在**联机协议**或**玩法状态机**这类
  与"曲线算法"无关的主题上；
- 复原子仓库的 docs 里出现与上游报告**重复且开始不一致**的论述；
- 需要把工具链（`.eh_frame` 教训、Ghidra 边界、地址换算）独立成一份
  可被其他逆向项目复用的说明。

## 4. 若拆分，切法已经想好

```
REPORT.md                 算法本体（§0/§2/§3/§5）+ 一句指向下面两份
docs/toolchain.md         函数边界、交叉引用、unicorn 预言机、地址换算、验证方式
docs/gameplay.md          协议形状、坐标系、碰撞掩膜、回合/关卡/AI（逐步补齐）
```

判据：**按"读者要回答什么问题"切**，不按代码模块切。
想确认"我的复刻对不对"→ 算法本体；想确认"我怎么得出这个结论"→ toolchain；
想知道"游戏怎么运作"→ gameplay。

复核（第 7 轮）：上游目前**没有已知的过时断言**；§9 的两处过时项已修掉。

复核（第 12 轮，收尾）：再次全文扫描确认
- 「13430 个真实函数」「函数边界（已生成）」「Ghidra 12.2 + 脚本」三处旧表述均已消失；

**最终决策：不拆分。** 三条依据：
1. 744 行未达自定的 1200 行阈值；
2. 第 11 轮新增的 y 轴澄清仍属"曲线怎么飞"主线，不构成新主题；
3. 复原子仓库已用 16 篇文档承担实现与观测量，上游再拆会出现两份讲实现的东西。后续若有新观测与此冲突，
按"观测优先、报告有错就改"的原则处理，不必等拆分。
