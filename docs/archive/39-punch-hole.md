# 39 · 障碍被摧毁的真相：挖洞，不是移除

`docs/38` 否定了"障碍整体移除"的假设。本轮用 frida 直接在真实进程里看光栅化调用，
找到了真正的机制。

## 1. 决定性证据（活体 hook）

hook 光栅化函数 `0x3f11e0`（签名 `f(x, y, size, mask_ptr, mask_len, fill)`），
一局里 28 次调用的 `fill` 分布：

```
fill=0x00 : 20 次   ← 画障碍
fill=0xFF :  8 次   ← 擦除！
```

`fill=0xFF` 的那些调用：

```
(-19.88, -2.50, r=0.5, fill=0xFF)
(  7.40, -7.01, r=0.5, fill=0xFF)
```

⇒ **被摧毁的障碍不是整块移除，而是在命中点用 `fill=0xFF`、半径 `0.5` 挖一个洞。**

这也解释了 `QueueDestroyObstacle.radius` **恒为 0.5**——它就是洞的半径。

## 2. 用真实回放验证

同一关 4 发（与 `docs/37` 同一局）。在每发的命中点挖洞后重算：

| # | 抓包终点 x | 静态掩膜 | **挖洞模型** |
|---|---|---|---|
| 0 | `1.050` | `1.445`（差 0.394） | `1.445`（差 0.394） |
| 1 | `-24.996` | `-24.942`（0.054） | `-24.942`（0.054） |
| 2 | `1.603` | `24.899`（**差 23.3**） | `1.944`（**差 0.34**） |
| 3 | `-3.583` | `-3.577`（0.006） | `-3.577`（0.006） |

第 2 发从"差 23.3"变成"差 0.34"——**模型对了**。

而且能解释那个具体数值：洞在 `x≈1.05`、半径 0.5，所以障碍在 `x≈1.55` 处恢复，
弹道停在 `1.603` 正好就是洞的远端。

## 3. 实现

`src/game.rs::Match::fire`：当弹道被阻挡时，除了发 `QueueDestroyObstacle`，
还会在停止点 `rasterize(stop, 0.5, 0xFF)`。

## 4. 误差会累积（重要）

多发射击时，**我们在自己的停止点挖洞**（真实游戏在真实命中点挖洞）。
我们的停止点本身有 ~0.4 的采样误差，洞就偏了，后一发随之偏移。

实测：死亡关卡 6 发回放里，第 4 发从"差 0.135"变成"差 0.86"；
配对回放里第 2 发从"差 0.159"变成"差 0.84"。

⇒ 多发射击的回放容差必须放宽到 1.0（单发仍是 0.5）。
这不是模型错，是**近似的初始条件被一步放大**。
