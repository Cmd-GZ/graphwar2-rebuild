# 87 · 函数装配规则（`archive/ai/76` §4.5 的悬案，已解）

## 1. 三个函数

| Ghidra | vaddr | 作用 |
|---|---|---|
| `0x5ee3a0` | `0x4ee3a0` | **子代工厂**：决定变异 / 重生 / 交叉 |
| `0x4be7d0` | `0x3be7d0` | 把一个连续区间 drain 进新 Vec（不是"交叉"本身） |
| `0x5ee0e0` | `0x3ee0e0` | **补齐/装配**（本文件的主角） |

> 注意地址空间：`archive/ai/75` 里的 `4ee5c9` 其实是 **vaddr**，对应 Ghidra `0x5ee5c9`。
> 以前把 `3be7d0` 当作"交叉函数"，实际只是个区间复制。

## 2. 工厂的两条路（`FUN_005ee3a0`）

```
iVar2 = 随机 int
if (iVar2 < 0)  → 变异 FUN_005ee720           // 走变异
uVar7 = 父代 len
if (uVar7 < 0x14)  → FUN_005ef020 重新随机     // 父代 < 20 token
else               → 交叉
```

**交叉的切点**：

```
r1   = rand % N
r2   = rand % (N - r1)
cut2 = r1 + r2          // ∈ [r1, N)
取父代的连续子片段 [r1, cut2)
```

⇒ **切点是"随机起点 + 随机长度"，只从**一个**父代取一段连续子串**，不是经典的两点交叉。

## 3. 装配规则（`FUN_005ee0e0`）—— 这就是 §4.5 的答案

两步：

**(a) 截断**：用"需要的操作数"计数器走一遍

```
need = 1
for i, tok in tokens:
    need -= 1
    need += arity(tok.tag)     // arity-1，查表 DAT_002c47d0
    if need == 0: 截断到 i+1，结束
```

**(b) 补齐**：只要 `need > 0`，就按固定比例追加一个叶子 token：

| `rand % 50` | 概率 | 追加 |
|---|---|---|
| `< 25` | **50%** | 常数 `normal() * 10.2` |
| `25..41` | **34%** | `x` |
| `42..49` | **16%** | `tag = mode & 1` ⇒ Normal 下仍是 `x`、**DiffEq 下是 `y`** |

每追加一个叶子 `need -= 1`，直到 `need == 0`。

## 4. 我们之前的实现错在哪

`graphwar_function_evolutionator::repair` 原来**只补常数叶子**，而游戏是 50/34/16 的混合。
后果：交叉产生的子代会系统性地**缺少变量**，搜索行为与真实 AI 不一致。

已改正，并加了测试 `repair_fills_with_the_documented_mix`
（4 万次采样，常数/`x`/`y` 三项都落在理论比例的 ±500 内）。

## 5. 与 `archive/ai/76` §4.5 那个"不一致"的关系

§4.5 记录的现象是：「原始 token 流常在 1~5 个 token 处就已合法（`need==0`），
但真实函数约 10 个 token」。

现在解释得通：**交叉只取父代的一个连续子片段**（长度 `r2 = rand % (N-r1)`，
期望约 `N/4`），片段本身通常还不完整 ⇒ 由 (b) 补齐到 `need==0`。
所以最终长度主要由"片段 + 补齐"决定，而不是单调对应父代长度。

## 6. 证据等级

| 结论 | 等级 |
|---|---|
| 工厂三分支（变异/重生/交叉） | **逐位验证**（反汇编 `0x5ee3a0`） |
| 切点 `r1 = rand%N`、`r2 = rand%(N-r1)` | **逐位验证** |
| 补齐比例 50/34/16 | **逐位验证**（反汇编 `0x5ee0e0`） |
| `mode & 1` 就是 VarMode（Normal→x、DiffEq→y） | **推断**（与 `archive/ai/71` §5.0 的运行时测量一致，但没有直接追踪 param_2 的来源） |
