# 审计报告：哪些工作在复原**源代码**，哪些把"复原行为"当成了终点

> 生成：2026-11-26 · 依据：五个独立审计面（`docs/06` §85/§86/§87/§88/§90）+ lead 复核
> 台账：`fixtures/source_audit_{client,src,tests,docs}.tsv`、`fixtures/function_coverage.tsv`
> 这份报告的目的不是清算谁，而是**指出方法论层面的偏差**，让后续排期不再重犯。

---

## 0. 一句话判决

**项目此前处在「行为对得上、源码不在手上」的阶段。**

- 文件名/模块名对得上 → 但**函数边界只有 131/527 = 24.9%**，**249 个原版函数（47.2%）在源码层根本没有函数体**；
- 客户端能跑、截图能对齐 → 但**控制器整层是我们写的 GDScript**，**原版 31 份 `.tscn` 一份都没进仓库**；
- 测试 1,772 条全绿 → 但**真正拿我方输出与真值逐值/逐字节对拍的只有约 170 条（9.6%）**，**341 条（19.3%）是纯自洽**；
- 招牌数字 `527/527 已实现、未做 0` → 这是**模块级**口径（每个模块都有文件 + 写了档位），**不是**函数级复原率。

⇒ 一句话：**擦亮了窗户，但房子不是原版的。**

## 1. 判据：什么才算"奔着复原源代码"

一条工作算**源码级**，必须同时满足四条（缺一条就是行为重建）：

| # | 判据 | 合格 | 不合格 |
|---|---|---|---|
| 1 | **归属** | 落在**原版模块名**的文件里，或用 `recovered-src/` 的**原版字节** | 逻辑住在 `_scaffold/`、GDScript、"顺手"的文件 |
| 2 | **物证** | 能指到 `panic::Location` / 符号表 / 指令地址 / 抓包 / 真帧 | "看起来对""跑通了""像素 0 px" |
| 3 | **单一实现** | 同一条规则**只有一处**，且在正确位置 | Rust 与 GDScript **各写一遍**（两份都不算原版） |
| 4 | **诚实标档** | `逐位/观测/推断/未知` + 可复核出处 | 把推断写成陈述句、把测试条数当进度 |

分档：`A` 达标 / `B` 行为对了但**原版对应物不存在** / `C` 同一条规则**两处实现** / `D` 期望值来自我们自己（自洽）/ `E` 判不了。

## 6. 这份审计本身的局限

- 审计只看**"函数边界 / 名字 / 住处 / 重复 / 期望值来源"**，**不判语义对错**——A 档也可能语义是错的。
- 函数级判档里 F3 的 `named-miss` **不等于行为没做**（可能内联/合并成表/改名），它量的是"函数边界与名字有没有对上"。
- 527 这个分母本身含 26 条宏产物 + 45 条编译产物（闭包/冷 panic），把它当"源码函数总数"偏高；修正分母后 M1 = 131/501 = 26.1%。
- 抽样率低（文档 0.4%、测试按二进制聚簇），因此 38% 不可信率是**上界**，不能反推全文。
- 五份审计都做了正对照（判法先在校准样本上验证），但"锚定 ≠ 正确"：注里给了地址也可能抄错。

---

**结论**：这个项目**不是**在"造一个能玩的替代品"路上失控，但它确实**长期用"行为对得上"来替代"源码在手上"**——最具体的表现就是：能跑、能对齐、测试全绿，而**函数边界只有 24.9%、原版视图文件一份没进、控制器整层是仿写的**。审计之后，衡量标准已换成「**能不能指到原版的文件/函数/结构**」，并且这一条写进了 `HANDOVER` 顶部。
