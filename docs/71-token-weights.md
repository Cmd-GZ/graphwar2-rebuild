# 71 · 随机函数生成器的 token 权重表（二进制直读）

## 1. 找到它

`docs/70` 里找 AI 生成器未果，改用运行时定位：hook 正态采样器 `0x4625b0`，
记录**调用方返回地址**，得到 AI 区域的 6 个抽随机数的位置：

```
5638×  0x4ef1dc     4824×  0x4ee26e     4647×  0x4ef068
1800×  0x4ee881     1569×  0x4eed40     1507×  0x4eeb9c
```

其中 `0x4ef1dc` 之后同时出现 `mulsd [0x19f758]`（=**10.2**）和一连串
`cmp $imm / jb` 阈值比较 ⇒ 就是**加权 token 分派**。
所在函数：`FUN_005ef020`（Ghidra `0x5ef020`，虚地址 `0x4ef020`）。

## 2. 分派逻辑（`0x4ef1b0`–`0x4ef2da`）

```asm
4ef1b0: mov  %r12d,%eax
4ef1b3: imul %rbp,%rax
4ef1b7: shr  $0x26,%rax
4ef1bb: imul $0x55,%eax,%eax     ; 0x55 = 85
4ef1be: sub  %eax,%r12d          ; idx = random % 85
4ef1c1: cmp  $0xb,%r12d          ; idx < 11 → 常数
        call 4625b0              ;   正态采样
4ef1dc: mulsd 10.2               ;   常数 = N(0,1) × 10.2
        mov  $0x11,%r13d         ;   tag = 17 (const)
4ef220: cmp  $0x11 ...           ; 其余按区间给 tag
```

**总权重 85**，用区间比较实现加权抽样。tag 含义见上游 `AGENTS.md`
（`0..17 = x y y' + - neg * / ^ sqrt log ln exp abs sin cos tan const`）。

## 3. 完整权重表

| idx 区间 | 个数 | tag | token |
|---|---|---|---|
| 0–10 | **11** | 17 | `const`（= `N(0,1)×10.2`） |
| 11–20 | **10** | 0 | `x`（11–16 是立即数分支，17–20 走栈上预存值；普通模式下两者都是 `x`） |
| 21–30 | **10** | 3 | `+` |
| 31–35 | **5** | 4 | `-` |
| 36–46 | **11** | 6 | `*` |
| 47–53 | **7** | 7 | `/` |
| 54–55 | **2** | 8 | `^` |
| 56 | **1** | 9 | `sqrt` |
| 57 | **1** | 10 | `log` |
| 58 | **1** | 11 | `ln` |
| 59–64 | **6** | 12 | `exp` |
| 65–71 | **7** | 13 | `abs` |
| 72–78 | **7** | 14 | `sin` |

合计 `11+10+10+5+11+7+2+1+1+1+6+7+7+5+1 = 85` ✅

值 token 合计 21/85 ≈ **24.7%**，算子 64/85 ≈ **75.3%**
（GW1 是值/算子各 50%，GW2 明显偏向算子）。

在分派汇合点 `0x4ef2b0` hook 读 `r13d`（= tag），统计实际分布

| 17 `const` | 12.97 | 12.94 |

## 4. 这推翻了 `docs/68` 的统计结论 ⚠️

`docs/68` 用 OCR 统计了 149 个算子 token，`sqrt`/`ln`/`^` 都是 **0 次**，
当时写成了"token 集不含这三者"。**这是错的**。

按本表，它们的权重分别是 1/64、1/64、2/64，
在 149 个 token 下的期望只有约 **2.3 / 2.3 / 4.7** 次——
一次都没抽到完全正常（`(1-2/64)^149 ≈ 0.008`，`sqrt`/`ln` 各约 0.8% 量级，
两者同时为 0 并不罕见）。

**教训**：小样本的频率为 0 **不能**推出"不存在"。这正是用户说的
"统计只能参考，二进制才是标准"。

## 5.0 ⭐ DiffEq（y'）模式：那 10 个变量权重会拆开（本轮补上）

之前所有测量都在 **NormalFunction** 模式下做，漏了另一种模式。
用探针把 `FunctionModeButton` 按一次切到 **DiffEqFunction**（`y' = f(x, y)`）后重测：

| tag | Normal（按 0 次） | **DiffEq（按 1 次）** |
|---|---|---|
| `x`(0) | **11.92%** | **6.83%** |
| `y`(1) | **0** | **4.86%** |
| `y'`(2) | 0 | 0 |
| 其余 15 项 | 基本一致 | 基本一致 |

`x + y` = 11.69%，与 Normal 下 `x` 的 11.92% 相当；
而 **6/85 = 7.06%、4/85 = 4.71%**，与实测 6.83% / 4.86% 吻合。

⇒ **分派表 idx 11–16 给 `x`（6 个权重）、idx 17–20 给 `y`（4 个权重）；
Normal 模式下那 10 个权重全给 `x`。`y'` 在两种模式下都不产生。**

已实现为 `aigen::VarMode { Normal, DiffEq }` + `table(mode)`。

### replay 交叉验证（375 局真实对局）

| 模式 | 机器人开火 | 含 `y` 的比例 |
|---|---|---|
| NormalFunction | 100 | **0.0%** |
| DiffEqFunction | 57 | **42.1%** |

从权重 4/85、函数平均 10 个 token 预测 `P(含 y) ≈ 1-(1-4/85)^10 ≈ 37%`，
实测 42.1%——在 n=57 的抽样噪声内。**二进制读数与真实数据一致。**

## 5. idx 17–20 那 4 个权重（已解决）

它们取的是 `0x40(%rsp)` 里预存的值（不是立即数）。运行时实测显示
普通模式下这 4 个也产出 tag 0（`x`），所以 **`x` 的总权重是 10**（见 §3.5）。

其余模式下（ODE）是否换成 `y`/`y'` 仍未测——但那不影响 NORMAL 模式的复刻。
