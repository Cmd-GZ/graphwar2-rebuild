# 73 · 变异算子：改常数、或把值包进 `+`/`*`/`/`

## 1. 位置

`FUN_005ee720`（Ghidra 址；函数表里它的体一直延伸到 `0x5ef3xx`，
因此 `docs/71` 的 token 分派也落在它体内——Ghidra 另外切出来的
`FUN_005ef020` 只是中途跳转产生的碎片）。

## 2. 逻辑（伪代码直读）

```c
// param_2 = Vec<Token> {ptr, cap, len}
uVar11 = 数出"值 token"的个数            // tag == 0(x) || 1(y) || 0x11(const)
if (uVar11 == 0) return;                  // 没有值就什么都不做
uVar3 = random_u64() % uVar11;            // 挑一个值 token
```

然后按被选中的那个 token 走三条路：

| 被选中的 token | 动作 |
|---|---|
| `y`（tag 1） | **插入**一个常数 token，值 = `N(0,1) × 10.2` |
| `const`（tag 0x11） | 掷一次随机：<br>• 一半：**原地乘** `(1 + N(0,1))` ← **微调**<br>• 另一半：换成新的 `N(0,1) × 10.2` |
| 其它 | 插入常数后，再按随机把该位置**换成** `+`(3) / `*`(6) / `/`(7) 之一 |

常数缩放常数 `0x4024666666666666` = **10.2**，与 `docs/71` 的 token 生成器一致。

## 3. 这解释了 `1770417.48`

`const *= (1 + N(0,1))` 是**乘性随机游走**：每变异一次，常数乘上一个均值 1 的随机因子。
1000 代、250 种群下常数会被反复微调上千次 ⇒ 漂到百万量级完全正常
（`docs/68` 里观测到的 `1770417.48` 就是这么来的）。

GW1 的 `mutateFineTune` 做的是同类事情，两代思路一致。

## 4. 与 GW1 的差异

GW1 的变异是"用波兰式构造器生成一个新的子表达式"，这里看到的是**在原 token 序列上就地插入/替换**，
并且明确区分子类：值 token（改常数）与算子（包一层）。

## 5. Rust 实现（已落地）

`src/aigen::mutate` 实现了**语义已读清的两条路**：

- 选中 `y` → 在其前插入 `N(0,1)×10.2` 常数；
- 选中常数 → 一半概率 `*= (1+N(0,1))`，一半换成新的 `N(0,1)×10.2`。

**第三条路（选中 `x` 或算子）本轮已实现为"推断"**：把它包一层。
伪代码里出现**两次 `memmove` + 两次写入**，最自洽的读法是

```
v  →  (op const v)      op 按 50/25/25 取 + / * / ，const ~ N(0,1)×10.2
```

实现已按此写进 `src/aigen::mutate`，并在注释里**标明这是推断**（`docs/73` §5）。

### 5.1 实现时发现的一个矛盾（待查）

测试跑出来：**`y` 分支插入常数后会短暂出现"两个值相邻"**，这在前缀式里不合法。

两种可能：

1. 调用方后面还有一趟修复（GW1 里正好有 `adjustFunction`）；
2. 我对 `y` 分支的读法不完整（例如它还会补一个算子）。

当前实现按 (1) 处理：只断言"长度不会变小、不会 panic"，
**没有**断言"变异后立刻是合法前缀式"——因为那是我未证实的假设。

配套 4 条测试：无值 token 时不动、`y` 前插常数、常数每次必变、
多轮变异后常数偏离初值（复现那条漂移）。
