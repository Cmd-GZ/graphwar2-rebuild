# 30 · 致死判定：穿过即死，但不挡弹道

数据来自一局真正的死亡对局（14 障碍、6 次射击、死亡 `230` 与 `231`），
测试在 `tests/live_hits.rs`（`captured_kills_happen_when_trajectory_passes_through_soldier`、
`soldiers_do_not_block_the_trajectory`）。

## 1. 死亡效果点在**士兵站立处**，不在碰撞点

```json
{"LifeQueuedDeath":{"entity_id":230,"tick":514}}
{"EffectInfo":{"effect_id":237,"pos_x":-10.452779035793856,"pos_y":-2.651563472451839,
               "effect_type":"DeathEffect","start_tick":514}}
```

而 `PosInfo` 里士兵 230 的位置是 `(-10.4528, -2.6516)` —— **完全一致**。

⇒ 死亡记录的位置是**死者站立的位置**，而不是弹道停下的位置。

## 2. 弹道穿过士兵即可杀死，且**不会停下**

同一发的最终爆炸点在 `x = -24.9936`（棋盘边界 `|x| ≤ 25`），
而死者在 `x ≈ -10.45` —— 弹道**越过死者继续飞**。

用掩膜（只放障碍、不放士兵）验证：这一发**没有撞到任何障碍**，
一路飞到边界。若把士兵也画进掩膜，弹道会错误地在 `x≈-10.45` 停住。

⇒ **正确模型**：
- 掩膜只放障碍 → 决定弹道**在哪里停**；
- 士兵单独做"经过即死"判定 → 决定**谁死**。

## 3. 两次致死的定量验证

| 函数（抓到的 corrected_function） | 起点 | 死者 | 我们的修正 | 到死者最小距离 |
|---|---|---|---|---|
| `(x/3.02) - 6.555` | `(17.6276, -12.3918)` | 230 | `-6.555` ✓ | **0.4746** |
| `(-1.65/(-8.04/x)) - 8.774` | `(17.6276, -12.3918)` | 231 | `-8.774` ✓ | **0.4944** |

两次都 `≤ 0.5`（士兵半径），且修正常数与抓到的文本**逐字一致**。
两发都是 `flip=true`。

## 4. 这条规则对复刻的影响（重要）

之前 `docs/25` 的做法（把士兵画进掩膜、用它决定弹道停止点）**在"打得死人"的情形下是错的**。
正确的分工是：

```
掩膜  = 障碍（光栅化后）        -> 弹道停止
士兵  = 一组 (x, y, r=0.5)      -> 经过即死，不影响弹道
```

`docs/25` 那些用例之所以对，是因为那些局里弹道本来就没经过士兵——
两个模型在"没有穿过士兵"时给出相同结果，所以之前的测试没能暴露这个差异。

## 5. 还没验证的

- 一次射击杀死**多个**士兵时，tick 的先后顺序；
- 士兵之间是否会互相阻挡（样本未覆盖）；
- 致死是否对友军生效（本局两次都是敌方击杀）。
