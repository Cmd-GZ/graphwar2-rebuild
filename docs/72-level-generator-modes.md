# 72 · 关卡生成的三种模式

## 1. 判别方法

`place_obstacle`（虚地址 `0x4f17a0`）是"往关卡里放一个障碍"的唯一入口。
它的全部调用者只有 3 个：

| 调用者 | 是什么 |
|---|---|
| `0x4e2830` | **网络事件分发器**（`remote_event_handler.rs`，switch 事件 tag 2..0x45），不是生成器 |
| `0x4f1e50` | **随机散布**生成器（`docs/55`） |
| `0x59f370` | **中心单障碍**生成器（本轮新发现） |

⚠️ **这个方法有盲区**：圆盘式生成器（`0x5ea6dc`）不调 `place_obstacle`，
而是直接把障碍结构体写进 Vec，所以不会出现在上面那份列表里。
（Ghidra 也自报该列表"另有 2 条调用引用未解析"，所以 3 个也未必穷尽。）

## 2. 三种模式

| 模式 | 入口 | 数量 | 位置 | 半径 | 随机数消耗 |
|---|---|---|---|---|---|
| **随机散布** | `0x4f1e50` | `trunc(N(0,1)*7+15)` | `x=(2r+25)(2u−1)`、`y=(2r+15)(2v−1)` | `max(N(0,1)*1.6+2.6, 0.8)` | 每个约 3~4 次（含拒绝采样） |
| **中心单障碍** | `0x59f370` | **1** | **固定在原点 (0,0)** | `u*5.0 + 3.0` ∈ **[3, 8)** | **1 次** `next_u64` |
| **圆盘式** | `0x5ea6dc` | **80**（64 + 16） | 圆内：`angle=2πu₁`、`r=7.5u₂`（后 16 个 `r=3.0u₂`） | 同上那个 `r` | 每个 2 次 |

### 2.1 中心单障碍（本轮新）

```c
FUN_004f19a0(ctx + 3);                                  // 重置掩膜
u = (double)(FUN_0057f700(ctx + 2) >> 11) * 2^-53;      // u ∈ [0,1)
FUN_004f17a0(u * 5.0 + 3.0, ctx + 3, &(0.0, 0.0));      // 半径, 掩膜, 位置=原点
```

即：**整关只有 1 个障碍，位于原点，半径 ∈ [3, 8)**。只消耗 1 次 `next_u64`。

### 2.2 圆盘式的补充细节

> ⚠️ **半径语义存疑（本轮踩到）**：圆盘式写进 Vec 的每项只有
> `{f0, f1, x, y, type, style, flag}` 七个字段，**没有独立的半径字段**，
> 位置就是极坐标算出的点。我一度把"到圆心的距离"当成障碍半径写进 Rust，
> 测试立刻暴露了矛盾（`o.r == 距离` 这个假设没有依据）。
> 因此 `src/levelgen.rs` **只实现了中心单障碍**；圆盘式等半径语义确认后再实现。


- 64 个：`angle = 2πu₁`、`r = 7.5·u₂`、`x = cos·r`、`y = sin·r`、`style = 0xf`、`flag = 1`
- 16 个：同上但 `r = 3.0·u₂`、`flag = 0`
- `type` 码 = 入口参数 + 10
- 同族还有 4 个兄弟函数（`0x5ea8a0`、`0x5ea9bc`、`0x5eab32`、`0x5eaca6`），
  各有一个调用者且都调 `next_u64`；其中 `0x5ea8a0` 只有 62 条指令，**可能是别的图案，尚未展开**。

## 3. 协议里没有"模式"字段

关卡传输就是：

```
ClearObstacles（空消息） + N × AddObstacle{pos_x, pos_y, radius}
```

`DestroyObstacle{pos_x, pos_y, radius}`（radius 恒 0.5）是挖洞，与生成无关。

抓包里没有 mode/pattern/type 之类字段（`TimeModeInfo`/`TurnModeInfo`/`AxisModeInfo`/
`FunctionModeInfo` 都与关卡形状无关）。

⇒ **客户端不关心、也不需要知道是哪种模式**；模式只存在于服务端生成逻辑里。
复刻时只要按模式生成、再逐条下发即可。

**抓包佐证**：现有 `fixtures/protocol_match.jsonl` 里 3 个障碍，最小半径 **0.80** ——
正是散布式 `max(N*1.6+2.6, 0.8)` 的下界 ⇒ 那份抓包是**随机散布**模式。
**目前没有任何圆盘式/中心式的真实抓包**。
