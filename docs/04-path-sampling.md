# 04 · 点序列采样（核心算法）

文件：`graphwar_path_calculator.rs`，`0x3c2530`（Ghidra/REA 地址 `0x4c2530`）。
这是整个游戏最关键的一段代码：**它决定子弹怎么飞**。

## 1. 它在解什么问题

玩家给的是函数 `y = f(x)`；游戏要画出一条**看起来匀速运动**的曲线，
于是要求相邻两点的**弦长**恒为 `step`：

```
L(i) = hypot( x_{i+1} − x_i ,  y_{i+1} − y_i )  =  step
```

直接把 `x` 加 `step` 是错的（斜率大时弦长会变大）。所以对每个新点，
在 `x` 的区间上做**二分**，逼近"弦长等于 step"的那个解。

## 2. 算法

```
pts = [(x0, y0)]                      # 首点就是士兵位置
x = flip ? -x0 : x0 ;  y = y0
n = (200.0 / step) as i32 ; if n < 1 { n = 1 }   # 点数预算，饱和转换（04-path-sampling.md §4.4）

repeat at most n times:
    lo = x ;  hi = x + step
    repeat at most 100 times (首次进入不计次):
        mid = (lo + hi) / 2
        L   = hypot(mid - x, F(mid) - y)
        if not (|L - step| < 0.001):       # 严格 <；等号与 NaN 都走"不满足"
            if L > step or is_NaN(L):  hi = mid
            else:                      lo = mid
            continue

        # 容差已满足 —— 普通模式还要做一次"半步复检"
        if 普通模式:
            mid2 = (x + mid) / 2
            L2   = hypot(mid2 - x, F(mid2) - y)
            hi   = mid2                    # ★ 比较之前就无条件写（0x3c2a0a）
            if not (L > L2):               # 复检不通过
                lo = x                     # ★ 退回基点（0x3c2a47）
                continue                   # ★ 两行必须同时有

        # 接受
        px = flip ? -mid : mid
        if is_NaN(px) or is_NaN(F(mid)): return pts
        if |mid| > 25 or |F(mid)| > 15:  return pts
        pts.append((px, F(mid))) ; x = mid ; y = F(mid) ; break

    若二分 100 次未收敛：整条曲线到此结束（不裁剪、不留坏点）
```

**三处"用 `x` 不用 `lo`"**：弦长算 `mid - x`、`mid2 = (x + mid)/2`、退回时 `lo = x`。
`x` 是**本点的基点**（整段内层不变），`lo` 只是本轮搜索的下界。

> ⚠️ **★ 那三行是长期漏实现的地方**。参考实现曾只写了 `lo = x`，没写 `hi = mid2`，
> 于是复检不通过后退回区间宽了一倍，在"陡峭 + 穿越对称中心"的函数上从第 4 点起分叉，
> 表现为"弹道在半空提前终止"（实况步长下约 23% 的射击）。
> 2026-11 补齐后与真二进制 **24/24 用例整条点序列逐位相等**。
> 逐条汇编清单见 **[`91-bisection-loop.md`](04-path-sampling.md)**（现行、改码依据）。
>
> 另两点：① 复检**不是**可选优化——去掉它会让二分接受远处的候选（`06-verification.md` §18 已否证）；
> ② **ODE 模式没有这段复检**（`0x3c2840` 在容差满足时直接接受），两边的 ODE 分支都不要动。

其中 `F(x)`：

- 普通模式：`F(x) = eval(tokens, x, 0, 0)`，即 `y = f(x)`
- ODE 模式：`dy/dx = eval(tokens, x, y, 0)`，用 **RK4** 积分（`h = step`）

## 5. 边界与终止

点在**入列前**检查，任一成立就停止（不是裁剪）：

- `|x| > 25` 或 `|y| > 15`
- `F(mid)` 或 `mid` 为 `NaN`
- 该点二分 100 次未收敛

后果：函数在某处无定义时，曲线干净地停住；如果第一个点就无解，子弹只有起点（哑弹）。

## 6. 两个容易踩的细节

**6.1 点数预算的饱和转换**

`(200.0 / step) as i32` 在 Rust 里是**饱和**转换：`step` 极小时得到 `i32::MAX`，
不会回绕成负数。这意味着异常小的 `step` 会让循环试图跑二十多亿次。

**6.2 第三变量 `y'` 是死的**

ODE 求值时第三个参数在**全部 7 个调用点**都传 `0`：`y'` 这个记号永远等于 0。
玩家写 `y'` 得到的不是斜率，是零。

## 7. 已知偏差（越界参数，不影响游戏）

对拍发现：`step ≈ 50` 且起点贴近 `|x| = 25`、函数在负半轴无定义（如 `ln`）时，
复刻实现会比真二进制多接受一个点。真二进制在该退化情形下更保守。

服务端 `step` 恒为 `0.01`，该区间在游戏中不可达，因此不影响玩法保真；
但严格来说，"逐位一致"的边界应描述为**游戏可达参数域内**。

## 9. 二分复检：`lo` / `hi` 的更新规则（逐条指令）

> 合并自 `91-bisection-loop`（逐条指令清单、变量地图、等价伪代码与 24/24 逐点对照：
> `archive/91-bisection-loop.md`）。这一条曾长期漏实现，是"弹道半空截断"的根因；
> `89-real-step` §5–§29 的推理已被本节结论更正（见 §9.3）。

### 9.1 一句话结论

> **半步复检不通过时，`lo` 回到基点 `x`，同时 `hi` 被拉到 `mid2 = (x+mid)/2`。**
> 判据是 **`not (L > L2)`**（汇编 `ucomisd` + `jbe`：`chord > chord2` 不成立就走退回；
> **NaN 也走退回**，因为 unordered 时 CF=ZF=1 ⇒ `jbe` 成立）。写成 `L <= L2` 会漏掉 NaN 那一支。
> 参考实现只做了前者，`hi` 保持原值 ⇒ 拒绝后的搜索区间宽了一倍 ⇒ 从第 4 点起走到另一条轨迹。

两条 `mov` 就写在比较指令的两侧，位置极容易被漏读：

| 地址 | 指令 | 作用 |
|---|---|---|
| `0x3c2a0a` | `movsd %xmm0,0x50(%rsp)` | **`hi = mid2`**（`0x50(%rsp)` = `hi`，在比较**之前**无条件写） |
| `0x3c2a47` | `movsd 0x70(%rsp),%xmm0` | **`lo = x`**（`0x70(%rsp)` = 基点 `x`，在 `jbe` **之前**装好） |
| `0x3c2a4d` | `jbe 0x3c2955` | `not (chord > chord2)`（含 NaN）→ 带着新的 `(lo=x, hi=mid2)` 进下一轮 |

证据等级：**逐位验证（读指令）+ 逐点对照真二进制（24/24）**。

### 9.2 复检「不通过」时 `lo`/`hi` 怎么变

```
0x3c2a0a  hi  := mid2 = (x + mid) * 0.5      ; 早在比较之前就写了
0x3c2a47  lo  := x                            ; 预装进 xmm0
0x3c2a4d  jbe 0x3c2955                        ; → dec ebx → 0x3c295d
0x3c295d  [0x90] := lo ; xmm0 := lo + hi = x + mid2
```

即：

```
lo = x
hi = (x + mid) / 2
```

**注意 `hi` 用的是 `mid2`，不是 `mid`。** 这是与参考实现唯一的分歧点。
【逐位：`0x3c2a0a` 确认落点是 `0x50(%rsp)`；`0x3c2966` 确认 `0x50(%rsp)` 参与 `lo+hi`】

副作用（重要）：这次「退回」**不是**在原有区间内收缩，而是把区间重置成 `[x, (x+mid)/2]`。
当 `lo` 已经被之前的迭代推到 `x` 右边时，新区间可能**与旧区间不交**、甚至更宽
（例：`lo=x+0.4s, hi=x+0.45s` → 新区间 `[x, x+0.2125s]`）。
所以这个二分**不是单调收敛**的，`MAX_BISECT=100` 不是多余保险。
【逐位（由 4.1–4.3 的更新式直接推出）+ 实测（§6 的轨迹确实跳回去了）】

### 9.3 残留未知 / 边界

#### 9.3.1 `chord2` 为 NaN 的那一瞬 —— ✅ **两头已同构，不再是差异**

`ucomisd` 的 `jbe` 在 unordered 时成立 ⇒ 汇编走「退回」；
若实现写成 `ln <= ln2`，`ln2 = NaN` 时为 `False` ⇒ 会走「接受」，与汇编不等价。
触发条件：`f(mid)` 有限但 `f(mid2)` 为 NaN（例如 `sqrt`/`log` 定义域边缘的窄带）。

> **2026-11 复核：两边都已改成 `not (L > L2)`，与 `jbe` 同构。**
> 依据：父仓库 `graphwar_curve.py` 第 475 行 `if not (ln > ln2):`、
> 本仓库 `src/graphwar_path_calculator.rs` 第 94 行 `if !(chord > chord2) {`。原文"建议按 §7.1 一起改掉"**已执行**。

- 汇编行为：**逐位验证（读指令）**；
- 这条差异在真游戏里是否真的发生、影响多大：**仍未实测**（现有 24 例没触发）——
  这是**残留未知**，不是实现差异。

#### 9.3.2 `0x90(%rsp)`（`lo` 备份）在复检段被 `chord` 覆盖

`0x3c2a13` 把 `chord` 写进 `0x90(%rsp)`，而「不满足」分支的 `hi = mid` 路径会在
`0x3c2a8c` 从 `0x90(%rsp)` 读回 `lo`。看似会读到垃圾，**实际不会**：

- `0x3c2a13` 之后只有两个出口：`0x3c2aa0`（接受，不再用 `0x90`）或 `0x3c2a4d → 0x3c2955`
  （回到 `0x3c295d`，第一件事就是 `movsd %xmm0,0x90(%rsp)` 重新写入 `lo`）；
- 而 `je 0x3c2b5d`（计数用尽）也不需要 `0x90`。

⇒ 这是编译器的槽位复用，不是语义。**逐位验证（读指令）+ 人工走全部出口**。
