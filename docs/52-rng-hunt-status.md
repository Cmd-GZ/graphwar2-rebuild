# 52 · 找 RNG：目前的进展与断点（可复现的失败证据）

## 1. 已确定：障碍从生成到发送的调用链

`tools/hook_addobstacle_bt.js` —— 在 `send` 见到 `AddObstacle` 时取调用栈，
三次样本链路一致：

```
0x8f46c3(发送) → 0x45d404 → 0x3d8d2b → 0x45a60c → 0x3f1d85 → 0x3d21f5 → 0x3d3730
              → 0x451be5 → 0x438876 → 0x43b6cb → 0x90ab4f(线程入口)
```

这是**确定**的：随机数一定在 `0x3f1d85` 或其上层被消费。

## 2. 未成：两次内存扫描都没找到活的 PRNG 状态

### 2.1 全内存扫（`tools/scan_chacha_state.js`）

在发出 `AddObstacle` 的瞬间扫 61 个 `rw-` 区间找 σ 常量 `expand 32-byte k`：
命中 7 处，全部是 **72 字节步长**的数组元素，第二、三次运行确认同样的形状。

### 2.2 栈扫（`tools/dump_stack_at_obstacle.js`）

同一时刻读调用者栈（`rsp` 起 8 KB），命中 2 处，形状与上一致：

```
+0x210  61707865 3320646e 79622d32 6b206574   ← σ 常量
        2f187e70 00000000 00000028 80000000   ← 密钥位置
        addfdacf 402ef64f 308d17ed 4025b620   ← 像 double（≈15.4 / ≈10.8）
        fd419ef4 40102cf7 02758ae9 ea41bba4   ← 像 double（≈4.04） + 垃圾
```

### 2.3 判据：这不是 ChaCha 状态

ChaCha 状态是 **16 个 u32 = 64 字节**：`[σ(4), key(8), counter(2), nonce(2)]`。
密钥位必须是随机字节。实测该位置是：

| 运行 | 偏移 +16 处的值 |
|---|---|
| 第一次（全内存扫） | `0x00007f1fe80012f0`（堆指针） |
| 第二次（栈扫） | `0x00007f69580012f0`（另一个堆指针） |
| 第三次（栈扫） | `0x000000002f187e70`（低地址，像静态/vtable） |

**每次运行都变、且不是随机字节** ⇒ 这些是"带指针的结构体"，不是 ChaCha 状态。
另外元素步长是 **72 字节**（不是 64），也对不上 `ChaCha` 结构。

## 3. 断在哪一环

| 环节 | 状态 |
|---|---|
| 定位"谁发出 AddObstacle" | ✅ 已定位（调用链） |
| 定位 RNG 实例 | ❌ 未定位：内存里的 σ 常量副本结构与 ChaCha 状态不符 |
| 读取状态并重放 | ❌ 未到达（上一步未成） |

**根本原因**：strip 后的二进制里没有符号，无法直接知道哪个函数是 `RngCore::next_u64`，
只能靠形状猜测；而候选结构（72 字节、密钥位是指针）与 rand_chacha 的内存布局不一致。

## 4. 复现方式（失败证据本身）

```bash
node tools/scan_chacha_state.js          # 全内存扫，输出命中与 16 个 u32
node tools/dump_stack_at_obstacle.js     # 栈扫，含 deref 尝试
node tools/hook_addobstacle_bt.js        # 调用链（这条是成功的）
```

每次运行的命中内容都会打印，可直接与本文档对照。
