# 74 · 适应度公式的修正版（反汇编核对）

## 1. 结论

```c
score = hits * 2_000_000.0
      - friendly_count * X * 100.0
      - 1_000_000.0
      - (V*V) / 100.0
      - (V > limit ? 50_000_000.0 : 0.0)
```

## 2. 证据（`0x51b079`–`0x51b100` 逐条）

```asm
51b079: movsd  [0x19f6d8] -> xmm0      ; 100.0
51b08f: mulsd  xmm0, xmm3              ; xmm3 = [rsp+0x78] * 100.0
51b098: cvtsi2sd esi -> xmm1           ; esi = 友军数
51b09d: mulsd  xmm3, xmm1              ;   × [rsp+0x78] × 100
51b0a1: subsd  xmm1, xmm2              ; xmm2 = -友军项
51b0ad: cvtsi2sd eax -> xmm1           ; eax = 命中数
51b0b1: mulsd  [0x19fc00], xmm1        ;   × 2_000_000.0
51b0b9: addsd  xmm2, xmm1              ; += 友军项（负）
51b0c0: imul   rdx, rcx                ; rcx = V*V  ← 整数平方
51b0d9: subsd  0x8(%rsp), xmm1         ; -= 1_000_000.0  ← **是减不是加**
51b0e7: addsd  xmm2, xmm3
51b0eb: divsd  xmm0, xmm3              ;   / 100.0
51b0ef: subsd  xmm3, xmm1              ; -= V²/100
51b0f3: mov 0x38(%rsp),%rcx ; mov 0x58(%rcx),%ecx   ; limit
51b0fb: cmp %rcx,%rdx ; jbe skip       ; V <= limit 则跳过
51b100: addsd [0x19f478], xmm1         ; += -50_000_000.0
```

常数核对（直接读 `.rodata`）：
`0x19f478 = -50000000.0`、`0x19fb30 = 1000000.0`、`0x19f6d8 = 100.0`、`0x19fc00 = 2000000.0`。

## 3. 修正了什么

| 旧说法（`docs/66`） | 实际 |
|---|---|
| `±2e6 每次命中 + (1e6 − minDist²)` | 命中 `+2e6`、友军负项、**`−1e6`**、**`−V²/100`** |
| `− minDist²/100` | 减数不是"最小距离"，而是**整数 `V` 的平方除 100** |

`minDist²` 这个说法是从 GW1 源码（`totalPoints += 1000000 - minDistSquared`）带过来的，
**GW2 改成了减 1e6 再减 V²/100**。我此前没核对符号就写进文档，属于把 GW1 的记忆当成了 GW2 的事实。

## 4. 惩罚阈值随难度变化（实测，每档 400 样本恒定）

| 难度 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| `*(u32*)(ctx+0x58)` | 5 | 5 | 10 | 15 | 25 | 200 |

难度 6 的 200 实际等于不设限（400 次采样中 `V > limit` 出现 0 次）。
比例：难度 1 约 4.25%、难度 2 约 6%、难度 4 约 7% 的评分会吃到这 5e7 惩罚。

⇒ 这是一个**随难度放宽的复杂度惩罚**：难度越高越允许多项式变复杂。

## 5. `V` 的语义：**未证明**（本轮把排查范围缩小了）

**结构上的新事实**：适应度函数的真正起点是**虚地址 `0x51ae50`**
（Ghidra `0x61ae50`；`0x51a8af` 那段属于另一个函数 `0x51a890`，两者栈帧不同，
我一开始把它们的 `0x58(%rsp)` 当成了同一个槽，是错的）。

在 `0x51ae50` 里：

```asm
51afbf: mov  %rdx,0x58(%rsp)     ; rdx = 函数的**第三个入参**
51b0a5: mov  0x58(%rsp),%rdx     ; 之后按整数使用（imul 求平方）
```

⇒ **`V` 是调用方传进来的，不是在评分函数内部算出来的**。
它的调用方只有两个（Ghidra `0x47ddf0`、`0x48b040`）——
要继续追语义，应该从这两个调用点看 `rdx` 怎么来的，而不是在评分函数里找。

观测（难度 5，400 样本）：
`3×109, 5×27, 7×26, 8×19, 14×19, 21×19, 4×15, 9×15`，**以奇数为主，且从不出现 1 或 2**。

与"表达式 token 数"的直觉最接近，但 `x` 只有 1 个 token、`sin(x)` 只有 2 个，
而 `V` 从不为 1/2 ⇒ **不能断言 V 就是 token 数**。
也可能是"算子个数""叶子数 + 根"之类。**这里只记录观测，不下结论。**

## 6. 选择与代际构成（实测条数）

| 项 | 观测 |
|---|---|
| 交叉子代 | **每代 = 0.8 × 种群**（种群 50/100/150 → 每代 40/80/120 次，稳定重复 4 代） |
| 随机新个体 | 只在**首次**批量生成，个数 = `a5 − 1`（种群 50/100/150 → 9/19/29） |
| 精英 | 栈参数恒为 5（`docs/67`） |
| 轮盘赌 | **未发现**；父代用 `rand % N` 与 `rand % (N-i) + i` 均匀随机取一段连续切片 |
| 剩下 20% | **直接复制**（详见 `docs/75`：实测不经过子代工厂；工厂入口恒为 0.8×种群） |

⇒ GW1 的「精英 5 / 变异 25 / 交叉 20」三分结构在 GW2 里**不成立**。
GW2 的实际结构见 `docs/75`：**80% 走子代工厂（交叉/随机重生 + 变异），20% 直接复制**。
（本文件早前"剩余 15% 构成未知"的说法已被 `docs/75` 的实测取代。）
