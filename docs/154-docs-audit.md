## E. 这轮审计的方法（可复跑，别只信我的话）

1. **数字**：`grep -rnE '[0-9]{3,5} passed|[0-9]{2,4} ?/ ?1080|1074|1075|647|633|327|348' docs/` 逐条判语境
   （"当前值" vs "当轮"），再用 `fixtures/guardrails.json` + `tools/coverage_matrix.py --check` 定真值；
2. **链接**：一个 20 行的脚本，对 `[`NN`](NN-*.md)` 逐行比"标签号 vs 目标文件号"，对 `[x](path)` 逐个
   `Path.exists()`；`§` 引用按"同一行里 § 之前最近的文档标记"定归属（与 `check_doc_refs.py` 同规则），
   再查该文档有没有这个节号；
3. **冲突**：同一事实在两处数值不同 ⇒ 找**更硬的那一方**（逐位 > 观测 > 代码/生成物 > 散文），
   把弱的改掉或加注；
4. **测试条数**：`cargo test 2>&1 | grep '^test result'` 再逐行求和（`cargo` 只给每个二进制的总数，
   不给全局总数 —— 这也是历史上"条数"反复写错的原因之一）。

**留给下一轮的（按性价比排）**：

1. C1/C2（把两份逐轮日志拆进 `archive/`）——主文档瘦身 5,100 行，收益最大；
2. D7（124 条空号 `§N.M` 逐条重映射）——需要先定"合并后节号"的唯一口径；
3. B13（`module_map.tsv` vs `coverage-matrix.tsv` 的模块/函数口径差：56/544 vs 78/527）——同一份函数表上重算一遍就能定案；
4. B12/B14（`AGENTS.md` 的 57 vs 58、`README.md` 的 694 → 709）——**改的人得是维护者**，不在子 agent 的改动范围里。
