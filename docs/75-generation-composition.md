# 75 · 每一代是怎么组装出来的（实测 + 反汇编）

## 1. 子代工厂 `FUN_004ee3a0`

它不是"纯交叉"，而是一个**子代工厂**，按父代长度分两条路：

```asm
4ee463: cmp $0x14,%r15        ; 父代 token 数 < 20 ?
4ee467: jae 4ee4d3            ;   否 → 走下面的交叉路径
4ee470: call 4ef020           ;   是 → 直接造一个**全新随机函数**
...
4ee5c9: call 3be7d0           ; 交叉：按 token 向量切片生成子代
4ee4c9: call 4ee720           ; 交叉之后再**变异**
4ee61d: call 4ee0e0           ; 构造/收拾成最终子代
```

⇒ 父代太短（< 20 token）时退化"重新随机"，否则"交叉 + 变异"。

## 2. 每代实测构成（难度 5，种群 250，每代 = 253 次评分）

按"每 253 次评分 = 一代"对齐，连测 8 代（`tools/hook_ga_pergen.js`）：

| 代 | 工厂入口 | mutate | randfunc | cross_core | ctor |
|---|---|---|---|---|---|
| 1 | **200** | 154 | 140 | 96 | 146 |
| 2 | **200** | 108 | 91 | 93 | 94 |
| 3 | **200** | 103 | 88 | 98 | 99 |
| 4 | **200** | 94 | 68 | 106 | 106 |
| 5 | **200** | 108 | 45 | 92 | 92 |
| 6 | **200** | 103 | 67 | 97 | 97 |
| 7 | **200** | 103 | 97 | 97 | 97 |
| 8 | **200** | 97 | 103 | 103 | 103 |

关键：

- **工厂入口恒为 200 = 0.8 × 250**（八代完全一致，这是最硬的观测）；
- 工厂内部 `mutate` / `randfunc` / `cross_core` 大致各在 90~110 区间波动，
  但**三者之和（约 290）大于工厂入口（200）** ⇒ 它们之间存在**嵌套调用**
  （例如交叉路径内部还会调变异），**不能简单相加**；
- 剩下 **50 个槽位（20%）完全不经过工厂** ⇒ 只能是**直接复制**（含 5 个精英）。

分支条件（反汇编）：

```asm
4ee449: test %ebp,%ebp        ; ebp = 新抽的随机整数
4ee44b: js  4ee4af            ; 为负（约 50%）→ 走 mutate 路径
4ee44d: mov 0x10(%r14),%r15   ; r15 = 第二父代的 token 数
4ee463: cmp $0x14,%r15        ; < 20 ?
4ee467: jae 4ee4d3            ;   否 → cross_core 交叉
4ee470: call 4ef020           ;   是 → 直接造全新随机函数
```

## 2.5 那 20% 是什么：**克隆数组头部**（本轮查清）

### 循环结构（实测 6 代稳定）

| 项 | 每代次数 |
|---|---|
| 外层循环 `0x51b829` | **50**（= 0.2 × 250） |
| 内层循环 `0x51bdb2` | **200**（= 4 × 50） |
| 子代工厂 `0x4ee3a0` | **200**（唯一调用点 `0x51be93`，运行时 9000/9000 命中） |
| 评分 `0x51a750` | 253（= 250 + 3 次精评） |

⇒ **每个外层迭代 = 1 个克隆 + 4 个工厂子代**，`50 + 200 = 250` ✅

### 克隆的代码路径（反汇编，已复核）

```asm
51b829: cmp %r14,%r12 ; jbe 51b900      ; 外层：r14 < r12 时继续
51b832: lea (%r14,%r14,2),%rax
51b836: shl $0x4,%rax                   ; rax = 索引 × 48（元素 48 字节）
51b83a: mov 0xb8(%rsp),%rsi             ; 个体数组基址
51b845: mov 0x10(%rsi,%rax,1),%r14      ; 读该条目的长度
51b874: mov 0x8(%rsi,%rax,1),%rsi       ; 读 token 指针
        ; 随后 malloc + 深拷贝 token 数组   ← 克隆
```

**索引就是外层循环计数器本身**（0,1,2,…），运行时实测克隆索引序列为 `[0,1,2,…]` 顺序前进。
⇒ **克隆的是数组头部 `0.2 × 种群` 个条目**（种群 250 → 前 50 个）。

### "为什么是头部"：**推断**

- **实测否定**：堆排序候选 `0x5605f0` 每代调用 **0 次**；插入排序候选 `0x51b500`
  **attach 失败**（不是有效指令边界）⇒ 没抓到显式排序动作；
- **实测支持**：克隆集跨代保持 **15~24 / 40 完全相同**（约 40~60%）；
  若克隆是随机挑的，跨代相同的期望接近 0（250 里随机取 50）。

⇒ **推断**：数组头部是按质量排好序的（可能是增量维护有序，而不是显式 sort），
克隆取头部 20%。**排序动作本身没有直接证据**。

### 精英 5 ≠ 这 20%

20% 在种群 250 时是 **50 个**，而栈参数恒为 **5**，两者不是同一个量。
"精英 5" 的用途仍未定（可能与精评候选或父代采样有关），**不要**把它和这 50 个克隆混为一谈。

## 3. 结论

| 项 | 结论 | 证据 |
|---|---|---|
| 交叉/工厂 | **0.8 × 种群** | 实测，八代恒 200/250 |
| 精英 | **5**（栈参数）——**与那 50 个克隆不是同一个量**，用途未定 | 实参直读（`docs/67`） |
| 剩下 20% | **克隆数组头部** `0.2×种群` 个（索引顺序） | 反汇编 `0x51b832` + 运行时索引序列 `[0,1,2,…]` |
| 变异 | 发生在**工厂内部**（交叉之后），不是独立的一类个体 | 反汇编 `4ee4c9` |
| 随机重生 | 工厂内部，父代 < 20 token 时触发 | 反汇编 `4ee463` |
| 轮盘赌选择 | **不存在**；父代均匀随机 | 反汇编 `4ee3a0` 内只用 `rand % N` |

⇒ **GW1 的「精英 5 / 变异 25 / 交叉 20」三分结构在 GW2 里不适用**。
GW2 的实际结构是：

```
每代 = 50 × (1 个克隆 + 4 个工厂子代) = 250
      克隆：数组头部 0.2×种群 个（推断：头部已按质量排序）
      工厂：交叉 [+ 变异]，或父代太短时重生随机函数
```

## 4. 仍未确定

- `cmp $0x14`（20）比较的是 **`[r14+0x10]`**，即**第二个父代** Vec 的 len
  （`mov 0x10(%r14),%r15` 直接读到，已确认来源；但"为什么只看第二个父代"未解释）；
- 数组头部的**排序动作**没有直接证据（推断）；个体结构里的分数**字段位置**未定位；
- 工厂内部 randfunc/mutate 的比例随种群状态浮动（81~134），不是固定 50/50。
