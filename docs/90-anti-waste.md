## 2.5 并发作业时的文件纪律（本轮新增，我自己犯的）

**事故**：我在修复 `live_hits` 的提交里用了 `git add -A`，把另一个 agent
**正在写、尚未完成**的 `docs/94-var-mode-trim.md` 一起扫进了我的提交。

后果：那个文件的"首次落库"落在了错误的提交里，提交信息与内容不符；
内容本身没坏（原作者随后用 `a447099` 补了最终版），但历史被污染了。

**规矩**：

1. **有并发 agent 时，禁止 `git add -A` / `git commit -a`**；
2. 一律显式 `git add <我这次改的文件>`；
3. 提交前 `git status --porcelain` 看一眼，确认列出的文件都是自己的；
4. 提交信息里不要声称"只改了 X"，除非核对过 `git show --stat`。

## 3. 下结论前的三条硬规矩

1. **先查 `AGENTS.md` 的 "Hard facts (do not re-derive)" 表**——那里已有的，禁止再"发现"一次；
2. **先证明测量工具是对的**：构造一个已知答案的用例，工具跑出已知答案，才允许用它的输出下结论；
3. **否证优先**：任何"新现象"先问"是不是我的参数/工具错了"，再问"是不是被测对象错了"。

## 2.6 ⚠️ REA 的静默陷阱：给不存在的过程地址会**按文件偏移**解析

**事故**（`docs/103` 的 agent 遇到，差点写错结论）：

给 `procedure_pseudo_code` 传一个**不存在的过程地址**时，REA **不会报错**，
而是把它当成**文件偏移**再加 `0x101000` 映射，返回一个**完全无关的函数**。
实测：传 `0x6ea6dc`（比我该用的地址多加了一次 `0x100000`）拿到的是 `FUN_007eacb0`
（一个 SSE 图像滤波函数），看起来"像那么回事"，差点被当成结论。

**规矩**：

1. 调 `procedure_pseudo_code` / `analyze_function` **之前**，先用 `procedure_info` 或
   `resolve_containing_procedure` 确认那是**函数入口**；
2. 看返回里的 `selection.mapped_address` —— 若与请求地址不同，说明它做了偏移映射，
   **结果不可用**；
3. 反汇编侧用 `objdump` 交叉核对第一条指令，别只看伪代码。

## 2.7 地址换算的老坑（再记一次）

**Ghidra = vaddr + 0x100000**，且**只能加一次**。本轮任务书里把
"vaddr `0x4ea6dc`"写成"Ghidra `0x6ea6dc`"，多加了一次 `0x100000`，
正是 2.6 那个陷阱的触发条件。真值是 **vaddr `0x4ea6dc` = Ghidra `0x5ea6dc`**。

## 2.8 REA 使用准则（本轮决策）

### 结论：**保留，但默认不用；用它之前必须先过一道检查**

弃用 REA 的理由确实存在：

- 共享会话——多个并发 agent 会互相踢掉（`start_gdb_session` / `gdb_console` 明确会关闭分析会话）；
- 首次 Ghidra 导入约 21 分钟；
- **静默陷阱**（§2.6）：过程地址不存在时不报错，按文件偏移解析出**无关函数**。

但它有一个**不可替代**的能力：**反编译伪代码**。`objdump` 只有汇编，
我们自己没有反编译器。所以不能一刀切弃用。

### 优先级（以后按这个顺序）

| 顺序 | 手段 | 适用 |
|---|---|---|
| 1 | **读现有文档 / 已有反汇编结论** | 能查到就别重新逆 |
| 2 | **`objdump`** | 需要**精确指令字节**（判据、常量、调用点）——这几轮所有确凿结论都来自它 |
| 3 | **frida 运行时观测** | 需要"实际怎么跑"（`docs/93` 的 25 秒上限就是运行时确认的） |
| 4 | **REA 伪代码** | 只有在①~③都给不出结构时，用来**快速看懂控制流** |

### 用 REA 的强制前置检查

1. 先 `procedure_info` 或 `resolve_containing_procedure` 确认**是函数入口**；
2. 看返回的 `selection.mapped_address`，**与请求地址不一致就丢弃结果**；
3. 拿到的结论**必须用 `objdump` 在其中至少一处关键指令上交叉核对**，
   对不上就以 objdump 为准。

### 并行约束

- 有 **≥2 个 agent 在读汇编**时，禁止任何 agent 调用会切换/关闭会话的 REA 操作；
- 派活时在 prompt 里显式写明"不要 `open_binary` / 不要开 GDB"。

### 现状

静态分析的大头已经做完（AI 代循环、采样器、掩膜、协议），
后续新任务**默认用 objdump + 运行时**，需要看结构时才动 REA。
