| # | 模式 | 本次实例 | 代价 |

## 2. 对策：`tools/preflight.sh`（开工前必跑）

它不是仪式，每一条都对应上面一个失败模式：

| 检查 | 对应 # |
|---|---|
| 全量 `cargo test` 必须绿 | 2 |
| 扫描 `examples/ tests/` 里硬编码的步长 | 1 |
| 断言 `SERVER_STEP == 0.01` 且与 `AGENTS.md` 一致 | 1 |
| 跑已知的早停 canary，**必须报告当前是否仍复现**（不静默通过） | 3 |
| 检查工作区是否干净、有无误提交的实验改动 | 4 |
| 打印 `.pck` 场景数 / `docs/88` 台账是否更新 | 5 |

## 3. 下结论前的三条硬规矩

1. **先查 `AGENTS.md` 的 "Hard facts (do not re-derive)" 表**——那里已有的，禁止再"发现"一次；
2. **先证明测量工具是对的**：构造一个已知答案的用例，工具跑出已知答案，才允许用它的输出下结论；
3. **否证优先**：任何"新现象"先问"是不是我的参数/工具错了"，再问"是不是被测对象错了"。
