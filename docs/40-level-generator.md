# 40 · 关卡生成：随机源是操作系统熵（不可确定性复现）

## 1. 决定性证据（活体 hook）

hook `libc` 里的随机源，跑 40 秒真实对局：

```
getrandom   : 921 次
getentropy  :   2 次
rand        :   0 次
random      :   0 次
srand       :   0 次
```

⇒ 游戏用的是 **Rust 的 `OsRng` / `thread_rng`**（底层 `getrandom`），
**种子来自操作系统熵**。

这意味着：即使我们知道生成算法，也**无法复现"同一局"的同一批障碍**——
种子不可知，而且 `getrandom` 的调用次数/位置（921 次）远超关卡生成所需，
说明整个程序在共享同一条随机流，无法从外部还原"关卡那一刻"的流位置。

## 2. 能观测到的分布（41 个障碍样本，来自 3 局）

| 量 | 观测 |
|---|---|
| 每局障碍数 | 5 / 8 / 9 / 14 / 15 / 17 / 20 / 21（各局不同） |
| `x` 范围 | `[-26.35, 25.80]` —— **超出棋盘 ±25** |
| `y` 范围 | `[-20.17, 20.58]` —— **远超 |y| ≤ 15** |
| `radius` 范围 | `[0.80, 5.26]`，均值 2.47、中位数 2.55 |
| `radius = 0.80` | 出现 6 次（占 15%），像**下限钳位** |

⇒ 障碍是**允许落在场外**的（这与"画布裁剪"一致：游戏只画可见部分，
但碰撞判定仍然对场外障碍生效）。

## 3. 结论

- **不可确定性复现**：种子来自 OS 熵，同局无法重现；
- **可统计复现**：障碍数、半径区间、位置范围有明确观测值，
  可以写出"分布上一致"的生成器，但那**不是行为等价**（判据 2 要求同输入同输出）。

因此这一行保持 `⬜/🔶`，并明确写：

> 关卡生成：观测到分布（障碍数 5~21、`r ∈ [0.8, 5.26]`、位置可越界），
> 但随机源是 OS 熵（`getrandom` 921 次/40s），**无法复现同一局**。

## 4. 唯一可能翻盘的路（未验证）

在关卡生成**之前**截获 `getrandom` 返回的字节，并把同一批字节喂给同版本的
Rust `rand`，尝试重放随机流。前提是：

1. 能确定游戏用的是哪个 RNG（`thread_rng` 是 ChaCha12）；
2. 能确定关卡生成在这条流上的**偏移**（中间有多少次其它消费）。

第 2 点从外部几乎不可能确定，所以这条路成功率很低。
